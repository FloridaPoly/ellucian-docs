Troubleshooting

Troubleshooting tips are provided.

Enable diagnostics logs

When testing a pipeline, you can toggle the Enable diagnostic log option to generate a log file after execution. After the test pipeline executes, an icon at the bottom will allow downloading the log file.

A log file is not generated if the pipeline test exceeds the maximum execution time of 2 minutes.

A generated log file contains detailed information on the input and output of each pipeline segment, as they are executed. The file information is in JSON format.

For example, a log file can contain:

  • Timestamp and type of fitting being executed.
  • Values assigned to context during pipeline initialization.
  • Output message of a fitting.

For more information on Diagnostic logging of Integration Packages pipeline jobs, please refer to the Integration Packages documentation.

Troubleshooting ideas

  • When testing, be advised that the pipeline may only execute for 60 seconds. Limit your data to a small number of records using filters or other parameters so that the pipeline can complete.
  • Disable fittings to find the problem:

    Whenever there is an issue with a pipeline, Ellucian recommends that you disable all the fittings and start testing one by one.

    By disabling the fittings, the pipeline keeps its form and data. When the test button is used, it will not use the disabled fittings. Enabling the fittings one after another and running a test allows you to identify the fitting that is causing issues.

  • Always stringify before writing a CSV file:

    Whenever the pipeline requires output into a CSV file, you need to stringify the JSON response first. There are extra properties in the File Writer fitting, such as Add Newline and Generate Presigned URL, that provide benefits.

    Setting Generate Presigned Url to ON is especially useful if you want to verify the resulted file. The test will provide the URL in the payload so you can download the file.

  • Use JavaScript Transform to pre-process data:

    Sometimes it is necessary to create data structures or format the data that you want before processing it. Ellucian recommends using the Javascript Transform fitting for this action. It is the easiest way to add, edit, transform or recreate the structure and the data as needed. The example below shows a simple rename of the properties.

    function transform (message, context) {
  const data = message.payload;
  let newPayload = {};
  newPayload.firstName = data['First Name'];
  newPayload.middleName = data['Middle Name'];
  newPayload.lastName = data['Last Name'];
  newPayload.fullName = data['Full Name'];
  newPayload.gender = data['Gender'];
  newPayload.race = data['Race'];
  newPayload.ethnicity = data['Ethnicity'];

  newPayload.oldData = data;
  message.payload = newPayload;
  return message;
}

    It is also possible to collect data from the context and use it to modify the payload.

    function transform (message, context) {
  const data = message.payload;
  let newPayload = {};
  
  // The date of birth comes in a "month cardinalDay, year" format,
  // so we are going to transform it into a local String format.
  let dateStr = data['Date Of Birth'];
  newPayload.dateOfBirth = '';
  if(dateStr) {
    // An example of how to use context values defined as our pipeline parameters.
    let dateArr = dateStr.split(context.get('dateSeparator'));
    // Format the date to change from ordinal to cardinal number for the days.
    let newDate = dateArr[0].substring(0, dateArr[0].length - 2).concat(dateArr[1]);
    newPayload.dateOfBirthFormated = newDate;
    newPayload.dateOfBirth = new Date(newDate).toISOString();
  }
  
  newPayload.oldData = data;
  message.payload = newPayload;
  return message;
}

Common questions

Some common questions are answered.

  • During pipeline execution, after an error occurs, how can I find which fitting the error belongs to?

    The Errors tab in Ethos Integration shows the fitting that caused the error. There is a View Errors link on the job run screen that takes you to an errors page. Or, you can manually search for the error on the Errors page by filtering on the Correlation ID, which is the same as the Job Run ID.

    During the design phase, the TEST button reports the exact fittings that failed.

  • Why am I receiving a timeout error?

    When testing, be advised that the pipeline may only execute for 60 seconds. Limit your data to a small number of records using filters or other parameters so that the pipeline can complete.

  • How do I successfully configure the SFTP Fitting by SFTP key?
    Make sure you have the following:
    • Create a parameter, for example sftpKey of type string, with multiline enabled.
    • Copy the value of the key. It should include the comments as well. For example, -----BEGIN OPENSSH PRIVATE KEY----- ...etc.
    • If receiving file errors, make sure the path is correct. For example /home/fileName.txt or /fileName.txt instead of just fileName.txt.
  • When scheduling a job I can set the Hours. What time zone does it use?

    You can enter the time in your local time zone and it will execute. Behind the scenes, time is stored as coordinated universal time (UTC).

  • Does the Data Connect job rerun again automatically if it fails due to any infrastructure or network issue?

    There are various levels of retry or resiliency built in:

    • When you run a job, it goes to a queue. If the Data Connect back end is down, it waits there until it can be picked up.
    • Individual HTTP calls have retry logic (like retry 10x or so) and timeouts (wait about three minutes on an individual call). After all retries have failed, the overall job in the user interface would be marked as TIMED OUT and could be run again manually or automatically on the next scheduled interval.
  • How many job runs are retained for a job?

    Data Connect retains the most recent 1000 job runs for a given job.
