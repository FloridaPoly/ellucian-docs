Quick Start

Users develop Data Connect integrations through the Integration Designer card in Ellucian Experience.

Set up access to Integration Designer

To enable a user to develop a Integration Designer Integration, you must grant that user access to the Experience card.

Example: Set up access to develop an integration

This example provides a high-level procedure for setting up users to accessIntegration Designer in Ellucian Experience. You can reference this example as you follow the detailed procedures.

This example assumes:
  • You have identified the following types of users who need access to Integration Designer: Users who can develop an integration.
  • You choose to use roles for all access (rather than assigning permissions to individual users).

High-level procedure example

Set up roles and users for Integration Designer

To enable a user to develop an integration in Integration Designer, you must grant that user access to the Experience card and to the Data Connect Designer. You must first set up the required roles and users.

About this task

Integration Designer uses a role for access to the Experience card, and either role or users for access to Integration Designer:
  • You grant card access by assigning the roles to the Experience card in on the Card Management tab of Ellucian Experience.
  • You grant Integration Designer access by assigning permissions to roles or individual users in the Permissions area of Experience Setup.

As a recommendation, you should limit access to Integration Designer to users who will be developing the integrations.

Procedure

  1. Identify all of the people at your institution who need access to Integration Designer.
    Those people will need access to the Experience card.
  2. Review the list of permissions in Data Connect Designer permissions, and identify the people who should have access within Integration Designer.
  3. Decide whether you want to grant Integration Designer permissions to individual users, or grant permissions to roles and then assign those roles to individual users.
  4. Set up the roles that you need for both card access and Integration Designer permissions, and add those roles in Experience Setup.
    See Set up roles for Ellucian Experience.
  5. In Experience Setup, add the individual users to whom you want to grant Integration Designer permissions.
    See Add administrative users.

Grant permissions for Integration Designer

In Experience Setup, grant the permissions that allow users to develop Data Connect Integration Designer integrations.

Before you begin

Before granting permissions, you need to set up the roles and users that you want to have different permissions. See Set up roles and users for Integration Designer.

About this task

Integration Designer uses a single Experience permission to support targeted user access. For example, this permission will allow the roles or individuals to:
  • Create and maintain all of the Integration Designer integrations that your institution has licensed.
  • Create, view and maintain Integration Designer crosswalks in the Integration Designer Experience card.
  • View all the Integration Designer integrations in the Integration Designer Experience card.

Procedure

  1. Access Ellucian Experience Setup:
    1. In the Ellucian Customer Center, click Tools and then select the desired Experience Setup instance under the Experience category:
      • Click Experience Setup (Test) to access the Test instance of Experience Setup.
      • Click Experience Setup to access the Production instance of Experience Setup.
    2. In Experience Setup, in the Environments drop-down, select the desired Ethos environment (for example, Test or Production).
  2. In the Experience Setup header, click Permissions.
  3. On the Permissions page, select DATA-CONNECT-DESIGNER.
  4. On the Data Connect Permissions page, assign permissions by selecting a feature in the left pane and then assigning the desired permissions to roles and individual users in the right pane.

    See Data Connect Integration Designer permissions for details about Integration Designer features and the access granted by the permission.

    See Data Connect Integration Designer permissions for details about Integration Designerr features and the access granted by the permission.

    For more information about Experience permissions, and the detailed procedure for granting permissions, see Experience application permissions.

  5. Click Save.
  6. Instruct any user whose permissions have changed to log out of Experience and log back in.
    Experience permissions are cached. Logging out and back in refreshes the cache and ensures that the user has the granted permissions within Experience.

Data Connect Integration Designer permissions

To access Integration Designer through Experience, a user must be granted permission to develop a Integration Designer integration. Additionally, this will also grant access to some features in the Integration Designer Experience Card.

The Designer-Develop permission enables users to do the following:
  • View, create and modify Integration Designer crosswalks. View all the packages and pipelines information
  • View, create, modify, delete, publish, share and unshare packages
  • View, create, modify, test, delete, publish, share and unshare pipelines
  • View, create, modify, delete, publish, share and unshare transform functions

Set up Integration Designer card in Experience

Users access the required Integration Designer functionality through the Integration Designer card in Ellucian Experience.

Before you begin

Before you set up the card, you need to set up the roles that you want to have access to the card. See Set up roles and users for Integration Designer.

Procedure

  1. Set up the Integration Designer card in the card setup wizard using the general card setup procedure in Set up an Experience card.
  2. In the Card Management tab, edit the card with Data Connect Designer in the Card Type column.
  3. In the Roles step of the card setup wizard, select the roles that you set up for access to the Integration Designer card.
    Any roles you assign to the card must have Develop permission.

First Integration Pipeline: Hello World

You can create an easy-to-follow first pipeline from start to finish.

Before you begin

The user must have Develop permission.

Procedure

Below is a sample payload in JSON format of a call to the persons API:

[
  {"name":"Viktor", "lastName":"Frankestein", "age": 30 },
  {"name":"Agatha","lastName":"De Lacey", "age": 20 },
  {"name":"Elizabeth","lastName":"Lavenza", "age": 22 },
  {"name":"Henry","lastName":"Clerval", "age": 29 },
  {"name":"Creature","age": 2 }
]
Given this input, you can:
  • Transform it into a CSV file with headers.
  • Extrapolate data, such as counting the number of records received and the average age.
  • Redact some sensitive data, such as the age of the persons.
  • Enable downloadable output.
  1. Enter your Designer Card from Experience.
  2. In the top-left corner, inside the packages sidebar, click the + button to create a new integration package.
    A package can have any number of related pipelines. The pop-up requires a package name. A package description is optional.
  3. Select your newly-created package and click +PIPELINE to add a pipeline.
  4. Add a pipeline name.
    A pipeline description is optional.
  5. Click Save.
    The Pipeline Designer displays. A list of available fittings display on the left side of the page. A fitting is a pipeline step. A pipeline contains many of these steps, which are executed in the order they are added.
  6. Expand the Transformations fitting category and select the fitting named Delimited Formatter.
    After you click it, the step is added to the pipeline and that step uses the selected fitting. A warning icon ! next to the TEST button indicates the fitting is not configured yet.
  7. Click the fitting to open the configuration section on the right side of the page.

    You can change the name to be more descriptive, such as Convert to CSV, and add an appropriate description if you want.

    Click the question mark tooltip at the right of each configuration field to learn more about its functionality.

  8. The Delimited Formatter fitting takes a JSON payload and can use a simple JSON path to extract data from said payload. Scroll all the way to the Detail section in the configuration dialog.
  9. Enable the Column Headers so that your output includes the name of the columns. Enter name to specify the path to get the name, and enter Person's Name as the label.
    The fitting evaluates the input like this, and extracts the value for name: {"name":"Agatha","lastName":"De Lacey", "age": 20 }
  10. Even though the pipeline build is not complete, you can run a test at this point. Click TEST at the top of the page.
    The test displays a form where you can execute the pipeline. Most of the pipelines retrieve their initial data from REST endpoints, files, or other data sources; however, you can pass initial data by enabling the Enter JSON Input Data option.
  11. Enable Enter JSON Input Data.
  12. Copy and paste the sample payload at the beginning of this page.
  13. Click RUN TEST.
    Note: This does not apply in this example; however, when testing, be advised that the pipeline may only execute for 60 seconds. Limit your data to a small number of records using filters or other parameters so that the pipeline can complete.
    A Results section displays below your JSON input data. By default the Raw tab result displays, but you might find the Payloads tab easier to read.
  14. Click the Payloads tab to see data formatted as CSV, such as the following: 
    [
  "Person's Name",
  "Viktor",
  "Agatha",
  "Elizabeth",
  "Henry",
  "Creature"
]
  15. Click CANCEL to go back to the configuration view.
  16. Add two more columns by clicking on ADD COLUMN button twice and fill the fields with the next information:

    Column1 - (Path: "LastName", Label: "Last Name") Column2 - (Path: "age", Label: "Age") And the test result, for reference:

    [
  "Person's Name,Last Name,Age",
  "Viktor,,30",
  "Agatha,,20",
  "Elizabeth,,22",
  "Henry,,29",
  "Creature,,2"
]

    You now have a working transformation from JSON to CSV.

  17. On the Configuration page, scroll to the Accumulators section and click ADD ACCUMULATOR.
    Accumulators are custom properties that store values to be used in the footer row. You can input a descriptive name (in this case use ageAvg) and then select the operation you want to execute (in this case Average) for parameter age.
  18. Add a footer to see the accumulated result by scrolling down to the footer section, and clicking on ADD FOOTER.
  19. You need to add a footer that is a literal type. This footer can have interpolation values. Use mustache.js to interpolate values.
    You can use this example in the Value field: Average Age:{{accumulators.ageAvg}}
  20. Run a test to validate that the data now includes a footer row with the average age. 
    [
  "Person's Name,Last Name,Age",
  "Viktor,,30",
  "Agatha,,20",
  "Elizabeth,,22",
  "Henry,,29",
  "Creature,,2",
  "Average Age:20.6"
]

    You must redact age, as it is sensitive data.

  21. Scroll to the Redaction Rules section below Accumulators.
    Similar to Columns, redact can use a JSON path to analyze data from the incoming message.
  22. Redact the age.
    1. Select the type Path to indicate that you will provide the path in the JSON.
    2. Add age to the list by typing it in the Enter Columns field and clicking the + button.
    3. To show that you have the age but are masking it, use "***" as the mask.
    The result below shows the age redacted with the specified mask.
    [
  "Person's Name,Last Name,Age",
  "Viktor,,***",
  "Agatha,,***",
  "Elizabeth,,***",
  "Henry,,***",
  "Creature,,***",
  "Average Age:"
]

    Your first pipeline is complete.

  23. Save your work for use during the exercises.
