Exercise I: Export persons data into a CSV file

To export persons data, it is necessary to configure a pipeline with fittings to collect and format the data, and finally export it into a file.

For this exercise, the first step is to add the ethosAPIKey parameter. This parameter is required for some fittings to work.

To add a parameter click on the drop-down menu aside the pipeline name, select Edit Pipeline Settings, and then click the + PARAMETER button.

Set the parameter as required and string type. The name should be ethosAPIKey so the fittings that require it select it by default. If the parameter does not have this specific name, the fittings that require it to have an API key parameter selected from the drop-down, like Ethos Proxy Get, will not work.

If the value for ethosAPIKey is known, it could be added as the default value to avoid setting it every time the pipeline run.

After adding the parameter, the next step is to create the pipeline. For this exercise the fittings needed are:

  • Ethos Proxy Get
  • For each
  • Object Mapper
  • Delimited Formatter
  • Stringify
  • File Writer

Ethos Proxy Get

This fitting is necessary to retrieve all the information of the persons API, which is going to be used to create the CSV. The configuration is simple:

  • Resource field is required, so use persons.
  • Accept version is required, so use the latest, which at the time of writing this document is 12. Write it down and then click the + button.

The response will come with a list of all the persons data adhering to the API schema format. For this exercise, review the schema of the persons API. It is necessary to provide a list of the properties that are wanted or needed in the file, and some of them might not be easily accessible because they are returned inside an array or in children objects.

This fitting is used to apply some modifications to every element in the list. It doesn't require extra configuration for this exercise.

Object mapper

The object mapper is a complex fitting, used to specify which data is required so it can be retrieved from the different properties of each person’s object.

The first property is a particular name from the list of names. The property used to filter the name from the list is preference, so any name in a persons object that has that property, is the one that is added to the file.

The following snippet is a portion of the persons payload:

"names": [
  {
    "firstName": "Pauline",
    "fullName": "Pauline Smith",
    "lastName": "Smith",
    "preference": "preferred",
    "title": "Ms."
  },
  {
    "firstName": "Pauli",
    "fullName": "Pauli Smith",
    "lastName": "Smith",
    "type": {
      "category": "favored"
    }
  }
],

In the first mapping, add the following configuration:

  • Sources -> Path: $.names
  • Target -> Name: _name

Add a transformation function to find the name that contains a property preference with the value preferred for each mapped name, for this, click in the + ADD button at the right of Transformation Functions and then configure it as:

  • Category: array
  • Function: find
  • Enter Parameters: preferred - $.preference (Click + button after entering each parameter)

After defining the names mapping, the content is accessed using the property _name in any of the mappings. You only need to add a reference in the default value, as described in the Object Mapper fitting for mappings.

Create a second mapping to retrieve the value of the firstName property inside _name, for this, click in the + MAPPING button at the end of Mappings section and fill the fields with the next information:

  • Sources -> Default Value: {{mapped._name}}
  • Target -> Name: First Name

It is necessary to create a transformation function for this seccond mapping to retrieve the value from the object, click in the + ADD button at the right of Transformation Functions and use the following:

  • Category: object
  • Function: get
  • Enter Parameters: $.firstName (Click + button after entering this parameter)

To retrieve middleName, lastName and fullName, it is necessary to create additional mappings with the same configuration as for firstName. For this exercise, the target values to be used are "First Name", "Middle Name", "Last Name" and "Full Name".

There might be cases where additional information is needed from a different part of the object or that require a certain format. For this example, three more properties will be retrieved: dateOfBirth, ethnicity and race.

Because dateOfBirth is a property that is accessible in the first level, it can be retrieved directly, however, a different format to the date is going to be used so it looks more user friendly. To do that, it is necessary to use a Transformation Function for date.

As described in the documentation, the transformation function category for date accepts input and output date format strings based on Moment.js Format documentation, so it will transform the date from "YYYY-MM-DD" to a "MMMM Do, YYYY" format by adding those parameters (the order is important).

Create a new map and fill the fields with the following information:

  • Sources -> Path: $.dateOfBirth
  • Target -> Name: Date Of Birth

And a transform function for the map with the following:

  • Category: date
  • Function: format
  • Enter Parameters: MMMM Do, YYYY - YYYY-MM-DD (Click + button after entering each parameter)

The next value from persons to be mapped is ethnicity. The code snippet shows the portion of the payload that contains it:

"ethnicity": {
  "ethnicGroup": {
    "id": "7582a6e5-328b-489b-9b28-6fdf7b555b89"
  },
  "reporting": [
    {
      "country": {
        "code": "USA",
        "ethnicCategory": "nonHispanic"
      }
    }
  ]
}

For this exercise, the ethnicCategory value is retrieved. To do that, another mapping is added with the next information in the fields (note that we are using full path as source):

  • Sources -> Path: $.ethnicity.reporting[0].country.ethnicCategory
  • Target -> Name: Ethnicity

The last mapping is for races, and like the names property, the races property is an array.

"races": [
  {
    "race": {
      "id": "598b3e89-544a-4a13-80a2-a1b7fca69d02"
    },
    "reporting": [
      {
        "country": {
          "code": "USA",
          "racialCategory": "asian"
        }
      }
    ]
  }
]

For this example, instead of filtering a particular race, like what was done with names, all the races the person has assigned will be retrieved and then concatenated using a “|” symbol.

The first step is to define the full path to get the racial category of every race object in the array. Create a new map and use:

  • Sources -> Path: $.races[*].reporting[0].country.racialCategory
  • Target -> Name: Race

The xpath definition used will return an array of racialCategories, so it is necessary to add a transformation function to concatenate or join the values. Add a transform function with:

  • Category: array
  • Function: join
  • Enter Parameters: | (Click + button after entering the parameter)

Delimited formatter

The delimited formatter is the fitting used to create the final format for the CSV, here is where the mapped properties created by the object mapper will be used.

This fitting has certain levels of customization for header, footer, and details, however for this exercise, only the details are going to be described. To do this, it is required to use the names of the properties and the mapped data that was created.

Most of the properties were already mapped using the object mapper, the target value of each of those mappings can be assigned to path so it can get the data, however, gender is a property that hasn't been mapped, it is contained in the original object, therefore the label Gender will be used as column header.

In the Details section, turn on the Column Headers check-box, your columns should look like this:

  • Path: First Name
  • Path: Middle Name
  • Path: Last Name
  • Path: Full Name
  • Path: gender, Label: Gender
  • Path: Ethnicity
  • Path: Race
  • Path: Date Of Birth

Running the pipeline using the RUN TEST button will retrieve all the persons data in a comma separated list of payloads.

The final step is to generate the CSV file, however each of the payloads that are going to be written to the file need to be transformed into a string, and then use a File Writer.

Stringify

This fitting doesn’t need any configuration. It is only necessary to add it after the Delimited Formatter to 'stringify' the JSON payloads.

File writer

This fitting will allow the pipeline to create a file into Ellucian cloud storage.

The only necessary input is the name of the file. Because it contains a list of persons information, the option Add Newline After Each Message will be set to ON or true. The option Generate Presigned Url should be set to ON or true too, so the payload will retrieve the presigned URL to get the file.

Finally, run the pipeline by clicking the RUN TEST button to verify everything works as intended.

Copy the URL in the payload and paste it in a browser to verify the CSV file was created with all the expected data.

Exercise II: Import persons data from a CSV file

You can import a CSV file that contains persons data and convert it to a JSON file.

The first thing needed is to configure the pipeline parameters. For this exercise, two parameters are required.

  • The first one is going to be fileName, of type file.
  • the second is going to be dateSeparator, of type string.

The purpose of fileName is to allow you to upload a local file to the S3 bucket, so it can be used as the input data. The file used is the same file that was created with the example file generated in Exercise I: Export persons data into a CSV file.

The second parameter, dateSeparator, is added to give an example of how to use context parameters in a JavaScript transform fitting. The default value for this parameter is a ",".

After configuring the parameters for the pipeline, The next step is to add and configure the fittings.

The fittings used for this exercise are:

  • JavaScript Transform
  • Add to Context
  • File Reader
  • Line Parser
  • Delimited Parser
  • Object Mapper
  • Stringify
  • File Writer

JavaScript Transform (Date)

The first fitting is used to add a datetime record to know when the file was imported. The main purpose of this fitting in the exercise is to show how to add values to the context so they can be used later. The data can come from any resource, either use an Ethos Proxy GET to retrieve some data, read a file, add a new variable, etcetera.

This fitting is used to inject the date into the payload. Set the parameter name as dateNow:

function transform (message, context) {
  // Put your code here.
  message.payload.dateNow = Date.now();
  return message;
}

Add to Context

Add to context is a simple fitting. It only provides a way to insert a value to the context from the payload so the configuration is easy. Use $.dateNow as the Source and _importDate as the Target. The fitting takes the dateNow value and creates a context parameter named _importDate.

File Reader

The file reader is a fitting used to retrieve the data of a file from the store.

The configuration of the File Reader requires only the name of the file in the Key field.

There are a couple of methods to add the file name, the first one is by using {{context.fileName}}.

If this method is used, you have to select the file (using the file parameter) every time to upload it to the store, then the file reader uses that name to find and retrieve the file.

The second method is to provide a specific file name in the configuration, like file.csv.

By doing it this way, selecting the file every time after the first time is not necessary. The file needs to be uploaded one time so that the file reader can find it, it won't be necessary to do it anymore as long as the file (with that name) exists in the store. If the file does not exist, the response will contain an error like this:

Line Parser

The line parser is a fitting that will split the payload into multiple messages for each new line character it finds. The line parser fitting does not need any configuration.

Delimited Parser

The delimited parser is a fitting that will format the message that comes either in a tab or comma delimited data into a JavaScript object.

The delimited parser configuration has an optional property named Target that can be used to place the output array, however this exercise is not going to use it.

The delimited parser assumes that the first line it receives is the header line, so the CSV file that was used works perfectly with this fitting. It will format the message into an array of JavaScript objects.

JavaScript Transform (Data)

This is the second JavaScript transform fitting used for this exercise. This time, the fitting will change some of the data.

The first part of the function reassigns the data to other object properties that are in a camelCase format.

The second part formats the Date of Birth. In the CSV file, the date was in a "MMMM Do, YYYY" format. This means the month is in full text and the day is an ordinal number like June 1st, 2010, however this value cannot be used to create a date so it is necessary to format it.

First, the dateSeparator parameter, which was defined as a comma for this exercise, is taken from the context and used to split the date string, this will return an array with two values (June 1st) and (2010), and then the values are concatenated to get August 13 1977. Finally, create a new Date object and convert it to a string following the ISO 8601 Extended Format.

function transform (message, context) {
  const data = message.payload;
  let newPayload = {};
  newPayload.firstName = data['First Name'];
  newPayload.middleName = data['Middle Name'];
  newPayload.lastName = data['Last Name'];
  newPayload.fullName = data['Full Name'];
  newPayload.gender = data['Gender'];
  newPayload.race = data['Race'];
  newPayload.ethnicity = data['Ethnicity'];
  
  // The date of birth comes in a "month cardinalDay, year" format,
  // so we are going to transform it into a local String format.
  let dateStr = data['Date Of Birth'];
  newPayload.dateOfBirth = '';
  if(dateStr) {
    // An example of how to use context values defined as our pipeline parameters.
    let dateArr = dateStr.split(context.get('dateSeparator'));
    // Format the date to change from ordinal to cardinal number for the days.
    let newDate = dateArr[0].substring(0, dateArr[0].length - 2).concat(dateArr[1]);
    newPayload.dateOfBirthFormated = newDate;
    newPayload.dateOfBirth = new Date(newDate).toISOString();
  }
  
  newPayload.oldData = data;
  message.payload = newPayload;
  return message;
}

In this step of the test, the original data of the payload (oldData), and the formatted date of birth (dateOfBirthFormatted) are assigned to the new object, the purpose is to show the changes, however both will be removed after this step. The payload now has the dateOfBirth formatted and ready.

Object Mapper

The object mapper is used to map some properties in the payload.

The first mapping uses the _importDate parameter that was added to the context before and adds to each object in the array of payloads:

  • Sources -> Default Value: {{context._importDate}}
  • Target -> Name: importDate

After that, add a transformation function that converts the date to a YYYY-MM-DD HH:mm:ss.SSS string format:

  • Category: date
  • Function: format
  • Enter Parameters: YYYY-MM-DD HH:mm:ss:SSS (Click + button after entering the parameter)

    Enter Parameters: YYYY-MM-DD HH:mm:ss:SSS (Click + button after entering the parameter)

Add a second mapping, this adds a new property, named ethnicityCode, to the object:

  • Sources -> Path: $.ethnicity
  • Target -> Name: ethnicityCode

This time, the exercise shows how to use crosswalks to customize some translation values, it also enables you to set a default code value in case the ethnicity comes with an empty value. The name of this crosswalk is ethinicityCrw. Add a transform function with the following values:

  • Category: util
  • Function: crosswalk
  • Enter Parameters: ethinicityCrw (Click + button after entering the parameter)

In the crosswalk section, click in the + CROSSWALK button to create the mappings for the crosswalk. In this exercise, two source values will be mapped: hispanic and nonHispanic, for anything else the ethnicityCode is going to have UNK as the value. Configure your crosswalk as follows:

  • Crosswalk Name: ethinicityCrw
  • Default: UKN
  • Mapping01:
    • Mapping Name: non hispanic
    • Target Value: NONHSPNC
    • Source Value: nonHispanic
  • Mapping02:
    • Mapping Name: hispanic
    • Target Value: HSPNC
    • Source Value: hispanic

Stringify

Stringify is added to transform the payloads to JSON strings so that they can be used later by file writer. It does not need any configuration.

File Writer

This fitting creates a file in Ellucian cloud storage.

To configure the file writer, the name is necessary. In this exercise the file name will be personsImportFromCsv.json. Switch the Generate Presigned Url feature to ON or true so the response contains the URL to download the file.

Both Add Newline After Each Message and Include Total Count are optional, for this exercise set both switches ON or true. The first configuration makes the JSON file more readable, the second option includes the total count in the response.

Finally, test the pipeline to verify that the file is created. Copy the presignedUrl and paste it in a browser to get the JSON file and verify that the data is correct.

Exercise III: HTML Formatter fitting example

You can use the HTML Formatter fitting to create HTML output that includes data gathered from one or more sources associated to the institution.

Before you begin

This example requires you to provide a JSON file as input when the pipeline is run, and that JSON file is to have the data that will be parsed by the HTML template Mustache expressions.

Under other use case scenarios, it is possible the data will come from GET API calls in the pipeline, made before running the HTML fitting, so the file as input is referenced here for example purposes.

About this task

When the pipeline is run, it uses the information provided as part of the HTML template, processes any Mustache tags, replaces them with the provided data, and produces HTML output that can be saved as a target file.

See HTML Formatter fitting for a description of the HTML Formatter fitting.

For more information on Mustache tag expressions, see https://mustache.github.io/mustache.5.html.

Procedure

  1. In Ellucian Experience, click the Integration Designer card to open the Integration Designer.
  2. Select the Integration Package this new pipeline will be in. An Integration Designer package should contain pipelines that relate to each other. If necessary, create a new package.
    1. To create a new package, click + in the Packages section of the Integration Designer.
    2. Create a unique name for the package.
    3. Optional: Add a description of the package contents.
    4. Click Save.
    5. Select the package you just created in the list of packages to continue.
  3. In the package, create a new pipeline.
    1. In the Pipelines section of the Integration Designer, click + PIPELINE to create a new pipeline.
    2. Enter a unique name for the pipeline.
    3. Optional: Add a description for this pipeline.
    4. Click Save to save the pipeline.
  4. In the Integration Designer for your new pipeline, click More next to the pipeline name.
  5. Select Edit Pipeline Settings.
  6. Click + PARAMETER to add the parameter to allow you to upload a JSON data file each time the pipeline is run.
  7. Define the new parameter to upload the file.
    1. Enter a unique name for this parameter.
      The parameter name must be a single word starting with a letter, dollar sign, or underscore, and cannot have any special characters.
    2. Set Label and Default to None (default).
    3. Enable Required.
    4. Disable Sensitive (default).
    5. Change Type to File.
    6. Click Add Parameter.
      Next, you will add the necessary fittings to the pipeline: File Reader, Reducer, JSON Parser, HTML Formatter, and File Writer.
  8. Add a File Reader fitting.
    This will retrieve the contents of the file that will be provided when the pipeline is run.
    1. In the side menu, click Sources to open the list of fittings that consume data.
    2. Click File Reader to add a File Reader fitting to the pipeline.
      For additional information about this fitting, refer to File Reader fitting.
    3. Click the new File Reader fitting to open the details pane.
    4. Optional: Replace the default fitting name (File Reader) with a descriptive name.
    5. Optional: Add a description for this fitting.
    6. Enter the file name in the Key field.
      The file name must be all lowercase letters and should match the name of the file that will be provided when the pipeline runs.
    7. If uploading a local file, do not select any values for Bucket, Access Key ID, or Secret Access Key.
    8. Click Save to save the segment.
  9. Add a Reducer fitting.
    This will ensure the full contents of the file are accumulated and passed along as a single message to the rest of the pipeline fittings.
    1. In the side menu, click Destinations to open the list of fittings that send data to an end state.
    2. Click Reducer to add a Reducer fitting to the pipeline.
      As part of the reducer, you can specify which property will include the captured data and pass it along to the next fitting. You can specify the default payload property as the accumulator See Reducer fitting.
    3. Click the new Reducer fitting to open the details pane.
    4. Optional: Replace the default fitting name (Reducer) with a descriptive name.
    5. Optional: Add a description for this fitting.
    6. Required: Enter a value in the accumulator field.

      This is the property in the new payload upon which to set the accumulated array of payloads.

      For this example, save this back to the payload property. See the reference in the HTML Formatter fitting to the message.payload in Mustache.

    7. Click Save to save the segment.
  10. Add a JSON Parser fitting.
    At this moment, the JSON file contents are in string format, so the JSON object needs to be restored. To achieve this, include a JSON Parser fitting.
    1. In the side menu, click Transformations to open the list of fittings that transform data.
    2. Click JSON Parser to add a JSON Parser fitting to the pipeline.
      For additional information about this fitting, refer to JSON Parser fitting.
    3. Click the new JSON Parser fitting to open the details pane.
    4. Optional: Replace the default fitting name with a descriptive name.
    5. Optional: Add a description for this fitting.
    6. The fitting accepts any type of incoming message, but will only parse one that has a JSON string payload.
    7. Click Save to save the segment.
  11. Add a HTML Formatter fitting.
    As part of the template property, include any HTML content you want the fitting to process, including Mustache tag references to the data that is being passed along.
    1. In the side menu, click Transformations to open the list of fittings that transform data.
    2. Click HTML Formatter to add a HTML Formatter fitting to the pipeline.
      For additional information about this fitting, refer to HTML Formatter fitting.
    3. Click the new HTML Formatter fitting to open the details pane.
    4. Optional: Replace the default fitting name with a descriptive name.
    5. Optional: Add a description for this fitting.
    6. Required: Enter a value in the Template field.
      This is HTML content with or without Mustache expressions. If payload data is referenced from the Mustache tags, ensure the tags reference the full structure, such as {{message.payload.field}} or the corresponding property where the JSON data objects are stored.
    7. Click Save to save the segment.
    After the pipeline processes the HTML content and replaces any Mustache tag placeholders, a File Writer fitting can capture this output and generate a file for it.
  12. Add a File Writer fitting.
    1. In the side menu, click Destinations to open the list of fittings that send data to an end state.
    2. Click File Writer to add a File Writer fitting to the pipeline.
      For additional information about this fitting, refer to File Writer fitting.
    3. Click the new File Writer fitting to open the details pane.
    4. Optional: Replace the default fitting name with a descriptive name.
    5. Optional: Add a description for this fitting.
    6. Enter a File Name for the output HTML file name.
    7. Optional: For testing purposes, you might want to select Generate Presigned Url to configure the File Writer to generate a presigned URL with the output for the file.
    8. Configure Bucket, Access Key ID, or Secret Access Key information as needed for a target location, or leave this information blank so the file can be downloaded from the job run page as needed.
    9. Click Save to save the segment.
  13. Click Save to save the pipeline.
    Your pipeline should look similar to this example.

  14. Optional: Test the pipeline, providing a JSON file as input that matches the data structure the HTML template is expecting.
    1. While viewing your new pipeline in the Integration Designer, click Test.
    2. Click Upload File and select the input JSON file.
    3. Optional: Enable Enable Diagnostic log to generate a diagnostic log for this pipeline execution.
      The log file will be available after the test completes. Refer to Enable diagnostics logs in Troubleshooting for more details.
    4. Click RUN TEST.
    5. When the test completes, review the results.
      The Raw tab result displays by default.

      Results display for the last segment executed. See the log file for test results for other segments in the pipeline.

      If the test is unsuccessful, review your fittings setup and refer to Troubleshooting for more assistance.

    6. If you turned on the Generate Presigned Url property on the File Writer, the Raw output of the test will include the URL with the location of the HTML file that was generated. Copy and paste this address (without the quotes) in another window in your browser to see the contents of the file, and verify it is the output that you expected.
    For more details about the Test process and overall publishing process, see Publish integration pipelines.
  15. Publish the pipeline.
    1. Click Publish.
    2. Select a release version to publish.
    3. Click Publish.
  16. Access the Integration Packages card from Data Connect. Ensure permissions have been granted for your user in Experience Setup so that the new pipeline is available. See Quick Start.
  17. Select the new pipeline you just published and click + New Job to create a new job.
    1. Enter a job name.
    2. Click Upload File and provide a JSON file as input that matches the data structure the HTML template is expecting.
    3. Leave Run Now selected (default).
    4. Click Save to run the job.
  18. If there is an error while the Data Connect job is running, review the Data Connect logs.
    See Common questions.

Snippet: Crosswalk setup

You can set up a global crosswalk.

This is a simple example of setting up a global crosswalk. See Develop pipelines: Crosswalks.

Refer to Object Mapper fitting documentation for more Crosswalk configuration details.

For this example, you can work with the following input:

[
  {"name":"Jim", "lastName":"Hawkins", "job": "Cabin boy" },
  {"name":"Long John","lastName":"Silver", "job": "Pirate" },
  {"name":"David","lastName":"Livesey", "job": "Doctor" }
]
You will create a crosswalk that will translate job into a generic codes: SEA_BASED, EARTH_BASED.
  1. First create the crosswalk in the Crosswalks page. Click Crosswalks in the navigation menu within the Integration Packages extension.
  2. Click on + after List of Crosswalks to add a new crosswalk, for this exercise, we will name it jobCrosswalk
  3. Use the presented screen to create mappings.
  4. Use {{input}} as the Default Target Value. This value will cause the original input to be used if no match is found.
    Note: The Mapping Name is free form, Target Value defines the output code and Source Values can be a list with values that the engine will match on the input.

For this example, use the next mappings:

  • Mapping01:
    • Mapping Name: earth job code
    • Target Value: EARTH_BASED
    • Source Value: Doctor
  • Mapping02:

Snippet: How to retrieve nested data from payload

There might be cases when you need to collect data from different arrays or properties in a JSON response. For these cases, Ellucian recommends to first find the information that you want to retrieve. Try retrieving the names from the persons resource.

After calling the resource, the response is returned with something similar to:

"names": [
  {
    "firstName": "Katherine",
    "fullName": "Katherine Jenkins",
    "lastName": "Jenkins",
    "preference": "preferred",
    "title": "Ms."
  },
  {
    "firstName": "Kate",
    "fullName": "Kate Jenkins",
    "lastName": "Jenkins",
    "type": {
      "category": "favored"
    }
  }
],

The objective is to retrieve the preferred name, so it is necessary to create an Object Mapper (If there are multiple objects, you must create a For Each fitting before the Object Mapper), define a mapping and a function.

Path is a JSONPath so, the mapping requires to define the path and a target name:

  • Sources -> Path: $.names
  • Target -> Name: Name

If the test is run like this, the response will contain the whole array defined in names, so a transformation function is required. The function find requires you first define the value and then the property in the parameters list:

  • Category: array
  • Function: find
  • Enter Parameters: preferred - $.preference (Click + button after entering each parameter)

The response payload contains the object that preference value was preferred.

This can also be refined by adding an extra transform function to collect only the firstName:

  • Category: object
  • Function: get
  • Enter Parameters: firstName (Click + button after entering the parameter)

The response payload retrieves the expected value: "Name": "Katherine".
