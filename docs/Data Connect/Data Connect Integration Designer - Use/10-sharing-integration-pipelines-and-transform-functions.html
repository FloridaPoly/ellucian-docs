Sharing integration pipelines and transform functions

Pipelines and transform functions can be shared with another tenant, if required.

Sharing an artifact will also automatically share the package that the pipeline belongs to, however the shared package in the target tenant will only contain the shared pipelines and transform functions. Unshared artifacts in the original package will not be visible in the target tenant. Only published pipelines can be shared with another tenant.

A shared artifact will appear in the Integration Packages user interface (UI) of the target tenant under the original package name. From here, you can create jobs for the pipeline, however the shared pipeline or transform function will not be available under the Integration Designer for you to edit or use to create drafts. It will only be available in Integration Packages UI.

Major versions of a pipeline are treated as different pipelines; consequently, each major version of the pipeline can be shared separately. Pipelines and transform functions can be shared from the Integration Designer.

Share individual pipelines

You can share a single pipeline.

Procedure

  1. To share, access the Integration Designer. Each version of the published pipeline has a Share pipeline link that is shown when doing click on the three dots icon under Actions tab. This link can be used to view the tenants with which the pipeline has already been shared with and to then share it with additional tenants, if needed.
  2. Clicking on this link will take you to the Pipeline Shared With screen which displays all tenants with which the pipeline has been shared. If the pipeline has not been shared, the Not shared with any tenants message message displays. Click the SHARE button on the upper-right corner to share the pipeline.
  3. Clicking on the SHARE button opens up a Share Pipeline dialog box. This dialog shows a list of tenants that belongs to the current account, will also include all member institutions in the case of a multi-institution account.
  4. Below the name of the pipeline, there is a Search bar that you can use to search within the displayed tenant list by tenant id, tenant name, or account name. You can enter a complete or partial value for any of these identifiers and the table below will be filtered to display the tenants whose tenant ID, name, or account name contains the search string. The search is not case sensitive.
  5. When the search results display, you can select the required tenants from the search results, or if you want to share the pipeline with all tenants that are part of the search results, click Select all search results.
  6. Click Select all search results to select all tenants across multiple pages. If your search has a total of 14 results displayed across three pages, Select all search results selects all 14 available items. To clear the search, click the x Clear icon on the Search bar to display the original tenants list; however, if you selected all or some of your search results, those tenants remain selected as shown by the "number Selected" text at the bottom left corner of dialog.
  7. If you want to share the artifact with all the tenants that belong to your account, you can choose the Select all n option where n is the total number of tenants displayed. You can manually unselect any of the selected tenants or use the CLEAR SELECTION button to clear all your selections. Select All and CLEAR SELECTION only appear in the dialog if you have selected at least one tenant in list already.
  8. When you are satisfied with your selections, click the SHARE button to proceed with sharing the pipeline with the selected tenants.
  9. This action opens up a confirmation dialog that shows a list of your selections so you can verify and confirm that you want to proceed with the share. Click BACK to return to the tenant selection screen and click CANCEL to exit out of the entire process. Click the SHARE button to share the pipeline with the selected tenants.
  10. If sharing is successful, you are returned to the Pipeline Shared With screen where a Pipeline shared successfully message and the tenants that you shared the pipeline with display. If an error occurs during sharing, an error message displays on the screen. This screen also contains a search bar where you can search within the tenants with which the pipeline has been shared.
  11. If you publish a new patch or minor version of the shared pipeline, the tenants that you have already shared the pipeline with do not have the updated version of the pipeline. To ensure that the shared tenants have the latest update of that major version, use the UPDATE ALL button in Pipeline Shared With screen.
    Note: The SHARE button does not appear until you have clicked UPDATE ALL.
  12. Click UPDATE ALL to display a confirmation dialog asking you to confirm the update. Click UPDATE ALL from the confirmation dialog to update the shared tenants with the latest version.
  13. As each major version of the pipeline is considered to be a different pipeline, the update all functionality only becomes available to new patch or minor versions of an already shared major version. For example, if v1.0.0 has been shared, update all is available to all 1.x versions (1.0.1, 1.1.0 and so on). A new major version, such as v2.0.0, is not considered as shared.

Share multiple pipelines

You can share multiple pipelines at the same time.

Procedure

  1. If you want to share multiple pipelines all at once, you can do so from the Integration Designer screen. When selecting a pipeline by clicking on the check box, a share icon displays on the top right corner. Next to the share icon is a CLEAR SELECTION button to clear all selections, a Select All button to select all pipelines, and text showing the number of pipelines selected. Clicking on the share icon opens up the Sharing dialog.
  2. The Sharing dialog is the same as that for sharing individual pipelines. However, in this case the names of all the pipelines that are shared display at the top.
  3. Search for, select, and add tenants in the exact same way as for individual pipelines. When you are done, click SHARE to open the confirmation dialog with the list of selected tenants.
  4. Click the SHARE button to share all the selected pipelines with the selected tenants. A Pipeline shared successfully message displays when sharing is successful. Click Share Pipeline for each pipeline to confirm the share.

Share transform functions

Pipelines and transform functions can be shared with other tenants.

Procedure

  1. The process for sharing transform functions is very similar to pipelines. The link for sharing individual transform functions display when you click the three dots icon under the Actions tab for each transform function. Selecting at least one of the transform functions displays the multiple sharing icon.
  2. Clicking either sharing option displays the share dialog with the tenant selection. Sharing each transform function or multiple transform functions at the same time is exactly the same the pipelines steps.
    Pipeline and transform functions can now be shared with other tenants.

Unshare

There are certain situations, such as when you accidentally share a pipeline to a wrong tenant or discover a critical issue with a shared pipeline, when a pipeline needs to be unshared from a certain tenant. To address this, Designer provides the unsharing feature.

About this task

You have the ability, using the unsharing functionality, to remove previously shared pipelines and transform functions from a target tenant. However, there are some things to take into consideration before unsharing:

  • Ellucian recommends that the target tenants terminate any active or scheduled jobs before unsharing a pipeline from them. Unshare carefully and communicate beforehand.
  • Major versions of a pipeline are treated as different pipelines. Consequently, they are unshared by major version; This means that you can unshare Pipeline 2.X.X but the target tenant can still see and use Pipeline 1.X.X in their Integration Packages UI.
  • When unsharing happens, the unshared pipeline are no longer visible in the Integration Packages UI of the target tenant so they are not able to create more Jobs or make new job runs from it.
  • If no more pipelines and transform functions belonging to the same integration package are left shared in the target tenant, the package is not listed any longer in their Integration Packages UI.
  • Unsharing a transform function can result in unexpected behavior: Transform functions are cached by jobs for up to one (1) hour, and therefore can still be used for some time by an active job.
  • It is not recommended to unshare transform functions before unsharing the pipelines that use them first.

It is important to note that unsharing a pipeline and a transform function are the exact same process, in this example a transform function will be unshared.

Procedure

  1. To unshare, access the Integration Designer screen and select a transform function. Click the three dots icon under the Actions tab and then select Share.
    The Sharing Details screen displays.
  2. All current tenants that the transform function is shared with display in the main table. Select and unshare multiple tenants in one batch or unshare them individually. To unshare in one batch, select the tenants you want to target for unsharing by clicking the check box on the left hand side of the table, and then click on the UNSHARE TRANSFORM FUNCTION button located in the top right corner.
  3. This will prompt a confirmation dialog showing the selected tenants. Click the UNSHARE TRANSFORM FUNCTION button.
  4. This transform function has been successfully unshared from the target tenants. Only this major version of the function has been unshared; other major versions of this function (if shared earlier) are still shared. To unshare any other major version you can repeat this process by selecting that specific version.
  5. Click the UNSHARE TRANSFORM FUNCTION located inside the rows of the main table to unshare the transform function individually.
    Note: This action does not ask for a confirmation and the unshare is done instantly.

Rollback

The rollback feature allows you to remove the last shared version from tenants it was shared with.

Procedure

Any previous versions that were shared will remain intact and users on the shared tenant side will still be able to view and run previous versions. If you need to completely remove a pipeline, see the Unshare process.

Considerations to be taken into account while rolling back a version of the pipeline are similar to that of unsharing:

  • It is recommended that the target tenants terminate any active or scheduled jobs before rolling back a pipeline from them. Rollback should be done carefully and with communication beforehand.
  • If any previous versions of the pipeline were shared with the target tenant, that version will still be visible on the Integration Packages UI of the target tenant.
  • After a rollback, the package may not be listed in the target tenant. If no more pipelines and transform functions, belonging to the same Integration package, are left shared in the target tenant, the package will not be listed any longer in the Data Connect Integration Packages user interface.
  • Use the same process to rollback a transform function.

For example:

  1. Tenant A has shared pipeline version 1.1.0 and 1.1.1 shared with Tenant E.
  2. On Tenant E's Integration Packages UI only the latest version (1.1.1) is visible.
  3. To rollback pipeline v1.1.1, you need to access the Integration Designer screen of the owner tenant (Tenant A). Click the Share Pipeline action of pipeline v1.1.1 to display the Pipeline Shared With screen.
    A ROLLBACK ALL button is present on the top right corner of the screen.
  4. Click the ROLLBACK ALL button to display a confirmation dialog asking you to confirm that this particular version is being rolled back from all shared tenants. You will also be informed that if only this version has been shared, the tenant will no longer have the artifact.
    A Pipeline rolled back from tenants successfully message displays.
  5. When the process completes, the Pipeline Shared with screen displays the UPDATE ALL button, because the older version is still shared with tenants. This is to prompt you to update shared tenants with latest version (v1.1.1).
  6. Now on Tenant E's Integration Packages UI, only the previous version of the shared pipeline (v1.1.0) displays.
  7. The rollback process for the transform function is the same as that of the pipeline.

Share serverless APIs

You can share serverless APIs.

Sharing serverless APIs follows the same general rules as Sharing integration pipelines and transform functions. After a serverless API is shared with a target tenant, it needs to be setup to be called by enabling the proper Authorization according to its type.
