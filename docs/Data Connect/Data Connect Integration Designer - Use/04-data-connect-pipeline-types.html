Data Connect pipeline types

Integration pipelines

Integration pipelines should be used for long running and scheduled batch jobs.

They should also be used when integrating external data and applying transforms in Insights. They can also be used to generate and download files from the UI.

Diagnostic logs

A diagnostic log file can be generated when testing an integration pipeline.

See Troubleshooting: Enable diagnostic logs for more details.

Concurrency

Integration pipelines use concurrency, also known as multithreading or parallelism, when a forEach section is encountered on the pipeline. At that moment, pipelines are automatically divided into one or more phases. Each phase consists of one or more segments, and some phases can be parallel. When a phase runs in parallel, it divides up the work into multiple jobs, one for each message that needs to be processed, to speed up processing time.

After all the records are processed, the engine will fan-in the results into an array and push each message of the aggregated results to the next phase.

Note: Consider that multiple partial jobs can be reading or posting data to the APIs at the same time, and that might cause additional load on the client APIs.

To see the parallel execution plan for your pipeline, you can enable the Diagnostic Log when the pipeline is executed as a job. The zip file will include a plan.json file, indicating which phases will run in parallel (the runInParallel attribute).

Max job concurrency can be tuned through the Job page. The default value for concurrency is 10, which means that a maximum of 10 jobs can be consuming APIs at the same time. This value can be turned up or down to tune the performance, from 1 to 50. Greater concurrency will mean a faster processing speed, but a higher load on the target APIs.

In addition, the default maximum concurrency value can be changed from the Designer. It is still tied to the 1 to 50 range, but this will limit the maximum concurrency value that you can set on a Job screen. The new default maximum value can be set by clicking the drop-down menu aside the pipeline name and then selecting Edit Pipeline Settings in the Designer, selecting the Max Concurrency tab and then turning the Set Max Concurrency switch on. Doing this allows you to adjust the value, just like on the Job Screen.

This setting will limit the value on the Job creation screen. Consequently, operational users will be able to set a max concurrency value in the New Job or Edit Job screen to anything less than or equal to the max concurrency value set in the Designer.

Note: One key difference between testing in the designer and running an integration pipeline as a job, is that parallelism is activated for jobs. Designer test runs are not parallelized.

See Common patterns for more details about concurrency.

Data Connect Serverless APIs

Serverless APIs are pipelines meant to be short-running and cannot run for longer than 60 seconds.

Serverless APIs can be called from a custom Experience card without deploying an intermediate authorization proxy. Serverless APIs can also be called by a 3rd party through Ethos Integration to fulfill custom JSON data requests.

For information on how to develop Integration Designer serverless APIs, see Develop serverless APIs.
