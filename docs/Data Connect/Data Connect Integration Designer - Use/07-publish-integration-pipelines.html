Publish integration pipelines

A pipeline that has already been developed in the Designer can be published so it becomes available to Integration Packages.

About this task

Publishing a pipeline makes it available to clients to create jobs. A job is a pipeline that is scheduled to run, either as soon as possible or in the future. After a job is created and executed at least once, a job run is available to view on the Pipeline Runtime dashboard. If a job is scheduled to run once, it only ever has one job run. If a job is scheduled to run on a recurring basis, it has a job run for every recurrence.

An unpublished pipeline is considered a draft. Draft pipelines are viewed from the Integration Designer. A draft pipeline can be deleted by clicking on the trash icon under the Actions menu. After a pipeline is published, it can only be deleted if is not currently shared.

Clicking on the name of the draft pipeline opens up the pipeline in Designer where you can either edit or publish the pipeline.

Procedure

  1. Click the name of the draft pipeline to open the pipeline in Designer.
  2. If all fitting configurations are complete and if all the fittings are enabled, the PUBLISH button is enabled. If PUBLISH is disabled, check the errors badge at the left of the test button to make sure that a fitting does not have an incomplete configuration or is disabled.
  3. When ready, click on the PUBLISH button. This action displays the Publish Pipeline dialog.
    This dialog asks for confirmation of pipeline publish and recommends a test run to ensure that the pipeline is valid. The recommended release version options are displayed. See: Pipeline versioning guidelines
  4. Select the required version (following the guidelines above) and click PUBLISH.
    On successful publication, the Designer closes and the Integration Designer displays with the updated pipeline status. In case of failure, the dialog closes and you are returned to Designer where an error message displays at the top of the designer.
  5. After your pipeline is successfully published, if it needs to be further edited, create a new draft of the pipeline. To do this, click on the name of the pipeline to enter Designer. The Designer displays the pipeline in "read only" mode. Fittings cannot be added and pipeline configuration cannot be edited.
  6. To create a new draft of this pipeline, click the CREATE DRAFT button.
    This creates a draft version of the pipeline. The pipeline saved successfully message displays and any edits can now be performed on the pipeline. On the Integration Designer the new draft pipeline displays and the draft column displays an info icon. Hover over the icon or tab to it to display the original pipeline from which the draft was created.
    The draft pipeline can be edited, new fittings can be added, or parameters can be edited or added as per your requirements. If any change is made to required parameters or if any new required parameters are added, you need to publish a major version of the pipeline.
  7. After development is completed on the draft, click the PUBLISH button to publish this pipeline. As a new required parameter has been added, the publish pipeline dialog informs you that pipeline version will be updated to the next major version. If no breaking changes are made, the dialog displays with options to choose next patch, minor, or major version.
    When you click PUBLISH, the pipeline publishes with version, as per your selection (or next major version in case of breaking changes) and the newly published pipeline displays in the Integration Designer.
    If you do not make any breaking changes and publish a patch or minor version of the pipeline, then only the latest patch or minor version (of each major version) displays. If, for example, you published 0.0.1, 0.0.2 and 1.0.0 versions, only 0.0.2 and 1.0.0 display because they are the latest versions of 0.x and 1.x major versions respectively.
    The pipeline is now successfully published.
  8. Apply permissions for roles before the pipeline is visible. For an Integration pipeline, permissions for the package need to be given to a role. Then, it will be available in the Integration Packages UI.
  9. Optional: If there is an Integration Pipeline breaking change, the following scenarios require a new major version number:
    Regular parameters
    Case Marked as required Force major Justification
    A parameter name is changed. Yes Yes Any existing Experience page could fail to start the pipeline because the parameter is not registered with a value.
    A parameter name is changed. No No Because the parameter is optional, it should not be considered necessary to execute the pipeline.
    A parameter type is changed. Yes Yes Any existing Experience page could fail to start the pipeline because the parameter is the wrong type.
    A parameter type is changed. No Yes If the pipeline starts failing due to validation then this is considered a breaking change if the parameter was provided, so it requires a major version update.
    A parameter is added. Yes Yes If it has no default value, the pipeline may fail to start.
    A parameter is added. No No Because the parameter is optional, it should not be considered necessary to execute the pipeline.
    A parameter is deleted. Yes Yes When a parameter is removed, it should be considered a breaking change.
    A parameter is deleted. No No Because the parameter is optional, it should not be considered necessary to execute the pipeline.
    A parameter was changed to Required from Optional. Yes Yes Changing a parameter from optional to required means that because it was optional before, it may not have been registered with a value, and therefore the pipeline could fail to start.
    A parameter was changed to Optional from Required. No No When a required parameter changes to optional, it should not be considered a breaking change.
    A required parameter with a default value is changed to a sensitive parameter. Yes Yes When a required parameter changes from normal to sensitive and there is a default value, the default value is removed and needs to be set by the end user.
