Pipeline versioning guidelines

There are versioning guidelines for pipelines.

Follow the pipeline versioning the guidelines listed below:

  • Pipelines must be versioned using Semantic Versioning.
  • Pipelines must use a new major version number when a breaking change is made. The table below describes breaking changes.
  • A new minor or patch version does not require you to do anything. Existing jobs or Serverless APIs will continue to work.
  • A new major version requires you to set up a new job for the pipeline.
