Data Connect release notes

These release notes describe new features, enhancements, and updates in Data Connect releases, including changes to both Data Connect Integration Packages and the Data Connect Integration Designer.

Data Connect 2026-06-04

This release of Data Connect implements updates to enhance overall system stability and performance and resolves product defects.

Bug fixes

This release provides the following bug fixes:
  • PD0032218: Improved job management behavior for running jobs. You can now disable a job while it is actively running from the Job Details page. The current job continues until completion but the job is automatically disabled afterward which prevents all future scheduled, manual, or event-triggered job runs until that job is re-enabled.
  • PD0033742: Addressed an issue in the Delimited Parser fitting where fields containing literal double quotes could merge subsequent fields unexpectedly. Added a new Literal Quotes toggle option which allows quotes to be treated as plain text characters when needed. Existing behavior remains unchanged unless enabled.
  • PD0034739: Fixed an issue where Data Connect Pipelines were not visible in Permissions for tenants without previously published or shared pipelines.

Accessibility

PD0030307: Filter selections on the All Runs page now announce content changes to screen readers (JAWS/NVDA).

Stability and Performance

The following stability and performance updates have been made:

  • Enhanced SFTP connection reliability, which reduces hangs and timeouts during file transfers.
  • Implemented multiple updates to enhance overall system stability and performance.

For details about the release, see the release page PR00043640 in the Ellucian Customer Center.

Pipeline context execution limit

To improve system stability and clarify execution boundaries, the total amount of data stored in pipeline context is limited to 2.5 GB per execution. This includes data added using the Add to Context fitting or the JavaScript Transform fitting. Pipelines that exceed this limit will fail with a clear error message. See the documentation for additional details and best practices:
  • Pipeline context execution limit
  • Common patterns
  • JavaScript Transform fitting

Data Connect 2026-02-19

The 2026-02-19 release of Data Connect provides job schedule time zone support and event‑driven job execution.

This release includes:
  • Job schedule time zone support: Job schedules will follow the configured time zone, ensuring accurate execution during Daylight Saving Time changes. The timezone can be set under Integration Packages > Settings. For the details, see Time zone setting below.
  • Event‑driven job execution: Pipelines can now be triggered directly by change notifications or business events, enabling near real-time integrations and mitigating the need for scheduled jobs that poll for change notifications. For the details, see Pipeline job triggered by event below.
  • Stability and performance enhancements: Internal optimizations have been implemented to further improve system stability and performance.

For more information, see the release page PR00043085 in the Ellucian Customer Center.

Time zone setting

When you create a pipeline job, you can optionally set up a repeating schedule for the job including the time when the job should run. Previously, the time was based on the computer settings for the person who set up the job, which might not be in the same time zone as your institution. Also, the specified schedule was converted to UTC time, which does not account for time changes in the Spring and Fall. As a result, the job would run an hour earlier or later after each time change.

You can now specify a time zone in the new Tenant time zone setting on the Settings page. Specifying the time zone is a one-time procedure. When setting up a schedule for a pipeline job, using either the Simple or Cron format, you will enter the local time when you want the job to run in the selected time zone. If that time zone observes a time change in the Spring and Fall, the schedule will be automatically adjusted so that the job continues to run at the specified time after the time change. The user interface now displays the schedule using local time rather than UTC time.

After you select a time zone, any job schedules that you set up previously will automatically be adjusted to be based on local time in that time zone rather than UTC time. You can see the adjusted schedule by editing the existing job.

For the new procedure for specifying the time zone, see Specify the time zone. The steps for scheduling job runs in Create a pipeline job have been updated to reflect the new setting.

This enhancement addresses Product Enhancement PE0006826 in the Ellucian Customer Center.

Pipeline job triggered by event

Some pipelines process data that is sent through Ethos Integration using either an Ethos change notification or a business event from Banner or Colleague. Previously, this required scheduling the pipeline job to run frequently to check for new events (change notifications or business events), and many of those job runs would not process any data because there were no new events. The Job Run Details section of pipeline job setup now includes a new option, Triggered by event, with which you can set up the job to run automatically in response to a change notification or business event. This enhancement removes the need to schedule frequent job runs.

The Ethos Consume Change Notification fitting has been renamed the Ethos Consume Event fitting, as both change notifications and business events can now be consumed through Ethos Integration.

For the updated documentation, see Ethos Consume Event fitting, Ethos Consume Confirm fitting, and Create a pipeline job.

Sub-pipelines

When you create an integration pipeline, you can mark it as a sub-pipeline to add an extra step or sub-process to existing pipelines. This is now generally available.

You will see an option to select the This is a sub-pipeline check box when you create a pipeline.

After you create and publish a sub-pipeline, it displays as an option to be selected in the Sub-pipeline fitting. The Sub-pipeline fitting is used to select the sub-pipeline to be run at that step in the pipeline. See Develop pipelines and Sub-pipeline fitting.

When you set up jobs for a pipeline that uses sub-pipelines, you can select the sub-pipeline and version. See Set up pipeline parameters and sub-pipelines.

Access to Data Connect from the Application menu in Experience

In previous releases, users could access Data Connect through cards on the Ellucian Experience dashboard. This release adds the ability to access Data Connect from the Application menu in the Experience navigation area:
  • You can now access the Data Connect Integration Designer from either the Integration Designer option on the Application menu or from the Integration Designer card.
  • You can now access Data Connect integrations from either the Integration Packages option on the Application menu or from the Integration Packages card.

Any users who already have access to the Integration Designer or integration packages through the Experience cards will automatically have access through the Application menu. No additional permissions or setup are needed.

For the updated procedures that include granting user access through both the Experience card and the application menu, see Set up user access to the Data Connect Integration Designer and Set up user access to Data Connect integrations.

All procedures for using the Integration Designer and managing pipeline jobs are updated to describe the two access options.

Other updates

  • Resolved issue that improves resiliency when using Test Mode. Pipelines executed in Test Mode will automatically cancel after 60 seconds. Previously, some pipelines continued running in the background, potentially leading to unintended data fetching.
