Create and manage Data Connect rulesets

Rulesets enable you to intuitively define rules based on business logic that reflects policies at your institution. Those rulesets can be used within Data Connect integrations delivered by Ellucian or integrations that you develop with the Data Connect Integration Designer, using the Run Ruleset fitting.

This section includes general procedures for creating, testing, and publishing rulesets for Data Connect. For Ellucian-delivered Data Connect integrations that use rulesets, the documentation for that solution provides specific guidance specific for creating rulesets for that integration.

Create a ruleset for Data Connect

Create a ruleset to be used within a Data Connect pipeline.

Before you begin

The user performing this procedure must have the following access:
  • The Edit permission on Data Connect rulesets.
  • The View or Edit permission on Data Connect facts.
  • The View or Manage permission on at least one integration package, to access the Integration Packages page where the Rulesets tab is located.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access for Data Connect rulesets.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the Rulesets tab.
  3. Create a new ruleset.
    1. From the Rulesets list, click Create Ruleset.
    2. Enter a unique Ruleset Name.
      The ruleset name is case sensitive. For example, MyRuleset differs from myRuleset. New Draft rulesets cannot have the same name as another ruleset. If you decide later to rename the Draft ruleset, you can rename it from the Ruleset list page or the Ruleset builder page. After a ruleset is published, you can no longer change its name.
    3. In the Result Set field, select the data type for the result of rules in this ruleset.
      Rulesets can contain multiple rules. In any ruleset, all rules must have the same data type for results. If this ruleset can have multiple results that require different result data types, you must build one ruleset for each potential result.
    4. Click Create.
    The Ruleset builder displays. All rulesets begin with one empty rule.
  4. Optional: Select a Group to limit the elements displayed in the Element list.
  5. Select an Element from the drop-down list.
    You can enter text to limit the list to elements that include that text.

    Ellucian defines the available elements. Select an element that best describes the business logic that is being evaluated by the rule you are creating. When you use this ruleset in a Run Ruleset fitting in the Integration Designer, you will map this element to data in the pipeline. Because of that mapping, the element you select does not need to match a data name used in the pipeline.

    When you select an element, the Operator and Value fields display the permitted choices for that element. Review the choices in those fields to confirm that the selected element is appropriate for the pipeline data that will be mapped to that element.

    For example, to build a rule for this expression: IF FOOD = APPLE THEN FOODGROUP = FRUIT, select FOOD as the Element.
  6. Select the operator for this rule condition.
    The list of available operators depends on the type of element selected. Operators documented here may not be available for every element.

    Continuing the previous example, select the operator is equal to.

  7. Select or enter the value for the selected element.
    Considerations when entering the element value:
    • Operators such as is empty or is not empty do not require an associated value.
    • Number elements may have predefined minimum or maximum values. If you enter a value for that number element that does not meet those criteria, you cannot save the ruleset until the number meets the predefined setting.
    In the previous example, select apple from the list of values.

From here, continue to build out the rule conditions as needed. Steps 8 - 13 provide information on optional building blocks you can use when building rules and a ruleset.

  1. Optional: Click Add Condition to add an AND or OR clause to your condition statement.
    By default, the system uses an AND operator when adding a condition. You may change this to OR as needed. Any additional conditions will carry forth the selected operator.
  2. Optional: Click Add Nested Group to add a nested group under the parent group.
    By default, the system uses the AND operator when adding a nested group if there is only one condition above the nested group. The system uses an OR operator if that operator is used in the parent group. You may change these default operators as needed.
  3. Optional: Click Add Group to add another parent group within the rule.
    By default, the system uses an AND operator when adding another group. You may change this to OR as needed. Any additional groups will carry forth the selected operator.
  4. Optional: To add another rule to the ruleset, click Add Rule.

    Each rule within a ruleset is evaluated for its own conditions and has its own THEN result.

    Tip: If you want to create a rule that is similar to an existing rule in the ruleset, click Duplicate on the existing rule to save time.
  5. Optional: If you need to change the order of the rules within the ruleset, use the arrows to move the rules up, down, to the top, or to the bottom of the ruleset.
    The rules within the ruleset are not dependent on each other; that is, they do not use the results from one rule as input to another. However, the order of the rules is relevant when Return First Match is enabled. The system processes the rules in sequential order starting at Rule 1, so if Return First Match is enabled and the system finds a match to the rule criteria, the system will stop processing any remaining rules in the ruleset.
  6. Optional: To delete any part of the ruleset (rule, group, condition, nested group), click Delete or Remove for the associated item.
  7. At the bottom of the rule definition, in the Then field, enter the value to be returned if the rule is satisfied.
    The permitted values depend on the data type (boolean, number, or string) that you selected in the Result Set field in Step 3.c.
  8. Click Save.

What to do next

Test the ruleset to confirm the rules and conditions meet your needs. See Test and publish a Data Connect ruleset.

Test and publish a Data Connect ruleset

Use the Test Ruleset feature to verify that a ruleset meets your intended rules logic and provides the expected outcome.

Before you begin

The user performing this procedure must have the following access:
  • The Edit permission on Data Connect rulesets.
  • The View or Edit permission on Data Connect facts.
  • The View or Manage permission on at least one integration package, to access the Integration Packages page where the Rulesets tab is located.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access for Data Connect rulesets.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the Rulesets tab.
  3. On the Rulesets page, click the name of the ruleset that you want to test.
  4. Click Test on the Ruleset builder page to open the Test Ruleset feature.
    Any unsaved changes to the ruleset are saved.
  5. Select the elements to use to verify your ruleset.
    The element list contains all elements for all rules in the ruleset, listed in alphabetical order. Unselected elements are considered empty when testing.
  6. For each selected element, enter a value to build a test scenario for this rule.
    You can choose to enter information for which you know what the outcome will be, either pass or fail. Selected elements without a value assigned are considered empty when testing.
  7. Click Test to execute the ruleset with the provided values.
    If the ruleset contains multiple rules, all rules are evaluated for their own criteria.
    Review the Test Results section to see if it matches your expected results.
    • If Return First Match is disabled on the ruleset and the provided values pass the criteria for at least one rule in the ruleset, the Test Results display the outcome for each passing rule.
    • If Return First Match is enabled on the ruleset, the Test Results display the outcome for the first passing rule.
    • If the provided values do not pass the criteria for any rule, the Test Results indicate that no rules have matched the provided criteria.
  8. If desired, enter different criteria in the Test Ruleset dialog and test again.
  9. To return to the ruleset configuration, click Cancel.
  10. To make this ruleset available for evaluation, click Publish. Review the confirmation information and click Confirm when ready.
    Any unsaved changes to the ruleset are saved.
    When your ruleset has published, notice these changes in the Ruleset builder page:
    • The status of the ruleset, located next to the Ruleset title, is changed from Draft to Published.
    • The ruleset configuration is read-only.

Understanding rulesets

Understanding these concepts will help you in building your rulesets.

Overview

A ruleset is a collection of one or more associated rules that run together as a single unit against a set of data. Each group in the ruleset starts as a simplistic if-then statement. Depending on your needs, you can have multiple rule groups, add nested groups within rule groups, add multiple rules inside one ruleset. Your rulesets can be as simple or complex as you need.

When building a ruleset, keep these considerations in mind:

  • The system processes the rules in sequential order starting at Rule 1.
  • If the data meets the criteria of a rule, the result value is returned.
  • If the data does not meet the criteria of the rule, the result value is not returned.

Ruleset statuses

As you build and refine your rulesets, the rulesets progress through several statuses. The ruleset status determines what actions you can take with that ruleset.

Rulesets move through four statuses: Draft > Published > Outdated > Archived.

  1. All new rulesets start in Draft status, version 1.0.0. When a ruleset is in Draft status, you can edit it, test it, and save it as often as necessary. The version number does not increment when you save changes for a Draft ruleset.

    You can also move a Published ruleset to Draft status so that you can make updates to it. The system increases the version number when you create a Draft from a Published ruleset.

    To delete a Draft ruleset, locate the ruleset on the Rulesets list page. Click the Actions menu and then select Delete.

  2. When you publish a Draft ruleset to make it available for evaluation, the status of the ruleset is changed to Published. This applies to Draft rulesets of any version, whether it is the first publication or later versions.

    Published rulesets are view-only and cannot be modified. You can copy a Published ruleset to create a new ruleset with a unique name. This new ruleset starts version defaults to 1.0.0.

  3. When you publish a new version of an existing ruleset, the existing or former ruleset is changed to Outdated status. The version number does not change.

    It is useful to retain Outdated rulesets for a period of time because they may still be in use for evaluations until you move to the newer Published version.

    You can only view Outdated rulesets or archive them. Outdated rulesets are not available for any new processes to use in evaluation.

  4. When an Outdated ruleset is no longer used by any processes, you can move the ruleset to Archived status.

    Archived rulesets are view-only and intended for administrators to refer to for historical purposes. Archived rulesets are not available for evaluation.

    You can archive an Outdated ruleset either from the Actions menu on the Rulesets list page, or by clicking Archive on the Rulesets builder page.

Permitted data types and operators

Valid input element data types for rules are:

  • Number
  • Boolean
  • Date
  • String

Valid result data types for rules are:

  • Number
  • Boolean
  • String

Valid operators for rules are:

  • Is equal to
  • Is not equal to
  • Is greater than
  • Is greater than or equal to
  • Is less than
  • Is less than or equal to
  • Contains
  • Does not contain
  • Is in
  • Is not in
  • Is empty
  • Is not empty
Note: The list of available operators depends on the selected element type. All documented operators may not be available for every element.

Terminology

Term Description
condition A logical statement that determines whether an assertion is true. For example, expense amount > 100 is true if expense amount is greater than 100.

A condition is made up of three parts:

  1. Element: an attribute to be evaluated. For example, expense amount
  2. Operator: a logical operator used to evaluate the value of a field. For example, is greater than, is equal to, does not contain, and so on.
  3. Value: the content value of the named field in the condition. In this example, the value is 100.
condition group Conditions can be connected using logical AND and OR operators. For example, "expense amount > 100" AND "Is Manager = FALSE"
element An attribute used to build a business rule condition; see condition.
inputs The elements and their respective values to be evaluated by the rules within a given ruleset. All fields configured for a ruleset must be passed as input, even if they are null.
operator A logical operator used to evaluate the value of a field.
outputs The evaluated results of the rules within a ruleset that are actionable by the consuming application. The output could be more than one result. For example, any rules evaluated to TRUE would have a result in the output.
result The outcome of a condition or group of conditions being evaluated.
result set A group of result fields.
rule An explicit instruction within a ruleset comprising of conditions and results.
ruleset A named collection of rules.
value The content value of a named element.
