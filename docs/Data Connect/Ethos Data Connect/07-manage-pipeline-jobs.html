Manage pipeline jobs

Create, run, and manage pipeline jobs for Data Connect integrations.

Working with pipeline jobs

Data Connect pipeline jobs are managed in Integration Packages in Ellucian Experience.

Options for accessing Integration Packages in Experience

You can access Integration Packages in Experience from either the Application menu or the Integration Packages card (if supported at your institution).

Option Steps
From the Application menu Click the Applications menu icon in the Experience Bar and then click Integration Packages.

This is the recommended option, and all of the individual procedures in this documentation use this option.
From the Integration Packages card (if supported at your institution) On the Data Connect integration packages card on the Experience dashboard, click your integration package.

The title of the card on your dashboard is the name specified during card configuration by an administrator at your institution. The default title is Integration Packages.

Options for working with pipeline jobs

After accessing Integration Packages in Experience, you can access a particular package, pipeline, pipeline job, or job run from either the All Runs tab or the Integration Packages tab:

Tab Description
All Runs Displays existing job runs in reverse chronological order (most recent job runs at the top of the list). The All Runs tab supports searching by pipeline name, package name, job name, or job run ID, and for filtering by job run date, time, and status.

The All Runs table shows the job, package, and pipeline associated with each job run. You can search for jobs, packages, and pipelines on the All Runs tab, but those items are shown only if there is an associated job run. A package, pipeline, or job for which there are not yet any job runs can be accessed from the Integration Packages tab.
Integration Packages Supports browsing using the Data Connect hierarchy of Package > Pipeline > Job > Job run. This was originally the only option before the addition of the All Runs tab. While this option remains available, the All Runs tab is the recommended and more intuitive option for working with pipeline jobs.

Search and filter on the All Runs tab

On the All Runs tab, you can use the search and filter options at the top of the page to help you locate a particular package, pipeline, job, or job run.
  • Search scope - In the dropdown, either accept the default (All) or select another option to limit the search to job name, job run, pipeline, or package.
  • Search term - The search results return only items that start with your search term. For example, a search for test would return a job named "Test Job" but would not return a job named "Pipeline Test."
  • Filter by date and time - Enter date and time ranges to show only job runs within that time span. Note that the date and time of a job run is based on when the job run was last updated, which might not correspond to the date and time in the Start or End columns.

    Date entries are limited to the most recent three months, and to a date range of two weeks or less.

  • Filter by status - Use the chips on the right side of the page to show only job runs with the selected statuses.

Set up pipeline parameters and sub-pipelines

Configure the parameters and sub-pipeline settings that apply to all jobs for a pipeline.

Before you begin

The user performing this procedure must have the following access:
  • The Setup permission on the integration package that includes this pipeline.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access to Data Connect integrations.

About this task

Some integration packages include the following items that are defined at the pipeline level.
  • Pipeline-level parameters - These might be sensitive parameters that should not be exposed to business users who manage pipeline jobs, or they might be parameters whose value is the same for all jobs within a pipeline.
  • Sub-pipelines - Some pipelines include fittings that use sub-pipelines, for which you can select the appropriate sub-pipeline and version from within Integration Packages.

This procedure includes the steps that are common to configuring pipeline parameters and sub-pipeline settings for all Data Connect pipelines. Information that is specific to a particular pipeline is with the documentation for setting up the Data Connect integration that includes that pipeline.

Note: Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the Integration Packages tab.
  3. In the PACKAGES list in the left pane, click your integration package.
  4. On the Package page, in the table of pipelines, click the pipeline for which you want to configure pipeline parameters or sub-pipelines.
  5. On the Pipeline page, click the Pipeline Parameters tab.
    If you do not see the Jobs and Pipeline Parameters tabs, either this pipeline has no pipeline-level parameters or sub-pipelines, or you have not been granted the Setup permission on this integration package.

    When you access the Pipeline Parameters tab, any previously-entered parameter values are displayed. Sensitive parameters are masked as a series of asterisks *****. You can click the Show link to have the first part of the entry unmasked. To avoid displaying the entire value for short entries, the Show link is not displayed for entries of five characters or fewer.

  6. Click the Edit Pipeline Parameters icon.
  7. If there are pipeline-level parameters displayed on the page, enter values for the parameters.
    Many parameters are specific to a particular Data Connect integration and pipeline. For guidance, see the documentation for setting up your integration.
    Note: Some pipeline-level parameters have a default value. These parameters will always have a value. If you clear the entry, you will be able to save, but any job runs for this pipeline will use the default value.
  8. If the pipeline parameters include an Ethos API Key parameter, this pipeline uses Ethos Integration for integrations. Perform the steps below to copy the API Key from Ethos Integration and enter it here.
    1. On the Ethos Integration header bar, click Applications.
    2. On the Applications page, click the name of the Ethos application that you created for this integration.
    3. On the Application Overview page, click the API Keys tab.
    4. On the API Keys page, click Copy to copy the API key.
    5. Back on the Data Connect Pipeline Parameters page, paste that API key into the Ethos API Key field.
  9. If the pipeline parameters include a multi-value list of sensitive parameters, there are special considerations for updating that list. To modify an existing value or add a value, you must first delete all existing values by clicking the X on each oval, and then enter all desired values.
    In the example below, there are two existing values.
    • If you wanted to modify one of the two values, you would first delete both existing values and then enter both desired values.
    • If you wanted to add a third value, you would first delete the two existing values and then enter all three desired values.


  10. If the page includes a Sub-pipelines section, select the appropriate sub-pipeline and version for each listed fitting.
    The appropriate selections are specific to a particular Data Connect integration and pipeline. For guidance, see the documentation for setting up your integration.
  11. Click Save.

Create a pipeline job

Enter the parameters for a pipeline job, and either run the job immediately or set up a schedule.

Before you begin

If this pipeline includes pipeline-level parameters, those parameters must be specified before you can create the pipeline job. See Set up pipeline parameters and sub-pipelines.

If you plan to set up the job to run on a schedule, Ellucian recommends that you set up your institution's time zone as described in Specify the time zone.

The user performing this procedure must have the following access:
  • The Manage permission on the integration package that includes this pipeline.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access to Data Connect integrations.

About this task

This procedure includes the steps that are common to setting up all Data Connect pipeline jobs. Information that is specific to a particular pipeline, such as settings entered in the Job Parameters section of the New Job page, is with the documentation for setting up the Data Connect integration that includes that pipeline.
Note: Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the All Runs tab (the default).
  3. Click + NEW JOB to access the New Job page.
  4. In the Basic Details section of the page, enter basic settings:
    Field Entry
    Integration Package Select the package that contains the pipeline for which you want to create a new job.
    Pipeline Select the pipeline for which you want to create a new job.
    Version Select the pipeline version.
    Job name Enter a descriptive name for this job. If you create multiple jobs for this pipeline, you can use this name to find this job in the list of jobs.
  5. In the Job Parameters section of the page, enter the parameters for this pipeline job.
    Many job parameters are specific to a particular Data Connect integration and pipeline job. For guidance, see the documentation for setting up your integration.

    If the message Missing Pipeline Parameters is displayed, this pipeline includes pipeline-level parameters that must be configured before you can create the pipeline job. Click Setup parameters and then configure those parameters as described in Set up pipeline parameters and sub-pipelines.

  6. If the Job Parameters section includes an Ethos API Key parameter, this pipeline uses Ethos Integration for integrations. Perform the steps below to copy the API Key from Ethos Integration and enter it here.
    1. On the Ethos Integration header bar, click Applications.
    2. On the Applications page, click the name of the Ethos application that you created for this integration.
    3. On the Application Overview page, click the API Keys tab.
    4. On the API Keys page, click Copy to copy the API key.
    5. Back on the Data Connect New Job page, paste that API key into the Ethos API Key field.
  7. In the Job Run Details section of the page, specify when you want the job to run:
    1. To run the job immediately, click Run now.
      You can also run this job later from the job runs page for the job.
    2. To run the job on a schedule, click Schedule and then do either of the following:
      • Click Simple to specify the schedule using the user interface fields.

        The default schedule for the Simple option runs at noon, local time, and runs one-time for each day.

      • Click Cron format to specify the schedule using a cron expression, which supports advanced scheduling scenarios not supported by the user interface fields.
      Note: Before setting up a schedule, Ellucian recommends that you set up your institution's time zone on the Data Connect Settings page. The time zone setting allows you to use local time rather than UTC time when setting up the schedule, and the schedule is automatically adjusted if that time zone has a time change in the Spring and Fall. The instructions below assume that the time zone has been set up.

      Enter the time when you want the job to run in the time zone specified on the Data Connect Settings page. The table below provides examples for both scheduling options.

      Job run schedule Entries for the "Simple" option Entry for the "Cron format" option
      Daily at noon
      1. In the Repeats field, select Daily.
      2. In the Hours field, enter 12.
      3. In the Minutes field, enter 0.
      		 0 12 * * *
      Every 6 hours
      1. In the Repeats field, select Daily.
      2. In the Hours field, enter 6 and select Use as interval.
      3. In the Minutes field, enter 0.
      		 0 */6 * * *
      Every day at 9 AM, noon, and 3 PM not supported 0 9,12,15 * * *
      Every 15 minutes between 6 AM and 6 PM not supported */15 6-18 * * *
      On the third Thursday of every month at 11 AM not supported 0 11 15-21 * 4
    3. To have the job run automatically in response to either an Ethos change notification or a business event from Banner or Colleague, click Triggered by event.
      The Triggered by event option is displayed only if the pipeline includes the Ethos Consume Event fitting.

      If you choose this option, you must set up email or notification alerts in the Job Completion Alerts section of this page, to ensure administrators are aware that the job was run and are made aware of any job run failures.

      This option requires the following:
      • The pipeline for this job must include both an Ethos Consume Event fitting and an Ethos Consume Confirm fitting. See Ethos Consume Event fitting and Ethos Consume Confirm fitting for details about using those fittings within the Data Connect Integration Designer.

        Event-triggered pipelines must include the Ethos Consume Confirm fitting to advance the subscriber's last processed ID. If the Ethos Consume Confirm fitting is not reached, the subscriber position will not advance and the job will execute repeatedly.

      • Set up Ethos applications in Ethos Integration for both the publisher and subscriber of the Ethos change notification or business event.
      • Enter the Ethos API key for the subscribing application in the Ethos API Key setting in the Job Parameters section of this page.
      • In the Ethos Consume Event fitting, the API Key field must include a pipeline parameter such as ethosApiKey. If the pipeline includes multiple Ethos Consume Event fittings, they must contain the same parameter name in the API Key field.
        Note: Each event-triggered pipeline must use a dedicated Ethos API key (subscriber). Do not use the same API key for multiple event-triggered pipelines. Event-triggered jobs rely on subscriber-level progress tracking. Using the same API key across multiple event-triggered pipelines can result in unintended job behavior.
      • (For change notifications only) In the Ethos Consume Event fitting, the Resources field must identify the Ethos resource/version for the change notification.
      If the initial job run fails, Data Connect retries the job. The maximum number of retries depends on the scenario:
      • Invalid API key: Up to 2 retries.
      • Unconfirmed event in pipeline due to error: Up to 10 retries.

      Data Connect also includes an automatic disable safeguard for event-triggered jobs to prevent unintended repeated execution. Forward progress is determined by whether new events are successfully processed and confirmed. When events are processed and the Confirm fitting is reached, the subscriber's position advances and the job continues normally. If no forward progress is detected across 10 consecutive runs, the job is automatically disabled to prevent repeated execution. After the retry limit is reached or the job is automatically disabled due to lack of progress, Data Connect sends an email or Experience notification with details about the failure. After resolving the issue, you must manually re-enable the job.

  8. If you set up a schedule for the job, and you want the schedule to end at a certain date and time, do the following:
    1. Enable the toggle switch for Setup Job Stop Date/Time?.
    2. Select the desired stop date.
    3. Enter the desired stop time in the HH:MM AM/PM format. If you leave this field blank, the stop time defaults to 11:59 PM.
  9. In the Advanced Options section of the page, modify the default settings as needed:
    1. In the Maximum Concurrency setting, specify the number of concurrent threads for this job.
      Some pipeline jobs use multiple concurrent threads for processing. Increasing the number of concurrent threads can improve processing time, but too many simultaneous threads might overwhelm the target system for the job.

      You can accept the default of 10 threads unless you are seeing performance issues. If the pipeline job is taking a long time to run, try increasing the number of threads. If you are seeing performance issues in the target system, try decreasing the number of threads.

    2. In the HTTP Request Timeout setting, specify how long this pipeline job should wait for HTTP requests to complete (in minutes).
      You can accept the default of three minutes unless a job run fails with the following error message: The request exceeded the maximum timeout of <#> minutes and was aborted. In that case, increase the timeout and run the job again.
  10. Enable the Enable Diagnostic Log toggle switch if you want diagnostic logs to be created for this job run.
    After the job run completes, you can view the diagnostic logs from the Status column on the All Runs tab.

    If you enable this setting, diagnostic logging is enabled only for the current job run. If you run the job again and want to generate diagnostic logs, you will need to edit the job parameters and enable the diagnostic log again. Similarly, for a scheduled job, diagnostic logging is enabled only for the first scheduled run. If you want to enable diagnostic logging for subsequent runs, you will need to edit the job parameters.

  11. Optional: In the Job Completion Alerts section of the page, set up emails or notifications to be sent upon completion of a job run.
    1. Enable the Job Completion Alerts toggle switch.
    2. Select the check boxes for the desired alert types:
      Alert type Description
      Email Emails are sent to the email addresses you specify. The email includes a "View Job Details" link that opens the Job Detail page in Experience.

      All emails are sent from data-connect-alerts@ellucian.com. Email recipients should add that email address to their safe sender list to avoid having the email go to a junk email folder.
      Notification A notification is displayed in the Ellucian Experience notifications pane, accessed from the Notifications icon in the Experience Bar. The notification includes a "View Job Details" link that opens the Job Detail page in Experience.

      Only the user who initially enabled the notification option, by selecting the Notification check box, receives a notification. To notify other users, use the Email option.

      Both the emails and notifications are displayed in the language of the user who enabled job completion alerts. This is the language selected by that user on the Profile page in Experience.

    3. If you selected the Email check box, add email addresses for the desired recipients. Enter each email address and then click the Add button .
    4. Select the check boxes for the job completion statuses (Succeeded, Failed, or Terminated) for which you want to send email or notification alerts.
      You must select at least one job completion status. Consider selecting only statuses requiring follow-up action (Failed, and possibly Terminated). Selecting Succeeded might result in many emails or notifications for job runs requiring no follow-up.
  12. Click Save.
    The display returns to the All Runs tab. See Monitor a job run for how to get additional information about a running job.

Troubleshoot a job run

If a job run fails, or if you are not seeing the expected results, you can access troubleshooting information from the All Runs tab.

Before you begin

The user performing this procedure must have the following access:

About this task

Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the All Runs tab (the default).
  3. In the table of pipeline jobs, in the Job Run ID column, locate the job run that you want to troubleshoot.

    You can use the search and filter options at the top of the page to locate the job run, as described in Working with pipeline jobs.

    Note: Data Connect retains only the most recent 1,000 runs for a job.
  4. In the Status column, view information about the job.
    Display Description
    Status (Created, Running, Succeeded, Failed, or Terminated) Overall status of the job run.
    View Ethos logs Info, warning, and error information from the job run is logged to the Ethos logs. Click the View Ethos logs icon to view the logs.
    Open output file If you enabled diagnostic logs for this job run when you set up the job, a diagnostic log zip file is generated after the job runs to completion. Click the Open output file icon and then download the diagnostic logs zip file from the Job Run Files dialog box.

    Ellucian might request access to the diagnostic log files to troubleshoot an issue with a pipeline job. Note that these files could contain sensitive information and should be handled accordingly.

    The zip file contains:
    • A plan.json file that describes the structure of the job run.
    • One or more execution log files with details about what happened during the job run. The execution logs have filenames like <job_run_id>_n_n.json

    In some cases, for example if the pipeline execution fails validation, the zip file will contain only the plan.json file, with no execution logs.

    A complex job run might generate a large number of execution log files. The zip file is capped at a maximum of 1,000 files. If the zip file from a job run contains 1,000 files, this indicates that some data from the job run is not included in the log files.

    The diagnostic logs zip file is automatically deleted seven days after the job run.

Disable or enable a pipeline job

When you create a pipeline job, the job is initially enabled. After creating the job, you can temporarily disable it.

Before you begin

The user performing this procedure must have the following access:
  • The Manage permission on the integration package that includes this pipeline.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access to Data Connect integrations.

About this task

Disabling the job prevents any future scheduled runs if you have set up a recurring schedule for the job. It also prevents you from manually running the job. If you re-enable a disabled job, scheduled runs can resume and you can again run it manually. You can toggle the Enabled switch at any time, even while a job is actively running.

If you disable a running job, a confirmation dialog informs you that the current job run will continue and the job will be disabled after the run completes. While waiting for completion, the toggle reflects the pending disabled state. Future scheduled, manual, or event-triggered job runs are blocked until the job is re-enabled.

To stop a currently running execution immediately, see Terminate a job run.

Note: Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the All Runs tab (the default).
  3. In the table of pipeline jobs, in the Job Name column, locate the job that you want to disable or enable.

    You can use the search and filter options at the top of the page to locate the job, as described in Working with pipeline jobs.

    Note: The All Runs tab displays only jobs that have at least one job run. For jobs that don't yet have a job run, switch to the Integration Packages tab and browse to the job.
  4. Click the job name to access the Job page for that job.
  5. On the Job page, toggle the Enabled switch to enable or disable the job.
    Note: If the job is currently running when you disable it, a confirmation dialog appears. Confirm the message to proceed. The job will be disabled when the current job finishes. While the job run is in process, the toggle reflects the pending disabled state. Scheduled, manual, and event-triggered job runs are blocked until you re-enable the job.

The user performing this procedure must have the following access:
  • The Manage permission on the integration package that includes this pipeline.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access to Data Connect integrations.

About this task

Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the All Runs tab (the default).
  3. In the table of pipeline jobs, in the Job Name column, locate the job you want to delete.

    You can use the search and filter options at the top of the page to locate the job, as described in Working with pipeline jobs.

    Note: The All Runs tab displays only jobs that have at least one job run. For jobs that don't yet have a job run, switch to the Integration Packages tab and browse to the job.
  4. Click the job name to access the Job page for that job.
  5. On the Job page, in the left pane, click  DELETE JOB.

Create a crosswalk

Create a crosswalk that maps values between the applications that you are integrating with Data Connect.

Before you begin

The user performing this procedure must have the following access:
  • The Edit permission on Data Connect crosswalks.
  • The View or Manage permission on at least one integration package, to access the Integration Packages page where the Crosswalks tab is located.
  • (Optional) A role that has been assigned to the Experience card. (Required only if your institution supports access through the card in addition to the Application menu.)

That access is granted by an administrator as described in Set up user access to Data Connect integrations.

About this task

This procedure provides the steps for accessing the crosswalk creation page. Information that is specific to a particular crosswalk, such as the required crosswalk name and the mappings, is with the documentation for setting up the Data Connect integration that includes that crosswalk.
Note: Data Connect provides multiple options for working with packages, pipelines, jobs, and job runs. The procedure below uses the recommended options for this task. For other options, see Working with pipeline jobs.

Procedure

  1. From the Experience dashboard, click the Applications icon in the Experience Bar and then click Integration Packages.
  2. Click the Crosswalks tab.
  3. Click the Add a new Crosswalk icon to create a new crosswalk.
  4. In the Add new Crosswalk dialog box, enter a name for the crosswalk and then click Create.
  5. Enter the mappings for your crosswalk.
    Mappings are specific to each Data Connect integration. For guidance in setting up the mappings, see the documentation for your integration.
