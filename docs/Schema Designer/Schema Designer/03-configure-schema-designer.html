Configure Schema Designer

All SaaS solutions require specific implementation and configuration of services and applications to enable communication.

You can use this section to review the prerequisites that are required or recommended for the implementation of Schema Designer. Use these procedures to either confirm that prerequisites are already installed and configured or implement them if your institution has not yet installed and configured them. This documentation provides the detailed steps that you need to follow and the specific resources that are required for Schema Designer Every Ellucian SaaS solution provides similar procedures, though applications and resources can be different.

Prerequisites

You must have the following prerequisites to use Schema Designer.

  • Ellucian Experience 1.94
  • Banner Integration 9.40
  • Banner General 8.26
  • Banner Common DB Upgrade 9.41

Ethos API configuration checks

Details about the configuration settings in the Ethos API that Schema Designer currently supports (Banner) that institutions may need to validate or review as they configure and set up Schema Designer.

The quartz.autostartup setting must be included in the IntegrationApi_configuration.groovy and the StudentApi_configuration.groovy configuration files and it is set to false. This ensures that any of the API security configuration updates that were made for an extended table API are not lost when the Banner job refreshes the formControllerMap. For more information, see quartz.autostartup.

The defaultBanEthosTableSpace and defaultClobBanEthosTableSpace settings must be included in the IntegrationApi_configuration.groovy and is set to the tablespace name. See Oracle tablespace for BAN_EXTENSIONS schema management for instructions to create a new tablespace.

Grant access to Schema Designer

Grant access to the Schema Designer application for an individual user with a Banner ID.

Before you begin

See Set up the Experience Application menu and Schema Designer Prerequisites.

About this task

Complete the following setup tasks to grant access to Schema Designer.

Procedure

  1. Configure permissions in Ellucian Experience for users to enable the Schema Designer application.
    For more information, see Enable access to Schema Designer in Ellucian Experience.
  2. Use the Banner Security Maintenance (GSASECR) page in Banner Access Management to grant access to the Schema Designer application to specific users.
    For more information, see Grant access to Banner security objects.

Enable access to Schema Designer in Ellucian Experience

Configure permissions in Ellucian Experience for users to access and use the Schema Designer application.

Before you begin

  • Set up the Experience Application menu.
  • Set up roles for Ellucian Experience.

Procedure

  1. Navigate to and log in to the Ellucian Experience application.
  2. Select the Permissions tab.
  3. Select the Environment.
  4. Search for Schema Designer.
  5. Select All Resources in the left pane.
  6. Select the Access check box for users that need to have access to Schema Designer.
  7. Click Save.

Grant access to Banner security objects

Users that require access to the Schema Designer application and Schema Designer APIs must have access granted to the Banner security objects on the Banner Security Maintenance (GSASECR) page.

Procedure

  1. Log in to Banner Access Management.
  2. Navigate to the Security Maintenance (GSASECR) page.
  3. Assign the following security objects to users:
    • API_EXT_CONFIGURATIONS to create an extended table.
    • API_EXT_CONFIG_REVISIONS to modify an extended table.
    • API_EXT_CONFIGURATIONS_DELETE to delete an extended table.
    • API_CUSTOM_TABLE_CONFIG to create a custom table.
    • API_CUST_TAB_CONFIG_REVISIONS to modify a custom table.
    • API_CUSTOM_TABLE_CONFIG_DELETE to delete a custom table.
    • BAN_ETHOS_API_OVERRIDE to update or delete an extended table and custom table created by another user.
    • API_DESIGNER_QUERY to access Banner tables.
    • API_EXT_MAPPINGS to create or delete the linking of the extended table and Banner Admin page using extension-mappings API.
    • API_SYSTEM_OBJECTS to view the Banner Admin Pages for extension mappings.
    • API_SCHEMA_EXT_ARTIFACTS to export the extended/custom artifacts.
    • API_EXT_CONFIGURATIONS and API_EXT_MAPPINGS to access the More Information page on the Banner Administrative pages.
    • GURMSDC and GURMSDV to execute the Supplemental Data Engine (SDE) migration jobs (GURMSDC and GURMSDV).

    For more information, see Supplemental Data Engine (SDE) migration to Schema Designer APIs.

API Registry configuration

To register OpenAPI specifications generated automatically in the API Registry, you must ensure that the necessary configuration values are set up in the GUACONF page. These configurations are associated with the GLOBAL application ID and are required for enabling secure communication with the API Registry. The following table outlines the required configuration values.

See Provision OAuth credentials in the ERP for the steps to generate the OAuth client ID and secret in Banner.

Name Type Description
banner.oauth.clientId string Client ID for OAuth authentication required to obtain access tokens.
banner.oauth.clientSecret string Client secret for OAuth authentication used along with the client ID to secure API calls.
banner.oauth.oauthEndpoint string The OAuth token URL retrieved from the GUROCFG table where GUROCFG_NAME = banner.oauth.oauthEndpoint.
banner.oauth.resource string Resource identifier for the API Registry indicating the target application to authorize.
banner.api.registry.url string Base URL for the API Registry service used to register and manage endpoint specifications. Use the URL that corresponds to your geographic region:
  • AP: https://registry-ap.api-registry.elluciancloud.com
  • CA: https://registry-ca.api-registry.elluciancloud.com
  • EU: https://registry-eu.api-registry.elluciancloud.com
  • US: https://registry-us.api-registry.elluciancloud.com

Supplementary Data Engine (SDE) migration configuration

The setup in GUACONF for the Supplementary Data Engine (SDE) migration requires specific configuration values. These configurations are associated with the GLOBAL application ID and are mandatory for enabling secure communication with the Banner Integration API application.

These configuration values establish the connection between SDE and the Banner Integration API application and ensure that requests are authenticated and securely transmitted.

Name Type Description
banner.api.integration.url String The base URL of the Banner Integration API application where API requests are sent.

For example, https://<server>/IntegrationApi
banner.basic.auth.username String The username used for basic authentication to access the Banner Integration API application. For example, ethosapiuser.
Note: This user should have access to the Banner security object API_EXT_CONFIGURATIONS.
banner.basic.auth.password Encrypted String The password associated with banner.basic.auth.username for basic authentication. This value is stored in encrypted format for security.

For example, ********.

For more information, see Supplemental Data Engine (SDE) migration to Schema Designer APIs.

Configure More Information card

To access the More Information card through a Banner administrative page, you must first configure it in the card setup wizard.

Before you begin

The user performing this procedure must have been granted the Card Management administrative permission in Ellucian Experience Setup, as described in Grant Experience application permissions.

Depending on the browser being used, users may be prompted to acknowledge and allow usage of cookies. This is required to access the Banner applications, and different restrictions are imposed by each browser.

Procedure

  1. Access Ellucian Experience as a user with the Card Management administrative permission.
  2. From the Ellucian Experience menu , click Configuration to access the Configuration page.
  3. Click the Card Management tab.
  4. Locate the MoreInfoExtension card.
  5. In the Actions column, click More and then click Edit to start the Edit MoreInfoExtension Card wizard.
  6. In the Details step of the wizard, enter basic card settings.
    1. In the Card Information section, enter descriptive information:
      Setting Description
      Card title This title is displayed at the top of the card. Ellucian recommends a title length of 55 characters or less to ensure readability on all devices.
      Card description This description is not displayed on the card, but is used in search.
      Card tags Tags are used in search and to filter the cards displayed on the Discover page. You can enter multiple tags, separated by commas.
      Category Select the content category in which this card will appear on the Experience main menu for Experience users, and on the Card Management tab for content administrators.
      This card information helps Ellucian Experience users to find cards of interest to them on the Discover page:
      • The tags display at the top of the page. Users can click a tag to filter the display to only cards with that tag.
      • When a user searches for cards, the search includes the text that you enter for title, description, and tags.
    2. Optional: If you want a link to appear in the card action menu, enter the link information in the External Link section:
      Setting Description
      External link label Enter the text for the link as it will appear in the card.
      External link URL Enter the link target URL.
    3. Enable Show as default card in the home page if you want this card to be saved by default for new users, so that it automatically appears on the dashboard of new users when they first access Ellucian Experience.
    4. Click Next.
  7. In the Configure step of the wizard, enter the domain for Banner Administrative pages that are integrated with Experience.
    For example, https://banneradmin.ellucian-university.com:8080 or https://banneradmin.ellucian-university.com.
  8. In the Roles step of the wizard, do either of the following to specify which users will see this card.
    • Click Select all users to assign this card to all Ellucian Experience users.
    • Select roles to assign this card only to users with those roles. The available roles are defined by your institution in Ellucian Experience Setup.
  9. If there is a Preview step in the wizard, click Next and continue with step 10.
    If there is no Preview step, click Finish. You are done with this procedure.
  10. In the Preview step of the wizard, use the Enable card toggle switch to specify whether the card will be available now to Ellucian Experience users.
    You might disable a card, for example, if you want to create the card now but do not yet want to make it available to users.
  11. Click Finish.
    If you enabled the card, it is now available on the Discover page for users with a role that you assigned to the card.

Enable the More Info functionality from the Admin page

To enable the More Info functionality from a Banner administrative page, you must ensure that the necessary configuration values are set up in the GUACONF table.

These configurations are associated with the GLOBAL application ID and are required for accessing the Experience page.

Name Type Description
banner.experience.sdeExtension.url string The base URL for the Banner Experience page.
{MEPCode}.banner.experience.sdeExtension.url string (For MEP institutions) The tenant alias mapping for a specific MEP code to append to the Experience URL.
banner.mep.configurations list Possible values:
  • [all]
  • Comma separated MEP enabled configurations. For example, [EnableLoginAudit,footerFadeAwayTime]
  • []
  • Does not exist

If you set this parameter to [all], and when a parameter value is being looked up by the application, it checks for a MEP code for every parameter.

If the list of parameters are passed as values (for example, [EnableLoginAudit,footerFadeAwayTime]), then the MEP code is selected only for EnableLoginAudit and footerFadeAwayTime parameters. All other parameters fallback to baseline/default parameter values.

If the value passed is [] or if the banner.mep.configurations does not exist, then MEP enabled configurations are not considered for any of the parameter.

Example configuration for MEP institutions

For MEP institutions, the Experience URL must be appended with a tenant alias. The VPDI code does not directly provide the tenant alias, so an additional GUACONF setting is required to map VPDI codes to their corresponding aliases.

Example:

banner.experience.sdeExtension.url = "https://experience-test-internal.elluciancloud.com"

MEPInstitution01.banner.experience.sdeExtension.url = "https://experience-test-internal.elluciancloud.com/mepinst01-main"

In addition, the user must be granted access to the Banner security objects API_EXT_CONFIGURATIONS and API_EXT_MAPPINGS through the Banner Security Maintenance (GSASECR) page to successfully access and manage the More Info functionality.
