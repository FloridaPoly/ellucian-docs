Data source maintenance for Insights

Update Insights data sources when cloning a database

If you need to clone a database in your data source, you must take specific actions in Insights before and after the process so that the newly cloned database successfully connects to Insights.

About this task

  • These steps are only applicable to on-premise implementations.
  • For Ellucian SaaS or Managed Cloud source systems, Ellucian will perform these maintenance steps for you.
Note: This topic refers to actions to take before and after cloning your source database. However, these steps are applicable to several situations, including:
  • cloning your source database.
  • restoring a database to a previous snapshot.

Task 1: Pause data source ingestion before cloning the database

Before you begin the cloning process on your source database, you must pause Data Lake ingestion for all affected data sources.

Procedure

  1. In Insights Administration, go to Ingestion > Data Sources.
  2. Click Actions > Pause for each data source associated with the database to be replaced by the newly cloned database.
    If the Pause option is unavailable (such as when the data source is currently refreshing), wait until the Pause option is available again. If the data source is in ERROR state and cannot be paused, contact Ellucian Action Line.
  3. Optional: If you have recurring point-in-time jobs that capture data from the paused data source, consider pausing those jobs.
    If a point-in-time job is scheduled to occur while data source is paused, the job will successfully capture the data. However, the capture may not be accurate because any data changes on the data source will not be in the Insights Data Warehouse until the last step of this procedure (Task 4: Repopulate the Data Warehouse).

    See Pause or delete recurring jobs for instructions.

  4. Verify that ingestion for all affected data sources is paused.
    On the Ingestion > Data Sources tab, the status for the affected data sources must be PAUSED before you clone your source database.

What to do next

You can clone your source database now that you have paused the Data Lake ingestion processes.

Task 2: Post-clone data ingestion preparation

After you have cloned your source database, you may need to take actions on your source database to ensure it is properly prepared for Data Lake ingestion.

About this task

Note: The data preparation process is only applicable to on-premise implementations. It is not applicable to Ellucian SaaS or Managed Cloud source systems.

If you have an Ellucian SaaS or Managed Cloud system, you can proceed directly to Task 3: Ingest data to the Data Lake.

Procedure

  1. Banner and Degree Works only: Enable supplemental logging and archive logging.

    See Supplemental logging and archive logging for Oracle source systems for more information.

    If you have any custom datasets, you must also re-enable supplemental logging for the source system tables in the custom dataset. This is because table-level supplemental logging settings are not retained during a clone restore. See How to enable supplemental logging for individual tables in custom datasets for more information.

  2. Download and install the latest version of the Insights prerequisite scripts.
    Refer to the instructions for your source system:
    • Prepare your Banner source data
    • Prepare your Colleague source data and SQL Server
    • Prepare your Degree Works source data
  3. In Insights Administration, update any necessary data source connection details (such as endpoint or port changes) and verify the connection.
    During a typical database clone process, the database connection information does not change. Therefore, this step may not be needed. However if the database name or server has changed, you must update these in Insights

    Refer to Edit a data source for specific instructions.

Task 3: Ingest data to the Data Lake

After verifying your data source connection to the newly cloned database, you can continue data ingestion to the Data Lake.

Procedure

  1. In Insights Administration, go to Ingestion > Data Sources.
  2. Click Actions > Restart for each data source that was paused in Task 1: Pause data source ingestion before cloning the database.
    All replicating datasets associated with each data source are reingested to the Data Lake.
  3. On the Recent Activity tab, verify that all data sources and datasets have successfully been ingested to the Data Lake.
    Depending on the volume of data, you may need to wait for the ingestion processes to complete.
    • Load-only datasets display Loaded status when they successfully complete.
    • Replicating datasets display Active status when they successfully complete.

Task 4: Repopulate the Data Warehouse

After all affected data sources and datasets have been ingested to the Data Lake, you can begin to repopulate the Insights Data Warehouse.

Procedure

  1. Schedule a Load All job for your source system, using the specified job template.
    • Banner systems: Load All Banner Insights Product
    • Colleague: Load All Colleague Insights Product
    • Degree Works: Load Degree Works
    Refer to Schedule a job for instructions.
    Note: You may be able to use a Load All job that you previously created for your source system if the job details align with the details for the newly cloned database.
  2. If you have custom datasets that were associated with the old data source, you must schedule a load job for these.
    Refer to Schedule a job - custom datasets for instructions.
  3. If desired, create Data Warehouse refresh jobs for your source system, using the specified job template.
    • Banner systems: Refresh All Banner Insights Product
    • Colleague systems: Refresh All Colleague Insights Product
    • Degree Works: Refresh Degree Works
    Refer to Schedule a job for instructions.
    Note: You may be able to use a previously created recurring Refresh All job for your source system if the job details align with the details for the newly cloned database.
  4. Optional: If you paused point-in-time jobs in Task 1: Pause data source ingestion before cloning the database, you can now resume those jobs.

Results

After your initial Data Warehouse population successfully completes, you have completed the steps for updating Insights after cloning your source database.

Maintain Insights when applying source patches or upgrades

If you need to apply upgrades or patches to your source system (Banner, Degree Works, or Colleague), perform these steps to keep your Insights Data Warehouse in alignment with your database.

About this task

  • These steps are only applicable to on-premise implementations.
  • For Ellucian SaaS or Managed Cloud source systems, Ellucian will perform these maintenance steps for you.
Note: In this topic, the term source system refers to the Ellucian application that is the data source for Insights: Banner, Degree Works, or Colleague.

Task 1: Pause data source ingestion before applying source system patches or upgrades

Before you apply the patches or upgrades to your source application, you must pause Data Lake ingestion for all affected data sources.

Procedure

  1. In Insights Administration, go to Ingestion > Data Sources.
  2. Click Actions > Pause for each associated data source.
    If the Pause option is unavailable (such as when the data source is currently refreshing), wait until the Pause option is available again. If the data source is in ERROR state and cannot be paused, contact Ellucian Action Line.
  3. Optional: If you have recurring point-in-time jobs that capture data from the paused data source, consider pausing those jobs.

    If a point-in-time job is scheduled to occur while data source is paused, the job will successfully capture the data. However, the capture may not be accurate because any data changes on the data source will not be in the Insights Data Warehouse until the last step of this procedure (Step 5).

    See Pause or delete recurring jobs for instructions on pausing upcoming point-in-time jobs.

Task 2: Actions after source system upgrades and patches

After applying upgrades or patches to your source system, you can continue ingestion to the Data Lake. You must also reingest the Data Catalog, and any dataset templates containing data structure changes.

Procedure

  1. Resume ingestion for each data source that was paused in Task 1: Pause data source ingestion before applying source system patches or upgrades.
    Note: Be sure to select Resume, not Restart, for each paused data source. Selecting Resume continues CDC processing from the point where ingestion was paused. Selecting Restart starts the ingestion process from the beginning, and also requires a reload to the Data Warehouse. Restarting the ingestion can take a long time, depending on the size of your database.
    1. In Insights Administration, go to Ingestion > Data Sources.
    2. Click Actions > Resume for each affected data source.
    The resumed ingestion is complete when the data source status on the Ingestion > Data Sources tab is Active.
  2. Reingest the data catalog for your source system to ensure it reflects any data structure changes made in the source.
    • Banner Data Catalog
    • Degree Works Data Catalog
    • Colleague Data Catalog

    See Reload source data into the Data Lake for specific instructions.

  3. After the data catalog ingestion completes, reingest any datasets, including custom datasets, for any modules containing data structure changes, such as Banner Student or Colleague Student.

    Reloading the affected datasets ensures that the Data Lake reflects any data structure changes on your source system.

    See Reload a dataset for specific instructions.

    To determine which modules contain the structure changes, refer to your source system's release notes.

  4. Schedule a population job to repopulate the Data Warehouse for the affected modules, such as Load Banner Student or Load Colleague Student.

    Running the population job ensures that the Data Warehouse reflects any data structure changes on your source system.

    See Schedule a job and Schedule a job - custom datasets for specific instructions.

  5. Optional: If you paused point-in-time jobs in Task 1: Pause data source ingestion before applying source system patches or upgrades, you can now resume those jobs.

Update Insights when switching your data source

Switching or changing the Insights data source requires Insights administrators to remove configurations, job schedules, and datasets associated with the old data source and recreate those on the new data source. This ensures that the Data Lake and Insights Data Warehouse synchronize with the new data source.

About this task

This procedure only applies to:
  • On-premise implementations.
  • On-premise implementations migrating to a SaaS or Managed Cloud implementation.
Note: This procedure does not include all necessary instructions for migrating from on-premise to a SaaS or Managed Cloud implementation. You should work closely with your Ellucian representatives for all guidance and directions in this scenario.
Follow this procedure if you are switching your data source, such as:
  • Moving from a non-Production (Test) data source to a Production data source.
  • The data source's server IP address changes.
  • The data source's service name or database name changes.
Note: In this topic, the term source system refers to the Ellucian application that is the data source for Insights: Banner, Colleague, or Degree Works.

The term old data source refers to the data source system you are moving from, and new data source is the data source you are moving to.

Task 1: Complete networking requirements

If you are switching your data source to a new server, complete these networking requirements.

About this task

Do not perform this task if:
  • Your new data source is on the same server as the old data source.
  • You are migrating from an on-premise data source to a SaaS or Managed Cloud implementation. Ellucian will perform these maintenance steps for you.

If you do not need to complete this task, proceed to Task 2: Review associated population jobs, custom datasets, and custom configurations.

Procedure

  1. Ensure your network protocols and permissions allow access to the new source database from traffic originating from the Ellucian VPN.
  2. Contact Ellucian Action Line to share the IP address of the new source database server. Ellucian needs this IP address to configure the NAT address in the VPN for the new data source.

What to do next

Ellucian Action Line will confirm when the VPN for the new data source has been created.

Task 2: Review associated population jobs, custom datasets, and custom configurations

Later in this process, you will remove datasets, population jobs, and custom configurations associated to the old data source and recreate them for the new data source. To minimize the work needed to recreate them, record your current administration settings in advance of switching your data source.

Procedure

  1. Review any recurring population schedules to be recreated with the new data source.
    1. In Insights Administration, go to Population > Recurring Schedules.
    2. Click the job name to see its details.
    3. Make note of the job details so that you can recreate it when the new data source is configured.
  2. Review any custom datasets associated with the old data source and download the template definitions.
    1. Go to Configuration > Custom Datasets.
    2. For all custom dataset templates associated with the old data source, click the dataset template name to view its details.
    3. If you want to recreate the custom dataset template to use it with the new data source, click Download to download a CSV file containing the template definition.
      Downloading the CSV files with the definitions will greatly assist you when you recreate the custom datasets for the new data source.
    4. Review the CSV definition of the custom dataset and adjust as needed.
      For example, you may need to remove tables that are no longer applicable in the new data source.
  3. If there are recurring point-in-time data capture jobs that include tables associated with the original data source, review the job details and evaluate whether the tables in the list should be captured on the new data source.
    1. Go to Configuration > Point-in-time Lists to review all lists.
    2. Click a point-in-time list name to review its details.
    3. For each point-in-time list, review the details and take action as needed.
      • If you do not want to keep the list for the new data source, delete the list. This also deletes any capture jobs associated with the list.
      • To keep the list and capture data using the new data source, and there are no changes to the tables in the list, you do not need to take any action. The list will be available for use with the new data source after you complete all steps in this procedure.
      • To keep the list and capture data using the new data source, but the list needs modifications (such as adding or removing tables), you do not need to take any action until after the Data Warehouse has been populated with the new data source. That can be done after Task 6: Populate the Data Warehouse and recreate jobs and custom configurations.
    4. For each point-in-time capture you want to keep for the new data source, go to Population > Recurring Schedules to review the schedules and update as needed.
      The recurring scheduled jobs for point-in-time lists are retained in Insights Administration unless you remove them. This allows you to retain the same data capture schedule for your point-in-time list after you switch to the new data source.
  4. Take note of any customizations you made to parameters.
    If you want to use these customizations with your new data source, you can reapply them later in this procedure (Step 1 of Task 6: Populate the Data Warehouse and recreate jobs and custom configurations).
  5. Take note of any customizations you made to display rules in Insights.
    If you want to use these customizations with your new data source, you can reapply them later in this procedure (Step 1 of Task 6: Populate the Data Warehouse and recreate jobs and custom configurations).

Task 3: Remove the old data source and associated dependencies

After reviewing all items associated with the old data source and recording any details you want to recreate on the new data source, you can remove them from Insights Administration. Then you need to delete the old data source from Insights.

Procedure

  1. In Insights Administration, delete all ingested datasets (including custom datasets) associated with the old data source.
    1. In Insights Administration, go to Ingestion > Datasets.
    2. Click Filter to narrow the display list.
    3. Select the old data source and click Apply.
    4. For each dataset, click Actions > Delete.
    See Delete a dataset for additional information.
  2. If you have custom datasets associated with the old data source and downloaded them in Task 2: Review associated population jobs, custom datasets, and custom configurations, delete the custom dataset templates.

    See Delete a custom dataset for instructions.

  3. Delete all recurring population jobs that are associated with the old data source.

    See Pause or delete recurring jobs for instructions.

    Note: You can retain recurring point-in-time jobs for the point-in-time lists you want to use with the new data source. Any unwanted point-in-time jobs should have been removed in Step 3 of Task 2: Review associated population jobs, custom datasets, and custom configurations.
  4. After removing all items associated with the old data source, you can delete the old data source from Insights Administration.
    See Delete a data source for instructions.

Task 4: Create the new data source and ingest the data

After safely removing all items associated with the old data source, you are ready to create the new data source in Insights Administration and ingest its data into the Data Lake.

Before you begin

  1. Ensure that Ellucian has created the VPN tunnel and provided you with the NAT IP address for your new data source. This should have been configured using the information you provided in Task 1: Complete networking requirements.

    Contact Ellucian Action Line if necessary.

  2. Banner and Degree Works source systems: If you have custom dataset templates, ensure supplemental logging is enabled for all tables in your custom dataset templates. See Supplemental logging and archive logging for Oracle source systems for instructions.

About this task

If migrating from on-premise to a SaaS or Managed Cloud implementation, do not perform Steps 1 and 2. Ellucian will perform these steps for you.

Procedure

  1. Perform all data ingestion prerequisites on the new data source.
    Note: If migrating from on-premise to a SaaS or Managed Cloud implementation, do not perform this step. Ellucian will perform this step for you.
    Follow the instructions in the data preparation section for your Ellucian source system:
    • Prepare your Banner source data
    • Prepare your Degree Works source data
    • Prepare your Colleague source data and SQL Server
  2. In Insights Administration, create the new data source.
    Note: If migrating from on-premise to a SaaS or Managed Cloud implementation, do not perform this step. Ellucian will perform this step for you.

    See Ingest your source data into the Data Lake for instructions. Be sure to test the connection to the new data source.

  3. Ingest the data from your new source to the Data Lake.
    Note: If you have any custom datasets, do not ingest them now. You will ingest them later in this procedure.

    For instructions, see Ingest your source data into the Data Lake.

  4. On the Recent Activity tab, verify that all data sources and datasets have successfully been ingested to the Data Lake.
    Depending on the volume of data, you may need to wait for the ingestion processes to complete.
    • Load-only datasets display Loaded status when they successfully complete.
    • Replicating datasets display Active status when they successfully complete.

What to do next

Warning: Do not proceed to Task 5 (Required): Contact Ellucian Action Line until you have completed all steps to this point in this procedure.

Task 5 (Required): Contact Ellucian Action Line

To ensure proper Data Warehouse population for the new data source, Ellucian must perform several key tasks for you.

Before you begin

Complete all previous steps in this procedure before contacting Ellucian Action Line.
  • Task 1: Complete networking requirements
  • Task 2: Review associated population jobs, custom datasets, and custom configurations
  • Task 3: Remove the old data source and associated dependencies
  • Task 4: Create the new data source and ingest the data
Warning: If you are migrating from an on-premise configuration to a SaaS or Managed Cloud implementation, notify your Ellucian representative that you have completed all previous steps. Your Ellucian representative will advise you when you can continue to Task 6: Populate the Data Warehouse and recreate jobs and custom configurations.

Procedure

  1. Required: Contact Ellucian Action Line to notify them of your data source switch.
    Be prepared to provide these details of your new data source:
    • The name of the new data source created, as defined on Ingestion > Data Sources.
    • The environment where the change will happen, such as Production, non-Production, Test.
    Ellucian Action Line will perform the necessary actions on your environment to prepare it for the new data source.
  2. Required: When Ellucian Action Line notifies you that you can begin to populate the Data Warehouse, Insights, you can proceed to Task 6: Populate the Data Warehouse and recreate jobs and custom configurations.

Task 6: Populate the Data Warehouse and recreate jobs and custom configurations

Perform the setup steps as you would for any new data source. You can refer to any records you kept in Task 2: Review associated population jobs, custom datasets, and custom configurations to streamline the process.

Before you begin

Warning: Do not proceed with these steps until you have received clearance from Ellucian Action Line to continue.

About this task

This process is nearly identical to the steps outlined in the Insights administrator section of the Ellucian Insights setup checklist. Refer to that topic or the linked topics for more information.

Procedure

  1. Review parameter records and update any customizations you applied to your old data source.
    See Review and update parameters before initial Data Warehouse population for instructions.
  2. Schedule a Load All job for your new data source, using the specified job template.
    • Banner systems: Load All Banner Insights Product
    • Colleague: Load All Colleague Insights Product
    • Degree Works: Load Degree Works
    Refer to Schedule a job for instructions.

    To check the progress of your population jobs, see Monitor Population job statuses for more information.

  3. If you deleted custom dataset template definitions in Task 3: Remove the old data source and associated dependencies, recreate and reingest the custom datasets.
    Note: Ensure that all population jobs have completed before attempting to ingest the custom datasets. The data catalog must be in the Data Warehouse before you can ingest a custom dataset.

    See Create a custom dataset and Ingest a custom dataset to the Data Lake for instructions.

    If you intend to upload the saved custom dataset definitions from Task 3: Remove the old data source and associated dependencies, review the data source information in those definitions to confirm the definitions are still valid for the new data source.

  4. If there are recurring point-in-time data capture jobs that include tables associated with the original data source, review the job details and make any necessary changes.
    1. Go to Configuration > Point-in-time Lists and evaluate whether the tables in the list should still be captured, considering the data source changes.
    2. If necessary, make any changes to the list.
      See Edit a point-in-time list for instructions.
    3. If the entire list is no longer valid, delete the point-in-time list, which also deletes any recurring jobs associated with it.
      See Delete a point-in-time list for instructions.
    4. If desired, create a new point-in-time list and new recurring point-in-time jobs for the updated data source.
      See Create a point-in-time list and Create a point-in-time job.
  5. Recreate any recurring population jobs that you deleted in Task 3: Remove the old data source and associated dependencies.
    See Schedule a job for instructions.

Results

Your new data source setup is complete.

What to do next

If your site uses Insights Custom Transformations with pipelines that refer to tables in the old data source, verify the same tables exist in the new data source.

If they do not exist on the new data source, make any necessary adjustments to the pipelines so that the pipelines do not fail. Alternatively, you may choose to delete pipelines that are no longer applicable.

Update Insights data sources for database credentials changes

If the password or other connection credentials have changed on your source system, you must update the data source connection information in Insights Administration.

About this task

  • These steps are only applicable to on-premise implementations.
  • For Ellucian SaaS or Managed Cloud source systems, Ellucian will manage the password change. If an error occurs because of an incorrect username or password, contact Ellucian Action Line.

See Edit a data source for more information.

Procedure

  1. In Insights Administration, go to Ingestion > Data Sources.
  2. For the affected data source, click Actions > Pause.

    If the Pause option is unavailable (such as when the data source is currently refreshing), wait until the Pause option is available again.

    If an affected data source has an ERROR status, click the error message and review the status. If the error is due to a connection or credentials error, you do not need to pause the data source ingestion.

  3. Click Actions > Edit.
  4. Enter the new password for the data source.
  5. Click Verify to confirm the connection using the new password.
  6. Click Save.
  7. Click Actions > Resume to resume data ingestion for this data source.
    Note: Be sure to select Resume, not Restart for the paused data source. Selecting Resume continues CDC processing from the point where ingestion was paused. Selecting Restart starts the ingestion process from the beginning, and also requires a reload to the Data Warehouse. Restarting the ingestion can take a long time, depending on the size of your database.

Maintain Insights when updating the data source operating system

If your source system will shut down during an operating system update, perform these steps to keep your Insights Data Warehouse in alignment with your data source when it returns online.

About this task

  • These steps are only necessary if you have to take your data source databases offline when applying updates to the source system's operating system.
  • These steps are only applicable to on-premise implementations.
  • For Ellucian SaaS or Managed Cloud source systems, Ellucian will perform these maintenance steps for you.

Task 1: Actions before the operating system updates

You need to ensure logging is enabled and then pause all affected data ingestion processes before you begin applying any operating system updates.

Procedure

  1. Banner and Degree Works only: Enable supplemental logging and archive logging, if not already enabled.

    Because you will be pausing ingestion during the operating system updates, enabling supplemental logging ensures that the required archive logs are retained until the CDC process is complete after ingestion is unpaused.

    See Supplemental logging and archive logging for Oracle source systems for more information.

  2. Pause ingestion for the affected data sources.
    See Pause, resume, or restart a data source.
    1. In Insights Administration, go to Ingestion > Data Sources.
    2. Click Actions > Pause for each associated data source.
      If the Pause option is unavailable (such as when the data source is currently refreshing), wait until the Pause option is available again. If the data source is in ERROR state and cannot be paused, contact Ellucian Action Line.
  3. Optional: If you have recurring point-in-time jobs that capture data from the paused data source, consider pausing those jobs.

    If a point-in-time job is scheduled to occur while data source is paused, the job will successfully capture the data. However the capture may not be accurate because any data changes on the data source will not be in the Insights Data Warehouse until the last step of this procedure (Step 3).

    See Pause or delete recurring jobs for instructions on pausing upcoming point-in-time jobs.

Task 2: Continue ingestion after operating system updates

After all operating system updates on your source system are complete, you can continue data ingestion.

Procedure

  1. In Insights Administration, go to Ingestion > Data Sources.
  2. Click Actions > Resume for each data source that was paused in Task 1: Actions before the operating system updates.
    Note: Be sure to select Resume, not Restart for the paused data source. Selecting Resume continues CDC processing from the point where ingestion was paused. Selecting Restart starts the ingestion process from the beginning, and also requires a reload to the Data Warehouse. Restarting the ingestion can take a long time, depending on the size of your database.
  3. Optional: If you paused point-in-time jobs in Task 1: Actions before the operating system updates, you can now resume those jobs.
