Build reports and dashboards using the Insights reporting tool

Ellucian Insights offers you many ways to navigate and view your institution's data. Refer to this overview topic as a starting point for viewing your Insights data and creating new reports, dashboards, and collections.

Note: The Insights reporting tool is available only with Ellucian Insights Premium.

Insights home page

To access your institution's reporting content and data sources, click Launch Reports on the Insights card on your Ellucian Experience dashboard. Or click the Insights home button from any page in Insights.

Alternatively, you can access the Insights reporting tool from anywhere in Experience using the Application menu . Selecting Insights in the Application menu takes you to the Insights home page.

The navigation bar displays on the left of the Insights home page and contains the collections, dashboards, and reports that you have access to.

Note: If you attempt to access the Insights reporting tool before your Insights Premium setup has completed, you will not be able to access the reporting tool. If you believe this is in error, contact Ellucian Action Line.

Reports, dashboards, and collections

  • A report is the result set of a query of your data. A report can be anything from a simple tabular view of a table in your data source, a visualized image of the query result, or a complex and finely tuned SQL query.


  • A dashboard is a group of reports presented on a single page. Dashboards may contain filters to allow you to narrow down the data within the reports on the dashboard, as shown in the following example.


  • A collection contains associated dashboards and reports. Think of collections as the directories or folders that contain dashboards and reports. Collections are depicted by folders in the navigation bar.


Explore saved reports and dashboards

In Ellucian Insights, every dashboard section or component is an individual report. Click the title of a report on a dashboard to see the detailed view of that report.

When viewing a report's detail view, you can explore the report the same way you explore a dashboard. You can also click the headings of the tables to see more options, such as adding the values of a column, filtering based on that column, or displaying a distribution.

For example, in a table with a list of students, if you click the Age column and select Distribution, you will see a bar chart with the count of students in each age bracket.

Search for data sources, dashboards, reports, and more

Use the search bar to find dashboards, reports, collections, or any item found in Insights. You can select a previously viewed item, select from the typeahead results, or press Enter to view the search results page.

Tip: You can activate the search bar from anywhere by pressing the / key.

Searches take into account items’ titles, descriptions, and even the contents of your SQL queries. For example, you can search for statements like SELECT count(distinct "source"."Registered Count") to find that report you worked on two months ago.

Search results display an item’s description, the collection it is saved to, and the type of object it is.

Browse your data sources

Your institution's data is the foundation of any Insights report. To explore your database tables, reporting views, and schemas directly through Insights, expand Browse in the navigation sidebar.

For more information on browsing the database schemas and tables through Insights, see Browse your data.

Query and visualize your data

Ellucian Insights offers two ways to query the database:
  • Reports: You can use the query builder to compose simple or sophisticated queries. The query builder guides you through building custom expressions without needing to know SQL.
  • SQL queries: For advanced users with SQL experience, you can use the editor to compose more complex SQL queries.

For more information on how to query and visualize your data, see Create reports.

Download results

You can download results from a saved report, SQL query, or from an individual dashboard component.

Results can be downloaded:

  • From a report or SQL query: click Download results at the bottom of the page to reveal download options.

    See Download a report or dashboard for more information.

  • From a dashboard component: click More to reveal download options.

You can choose to download the results to CSV, XLSX, JSON, or PNG format.

Create reports

In Ellucian Insights, a report is simply the result of a data query. However, you can create a more meaningful visualization for the report containing the query results.

Insights provides two tools for building reports: the query builder and the SQL editor.

Create reports with the query builder

Most report designers will use the simple yet powerful query builder to create reports. You can build a simplistic tabular report based on filtering and summarizing data, or you can build more complex reports, join tables, create custom columns, add drillthrough capabilities, and more.

The benefit of using the query builder is that you do not have to know SQL to create queries and reports. You can duplicate an existing report and use it as a starting point for another query. Reports can also start with a table in a database, or with the results of a saved query. You can convert these queries to SQL at any time.

Create reports using SQL queries

For more advanced report designers, you can write your own SQL query to build complicated and advanced reports. Or, as with reports built with the query builder, you can duplicate an existing report and then use the SQL editor to add your advanced query code. You can also migrate reports previously written in SQL to Insights.

For reports written in SQL, you can use variables in your code to create SQL templates, including field filter variables that can create smart drop-down filters.

Use the query builder to build reports

Most reports that you build in Insights have the same building blocks. The query builder is an intuitive, user-friendly tool to help you assemble those blocks and meet most of your reporting needs.

How to start a new report

You can start a new report by using one of the following methods:
  • From any page in Insights, click + New > Report.

    This method builds a new report from scratch without using an existing report as the foundation.

    Note: This is the method highlighted throughout this topic.
  • Modify an existing report and save it as a new report.

    This method builds a new report using an existing report as the foundation. See Build a new report from an existing report for instructions using this method.

Select your data source

When you build a new report from scratch, you can choose from using models, raw data, or a saved report as your data source. For example, if you choose Raw Data, you might choose data-warehouse > odsmgr > Award By Person.

Note: You can only pick tables and saved reports that are from the same database as your starting data.

After selecting your data source, the query builder displays.

The query builder is a user-friendly interface for building your reports without needing to know SQL. It consists of a sequence of individual steps to help you build your report, such as selecting your data source, adding filters, and picking metrics or columns to summarize by.



Each section (or step) of the query builder includes additional tools pertaining to that step. As you build your report, you can use the preview button to view the first few rows of the results of your query up to that step.

Filters

Report filters narrow the data set based on specific criteria. If adding filters to your report, you can select one or more columns to filter on. Depending on the type of column you pick, the query builder may display intuitive filter options for the column, such as a calendar for date columns.

See Report filters for more information about adding filters.

Summaries

Adding a summarize step allows you to choose how to aggregate the data from the previous step of the query builder. You can select one or more metrics, and optionally group those metrics by one or more columns.

See Report summaries for more information about adding summaries to your report.

Sort results

Click the Sort button to select one or more columns in your table to use to sort the report results. For each selected column, you can also choose whether to sort ascending or descending. Simply click the arrow to change from ascending (up arrow) to descending (down arrow).

Set a row limit

Use the Row limit option to restrict the number of rows you want to display. For example, use this in conjunction with sorting to create a top 10 list, by first sorting by one of the columns in your result, then adding a row limit of 10.

Unlike other steps, the row limit step can only be added at the end of your report.

Note: Row limits are based on the data requested where 2,000 rows are displayed for raw data, and 10,000 rows are displayed for aggregate data.

Custom columns

Custom columns are helpful when you need to create a new column based on a calculation, such as subtracting the value of one column from another or extracting a portion of an existing text column.

Note: Columns you add to a report are not permanently added to the table of your data source. They are only present in the given report.

You can use math operators in your formulas, such as +, –, * (multiplication), and / (division), in addition to many spreadsheet-like functions. You can also use parentheses to clarify the order of operations.

View the SQL that powers your report

Beneath the surface, all Insights reports are written in SQL. If you are curious to see the SQL syntax for a report, click View SQL to display the SQL.

Build a new report from an existing report

Building a new report does not have to always start from scratch. You can use an existing report as the starting point for a new one.

Before you begin

  • You must have Edit permission to access the collection containing the report you want to duplicate.
  • You will need a unique name for your new report to prevent unwanted results.
  • You cannot duplicate reports in the Ellucian collection using this method.

Contact your Insights administrator for information about your account permissions and access to collections.

About this task

Basing your new report on a previously saved report gives you a head start. You can duplicate a fine-tuned SQL query and tailor the duplicate to meet your needs. You can even duplicate a report with one type of visualization and save it as another visualization type. For example, you can duplicate a line chart report and save it as a bar chart, so that you have the same data and report criteria but presented in two ways.

Note: Although you can duplicate a report by editing an existing report and then save it as a new report, Ellucian recommends following this process to avoid overwriting an existing report with your changes.

Procedure

  1. Navigate to the report you want to duplicate.
  2. Click More to reveal more options.
  3. Click Duplicate to create a copy of the report.
  4. Provide a unique name and useful description for the report.
    Note: Although it is possible to have multiple reports with the same name in the same collection, Ellucian strongly recommends using unique report names to minimize unexpected results.
  5. Select the Collection where this report will be saved.
    The collections list only contains the collections that you have permission to access.
  6. Click Duplicate.
    A confirmation window appears.
  7. If you want to add the new report to a dashboard now, click Yes please! to select the dashboard. Otherwise, click Not now.
    You can always add the new report to a dashboard at a later time.

Results

The new, duplicated report is ready for you to customize.

Report filters

When building queries and reports, you can add filters to target the information you are looking for.

The Filter button displays the columns available for filtering in the current table, in addition to columns from tables that are related to the one you are looking at. Depending on the column you select, you may see slightly different options for your filter.

Broadly speaking, there are three types of columns, each with their own set of filtering options:

  • Numeric columns allow you to add filters to only include rows in your table where this number is between two specific values, or is greater or less than a specific value, or is exactly equal to something.
  • Text or category columns allow you to specify that you only want to include data where this column is or is not a specific option, or you can exclude rows that do not have a value for this column.
  • Date columns show a calendar or input box so that you can select specific time ranges or choose all days before or after a certain date.
Note: When filtering on a date column, note the difference between specific dates and relative dates.
  • Specific dates always refer to the same date or date range, such as November 1, 2010, or June 3 – July 12, 2017.
  • Relative dates are ranges such as “the past 30 days” or “the current week.” As time passes, the actual dates in the range will change. Relative dates are a useful way to keep filter results up to date.

To apply the filter you created, click Apply filter and your data updates with your filter applied.

Tip:
  • To change your filter, locate the applied filter at the top of the report and edit as needed.
  • To remove any applied filter, click the X next to the filter.
  • You can add as many filters as needed.

If you have a more complex filter, click the Editor button. Locate the Filter section and click the button. Select Custom Expression from the end of the menu. You can use comparison operators such as greater than (>) or less than (<), in addition to spreadsheet-like functions. For example, [Subtotal] > 100 OR median([Age]) < 40.

Tip: You can add subsequent filter steps after every Summarize step. For example, you could summarize by the count of rows per month, and then add a filter on the count column to only include rows where the count is greater than 100. This is similar to using a SQL HAVING clause.

Report summaries

A summary is usually made up of two parts: a metric and how you want to see that metric grouped or broken out.

When you have a report requirement such as "How many applicants for the 2021-2022 academic year applied to the business school?” or "How many financial aid packages are missing the proof of citizenship document?", you are asking for a summary of the data.

Using the first example requirement: How many applicants for the 2021-2022 academic year applied to the business school?
  • The metric is "How many applicants."
  • The metric will be grouped by “the 2021-2022 academic year and business school.”

The two most common ways to summarize your data are to count the number of rows in your table and get the sum or average of a numeric column. Then you might group that number by time, place, or some other category such as academic year, course section, gender, state, etc.

Select your metrics and groupings

To summarize your data from a table, click the Summarize button to open the Summarize sidebar.



In the upper section, Summarize by, select the metric you want to see. In the lower section, Group by, select how to group that number.

By default, the row count metric is selected. You can summarize by one or more metrics by clicking Add a function or a metric .

When choosing your metrics, you can:
  • select from basic functions such as sum, average, and count
  • pick a common metric that has been defined
  • create a custom expression by writing a formula
Table 1. Metrics for summarizing data
Metric Description
Count (of rows) The total of number of rows in the table, after any filters have been applied.
Sum of The sum of all the values in a specific column.
Average of The average of all the values in a single column.
Number of distinct values of … The number of unique values in all the cells of a single column. This is useful when trying to find out things like how many individual applicants applied last academic period (not how many applications were received, as an applicant could submit more than one application).
Cumulative sum of… Provides a running total for a specific column. For this metric to be useful, group it by a date column to see it across time.
Cumulative count of rows Provides a running total of the number of rows in the table over time. For this metric to be useful, group it by a date column to see it across time.
Standard deviation of … A number which expresses how much the values of a column vary, plus or minus, from the average value of that column.
Minimum of … The minimum value present in the selected field.
Maximum of … The maximum value present in the selected field.

Select groupings for a metric

Depending on the grouping column you select, Insights displays what it thinks is the best default visualization or chart for this summary. For example, if you select a date column, you might see a line chart depicting a trend over time.

When you click a different grouping column, the grouping switches to use that column instead. But, if you want to add an additional grouping, click the Add button () on the right of the column name.

Some grouping columns give you the option of choosing how big or small to make the groupings. For example, if you select a Date column to group by, click the qualifier by month to change the grouping to week, day, hour, quarter, year, etc.



If grouping by a numeric column, such as age, Insights automatically groups or bins the results, so you will see your metric grouped in age brackets, like 0–10, 11–20, 21–30, etc. Similar to grouping dates, you can click on the current grouping option to change it to a specific number of bins.

If you summarize and add a grouping, you can then summarize again. You can also add steps to filter or join in between.

For example, your first summarization step is to get the count of registrations for every section of American History 101 for the past two academic years. Then you can add a second summarization step to get the average section enrollment by selecting the Average of… your count column.

After configuring your metrics and groupings, click Done to close the Summarize sidebar and view your results.

Join data in the query builder

You can use query builder to combine data with another table, or with a saved report.

Click Join Data to add a join step during the creation of a new report. You will be prompted to pick the data that you want to join.

Note: You can only pick data that is found within the same database as your starting data.
Figure 1. Join data step

After selecting the data you want to join, you must pick the columns you want to join on. Select a column from the first table and a column from the second table. The join stitches rows together where the value from the first column is equal to the value in the second column.

Figure 2. Join data column selection

By default, a left outer join will be used however you can change this. Click Change join type located between the two tables you selected to join.

The types of joins available are:
  • Left outer join: select all records from first table, along with records from second table that meet the join condition, if any.
  • Right outer join: select all records from second table, along with records from first table that meet the join condition, if any.
  • Inner join: only select the records from both tables, where the join condition is met.
  • Full outer join: select all records from both tables, whether or not the join condition is met.
Note: Not all databases support all types of joins. You will only see the options supported by the database you are using.
Figure 3. Join options

Join data with multiple join steps

There may be instances where you want to join multiple tables where not all the tables have a connection to each other. To do so, you must use multiple join steps. After you have completed your initial join data step, click Join Data to add another join step. This will take the results of the first join data step, and allow you to select another table to join.

Note: When using multiple join steps, the table selected in the additional join steps must have a connection with one of the tables in the prior step.

SQL queries in Insights

If you need to write a query that you cannot write using the query builder and editor, you can use SQL instead.

Note: Only Insights users with Edit permission can build reports using the SQL editor. Contact your Insights administrator if you do not have adequate permission to use the SQL editor.

Where to begin

You can create a new SQL query by clicking + New > SQL query from any page in Insights. Then you can begin writing SQL directly into the editor that appears.

You can also use an existing report as a starting point for a SQL query. To do this, go to a report and click the Editor button . Then click View SQL to display the SQL behind the report. You can copy and paste this SQL for future use. Or you can click Convert this report to SQL to use this as the starting point of a new query in the SQL editor. This is a handy shortcut to use the existing SQL generated by Insights, and then tweak and customize the query, saving it with a new report name.

Just like reports created with the query builder, you can save and download reports created with a SQL query. You can also add them to dashboards.

Run your SQL query

To test the report you are building, click the Run query button to run the SQL query. You can also run your SQL query by pressing Ctrl + Enter on Windows and Linux, or Cmd + Return on a Mac.

Tip: You can also run only the selected section of a query by highlighting the part you would like to run before clicking the Run query button .

Using SQL filters

If you or someone else wrote a SQL query that includes variables, your report might have filter widgets at the top of the screen. Filter widgets let you modify the SQL query before it runs, changing the results you might get.

See Add a basic input variable to a SQL report and Add a field filter to a SQL report for more information.

Create SQL snippets

SQL snippets are saved pieces of SQL code that you can reuse and share with other advanced report designers who write SQL queries. Anyone with SQL editor permissions for at least one database can use, create, and edit snippets.

Note: Only Insights users with Access permission for at least one database can use, create, and edit snippets.

To create SQL snippets, you must be in the SQL editor. Within the SQL editor you can create an SQL snippet by right-clicking a highlighted section of your SQL statement and selecting Save as snippet. Then save your snippet in the Our Snippets folder.

You can also create a snippet by clicking the SQL Snippets button . Followed by the New button , and then select New snippet.

You can also make a copy of an existing snippet. From within the SQL editor, click the SQL Snippets button , then locate the snippet you want to make a copy of. Click the expand button to display the SQL being used and copy that to your computer's clipboard or into a text editor. Followed by the New button , and then select New snippet. Saved snippets

Saved SQL snippets are stored within folders. These folders are divided into two groups: Ellucian Snippets and Our Snippets.

Ellucian Snippets is where you will find any delivered snippets provided by Ellucian, that can be used at your discretion. Our Snippets is the location where report writers at your institution should save any snippets that they have created.

Tip: If you want to use or make edits to snippets found within the Ellucian Snippets folder, it is recommended that you make a copy and save it to the Our Snippets folder. Any edits made within Ellucian Snippets will be overwritten during upgrades.

To use SQL snippets, you must be in the SQL editor. Within the SQL editor you can use SQL snippets by clicking the SQL Snippets button and selecting the snippet you want to use.

Add a basic input variable to a SQL report

When you create a report using SQL, you can include a filter to enable users to refine the data that the report displays. To do so, you can use a basic input variable.

About this task

Reports created using the Insights SQL editor use four types of variables: text, number, date, or field filter. These variable types are divided into two categories: basic input variables and field filters.
Basic input variables create simple filter widgets that enable users to input numbers, text, or dates to filter report results. Basic input variables work well for values that are not predefined, or range widely. Use basic input variables for the following scenarios:
  • Simple text, number, and date filtering.
  • Innumerable values that would not work within a drop-down menu.
  • Instances where data wrangling is required on the input variable in your SQL.

Field filters, however, are unique input variables. Field filters are connected to columns, and can provide a drop-down menu for users to select one or more values. For more information about field filters, see Add a field filter to a SQL report.

To use a basic input variable you must add a WHERE clause to your SQL query. The WHERE clause uses abbreviated syntax that precludes the requirement for an operator such as =. The format of the clause is WHERE {{variable_name}}, where variable_name is the name you want to use for the basic input variable.

Procedure

  1. Go to New > SQL Query.
  2. Enter your SQL code.
  3. To define the field filter variable_name, on a new line, enter WHERE {{variable_name}}, and replace variable_name with a meaningful name.
    The WHERE {{variable_name}} clause must follow your SQL SELECT statement unless you are using it to perform a calculation. If your SQL statement contains any GROUP or ORDER statements, your WHERE clause must precede them.
    The Variables menu appears after you type the first letter of your variable within your WHERE {{variable_name}} clause.
  4. Select Text, Number, or Date as the Variable type.
    When Text is selected for Variable type, an additional parameter How should users filter on this variable? appears with the following options:
    • Dropdown list: You must select Edit and follow the on screen prompts to configure the list options.
    • Search box: You must select Edit and follow the on screen prompts to configure the search options.
    • Input box: No further configuration is required.
    If Date is selected, Insights provides a widget that enable users to select dates and times rather than typing in values.
  5. Type a meaningful name for your filter in the Filter widget label field.
    It is recommended to name your filter widget similarly to the variable_name used in your WHERE clause to help identify for future edits.
  6. Optional: Click the toggle to enable Required?.
    If the Required? toggle is on, you must provide a default value in the Default filter widget value field.
    Note: If Required? is disabled, the toggle is shaded out, or gray in color.
  7. Click Save.
  8. On the Save new report window, provide a name for your SQL report, and then choose the location to save it.
  9. Click Save.
Add a field filter to a SQL report

When creating a report with SQL, you might also want to include a filter to display relevant data at a glance. You can do this by leveraging a special variable known as a field filter.

About this task

Field filters are a special type of variable that map a variable to a field or column in a table. You can accomplish this by adding a WHERE clause to your SQL query. The WHERE clause uses abbreviated syntax so there is no need for an operator such as =. The format of the clause will be WHERE {{variable_name}}, where variable_name is the name you want to use for the field filter variable.
Note: Field filters only work with the following field types:
  • Category
  • Entity name
  • Entity key
  • Foreign key
  • City
  • State
  • Zip or Postal code
  • Date
  • Time stamp

Procedure

  1. Go to New > SQL Query.
  2. Enter your SQL code.
  3. On a new line, enter WHERE {{variable_name}} to define the field filter variable name, replacing variable_name with a meaningful name.
    The WHERE {{variable_name}} clause must be after your SQL SELECT statement. If your SQL contains any GROUP or ORDER statements, your WHERE clause must be placed before them.
    The Variables menu appears after you type the first letter of your variable within your WHERE {{variable_name}} clause.
  4. Select Field Filter as the Variable type.
  5. Select the table and field you want to use for Field to map to.
  6. Select a Filter widget type.
    The filter widget types dynamically change depending on what you select in the Field to map to field.
  7. Type a meaningful name for your filter in the Filter widget label field.
    The name of your filter widget should be similar to the field chosen for Field to map to.
  8. Click Save.
  9. On the Save new report window, name your SQL report and choose where to save it.
  10. Click Save.

Save your report

When you save your report, Insights also saves the visualization option you chose for your report.

The Numbers option displays a single number for your answer. Number options include:

  • Setting the number of decimal places to display.
  • Multiplying your result by a number. For example, you could multiply a decimal by 100 to make it look like a percent. Or, if you want to divide by a number, you can multiply it by a decimal.


Trends

The Trend visualization shows how a single number has changed over time.

To use this visualization, you must have a single number grouped by a Time field, such as the number of applications in a month. The Trend shows the value of the number during the most recent period, in addition to how much the number has increased or decreased compared to its value in the previous period. The period is determined by your group-by field. For example, if you are grouping by month, the Trend displays the most recent month compared to the prior month.

By default, Trends display increases as green and decreases as red. However, you can reverse the positive/negative color indicators in the visualization settings.

Detail

The Detail visualization shows a single result record in a simple, two-column display. You can also cycle through records using the arrow buttons.

Progress bars

Use Progress bars to compare a single number to a goal value that you set.



To set the goal for your Progress bar, go to Settings and choose a value for your goal. Insights shows you how far away you are from the goal.

Gauges

Gauges allow you to show a single number in the context of a set of colored ranges that you can specify. By default, when you choose the Gauge visualization, Insights creates red, yellow, and green ranges for you.

Open up the visualization settings to define your own ranges, choose colors for the ranges, and optionally add labels to some or all of your ranges.



Tables

The Table visualization is a good option for viewing tabular data or lists. The options for table visualizations allow you to add, hide, or rearrange fields in the table you are looking at, in addition to modify the formatting.

Formatting for table visualizations contains details about formatting and visualization settings for tables.

Pivot tables

A pivot table groups rows and columns, and includes summary rows with aggregate values for those groupings. They’re called pivot tables because you can rotate (“pivot”) a column 90 degrees so that the values in that column become column headings themselves.



Line, bar, and area charts

Insights offers several options for chart visualizations. Generally, line charts are used to display the trend of a number over time, especially when you have lots of x-axis values.

Bar charts are a good option to display a number grouped by a category (such as the number of students you have by country). Bar charts are also useful for showing a number over time if you have a smaller number of x-axis values (like applications per month this year).



Area charts are useful when comparing the proportions of two metrics over time. You can stack both bar and area charts.



Trend lines are another useful option for line, area, bar, and scatter charts. If you have a report in which you are grouping by a time field, open up the visualization settings and turn the Show trend line toggle on to display a trend line. Insights will choose the best type of line to fit to the trend of your series. Trend lines will even work if you have multiple metrics selected in your summary. However, trend lines will not work if you have any groupings beyond the one-time field.



Combo charts

Combo charts let you combine bars and lines (or areas) on the same chart.

Insights will pick one of your series to display as a line, and another to display as a bar by default. Go to the visualization settings to change which series are lines, bars, or areas, in addition to changing per-series settings like colors. Click the down arrow at the right of a series to see additional options.



There are two approaches to setting up a Combo chart:

  • Select two or more metrics in the Summarize By section of your report, with one or two grouping columns.
  • Select a single metric and have two grouping columns.

Row charts

If you want to group a number by a column that has a lot of possible values, such as a list of section codes, try visualizing it as a row chart. Insights shows the bars in descending order of size, with a final bar at the bottom for items that did not fit.



Histograms

If you have a bar chart like Count of Graduates by Age, where the x-axis is a number, you will see a special kind of chart called a histogram. In histograms, each bar represents a range of values (called a bin). Note that Insights will automatically bin your results any time you use a number as a grouping, even if you are not viewing a bar chart. Reports that use latitude and longitude are also automatically binned.

By default, Insights chooses a good way to bin your results. But you can change how many bins your result has, or turn the binning off entirely by clicking the area to the right of the column being grouped by.



Visualization options for line, bar, and area charts

Line, bar, and area charts have very similar options: data, display, axes, and labels.

The Data option allows you to choose the columns to plot on your x and y axes. This is mostly useful if your table or result set contains more than two columns (such as graphing fields from an unaggregated table).

You can also add metrics to your chart by clicking the Add another series link below the y-axis drop-down, or break your current metric out by an additional dimension by clicking the Add a series breakout link below the x-axis drop-down.

Note: You cannot add an additional series breakout if you have more than one metric or series.

The Display option offers many choices, but the available choices depend on the data in your chart. Some of the display choices include:

  • Set the colors and labels for the series on your chart.
  • Change the style of your lines for Line and Area charts and choose whether to display dots on the lines.
  • Specify how to handle missing values. Use the “Replace missing values with…” setting to change how your chart deals with missing values. You can use linear interpolation or display those points as zero or as nothing.
  • Add a trend line. If you have a time series chart, you can turn on a trend line to show where things are heading.
  • Show values on data points. The default setting will try and fit as many values on your chart as will fit nicely, but you can also force Insights to show the values for each and every data point. Showing values also works with multi-series charts, but be aware that the more data points you add, the more crowded with values the charts become.

Use the Axes option to configure your axes in one of three ways:

  • Change the scale for your axes. If creating a time series chart (such as a year over year comparison), your x-axis can use a time series scale or an ordinal one. A time series scale displays in ascending order, oldest to newest, while an ordinal scale displays in the order the data is returned. Your y-axis can use a linear, power, or logarithmic scale.
  • Hide or show the tick marks on your axes. You can also choose to rotate the tick marks on the x-axis to help them fit better.
  • Edit the range of your y-axis. Insights sets an automatic range by default, but you can toggle that off and input a custom minimum and maximum value for the y-axis.

The Labels option is where you choose to hide the labels for your x- or y-axis. You can also customize the text for your axes labels here.

Waterfall charts

Waterfall charts are a kind of bar chart useful for visualizing results that contain both positive and negative values. Each bar on a waterfall chart shows either an increase or decrease, with a final bar on the right of the chart that represents the total value.

For waterfall charts, use a query that is a single metric grouped by a single dimension (time or category).



Scatter plots and bubble charts

Scatter plots are useful for visualizing the correlation between two variables, such as comparing the age of your students compared to how many credits they register for in an academic period. To use a scatter plot, you need a report that results in two numeric columns, such as Number of Credits grouped by Student Age. Alternatively, you can use a raw data table and select the two numeric fields you want to use in the chart options.

If you have a third numeric field, you can also create a bubble chart. Select the Scatter visualization, then open up the chart settings and select a field in the bubble size drop-down. This field will be used to determine the size of each bubble on your chart.



Scatter plots and bubble charts also have similar chart options as line, bar, and area charts, including the option to display trend or goal lines. Refer to Visualization options for line, bar, and area charts for details.

Pie and donut charts

A pie or donut chart can be used when breaking out a metric by a single dimension, especially when the number of possible breakouts is small. If you have more than a few breakouts, consider using a bar chart so that your users can more easily compare the relative sizes of each bar.

The pie chart options allow you to choose which field to use as your measurement, and which one to use for the dimension (the pie slices). You can also customize the color of each slice, the pie chart’s legend, whether or not to show each slice’s percent of the whole in the legend, and the minimum size a slice needs to be in order for Insights to display it.



Funnels

To create a funnel in Insights, you need a table with at least two columns: one column that contains the metric you are interested in, and another that contains the funnel’s steps.



Maps

When you select the Map visualization setting, Insights finds the best kind of map to use based on the table or result set: a United States Map, World Map, or Pin Map.



  • Creating a map of the United States from your data requires your results to contain a column that contains names of states or two-letter state codes.
  • To visualize your results in the format of a map of the world broken out by country, your result must contain a column with two-letter country codes.
  • If your results contain a latitude and longitude field, Insights tries to display the results as a Pin Map of the world. Insights puts one pin on the map for each row in your table, based on the latitude and longitude fields.

When you open up the Map options, you can manually switch between a region map (for example, United States) and a Pin Map. If you are using a region map, you can also choose which field to use as the measurement, and which field to use as the region (such as State or Country).

Build custom expressions with the query builder

Custom expressions are formulas that allow you to create more complex queries.

Custom expressions to create filters, metrics, and custom columns

To create and use a custom expression, click Custom column , or click Filter or Summarize to add a custom expression.

When using the query builder, you can use expressions to create new:
  • Filters. For example, the expression = contains([Column], "Ellucian") would filter rows where the Column field contains the word "Ellucian".
  • Metrics. Also known as summaries or aggregations. For example, = student([courseCredit] ≥ 3.5) would return students who have a course credit of 3.5 or higher.
  • Custom columns. You could use = [Column] / [Column] to create a new column.

Types of expressions

There are two basic types of expressions: Aggregations and Functions.
  • Aggregations take values from multiple rows to perform a calculation, such as finding the average value from all values in a column. You can only use aggregation functions in the Summarize section of the query builder, because aggregations use values from all rows for that column.
  • Functions, by contrast, do something to each value in a column, like searching for a word in each value, rounding each value up to the nearest integer, and so on.

To view all supported Aggregations and Functions, see Supported expressions.

Basic mathematical operators

You can use +, -, * (multiply), / (divide) on numeric columns with numeric values. You can also use ( ) (parentheses) to group your expressions.

For example, you could create a new column that calculates student account balance: = [Column] - [Column].

For example, you could create a new column that calculates student account balance: = [Column] - [Column].
Note: You cannot do math on timestamp columns.

Conditional operators

Insights permits conditional operators AND, OR, NOT, >, ≥ (greater than or equal to), <, ≤ (less than or equal to), =, ≠ (not equal to).

For example, you could create a filter for students from California or Vermont: = [Column] = "CA" OR [Column] = "VT".

Filter expression and conditions

Some items to keep in mind about filter expressions and conditions:
  • Filter expressions must return a Boolean value (something that is true or false). For example, you could write [Column] + [Column] < 100. This will look at each row, add the two columns, and check if that sum is less than 100. If it is, the statement evaluates as true and will include the row in the result. However a filter such as [Column] + [Column] would not be valid because it does not evaluate to true or false.
  • Functions can be used within conditional portions of the Countif and Sumif aggregations, such as: countif( round([Column]) > 100 OR floor([Column]) < 10 ).

Working with dates in filter expressions

Dates in filter expressions need to use the format YYYY-MM-DD.

For example, between([Column], "2020-01-01", "2020-03-31") OR [Column] > "2019-12-25" would return rows where Column is between January 1, 2020 and March 31, 2020, or where Column is after December 25, 2019.

Additional tips for creating helpful dashboards

To make a great dashboard, first decide what you want the dashboard to communicate about your data. What reports will provide insight into what you want to know? It helps to think of a topic or theme for your dashboard, such as recruitment goals or section enrollment trends.

How to link filters

You can also link filters to enable child filter to inherit filter selections that are activated in the parent filters.

For example, you have two filters, one to filter by State and the other to filter by City. You then link the City filter as the child to the State filter as the parent. If you then select California as the state, the city filter will only show cities in California.

To link filters, you can edit the child filter to define the parent-child relationship.
  1. Click Edit dashboard .
  2. Click Settings on the filter you want to change.
  3. From the sidebar, select the Linked filters tab.
  4. To limit the current (child) filter choices, toggle one of the listed filters to make it the parent filter, thereby limiting the choices for the current filter when selected.

    For example, in the previous example, we wanted to define the City filter as the child and the State filter as the parent. To do this, you edit the City filter and link it to the State filter. To continue the previous example, you would edit the City filter (child) and link it to the State filter (parent). The choices for the City filter now depend on what State is selected.

  5. Click Done > Save to save your changes.

Auto-apply filters

By default, each time you change the value in a filter on a dashboard, the dashboard will refresh the results of each card with the filter value applied. When a dashboard is large, slow, or you want to change the value of multiple filters, you can disable the automatic filtering.

To turn off automatic filtering, click More info, then turn off the toggle for Auto-apply filters.

Note: When Auto-apply filters is disabled, the toggle will be shaded out, or gray in color. A user must have edit permissions on a dashboard to set the Auto-apply filters toggle.

With the Auto-apply filters setting disabled, when a user selects a filter an Apply button will appear to the right side of the dashboard filters. After all filters are selected, the user can click the Apply button and the dashboard will refresh with all filter selections made.

Update a dashboard using cross-filtering

You can use cross-filtering to make a chart behave as a navigation report, or starting point, that filters data across other cards on the dashboard.

If your report viewer clicks a bar in a bar chart, you can send the value of the clicked bar to the dashboard's filter and update reports across the dashboard. This is known as cross-filtering.

Refer to the following image for an example. Clicking an award status in the Current Award Status Count report will filter the displayed results in the Fund Award Progress List report. Essentially, you will filter all reports on this dashboard by the selected Current Award Status value.



To set up cross-filtering, choose a dashboard filter that you want to update by a report on the dashboard. This is your navigation report. Instead of connecting this navigation report to the filter, you will connect all reports on this dashboard to the filter.

This example uses the Current Award Status Count report as the navigation report. Therefore, do not connect that report to the Current Award Status filter, but connect all other reports to the Current Award Status filter. In the example, there is only one other report.



With your filter connected, stay in dashboard edit mode and hover over the report you want to use as your navigation report to filter the dashboard. Click the Click behavior button and select Update a dashboard filter. Insights lists the filters you can update.

In this example, select the Current Award Status Count filter, and supply the value to that filter from the report’s Award Status Desc column of the Current Award Status filter.



To complete the changes, click Done in the sidebar, then Save your dashboard.

Now you can use your navigation report to interactively filter the data across your dashboard. When your report viewers click on a value in the navigation report, Insights sends the clicked value to the filter, and updates every card on the dashboard by filtering them for the clicked value.

The only card not updated is the navigation report: (Current Award Status Count, in this example). Insights does not update the navigation report because you still want the ability to click other bars to update the filter with a different value.

Create collections

Collections are the primary way to organize your reports and dashboards. You can think of them as folders or directories. You can nest collections in other collections and move collections around.

There are several ways to create a collection.

  • Create a new collection by clicking Create a new collection from any collection page. Or click Create a new collection next to the Collections header in the navigation bar.
  • While viewing a collection, you can create a new collection nested within that collection.
  • As part of the process to create a new report or dashboard, you have the option to save that object in a new or existing collection.

No matter how you create the collection, be sure to provide a unique name and helpful description for the new collection.

Note: Keep in mind these important guidelines when creating collections and adding reports and dashboards to them.
  • A collection should never contain multiple items with the same name. Each report or dashboard in a collection must have a unique name or a unique (collection) path.
  • A single object, such as a report or dashboard, can only be in one collection. The exception is that an object can be part of a collection that belongs to a parent collection.
  • Dashboards and reports within a collection have the same permissions as the collection. Similarly, if a collection has a sub-collection, the sub-collection has the same permissions as the parent collection.

Types of collections

Ellucian Insights has three main types of collections.

  1. Each Insights user has their own personal collection that only that user can see. Personal collections are separate collections from your institution's shared collections and the Ellucian collection.

    Use your personal collection as a sandbox or practice space while building or updating reports and dashboards. When you are ready to share your work, you can move reports and dashboards from Your personal collection into your institution's collections, if you have the necessary permissions. Refer to How to move items from collection to collection for more information.

  2. Your institution has a collection in which your custom reports, dashboards, and collections can be saved to. Other Insights users at your institution may also contribute to this collection.
  3. The Ellucian collection includes sample reports and dashboards you can copy to your institution's collection, and use as is, or as templates for your own reports and dashboards. See the Ellucian-provided dashboards and reports section of the Insights documentation for descriptions of these reports.

To access the list of collections in Insights, click Launch Reports on the Insights card in Ellucian Experience. Or use the Applications menu top launch Insights.

With models, you can tell Insights what kind of data is in each returned column by adding metadata.

Metadata can also make filtering better by showing the correct filter widget, and it will help the Insights reporting tool pick the right visualization for the results.

Note: While not a requirement, if you only set one kind of metadata, set the Column type so Insights knows what kind of data it is working with.

Create Experience cards for Insights visualizations

By publishing Insights visualizations on Experience cards, your end users can quickly discover and consistently track the most meaningful metrics for your institution.

Before you begin

  • The user performing this procedure must have been granted the Card Management administrative permission in Ellucian Experience Setup, as described in Grant Experience dashboard permissions.
  • The user performing this procedure must have View permission to the collections containing the visualizations to be added as Insights cards. Refer to the Insights reporting tool permissions section for more information about these permissions and how to set them.

About this task

Only visualizations and reports are available to display in Experience cards. Insights dashboards cannot be displayed in an Experience card.

Refer to Create a card from a template for general information about creating a card in Experience.

Refer to the Build reports and dashboards using the Insights reporting tool section for more information about building visualizations in Insights.

      Card description This description is not displayed on the card, but is used in search.

      The title, description, and tags help Ellucian Experience users to find cards of interest to them on the All Cards page and on category pages when accessed from the Experience main menu:
      • The tags are displayed at the top of the page. Users can click a tag to filter the display to only cards with that tag.
