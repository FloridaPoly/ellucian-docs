Use Insights Administration

Use Insights Administration to set up and configure the data ingestion to the Data Lake, the Data Warehouse population, and any necessary display rules or parameters so that your data correctly displays in your reporting tool.

How to access Insights Administration in Ellucian Experience

To open Insights Administration, go to your Ellucian Experience dashboard and locate the Insights Administration card.

Note: If the card does not show on your dashboard, go to the All Cards page, search for the Insights Administration card, and save it to your Experience dashboard.
The Insights Administration card has links to take you directly to a section.
  • Click Ingestion to define your data sources and datasets, and see recent Data Lake ingestion activity.
  • Click Population to schedule and monitor Data Warehouse load and refresh jobs.
  • Click Configuration to configure your display rules and parameters. You can also create custom datasets and point-in-time data captures in this section.

Alternatively, Insights administrators can navigate from any Experience application to Insights Administration using the Application menu in the Experience navigation area. Clicking Insights Administration in the Application menu takes you to the Ingestion > Recent Activity tab.

Note: If you attempt to access Insights Administration before your Insights setup has completed, you will not be able to access any of the administration sections. If you believe this is in error, contact Ellucian Action Line.

Prerequisites for all Insights Administration tasks

  1. Complete all tasks in Experience administrator setup tasks, including the tasks for the Insights reporting tool if you have Ellucian Insights Premium.
  2. For on-premise institutions, prepare the data sources for ingestion by completing the configuration updates as detailed for your source system in Prepare your source system for data ingestion.
  3. Ensure you have access to the Insights Administration card in Ellucian Experience.

    To confirm access, click the Application menu in the Experience navigation area. If you see the Insights Administration link, you have access. See Set up the Insights Administration card in Experience.

  4. Insights administrators must ensure you have Insights Manage permission for Insights Administration. See Grant administrative permissions for Insights.

When performing any tasks in Insights Administration, be sure to confirm all prerequisites have been completed as described in the documentation for that task.

Ingestion

Ingest your source data into the Data Lake

For your data to become available from Ellucian Insights, you first need to load it into the Data Lake using the data ingestion tool in Insights Administration.

Before you begin

Note: This topic provides instructions for ingesting your Ellucian source data to the Insights Data Lake.
  • If you are ingesting data from an external source, see How to import data from a non-Ellucian source for instructions.
  • If you are ingesting a custom dataset, see Ingest a custom dataset to the Data Lake for instructions.

Ensure you have completed these prerequisites before attempting to ingest your data into the Insights Data Lake.

  1. Prepare the data sources for ingestion by completing the configuration updates as detailed for your source system.
    This prerequisite does not apply to SaaS data sources, as SaaS data sources do not require any preparation for ingestion.
    • Prepare your Banner source data
    • Prepare your Degree Works source data
    • Prepare your Colleague source data and SQL Server
  2. Ensure you have access to the Insights Administration card in Ellucian Experience.

    To confirm access, go to the Application menu in the Experience navigation area. If you see the Insights Administration link, you have access. See Set up the Insights Administration card in Experience for more information.

  3. Ensure you have Insights Manage permission for Insights Administration. See Grant administrative permissions for Insights.

About this task

Data ingestion is the process of loading your source data into the Data Lake. After the initial data ingestion to the Data Lake, most datasets will use Change Data Captures (CDC) to replicate changes at the source into the Data Lake to keep it updated.

A data source identifies the connection to the source database from where the data is extracted.

A dataset represents a collection or grouping of tables that will be ingested to the Data Lake.

Refer to Ellucian Insights data flow overview for a high-level description and visualization of the data flows from your source system to the Ellucian Insights Data Lake, Data Warehouse, and your reporting tool.

Procedure

  1. Access the Ellucian Experience dashboard and locate the Insights Administration card.
    Note: If the card does not show on your dashboard, go to the All Cards page, search for the Insights Administration card, and save it to your Experience dashboard.
  2. Click Ingestion on the Insights Administration card.
  3. Click the Add Data tab.
  4. Select your data source from the Source drop down list.
    If this is the first data ingestion of your source data into the Data Lake, you must create a new data source connection.
    1. From the Source drop down, select New....
    2. Provide the required information for your new data source.
      Setting Description
      Name Enter the name you want to use for the data source to be represented in the Data Lake.
      Connection Type Select the connection source type applicable to your data source (Banner or Degree Works).
      Hostname Enter the hostname/IP address for the database instance.

      For on-premise databases: Enter the Ellucian-side NAT IP address for the database. The NAT IP address was enabled when Ellucian set up your VPN tunnel. Contact your network administrator for the NAT IP address.
      Port Enter the port for the database instance.
      Database Name/Service Name Enter the name of the database.
      Username Enter the username for the database:
      • Banner: Enter the DATALAKE_USER value in the login.sql file. See Step 3 of Update the login.sql file for Banner.
      • Degree Works: Enter the DATALAKE_USER value in the login.sql file. See Step 6 of Update the login.sql file and set environment variables.
      • Colleague: Enter the user account created in Step 1 of Set up SQL Server for connection to the Data Lake.
      Password Enter the password for the associated username.
      Warning: SaaS source systems: Do not attempt to add, edit, or delete the data source using Insights Administration. The data source for your SaaS source system was created during the provisioning and deployment process. Contact Ellucian Action Line with any questions.
  5. Optional: To ensure Insights can connect to the data source, click Verify.
    If the application cannot reach the source to validate the connection, review and correct the connection information before attempting to load data.
    • Banner SaaS and Colleague SaaS customers: if unable to verify your data source connection, do not attempt to edit the data source. Contact Ellucian Action Line for assistance.
    • If the password was incorrect, the database account may become locked as the result of multiple connection retries.
  6. Click Next.
  7. Select the datasets you want to load into the Data Lake.
    Note: If the dataset check box is disabled, that dataset cannot be loaded at this time. This can happen, for example, if the dataset is already in the process of being loaded. Go to Recent Activity or Datasets to check the status of the dataset and find more information about it.
  8. Click Load Now.
    If any errors occur, Ellucian recommends repeating the Verify process in Step 5 to confirm a connection can be established.

    Contact Ellucian Action Line if you cannot load your data.

What to do next

Refer to Monitor data source and dataset statuses for more information on the status of your data ingestion.

Ingest a custom dataset to the Data Lake

Just as with any source data you want to bring into the Insights Data Warehouse, you must first ingest the custom dataset to the Data Lake before you can load it to the Data Warehouse.

Before you begin

Complete these steps before you ingest your custom dataset.
  1. Review all information and instructions in How to prepare a custom dataset.
  2. Complete all steps in Create a custom dataset.
  3. If you intend to have ongoing replication for this dataset, you must enable logging for the source system tables in the custom dataset. Refer to Enable table-level supplemental logging for custom dataset tables for more information.

About this task

This procedure describes the steps to ingest your custom dataset to the Data Lake.

Refer to How to prepare a custom dataset for additional information about why and when to create a custom dataset.

Procedure

  1. Access the Ellucian Experience dashboard and locate the Insights Administration card.
    Note: If the card does not show on your dashboard, go to the All Cards page, search for the Insights Administration card, and save it to your Experience dashboard.
  2. If this custom dataset is newly created or has been updated after its last ingestion, you must update the Data Catalog.
    Otherwise, proceed to Step 3.
    1. Go to Ingestion > Add Data.
    2. Select your data source from the Source drop down list and then click Next.
    3. Select the Data Catalog template for your source system and then click Load Now.
      For example, Banner Data Catalog, Colleague Data Catalog, or Degree Works Data Catalog.
      Note: Do not proceed until the Data Catalog load completes. You can check the load status on the Recent Activity tab.
    4. Go to Population and click Add to create a job to load the Data Catalog.
    5. Enter a job name.
    6. Select your Data source.
    7. Select Utility for the Job type.
    8. Select your source system's Data Catalog (as loaded in Step 2.c) for the Job template.
    9. Select Run now and One time as the job run options.
    10. Review the job schedule summary and confirm your selections.
    11. Click Create Job.
    When the Data Catalog update job successfully completes, proceed to Step 3.
  3. To load your custom dataset, go to Ingestion > Add Data.
  4. Select your data source from the Source drop-down list and then click Next.
    If this is the first data ingestion of your source data into the Data Lake, you must create a new data source connection. Refer to Steps 4.a - 4.b in Ingest your source data into the Data Lake for more information.
  5. Optional: To ensure Insights can connect to the data source, click Verify.
    If the application cannot reach the source to validate the connection, review and correct the connection information before attempting to ingest data.
    • Banner SaaS and Colleague SaaS customers: if unable to verify your data source connection, do not attempt to edit the data source. Contact Ellucian Action Line for assistance.
    • If the password is incorrect, the database account can become locked as the result of multiple connection retries.
  6. Click Next.
  7. Select one or more custom datasets you created in Create a custom dataset.
    Note: If the dataset check box is disabled, that dataset cannot be loaded at this time. This can happen, for example, if the dataset is already in the process of being loaded. To check the status of the dataset and find more information about it, go to Recent Activity or Datasets.
  8. Click Load Now.

    Refer to Monitor data source and dataset statuses for more information on the status of your data ingestion.

    If any errors occur, Ellucian recommends repeating the Verify process in Step 5 to confirm a connection can be established.

    If you cannot load your custom dataset data contact Ellucian Action Line.

Results

In addition to ingesting your custom dataset into the Data Lake, Insights also creates a population job template for the custom dataset.

Use the Custom [name of custom dataset] job template when scheduling jobs for loading or refreshing this custom dataset. You can find this new template in the list of custom dataset job templates in the Population tasks.

What to do next

When the custom dataset load is complete (either Active status for replicating custom datasets or Loaded status for one-time dataset loads), you can load the custom dataset to the Insights Data Warehouse.

See Schedule a job - custom datasets for instructions.

Reload source data into the Data Lake

Although most Insights datasets automatically refresh their data as often as licensing allows, Insights administrators may need to manually reload (ingest) datasets that do not automatically refresh their data. Administrators may also need to reload a dataset if an error occurred on its last ingestion attempt.

About this task

Some ingested datasets do not support Change Data Captures (CDC), such as Banner Supplemental Data, and therefore cannot support automatic data refreshes. These datasets display Loaded status rather than Active status on the Recent Activity tab. Administrators must manually reload these datasets to the Data Lake to keep them up to date.

In addition, administrators may need to manually reload a dataset to resolve an ingestion error.

Note: Data catalog datasets do not support CDC changes. However Insights performs a nightly ingestion of your source system's data catalog for your convenience. If needed, you can still follow this procedure to load the data catalog outside of the nightly job run. See Data catalog updates in Insights for more information.

Procedure

  1. Pause all associated recurring jobs for the datasets you want to reload.
    1. Go to Population > Recurring Schedules.
    2. Locate the job you want to pause.
    3. Click Actions > Pause.
      The job's status changes to PAUSED and the job will not run until you choose to resume its schedule. The Next Run date and time does not change. It will display the next scheduled instance before pausing the job.
    4. Repeat for all recurring jobs associated with this dataset.
  2. Go to Ingestion > Add Data.
  3. Select your data source from the Source drop down list.
  4. Optional: To ensure Insights can connect to the data source, click Verify.
    If the application cannot reach the source to validate the connection, review and correct the connection information before attempting to load data.
    • Banner SaaS and Colleague SaaS customers: if unable to verify your data source connection, do not attempt to edit the data source. Contact Ellucian Action Line for assistance.
    • If the password was incorrect, the database account may become locked as the result of multiple connection retries.
  5. Click Next.
  6. Select one or more dataset to reload.
    If a dataset's check box is disabled, it cannot be loaded at this time. For example, the dataset might be currently loading. Go to the Recent Activity or Datasets tabs to check the status of the dataset.
  7. Click Load Now.
    Refer to Monitor data source and dataset statuses for more information on the status of your data ingestion.
  8. After the data ingestion successfully completes (ACTIVE status), you must repopulate the Data Warehouse with the reingested datasets.
    Depending on which datasets you reloaded, you could either:
    • Schedule a one-time Load domain job for the domain containing the datasets.
    • Schedule a one-time Load All job for your source system.

    Refer to Schedule a job for instructions and how to select the correct job type.

  9. After the job in Step 8 completes, resume the recurring jobs you paused in Step 1.
    1. Go to Population > Recurring Schedules.
    2. Locate the paused job you want to resume to its recurring schedule.
    3. Click Actions > Resume.
      The job status changes to ACTIVE and the job resumes its regular schedule, as specified in the Next Run column.
    4. Repeat for all paused recurring jobs associated with this dataset.

Edit a data source

You may want to edit a data source if any of the connection properties change; for example, the user's password or the data source name.

About this task

Insights administrators for on-premise implementations can update some settings of a data source.

Warning: SaaS source systems: Do not attempt to add, edit, or delete the data source using Insights Administration. The data source for your SaaS source system was created during the provisioning and deployment process. Contact Ellucian Action Line with any questions.
Note: Do not use these instructions if you are changing the hostname or service name (database name). To update these settings, follow the instructions in Update Insights when switching your data source.

Procedure

  1. Click Ingestion on the Insights Administration card.
  2. Click the Data Sources tab.
  3. Click Actions > Edit.
    Note: The Edit option may be disabled if the system is processing data. Refresh the data source listing to ensure the tab displays the options available based on the latest status of the data sources.
  4. Edit the settings as desired.
    Setting Description
    Name Edit the name you want to use for the data source to be represented in the Data Lake.
    Hostname To update the hostname, follow the instructions in Update Insights when switching your data source.
    Port Edit the port for the database instance.
    Service Name To update the service name/database name, follow the instructions in Update Insights when switching your data source.
    Database Schema Degree Works only: Edit or edit your database schema name. Default: DWSCHEMA.
    Username Edit the username for the database.
    Password Edit the password for the associated username.
  5. Click Verify to validate the data source connection.
  6. Click Save.
    If there are incorrect data source settings, an error message shows for the selected datasets. Ellucian recommends that you review and correct data source connection information before attempting to reload data.
    Note: After data loads, if any data is incorrectly entered for these settings, including the username and password, an error message displays. Ellucian recommends you review and database connection information and use the Verify button to confirm a connection can be established. If the password was incorrect, the database account may become locked as the result of multiple connection retries. After the error is fixed, the CDC continues processing for replicating datasets.

    Most datasets are automatically configured to refresh data as often as licensing allows. Some datasets require Insights administrators to reload the data to keep them updated.

    While data catalog datasets do not automatically refresh, Insights performs a nightly ingestion of your source system's data catalog. See Data catalog updates in Insights for more information.

Pause, resume, or restart a data source

Use the pause, restart, and resume actions to manage the connection between the Data Lake and your data sources. For example, you may need to pause a data source to perform a maintenance upgrade or apply a fix to the source.

About this task

Warning: SaaS source systems: Do not attempt to add, edit, or delete the data source using Insights Administration. The data source for your SaaS source system was created during the provisioning and deployment process. Contact Ellucian Action Line with any questions.
If you paused your data source ingestion and are ready to unpause it, you have two choices. Consider these options carefully as they have different impacts for your data ingestion.
  • Resume continues CDC processing from the point where it was paused.
  • Restart reingests all datasets for the specified data source, including datasets that were previously ingested. If you select Restart, you must also repopulate the Data Warehouse.
    Warning: Consult with Ellucian Action Line before restarting a data source. Because restarting a data source requires reloading (repopulating) the Data Warehouse, the Restart process could take as long as one or two days to complete. Therefore you should only restart your data source when absolutely necessary.

For additional help for choosing either Resume or Restart, follow the procedure and review the table in Step 3.

Procedure

  1. Click Ingestion on the Insights Administration card.
  2. Click the Data Sources tab.
  3. Click Actions and make your selection.
    Option Description
    Edit (Available only for on-premise implementations.) Edit the data source settings as permitted. Note that not all settings can be edited from this option.
    Pause Pauses any in-progress or future CDC processing.

    No new data or data changes will be ingested for the data source while the ingestion is Paused.
    Resume Continues CDC processing from the point where CDC processing was paused.
    Restart Reingests all datasets for the specified data source, including datasets that were previously ingested. When all dataset ingestion are complete, CDC processing continues as expected.
    Note: If you select Restart, you must also reload the Data Warehouse. You must continue to Step 4 when the data source ingestion completes.

    When you restart the data source, the status may briefly state Restarting and then change to Resuming.

    Delete (Available only for on-premise implementations.) Delete the selected data source. Review Delete a data source or Update Insights when switching your data source for specific precautions and associated actions to take.
    Not every action is available at all times. The Actions displayed are the actions available for the current state of the selected data source.
  4. If you unpaused the data source ingestion by selecting Restart, you must also reload the data to the Data Warehouse.
    This ensures the Data Warehouse is current with the changes to the Data Lake.
    1. Go to the Recent Activity tab and verify that all data sources and datasets have successfully been ingested to the Data Lake.
      • Data sources display Ready status when ingestion successfully completes.
      • Load-only datasets display Loaded status when ingestion successfully completes.
      • Replicating datasets display Active status when ingestion successfully completes.

      Depending on the volume of data, you may need to wait for ingestion processes to complete. Do not reload the Data Warehouse until all ingestion processes are complete.

    2. Go to the Population.
    3. Schedule a one-time Load All job for your source system.
      See Schedule a job for instructions.
    4. If you have custom datasets with ongoing replication, perform a one-time Load job using their corresponding templates.
      See Schedule a job - custom datasets for instructions.
  5. To display more information about the current status of a data source, click the status of the data source.
    For status descriptions and any required actions, refer to the table in Step 4 of Monitor data source and dataset statuses.

Data catalog updates in Insights

For your convenience, Ellucian Insights performs a nightly ingestion of the data catalog for the Ellucian source systems (Banner, Degree Works, and Colleague).

The subsequent Refresh All or Load All job occurrences populates the Data Warehouse with the data catalog changes.

The nightly data catalog ingestion begins at 2 a.m. local time for the time zone associated with your Insights deployment location. The start time remains at 2 a.m. if there are any daylight saving time offsets.

Location of Insights deployment Start time (scheduled)
USA 2 a.m. ET
Europe 2 a.m. GMT
Australia/Asia-Pacific 2 a.m. AET
Canada 2 a.m. CT

When to manually update the data catalog for Insights

If you need to apply a recent source system data catalog, change to Insights before the next occurrence of this nightly job, ingest the Data Catalog dataset, and then run the Data Catalog population job to update the Data Warehouse with the latest data catalog changes.

Delete a dataset

A dataset is a collection of tables that loads from the data source into the Data Lake. When you delete a dataset, the data is removed from the Data Lake.

About this task

Insights administrators may need to delete a dataset because it has an Error status. Causes of the Error status may include:
  • the database was down for an extended period of time
  • archive logs were deleted on the source system
  • the archive log space is full and the database went into archive error mode

If deleting a dataset because of its Error status, you should delete the dataset and then reingest and reload the deleted dataset. Refer to Reload a dataset for further instructions.

To confirm the population job results, perform the following validation checks with the information provided from the logs:

  • Review the count columns information to verify the data copied into the Data Warehouse tables is as expected.

    If the job shows as failed, or has run into problems, retrieve the log of that job and look at the error message column for each table to determine the error type. Troubleshooting each one of the error messages may require additional information. If needed, collect the failed records, and share them with Ellucian Action Line for further review and guidance.

Display rules overview

Ellucian Insights uses display rules to customize how data displays in the Data Warehouse. Insights administrators can add, edit, or delete display rules.

Display rules are defined for a given business profile or internal group. They consist of one or more related records that share the same profile, category, and subcategory that make up a single display rule.

There are two types of display rules:

Positional display rules

Positional display rules define the specific location, by position, of data in a view. Slotted views or tables require a set of positional display rules to store information in a meaningful way.

Use positional display rules with the slotted processes to determine which values to use to populate the slots.

For example, the TEST view in Ellucian Insights displays all valid test score values loaded from your source system to Insights. This data is stored in a vertical presentation as one row per person per test.

The corresponding TEST_SLOT view provides an alternative horizontal presentation that flattens the data to one row per person with the details of up to seven test scores as columns.

Positional display rules are required to define which seven test scores will be included, and in what position or order they will appear within this slotted presentation. These display rules are used to build the underlying MST_TEST_SLOT table.

Hierarchical display rules

Hierarchical display rules use a priority logic structure to define a specific order in which to retrieve a set of related data. These rules are required for a subset of non-slotted reporting views.

You can set an unlimited number of values with the hierarchical concept. The sequence number prioritizes the values. A hierarchy concept uses a process of elimination to determine which field values go into each attribute within a repeating group.

For example, the PERSON_ADDRESS and ADDRESS_ BY_RULE views display one address per entity per ADDRESS_RULE to be used for mailing purposes. The mailing address that displays is based on the hierarchical display rules to determine which address types should be retrieved for the mailing address. This creates a series of hierarchical display rules based on priority. If address type 1 does not exist, address type 2 is retrieved, and so on.

Initial setup of display rules

Within Insights Administration, there are a number of predefined display rule categories and associated subcategories. The default values for the display rules attributes are created during the initial load process.

When your display data does not match the reporting requirements or expectations, an Insights administrator can define and maintain the display rules by adding or editing the available tables and views from Ellucian Insights.

Insights parameters

Parameters specify how Insights manages or groups your information when your reporting tool accesses your data. Some parameters also determine how Insights processes your data when you run Insights jobs.

Insights administrators can use parameters to configure and define mappings when populating your data into the Data Warehouse. Each parameter has its own set of properties to define, given its particular use and target data in the Data Warehouse.

Within Insights Administration, there are several predefined parameters whose records are created when the environment is initially deployed. Insights administrators can add, edit, or delete the parameter records to customize the parameter configurations that Insights uses to process your data.

Warning: Ellucian strongly recommends you review all applicable parameters and make any adjustments to the parameter records defaults and settings before the initial Data Warehouse population job.

This ensures that the correct data loads into the Data Warehouse during the initial load. If you change these records after the initial load, you might need to reload a portion of the Data Warehouse to view the recent updates. Refer to Review and update parameters before initial Data Warehouse population for instructions.

Note: Reporting tools can query parameter records to define specific information that should be displayed as part of reports or dashboards. If this is needed, the parameter records are available from the ia_admin.MTVPARM table in the Data Warehouse.

  • Parameters reference - Colleague

Procedure

  1. Click Configuration on the Insights Administration card.
  2. Click the Parameters tab.
  3. Click the name of the parameter you want to update.
  4. To edit an existing parameter record:
    1. Locate to the parameter record to edit.
    2. Click Edit in the Actions column.
    3. Modify the parameter record as needed.
      Each parameter record has different properties and can be modified as needed. Refer to the information for that parameter in the Parameters reference for your source system.
    4. Click Save.

    1. Click Add to add a new parameter record.

    3. Click Create.
    Parameter records are sorted by sequence in ascending order. If multiple pages of parameter records exist, your new record may not show on the first page.

    Warning: Deleting a parameter record cannot be undone.
    1. Locate the record you want to remove.
    2. Click Delete in the Actions column.
    3. Confirm the removal and click Delete.

How to prepare a custom dataset

Custom dataset templates enable you to populate the Data Warehouse with tables in your Ellucian data source that are not included in the baseline Insights dataset templates. Custom dataset templates allow you to have access to more of your data to support your unique reporting requirements.

About custom datasets

A custom dataset template is a list of tables that you want to store in the Insights Data Warehouse for reporting purposes, but they are not included in the baseline dataset templates provided by Ellucian.

You may need to create custom dataset templates if:
  • Your institution created custom schemas or tables in your Ellucian data source.
  • You want Insights to include tables that are not part of the Insights baseline datasets.

Plan your custom datasets

Before you create the custom dataset template in Insights Administration, you must first prepare a comma separated value (CSV) file that contains required configuration information for the custom dataset.

For each table in your custom dataset, review these considerations.
  • Identify the schema it belongs to.
  • Determine whether you want to enable ongoing replication of the data from your source table to the Data Lake. If so, it is advantageous for one dataset to include the tables to have ongoing replication, while tables that are rarely updated can be in a single load dataset.
  • If you have many tables to add to a custom dataset, consider creating multiple datasets that are grouped in a logical organization. For example, you could have one dataset for all of your registration customizations, and another for your financial aid customizations.
  • Any tables that will have ongoing replication must have either a primary or unique key. If they do not have at least one of these, then attempts to ingest those tables will fail and cause the dataset to be in a failed status.

    Banner only: You can use the DBEU utility delivered with Banner to add a unique key on any Banner baseline table. For more details, see Add keys to Banner custom dataset tables without keys.

Required format

The CSV file must adhere to the following format.

Data Field Required Data Type Example
schemaName Yes String saturn
tableName Yes String SPRIDEN
isView Yes Boolean False

For example:

schemaName,tableName,isView
my_schema,table123,FALSE
my_schema,table456,FALSE

You can also refer to the attached example: ellucian_insights_custom_dataset_example.csv. To download an attached file, click Attachment on this topic, select the file, and click Download.

Schema and table names in custom datasets are not case sensitive in Insights. If two entries in the CSV file have the same schema and object name but use different uppercase and lowercase formats, Insights merges the entries into one object.

If you intend to have ongoing replication for your custom dataset, your source system must have logging enabled for the tables in the custom datasets you create. Logging is necessary so that Insights can track the CDC changes to the tables being replicated to the Data Lake.

If you configured your Banner custom dataset for ongoing replication, but one or more of its tables lack a primary or unique key, ongoing replication to the Data Warehouse will fail. Therefore, you must add a key to those Banner tables for successful ongoing replication to the Insights Data Lake.

Before you begin

Review these prerequisites and guidelines before running the procedure.

  • This procedure applies only to Banner custom datasets.
  • This procedure should only be performed on Banner tables in custom datasets that do not have primary or unique key columns.
  • If you have multiple tables that need a key, only run the procedure for one table at a time.
  • Only perform this procedure one time for any table requiring a primary or unique key.
  • Ellucian recommends performing this procedure when the specified table has little to no activity running against it. Therefore it might be best to perform this procedure overnight or on a weekend if possible.
Note: If your custom dataset (with ongoing replication) contains a non-Ellucian table that does not have a primary or unique key, you need to directly modify the table to add the unique key. The procedure in this topic only addresses Banner tables in the source system.

This procedure adds a unique key in the SURROGATE_ID column of the specified tables in your Banner source system. Only use this procedure for Banner tables that do not have primary keys and are part of custom datasets configured for ongoing replication.

Successful ongoing replication requires tables to have a primary or unique key because ongoing replication uses CDC processing. CDC processing relies on tables having a primary or unique key so that the data inserts, updates, or deletes are tracked. Therefore, each table in the custom dataset needs a primary or unique key.

Because some Banner tables do not use a primary or unique key, your custom dataset might include one or more tables that lack a primary or unique key. The Data Warehouse cannot refresh these tables using the ongoing replication method, and therefore cannot be included in a custom dataset until a primary key is added to those tables.

Note: If the custom dataset is configured for load-only replication, there is no requirement for a primary or unique key in each table. In load-only replication, the Data Lake ingests the source data in its entirety and replaces the data in the Data Lake. Because there is no need for CDC processing to identify changes, the tables in a custom dataset configured for load-only replication do not need a primary or unique key.

See the How the Data Lake identifies changes in your source system section of Supplemental logging and archive logging for Oracle source systems for more details on CDC processing by the Data Lake.

To create a unique key column in a Banner table on your source system for Insights, you can use the Banner Database Extension Utility (DBEU) to extend a table. The DBEU Extend procedure adds the unique key to the SURROGATE_ID column and enables trigger logic to ensure unique values are populated in that column.

The Insights data preparation scripts for Banner include a wrapper process for calling the DBEU Extend procedure. This wrapper, PKG_DATA_LAKE_UTILS.P_ADD_DBEU_EXT, not only simplifies use of the DBEU Extend procedure, but it also ensures that if the procedure is repeated, the unique key is only added one time to the SURROGATE_ID column.

For on-premise customers, the wrapper process was created when you ran the Banner preparation scripts. For SaaS and Managed Cloud customers, the wrapper process was created during the data preparation done by Ellucian.

The PKG_DATA_LAKE_UTILS.P_ADD_DBEU_EXT procedure was created in the DATALAKE_USER schema. Refer to the login.sql initialization script for the DATALAKE_USER definition.

Procedure

  1. Review the guidelines in Before you begin to ensure best results.
  2. Select a time to run this procedure.
    Ellucian recommends performing this procedure when your Banner system will have minimal processes running. Depending on the quantity and size of tables to update, this process can be resource and time intensive.
  3. Determine the argument values to use in the PKG_DATA_LAKE_UTILS.P_ADD_DBEU_EXT procedure.
    Argument Description
    P_OWNER Name of the table owner or schema.
    P_TABLE_NAME Name of the table to add the unique key to.
    P_PREFIX One-character Banner system identifier.

    The prefix is the first letter of the tables owned by that owner or schema. For example, S for Student tables, R for Financial Aid, etc. See Banner object naming standards for a list of system identifiers.
    P_API Values: TRUE or FALSE. Set this to FALSE unless otherwise directed by Ellucian.
  4. Run the PKG_DATA_LAKE_UTILS.P_ADD_DBEU_EXT command using the arguments for your table.
    exec dbeu_owner."PKG_DATA_LAKE_UTILS"."P_ADD_DBEU_EXT"('P_OWNER','P_TABLE_NAME', 'P_PREFIX','P_API');

    exec dbeu_owner."PKG_DATA_LAKE_UTILS"."P_ADD_DBEU_EXT"('GENERAL','GURFEED','G',FALSE);

    To see more examples of this command, refer to the dbeu_ext_cdc.sql data preparation script.

    Contact Ellucian Action Line if any errors occur while the command is running.

Point-in-time data captures

If you must perform event-based reporting, you need to create point-in-time data captures. Taking snapshots of related data at specified points in time allows you to keep a static copy of that data in the Data Warehouse for future event-driven analytic and reporting needs.

Capturing point-in-time data enables you to take snapshots of related data at any point in time and keep a static copy of that data in the Data Warehouse. You may want to run data comparison reports for the same points in time (such as each month, semester, or year). Or perhaps you need to build data comparison reports for business processes, such as your institution's enrollment census date, the end of a fiscal period, or a workforce snapshot period.

To accomplish this, you need to schedule the snapshots for those specific moments. As you accumulate these data captures over time, you build a history of data on which to report.

Insights captures data from a single table/view or from multiple tables/views. These criteria are defined in a point-in-time list. You will then schedule an Insights job to run and capture the data at the specified times.

After the job runs, Insights writes your data to the Data Warehouse and it is available to your connected reporting tool.

Guidelines

Consider these guidelines when building your point-in-time list and job schedule.

  • You can only schedule point-in-time captures for the present or future. You cannot create a point-in-time capture for past events.
  • The Point-in-time List Name should reflect the type of data you are capturing. For example, "Enrollment Data" or "Payroll Deductions."
  • The Point-in-time List Event Name should reflect the milestone or event that marks the snapshot time. For example, "Annual Census" or "Month End."

Example workflow for point-in-time captures

During a student registration cycle, your institution may want to capture course registration data at key milestones, such as:
  1. First day of registration for the academic period
  2. The first day of classes
  3. After the add/drop/withdrawal period ends
  4. The final day of the academic period

To accomplish this, you need to first create a point-in-time list with one or more relevant tables that track student course registration data. For each table on the point-in-time list, you will define a filter condition to qualify the data to be captured for each source table so that Insights only captures the relevant data for the specified academic period. For example, you want your point-in-time list to capture data for the Fall 2023 academic period, so you will qualify the table to only include data where the academic period is 202310.

After creating your list, you will schedule one or more jobs to capture the requested data at the needed milestones during the academic period. For example, you could create a job that captures the student course registration data and schedule it to run on a recurring schedule specifically on those four milestones.

Deleted CLOB values display in Insights

If you see data in your reporting tool or the Insights Data Warehouse that was deleted from a character large object (CLOB) column on your source system, refer to the following information to remedy the discrepancy.

Condition

Note: This condition only applies to Banner Oracle and Degree Works systems.

Your source system had data stored in a CLOB (Character Large Object) column of a table, and that data was deleted. However, your reporting tool and the Insights Data Warehouse still contain the data that was deleted on your source system.

In Oracle databases, CLOB columns store data that is too large to be stored in a VARCHAR column. Examples include comments or notes fields, or any other field where you need to store a large amount of text.

Cause

This issue occurs due to a known issue in Oracle supplemental logging for CLOB values when there are other changes to the same row in the table.

Oracle supplemental logging does not track the CLOB field value when other values in the same row are updated. In this scenario, Oracle logs a NULL value for the CLOB field, regardless of whether the CLOB value was deleted.

Insights has a solution for this shortcoming. When there is a changed row with CLOB columns, Insights ignores all NULL values in the CLOB columns. However, the consequence is that Insights also ignores CLOB values intentionally set to NULL, meaning intentionally deleted CLOB values.

Procedure

  1. In your source system, go to the table that contains the CLOB column.
  2. Locate the row where the value was deleted in the CLOB column.
  3. Replace the empty value of the CLOB column with any value.
    For example, you can use NULL, EMPTY, a space character, or any value you choose.

To see the change in Insights, you will need to reload your source data to the Data Lake, followed by a data refresh to the Data Warehouse.

  1. Reload your source data to the Data Lake.
    1. In Insights Administration, go to Ingestion > Add Data.
    2. Select your data source from the Source drop down list.
    3. Click Next.
    4. Select the dataset containing the changed table.
    5. Click Load Now.
    If needed, refer to Reload source data into the Data Lake for more information on reloading the Data Lake.
  2. Perform a data refresh to the Data Warehouse.
    If you have a recurring schedule for data refreshes, the next job occurrence will remove the deleted data from the Insights Data Warehouse.

    Otherwise, follow these steps. Refer to Schedule a job for more information.

    1. In Insights Administration, go to the Population tab.
    2. Click Add at the top of the Activity or Recurring Schedules tabs.
    3. Enter a Job name to use for future references to this job.
    4. Select the Data source.
    5. Select Bulk for the job type.
    6. Select Refresh All Banner/Degree Works Insights Product.
    7. Select Run now and One time as the job run options.
    8. Review the job schedule summary and confirm your selections are accurate.
    9. Click Create Job.
    The data refresh job is immediately added to the job queue.
