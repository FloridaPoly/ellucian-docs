Integration API Release 9.41.2

The Banner Integration API 9.41.2 release includes minor fixes for API designer.

Banner Integration API 9.41.2 runs on Banner platform version 11.6 and Banner Common DB Upgrade 9.42.1.

Tip: For more information about the following APIs, see the Banner API Catalog.

New additional-study-path-data ProCode API for TCSI

A new additional-study-path-data ProCode API has been created to manage data in SKASTSP/SKRSTSP tables, which is required for TCSI (Tertiary Collection of Student Information) reporting in Australia. This API enables clients to capture and manage the "Actual Course Commencement Date" for student study paths, a critical data element for TCSI SA02 reporting requirements.

The GET and PUT request methods are supported.

  • For GET requests, filter parameters are optional, and no placeholder path identifier is needed.

    Example:

    GET /IntegrationApi/api/student-additional-studypaths
    ?studentId=A00036352
    &effectiveTerm=602610

    Explanation:

    This GET request retrieves student additional study path records using the provided filters. You can pass studentId, studyPathKeySequence, and, or effectiveTerm in any combination.

  • For PUT requests, a path identifier is required, even though it serves no functional purpose. The record to be updated is determined through query parameters.

    Example:

    PUT /IntegrationApi/api/student-additional-studypaths/id
    ?studentId=A00036352
    &studyPathKeySequence=2
    &effectiveTerm=602610

    Explanation:

    id is a required dummy value in the path. Any non‑empty value is acceptable. The update is performed based on the query parameters and not the path identifier.

For detailed API specifications and usage examples, refer to the Banner API Catalog.

This enhancement addresses PE0008295 in the Ellucian Customer Center.

New operators in API Designer for query filtering

The API Designer now supports three additional query operators for more flexible filtering:

  • BETWEEN - Filters values within a specified range (For example, dates, numeric values)
  • IN - Returns results matching any value in a provided list.
  • NOT IN - Excludes results matching any value in a provided list.

All three operators can be used with literal values, database fields, custom fields, and model-as-function implementations.

This enhancement addresses PE0008301 in the Ellucian Customer Center.

Parameter support for IN operator in filters

The API Designer now supports parameterized values with the IN operator when defining filters. Instead of hard coding lists of values, API developers can define reusable parameters that are resolved at query time, enabling more dynamic and maintainable filter definitions.

This enhancement addresses PE0008303 in the Ellucian Customer Center.

Enhanced person-external-education API to v1.3.0

The person-external-education EEDM API has been enhanced to support the v1.3.0 schema. This enhancement includes a new transcripts array and graduationDetails property, enabling more comprehensive management of external education data.

The GET, POST, and PUT request methods are supported.

Key enhancements include:

  • BEP Event Updates - Business Event Publisher (BEP) events have been updated to include changes to details in the transcripts array, ensuring more accurate change notifications for external education records.
  • New Triggers - New event triggers have been added based on updates to the following database fields:
    • SORHSCH_TRANS_RECV_DATE - High school transcript received date
    • SORPCOL_TRANS_RECV_DATE - Previous college transcript received date
    • SORPCOL_OFFICIAL_TRANS - Official transcript indicator for previous college
    • SHRTRIT_TRANS_DATE_RCVD - Transfer institution transcript date received
    • SHRTRIT_OFFICIAL_TRANS_IND - Transfer institution official transcript indicator

The API now correctly identifies record updates and triggers the appropriate update event.

For detailed API specifications and usage examples, refer to the Banner API Catalog.

This enhancement addresses PE0007460 in the Ellucian Customer Center.

Enhanced person-hold-types API to v16.0.0

The person-hold-types Ethos GET API has been enhanced from v6.1 to v16.0.0, providing improved capabilities for managing and categorizing person hold types.

The GET request method is supported.

Key enhancements include:

  • Categories Array - A new optional categories array property allows clients to understand the affected areas of a hold type (for example, registration, transcript, financial, graduation, grade, account receivables, application, compliance, academic, administrative, disciplinary, health).
  • Academic Period Status - A new required academicPeriodStatus property indicates whether a hold type is eligible for term-based (academic period) holds. Values include academicPeriodEligible and academicPeriodIneligible.
  • Schema Updates - The root-level category property has been removed, along with startOn and endOn fields to align with the v16.0.0 schema.

For detailed API specifications and usage examples, refer to the Banner API Catalog.

This enhancement addresses PE0008181 in the Ellucian Customer Center.

New security-class-assignments-adjustment-process API

A new security-class-assignments-adjustment-process process API has been created to enable security administrators to add or remove security object assignments from security classes. This API follows the established pattern of the security-user-profiles-adjustment-process API, providing a consistent and reliable approach to managing security class configurations.

The process API supports batch operations, allowing security administrators to make multiple security class assignment adjustments in a single API call, improving operational efficiency and reducing administrative overhead.

For detailed API specifications and usage examples, refer to the Banner API Catalog.

This enhancement addresses PE0008091 in the Ellucian Customer Center.

Enhanced proxy-student-memos API

Batch processing capability is added to the proxy-student-memos API to significantly improve performance when inserting bulk student memo records. The new batch processing capability reduces processing time from over 8 hours to just a few minutes for large data volumes.

A new QAPI endpoint has been added: /api/proxy-student-memos/qapi-create

Table 1. Performance Improvements
Metric Details
Batch Size Handles 1,000+ records in a single batch operation
Processing Time Reduced from 8+ hours to a couple of minutes for 7,000 students (each with 5-20 memo records)
Transaction Model Synchronous processing with single-transaction commit

This enhancement addresses PE0007774 in the Ellucian Customer Center.

Enhanced section-additional-details-adjustment-process API

The section-additional-details-adjustment-process API has been enhanced with improved array processing capabilities before moving this API to General Availability (GA).

The array processing logic has been enhanced to perform intelligent comparison and synchronization operations. When processing array submissions, the API now:

  • Compares the submitted array with existing records
  • Updates any existing records that are included in the array
  • Deletes records that are not included in the submitted array
  • Adds any new records submitted in the array
Note: API users must still send the full array with each request. The enhancement enables the API to intelligently synchronize the data by comparing what exists versus what is submitted.

For detailed API specifications and usage examples, refer to the Banner API Catalog.

This enhancement addresses PE0008288 in the Ellucian Customer Center.
