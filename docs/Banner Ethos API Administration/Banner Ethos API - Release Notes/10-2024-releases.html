Integration API Release 9.36

The Banner Integration API 9.36 release contains enhancements and defect resolutions.

Banner Integration API 9.36 runs on Banner platform version 11 and Banner Common DB Upgrade 9.37.

Tip: For more information about the following APIs, see the Banner API Catalog.

Schema Designer 1.0.0 (beta release functionality)

Schema Designer is a new Ellucian Experience extension that provides a no-code solution for creating, managing, and extending database tables to meet unique institutional requirements. Designed for SaaS clients, Schema Designer enables users to set up and customize data structures without complex coding, which streamlines data management and supports seamless SaaS integrations.

Schema Designer leverages Ellucian's SaaS-safe APIs to create extended and custom tables. These APIs are accessible through the Banner Ethos API application, which enables efficient creation and management of tables to meet specific business needs.

Table 1. Schema Designer 1.0.0 dependencies
   
Ellucian applications You must have the following Banner application and versions installed and running:
  • Ellucian Experience 1.82.0
  • Banner Integration API 9.36
  • Banner Common DB Upgrade 9.37
  • Banner General 8.22
Bannersecurity objects You must have access to the following Banner security objects:
  • API_EXT_CONFIGURATIONS to create and modify an extended table
  • API_EXT_CONFIGURATIONS_DELETE to delete an extended table
  • API_CUSTOM_TABLE_CONFIG to create and modify a custom table
  • API_CUSTOM_TABLE_CONFIG_DELETE to delete a custom table
  • BAN_ETHOS_API_OVERRIDE to update or delete an extended table and custom table created by another user
  • API_BUILDER_QUERY to access the Banner tables

You must use the Banner Security Maintenance (GSASECR) page to assign security objects at the user level and not at the class or group levels.

For more information, see Schema Designer.

New employee-deduction-details API

The employee-deduction-details ERP API (v1.0.0) allows create, read, and update actions for an employee's benefits and deduction detail information on the Employee Benefit or Deduction (PDADEDN) administrative page. (The GET, PUT, and POST methods are supported.)

The PDADEDN page maintains information about an employee's benefits, deductions, and taxes. (Users can use it to establish a deduction record, change an existing deduction record, view United States Bond Purchase balances, or override the system calculated deduction amount for a deduction.)

This enhancement addresses PE0003161 in the Ellucian Customer Center.

New employee-job-earnings API

The employee-job-earnings ERP API (v1.0.0) allows create, read, and update actions for an employee's job earning information maintained on the Job Detail window of the Employee Job (NBAJOBS) administrative page. The Job Detail window is where users can maintain the employee's job history related to the job effective date, hours of pay, salary information and compensation details. (The GET, PUT, and POST request methods are supported.)

This enhancement addresses PE0003162 in the Ellucian Customer Center.

New employee-jobs API

The employee-jobs ERP API (v1.0.0) allows create, read, and update actions for job information in the Base Job window of the Employee Job (NBAJOBS) administrative page. (The GET, PUT, and POST methods are supported.) The Base Job window includes several job-related fields that are fixed, such as the original job begin date.

The employee-jobs ERP API is similar to the existing employee-job-details ERP API. In a future release, Ellucian will deprecate the employee-jobs-details API and you can use the employee API.

This enhancement addresses PE0003163 in the Ellucian Customer Center.

Updated fund-organization-security-details API

The fund-organization-security-details ERP API (v1.0.0) retrieves information from Banner Finance fund or organization security data. The GET request method is now supported. The fund-organization-security-details API allows administrators to restrict users to data in the finance ledgers that is appropriate to their financial and budgetary role at the institution.

The fund-organization-security-details API can be used to request and verify status of Banner Finance Fund-Organization security authorizations for a particular user:
  • Check authority for one of the two following two types of access:
    • Query access
    • Posting access
  • Request the authorization status for any number of funds, any number of organizations, or any number of funds and organizations for a specified Chart of Accounts.
Institutions can restrict a user's query and update access according to any combination of the following settings (in order from highest to lowest precedence):
  • 1 indicates specific Chart-Fund codes or specific Chart-Organization codes (independent configuration, fund and organization are not defined as combinations).
  • 2 indicates Chart-Fund and Chart-Organization hierarchy by using predecessor codes at any level of the hierarchies.
  • 3 indicates Chart-Fund Type Level 1 or Chart-Fund Type Level 2.

Administrators can also provide access without restriction across all of Banner Finance by using the Master Fund and Master Organization.

This enhancement addresses PE0004981 in the Ellucian Customer Center.

Automated API Registry Integration for Custom APIs For the api-specifications API, the system now automatically registers custom APIs with the API Registry when an OpenAPI specification is provided.

This registration occurs by using the POST /api/:tenantId/register endpoint, and the response includes a unique document ID.

This ensures proper cleanup and prevents stale API records from accumulating in the registry.

Third-party payment updates

A user making a payment can navigate to a third-party payment solution without selecting the term or amount when the Ellucian Payment Service is set to true. This means that Credit Card Audit Table (GORCCAU) does not populate a term and the amount defaults to zero (0). Additionally, if a user licenses a third-party payment solution, a user making a payment does not have to select a payment or term in Banner Self-Service because those steps are replicated at the third party site.

If the payer is not prompted for the term or amount, the GORCCAU value for term is null and the amount defaults to zero (0). When a payment is made through a third-party solution, the termCode value is set to null and the amount is set to zero (0) in the GORCCAU table if the account type is not null.

This enhancement addresses PE0005184 in the Ellucian Customer Center.

New termCodeList parameter

  • detailCodePayment
  • effectiveDate (effectiveStartDate and effectiveEndDate)
  • expirationDate (expirationStartDate and expirationEndDate)
  • releaseDate (releaseStartDate and releaseEndDate)
  • term
  • termCodeList

This enhancement addresses PE0005276 in the Ellucian Customer Center.

This facilitates quick and efficient attendance tracking.
