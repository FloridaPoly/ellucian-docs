Integration API Release 9.41.1

The Banner Integration API 9.41.1 release contains enhancements and defect resolutions.

Banner Integration API 9.41.1 runs on Banner platform version 11.6 and Banner Common DB Upgrade 9.42.1.

Tip: For more information about the following APIs, see the Banner API Catalog.

Spec API Enhancement

Resolved an issue where named parameters and criteria filters did not work correctly when used together in the Spec API. As part of this fix, support for non-standard and unsupported patterns that passed multiple values through named parameters has been removed. As a result of this product correction, implementations that rely on this pattern may no longer behave as expected after this release.

Customers must update implementations that relied on this unsupported pattern (for example, pastTerms='202310','202320') to use criteria-based filtering with the $in operator going forward (for example, "pastTerms":{"$in":["202310","202320"]}).

Additionally, updating the API request format alone is not sufficient. Customers must also ensure to update the underlying Spec logic to support criteria-based filtering (for example, mapping $in to an IN-style query).

For additional details and examples of the IN filter, refer Advanced filter operator support.

This update ensures consistent filtering behavior, aligns the API with supported standards, and improves overall reliability, addressing PD0033319 in the Ellucian Customer Center.

Schema Designer API Enhancement

Enhanced the extension-configurations and custom-table-configurations APIs to provide consistent handling of PIDM-related columns and resolve issues with ambiguous column definitions during GET operations.

Columns named pidm or <tableName>_pidm are mapped to xbannerId, while additional _pidm columns are exposed by replacing pidm with bannerId in the JSON property name (for example, xcustom_pidm_other → xcustombannerIdOther). This enhancement enables support for multiple PIDM-related columns without ambiguity in GET and POST operations.

Validation has also been introduced to ensure that pidm and <tableName>_pidm cannot coexist, as only one column can be mapped to xbannerId per table. The Schema Designer UI has been updated to enforce these rules when creating or modifying extended and custom tables.

For existing tables, extended table APIs must be regenerated by making a POST call to the /schema-extensibility-specifications API if:

  • Multiple PIDM columns exist, or
  • A PIDM column exists with a name other than pidm or <tableName>_pidm (for example, <tableName>_pidm_col)

This update resolves issues related to ambiguous column definitions and ensures consistent and reliable API behavior, addressing PD0025164 in the Ellucian Customer Center.

Schema Designer API Enhancement

Enhanced the extension-configurations-revisions and custom-table-configurations-revisions APIs to resolve an issue where the Attribute Order field could not be cleared after being set and published in extended or custom table configurations. Previously, when a value was entered and published, users were unable to remove or unset it using the revisions APIs.

With this fix, users can now clear the Attribute Order field by setting it to null, and update it as needed, providing greater control and consistency when modifying extended and custom tables.

This update improves usability and configuration flexibility in Schema Designer, addressing PD0032717 in the Ellucian Customer Center.

New invoice submission option as Incomplete for the accounts-payable-invoices API

The updated accounts-payable-invoices EEDM API (v11.1.0 and v16.1.0) has a new submission option with "processState": "inProgress" to accommodate manual review and completion of invoices.

This enhancement addresses PE0008117 in the Ellucian Customer Center.

Security group create, update, and delete support

We enhanced the existing security-group-details API for Banner Integration API to support write operations for security groups. Previously, the API supported only read access.

Security administrators can now:

  • Create new security groups using POST.
  • Update existing security groups using PUT.
  • Delete security groups using DELETE.

These changes allow institutions to manage Banner security groups programmatically, enabling automated provisioning and maintenance workflows.

For more information about request and response formats, status codes, and required permissions for these operations, see the security-group-details API in the API Catalog.

This enhancement addresses PE0006950 in the Ellucian Customer Center.

New graduation-types Ethos API

The graduation-types Ethos Data Model (EEDM) API supports external education integrations. This GET-only API provides a standardized endpoint for querying graduation types data as part of the person-external-education schema enhancement.

This parity API returns an empty set, as Banner does not natively store graduation types as a separate entity.

This enhancement addresses PE0007457 in the Ellucian Customer Center.

New transcript-types Ethos API

The transcript-types Ethos Data Model (EEDM) API supports external education transcript type queries. This GET-only API distinguishes between college and high school transcript sources as part of the person-external-education schema enhancement.

New GORGUID entries are created to categorize transcript types based on the source table (SORPCOL for college, SORHSCH for high school). The API automatically returns the appropriate transcript type based on the external education record source, enabling accurate transfer credit and admissions processing.

This enhancement addresses PE0007458 in the Ellucian Customer Center.

New transcript-statuses Ethos API

The transcript-statuses Ethos Data Model (EEDM) supports transcript verification status queries. This GET-only API returns the official/unofficial status of external education transcripts as part of the person-external-education schema enhancement.

New GORGUID values support three status classifications: official (verified college transcripts from SHRTRIT), unofficial (unverified college transcripts), and undetermined (all high school records). The API automatically determines the appropriate status based on source tables and verification indicators.

This enhancement addresses PE0007459 in the Ellucian Customer Center.

Student API Release 9.41.1

The Banner Student API 9.41.1 release contains enhancements and defect resolutions.

Banner Student API 9.41.1 runs on Banner platform version 11.6 and Banner Common DB Upgrade 9.42.1.

Tip: For more information about the following APIs, see the Banner API Catalog.

Student API 9.41 release record

For more information about the enhancements and defect resolutions for this release, see the Ellucian Customer Center Banner Student API 9.41.1 release page Related Enhancements and Related Defects.

Enhanced person-holds API

The person-holds Ethos API is enhanced to support term‑based registration holds stored in SPRTHLD, in addition to the existing person‑level holds in SPRHOLD

This is a breaking schema version (v16.0.0) relative to v6.x. Consumers must explicitly move to v16.0.0 to use term‑based holds.

The POST, PUT, DELETE, and GET request methods are supported.

This enhancement addresses PE0007779 in the Ellucian Customer Center.

Enhanced section-bases API

The section-bases QAPI has been enhanced in preparation for general availability. The updates include:

  • Added courtesy GUID for sections API to improve resource linking and management
  • Added loadOverrideIndicator and loadOverrideSource properties (both CalBstu regional)
  • Added grade scale assignment details object to provide comprehensive grading information
  • Added the following optional properties to the meetingTimesAndInstructorDetails.instructors object to align with the section-instructional-assignment-adjustment-process API
    • adjustedWorkload
    • contractType
    • position
    • suffix
    • assignmentType
  • Added the sectionMeetingId unique key to themeetingTimesAndInstructorDetails.meetings object to improve resource linking

The following property name corrections have been implemented to improve API consistency and accuracy:

This enhancement addresses PE0007661 in the Ellucian Customer Center.
