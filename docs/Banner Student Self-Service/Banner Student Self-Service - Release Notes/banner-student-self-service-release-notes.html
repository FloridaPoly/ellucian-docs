Multi-currency support for Statement and Payment History

The Statement and Payment History page in Banner Student Self-Service is enhanced to support multi-currency display. Students can now view transactions and totals in a selected currency rather than the base currency.

Context Details
New Currency Selector A currency drop-down is now available on the Statement and Payment History page and the Unbilled section, consistent with the currency selector available on other pages in the Student Accounts module.
Display Behavior Transactions and totals are displayed in the currency selected from the drop-down. The correct currency symbol is shown for each transaction line.
Prerequisite Multi-currency must be enabled in the institution's Banner configuration.

This enhancement addresses PE0007793 in the Ellucian Customer Center.

PayNow term display and payment amount restriction configuration

Two new GUROCFG configuration entries are introduced to provide institutions with greater control over the PayNow payment experience for students.

Configuration Key Description
banner.paynow.term.display.nonzero Controls whether the PayNow popup displays only terms with non-zero balances. When enabled, terms with a zero balance are hidden from the term list even when TBRACCD records exist for those terms.
banner.paynow.payment.amount.restriction Controls payment amount rules within the PayNow popup, including the ability to allow or block overpayments and underpayments by term.
Note: These configuration entries are managed through the GUROCFG page. Institutions should review and configure these settings according to their institutional payment policies before enabling the PayNow feature.

This enhancement addresses PE0007834 in the Ellucian Customer Center.

Grails 7.1.0 Framework Upgrade

This release upgrades the underlying application framework from Grails 6.2.3 to Grails 7.1.0. This major framework upgrade modernizes the technology stack to Jakarta EE 10, Spring Boot 3.5.14, Groovy 4.0.31, and Tomcat 10.1.x. There are no changes to application functionality or user-facing behavior. Existing configurations remain compatible and no database changes are required. JDK 17 continues to be the minimum supported version. Customers who have developed extensions or customizations must update their code to replace javax.* imports with jakarta.* equivalents, update CAS client imports from org.jasig.cas.client.* to org.apereo.cas.client.*, and align with the updated framework versions.

Refer to the Install Guide for the updated technology stack requirements and Grails 7.1.0 Migration Guide in Banner Self Service Developer Documentation.zip in Banner Self-Service - Get Started for detailed code change instructions.

This enhancement addresses PE0008352 in the Ellucian Customer Center.

Resolved in-progress payment processing

Ellucian resolved an issue where Flywire card payments and bank transfers in in-progress status incorrectly updated account records and displayed memos before transactions were completed. This fix ensures that account updates and memo displays occur only when payment transactions reach Delivered status.

The fix implements proper transaction timing for both payment types, Card Payments, and Bank Transfers and applies to Flywire payment processing in EPS (Electronic Payment Services) version 6.3.0 and later.

This defect addresses PD0031291 in the Ellucian Customer Center.

Term-Based Registration Holds (Phase 1)

Ellucian delivered Phase 1 of term-based registration holds for Banner Student, establishing the foundational architecture to support regulatory requirements and enhance institutional control over student registration.

Phase 1 focuses on establishing the core data model and administrative infrastructure:

  • New SPRTHLD Table:

    The table stores term-based registration hold information linked to student ID (PIDM) and term code. It includes active indicator field to control whether holds enforce registration restrictions. The table preserves inactive holds for historical reference without impacting registration. Supports both Oracle and PostgreSQL database environments.

  • New Hold Information Page (SGASTHD):

    A new Holds by Term section is introduced in Banner Admin to manage term-specific registration holds. The hold validation is restricted to registration hold types only. You can specify a single term specification without term ranges. An active indicator control is provided for enabling or disabling individual holds.

  • Registration Logic Scaffolding:

    Framework is established to check term-based holds during registration processes. Integration with existing hold severity configuration (SOBTERM_HOLD_SEVERITY). Supports Fatal and Warning hold severity levels. Validates that hold term matches registration term before restricting access.

  • API and Integration Framework:

    API scaffolding is delivered to support term-based hold operations. Foundation for batch processing capabilities to support large-scale hold assignments. The APIs are prepared for EIP (Ethos Integration Platform) synchronization.

This enhancement addresses PE0006095 in the Ellucian Customer Center.

Enhanced error messaging for payment troubleshooting

Ellucian improved error messaging for Electronic Payment Services (EPS) payment failures to help payers and administrators quickly identify the root cause of issues. The enhanced error handling distinguishes between system errors and configuration problems, enabling faster troubleshooting and resolution.

The system now displays context-specific error messages based on the type of failure:

  • For system-level failures (database or service layer issues)

    Unexpected error occurred during payment. Please contact your administrator.

    This message indicates a technical system problem that requires investigation by IT staff or system administrators.

  • For EPS configuration validation failures:

    Payment configuration error. Please contact your administrator.

This enhancement addresses PE0007622 in the Ellucian Customer Center.

Enhanced EPS payment processing reliability

Electronic Payment Services (EPS) integration with Banner Accounts Receivable is enhanced to address payment workflow issues affecting redirect flows and payload handling. These enhancements ensure smoother payment processing for students accessing accounts receivable through Experience and Self-Service. Ellucian resolved an issue where payment redirects from Experience to EPS failed when using the direct redirect configuration (pci=false and eps=true).

The payload sent to EPS for redirect payments includes only the required values. For Accounts Receivable redirect payments, EPS expects only two fields: clientId and createdBy.

This enhancement addresses PE0007796 in the Ellucian Customer Center.

Display Course Alias Regulatory Compliance (AB1111) support

To comply with the Common Course Numbering System (AB1111) regulatory compliance in California, Banner Student Self-Service displays a Course Alias field based on the system configuration.

Students can view the Course or Course Alias values based on the settings that are configured by Administrators in Banner Student Self-Service.

The following pages are enhanced to support the AB1111 changes:

  • Class List
  • Drop Roster
  • Student Profile
  • View grades
  • Student attendance tracking
  • Academic transcript
  • Degree evaluation

Display Course Alias:

  • If the Course Alias is enabled (Display Course Alias) on the Course Alias Usage Rules (SCACARL) page for a term or college, and if there is a value in the Course Alias field for a Course, the Course Alias field will display as the Course Number throughout all of Student Self-Service for that course.
  • If the Course Alias is enabled (Display Course Alias) on the SCACARL page for a term or college, and there is no value in the Course Alias field for a Course, the Course Number will display as normal throughout Student Self-Service for that course.
  • If the Course Alias is disabled (Display Course ID) on the SCACARL page for a term or college, regardless of whether there is a value in the Course Alias field for any course, the Course Number will display as normal throughout Student Self-Service.

Search by Course Alias:

  • The search parameter is compared against both the Course Number and Course Alias fields irrespective of the SCACARL configuration.
  • If the Course Alias is enabled (Display Course Alias) on the SCACARL page, and there is a value in the Course Alias field for a course, whether you search for the Course Number or Course Alias, the applicable course will be returned displaying the Course Alias.
  • If the Course Alias is disabled (Display Course ID) on the SCACARL page, and there is a value in the Course Alias field for a course, whether you search for the Course Number or Course Alias, the applicable course will be returned displaying the normal Course Number, and not the Course Alias.
