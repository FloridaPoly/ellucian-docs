Quick start for Intelligent Processes

To get Intelligent Processes up and running, set up Intelligent Processes in Ethos Integration, use the Ellucian Experience Setup application to configure roles and users in Ellucian Experience, and grant permissions to features in Intelligent Processes.

Set up Experience permissions and roles and users

Roles determine what content is available to each user and to grant administrative permissions. Intelligent Processes uses roles for access to the Intelligent Processes application.

Before you begin

Before setting up Intelligent Processes, you will need to set up Ellucian Experience.

About this task

To enable a user to view or manage workflows using Intelligent Processes, you must grant Experience application permissions to Intelligent Processes, set up roles, and assign permissions to those roles.

  • You need to give users access to view the Intelligent Processes application in the Experience Applications menu and to view and manage features of the Intelligent Processes application.

    Both of those are granted using Experience application permissions. See Enable links on the Experience Applications menu .

  • You add specific roles in the Roles area of Experience Setup.

    Roles are used to determine what content is available to each user and to grant administrative permissions.

  • You then assign permissions to those roles or individual users in the Permissions area of Experience Setup.

    For example, there might be a few people at your institution who can manage workflows in Intelligent Processes, others who can view, but not modify, a workflow and others who can view and take action on user tasks but not view or modify a workflow. You can grant all of those users access to the Experience card and then assign appropriate permissions to limit their access within Intelligent Processes.

Procedure

  1. Identify people at your institution who need access to Intelligent Processes. Those people will need access to the Intelligent Processes application.
  2. Review the list of permissions in Workflow permissions in Intelligent Processes, and identify the people who should have each type of access within Intelligent Processes.
  3. Decide whether you want to grant Intelligent Processes permissions to individual users, or grant permissions to roles and then assign those roles to individual users.
  4. Set up the roles that you need for Intelligent Processes permissions, and add those roles in Experience Setup. See Set up roles for Ellucian Experience and Add the roles in Ellucian Experience Setup.
  5. Set up Experience application permissions so users can view the Intelligent Processes application on the Experience Applications menu and to view and manage features for Intelligent Processes. See Set up workflow permissions.
  6. In Experience Setup, add the individual users to whom you want to grant Intelligent Processes permissions. See Add administrative users.

Set up workflow permissions

Grant the permissions that allow users to view and manage workflows in Intelligent Processes.

Before you begin

  • Before granting permissions, ensure you have configured the roles and users that require access. See Set up Experience permissions and roles and users.
  • Review Workflow permissions in Intelligent Processes for details about workflow features and the access granted by each permission.
  • Review About Experience application permissions and Grant Experience application permissions for Experience permissions and the detailed procedures for granting them.

About this task

Permissions control which users can manage or view workflows in the Designer application and start specific API-driven workflows. While permissions do not affect task engagement, they determine who can initiate or submit tasks. For example, if a Change Major card is available but a user lacks the Execute permission, they cannot initiate a request to change their major.

Intelligent Processes uses Experience permissions to control user access. You can specify which users and roles can:

  • Create, edit, schedule, and publish workflows.
  • View and schedule workflows without modifying them.
  • Start specific API-driven workflows.
Note: Permissions assigned to roles and users may take a few moments to take effect in Intelligent Processes.

Procedure

  1. Access Ellucian Experience Setup:
    1. In the Ellucian Customer Center, click Tools and then select the desired Experience Setup instance under the Experience category:
      • Click Experience Setup to access the Production instance of Experience Setup.
      • Click Experience Setup Test to access the Test instance of Experience Setup.
    2. (If applicable) In Experience Setup, in the Environments drop-down, select the desired Ethos environment.
      The option to select an environment is available only if multiple Ethos environments are associated with this Experience Setup instance.
  2. In the Experience Setup header, click Permissions.
  3. On the Permissions page, click Intelligent Processes.
  4. On the Intelligent Processes Permissions page, select the resource for which you want to manage permissions.

    The resources are displayed in a hierarchy. You can expand the parent resource to display the child resources under it. Granting (or revoking) permissions on a parent resource makes that same change for all of the child resources underneath it.

  5. In the Role or User column, locate the role or user to whom you want to grant permissions.

    The list of roles and users in this column comes from the Roles tab in Experience Setup. If you do not see the role or user to whom you want to grant permissions, you need to add it on the Roles tab.

    Important: For API-driven workflows with Start API types, you can grant the Execute permission to users or applications depending on the token type:
    • If the token type is Experience, you can assign the permission to a user.
    • If the token type is Ethos, you can assign the permission to an application. When you assign the Execute permission to an application, you must also grant the application access to the required platform components in Ethos Integration.
  6. Click Save.
  7. Instruct users whose permissions have changed to log out of Experience and log back in.
    Tip: Experience permissions are cached. Logging out and back in refreshes the cache and ensures users have the granted permissions.
  8. (Ethos Token only) If you assigned the Execute permission to an application, grant the application access to the Intelligent Processes and Experience platform components in Ethos Integration:
    1. On the Ethos Integration header bar, click Platform Components.
    2. On the Ethos Platform Components page, locate the Intelligent Processes tile and click View.
    3. On the Ethos Platform Component Overview page, click the Application Access tab.
    4. On the Application Access tab, click Add Application Access.
    5. In the Add Application Access dialog box, do the following:
      • In the Resource Owner drop-down list, select the Ethos application that you want to use to start the workflow.
      • Click Add.
    6. Repeat these steps for the Ellucian Experience platform component.

Workflow permissions in Intelligent Processes

You can restrict operations on a workflow so that only users who have the necessary permission can perform operations on the workflow.

Note: When you assign permissions to roles and individual users, there can be a delay for the permissions to take effect in Intelligent Processes.
Permission Category Permission Type What you can do
Workflow Read The Read permission allows a user to perform the following operations on a workflow:
  • View
  • Schedule
  • Resync schedule

The Read permission does not allow a user to create, edit or publish workflows.
Edit

The Edit permission allows a user to perform the following operations on a workflow:

  • View
  • Create
  • Edit
  • Schedule
  • Publish
Runs

The Runs permission allows a user to view and manage workflow instances.
Archive The Archive permission allows a user to archive a workflow.
Ellucian External Tasks Use

The Use permission allows a user to add an external task to a workflow. You cannot assign this permission until after you create the external task

In contrast to other permissions, which can be set in advance, the Use permission requires a two-step approach: creating the external task first, and then specifying who can use it.
Actions Create The Create permission allows a user to create and publish an action in Intelligent Processes.
Note: The Actions feature requires the Intelligent Processes Automation and the Experience Premium license.
External Tasks Create The Create permission allows a user to create and publish an external task in Intelligent Processes.
Approval Groups Read The Read permission allows a user to view approval groups that have been created.
Note: The Approval Groups feature requires the Intelligent Processes Automation and the Experience Premium license.
Edit

The Edit permission allows a user to create approval groups.

Note: The Approval Groups feature requires the Intelligent Processes Automation and the Experience Premium license.
All Workflows Execute The Execute permission allows a user or application to start specific API driven (Start API) workflows. You cannot assign this permission until after you create the API driven workflow.

In contrast to other permissions, which can be set in advance, the Execute permission requires a two-step approach: creating the workflow first, and then specifying who can execute it.

For API-driven workflows with Start API types, you can grant the Execute permission based on the token type:

  • If the token type is Experience, grant the permission to a user.
  • If the token type is Ethos, grant the permission to an application. When you assign the Execute permission to an application, you must also grant the application access to the Intelligent Processes and Experience platform components in Ethos Integration.
Note: The API-driven workflow feature requires the Intelligent Processes Automation and the Experience Premium license.
All Actions Use The Use permission allows a user to add an action block to a workflow. You cannot assign this permission until after you create the action.

In contrast to other permissions, which can be set in advance, the Use permission requires a two-step approach: creating the action first, and then specifying who can use it.

Note: The Actions feature requires the Intelligent Processes Automation and the Experience Premium license.

User permissions are created and managed through the Experience Setup application. See the Set up workflow permissions topic for information on how to set up permissions for the Intelligent Processes Designer application.

Access the Intelligent Processes Home page

Use the Home page to create, view, and modify details for a workflow.

Before you begin

To perform the initial setup of Intelligent Processes, make sure you have been granted the Card Management administrative permission in Ellucian Experience Setup, as described in Grant Experience dashboard permissions. Note that only the person performing the initial setup needs this permission; it is not required for all users.

Procedure

  1. Log in to Ellucian Experience.
    The system opens the Ellucian Experience home page.
  2. Click the Applications icon in the Experience navigation area and then click Intelligent Processes.
    The Intelligent Processes Home page appears.

    Each entry on the Home page shows the workflow name, the date on which the workflow was most recently updated (Last Modified), the date on which the workflow was created (Created Date), and the current status of the workflow.

  3. Click the sort arrows in a column header to sort the workflows on the Home page by that sort preference.
    • Columns that display alphanumeric data sort in alphanumeric order or inversely.
    • Columns that display dates sort in chronological order or inversely.
    • When the sort arrow points down, sort order is in descending order.
    • When the sort arrow points up, sort order is in ascending order.
  4. Click the More icon to take the following actions:
    • Change the name or description for a workflow in settings
    • View the version history for a workflow
    • View and schedule a workflow request

    The system dynamically updates the Home page as you create, modify, or transition from Draft stage to Published, to ensure the current information displays on the page.

Create a user for proxy API calls

Create a user in Banner or Colleague with the required data model permissions to support proxy API requests from Intelligent Processes.

Before you begin

Make sure you configured your authoritative source, Banner or Colleague, to communicate with Ellucian Ethos Integration.

Your authoritative source must have assigned resources in Ethos Integration, and must be set up to publish changes to those resources. For the procedures, see Connect applications to Ethos Integration.

About this task

The table below lists the resources along with the Banner security objects and Colleague permissions that provide access to those resources.

The permissions listed in the Banner Security Object column and the Colleague Permission column come from the API Catalog. To determine the required permission for any API, go to the home page of the Ellucian Documentation site, click API Catalog > Colleague API Catalog, and then search for the desired API. On the page for the API, expand the GET method. The permission is displayed as the value of the x-method-permissions field at the bottom of the expanded section.

Procedure

  1. In Banner or Colleague, create a user for proxy API requests.
    • For Banner, see Create and authorize a Banner user to enable Proxy API calls for Ethos Integration.
    • For Colleague, see Create Colleague users for proxy API requests.
  2. To support Intelligent Processes, assign the following permissions to the Banner or Colleague user.
    Resource Required Permissions Banner Security Object Colleague Permission
    persons Read API_PERSONS VIEW.ANY.PERSON
    person-filters Read API_PERSON_FILTERS Does not require that permissions be assigned in Colleague to support READ access for person-filters.
    person-hold-types Read API_PERSON_HOLD_TYPES Does not require that permissions be assigned in Colleague to support READ access for person-hold-types.
    person-holds Read and Write API_PERSON_HOLDS UPDATE.PERSON.HOLD

Add credentials for proxy API requests

Intelligent Processes makes API requests to the ERP through Ethos Integration. Each request includes the credentials for a user with permissions to access the data. You must add the user credentials to support proxy API requests to your ERP from Intelligent Processes.

Before you begin

Ellucian Ethos Integration communicates with your authoritative source, such as Ellucian Banner or Ellucian Colleague. Make sure you have created a proxy user in your ERP (Banner or Colleague) with the required permission on the data models that Intelligent Processes needs to access. See Create a user for proxy API calls.

About this task

In Ethos Integration, you must enter the Banner or Colleague credentials to allow Intelligent Processes to retrieve data from Banner or Colleague using API requests.

If you encounter a banner in Intelligent Processes, signaling a lack of access to specific features like Person Holds, make sure that you add credentials for proxy API requests made by Intelligent Processes, following the instructions below.

Procedure

  1. From the Ellucian Customer Center, click Tools.
  2. Under the Ethos menu, click the Integration link for your region.
  3. Select the desired environment and tenant (if applicable).
  4. On the Ethos Integration header bar, click Platform Components.
  5. On the Intelligent Processes card, select View.
  6. On the Credentials page, click Add Credentials to add credentials for the proxy user you created in Banner or Colleague using the Create a user for proxy API calls procedure.
  7. In the Add Credentials dialog box, enter the settings below.
    Field Entry
    Select application Select the Ethos application for your ERP, such as Banner Integration API,Banner Student API or Colleague.
    Username Enter the username and password for the user account you created in your ERP.
    Password
    Select a resource Select any Ethos resource to which that user account has permissions in your ERP.
    You can select any resource for which you granted that user account permissions in your ERP. Typical examples:
    • Banner Integration API: persons
    • Banner Student API: sections
    • Colleague Web API: persons or sections

    Ethos Integration uses that resource to validate the user credentials by confirming that the user account has access to at least one resource in your ERP.

    For Banner, you must complete these steps twice: one time for the Banner Integration API and one time for the Banner Student API. You can enter the same credentials (for the same Banner user) in both cases.

  8. In the dialog box, click Add Credentials.

Configure the UTC offset and timezone

Configure the timezone based on the location of your institution.

Configure Colleague time zone

You must define the Colleague time zone to ensure that time data communicated by APIs are correctly converted between Universal Time Coordinated (UTC) and Colleague local time.

Complete the Colleague Time Zone Settings (CTZS) form in the environment where you installed the Colleague Web API.

Note: The Colleague time zone is not necessarily the same as the time zone of the Colleague application server, database server, or web server. It is the time zone in which your institution operates.

Configure Banner time zone

Use the Banner Installation Controls (GUAINST) page to configure the timezone based on the location of your institution. For institutions with multiple campuses located in different time zones, use the Campus Code Validation page (STVCAMP) to configure the time zone for each campus.

The TimeZone ID fields on the GUAINST page and the STVCAMP page provide the information about the time zone and locations within each time zone. Based on this time zone set up, the Ethos APIs converts the institution time zone to the UTC date time format. The system creates the GUAINST_TIMEZONE_NAME and STVCAMP_TIMEZONE_NAME fields in the GUAINST and STVCAMP tables respectively, to store these TimeZone ID data setup by institutions.

See UTC Timezone support to learn how to configure the UTC time zone to the required time zone, based on the location of your institution.

Add the Intelligent Processes IP addresses to your firewall's allowlist.

Intelligent Processes communicates with your institution's authoritative systems through Ethos Integration to execute workflows, process tasks, and run actions.

If your institution restricts inbound or outbound network traffic, you need to add the Intelligent Processes IP addresses to your firewall's allowlist.
