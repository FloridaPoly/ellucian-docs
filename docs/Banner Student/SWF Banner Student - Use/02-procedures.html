Procedures

Use these procedures to modify Banner SWF according to the requirements of your academic institution.

Map SWF report data codes to Banner codes

Use this procedure to map reporting code group details to one or more Banner values.

Procedure

  1. Access SWF Report Data Mapping Rules (SVRDMAP) page.
  2. Enter the reporting code group in the Reporting Code Group field, then go to the next block.
  3. If the validation records are stored in a Banner table, then enter the table name of the Banner baseline table to be mapped in the Banner Table field. Else, leave the field blank.
  4. Enter the Banner baseline value to be mapped to the reporting code in the Banner Value field.
    You can enter the value either by selecting a valid value from the Banner table as entered in the Banner Table field or by entering a desired validation value.
  5. Save your changes.

Set up default calculation option for number of contact days per week

Use this procedure to set up the default five (5) contact days per week rule to calculate the total number of contact days in the academic year summary window of Standard Workload Form (SVAFSWF).

Procedure

  1. Access SWF Report Data Mapping Rules (SVRDMAP) page.
  2. Enter CD in the Reporting Code Group field or select the code from the Search button.
  3. Select Next Block.
  4. In the Base block, enter F in the Code field or select F from the Search button in the Code field.
  5. Enter Y in the Banner Value field.
  6. Click Save.

Define validation data for the SWF faculty member information

Use this procedure to set up validation data for the fields in SWF Faculty Information (SVASFAC) page.

About this task

Define or map the following reporting code groups with a set of valid values:
  • CS - Coordinator Status for the Category field in the SVASFAC page
  • ES - Employment Status for the Employment Status field in the SVASFAC page
  • SS - Service Status for the Service Status field in the SVASFAC page
  • PG - Program Group for the Program Group field in the SVASFAC page
    Note: To define validation data, you must initially map the reporting code group to one or more Banner values.

Procedure

  1. Access SWF Report Data Mapping Rules (SVRDMAP).
  2. Enter CS, for example, in the Reporting Code Group field or select the code from the LOV.
  3. Select Next Block.
  4. In the base block, enter the code in the Code field that will be defined for the CS reporting code group.
  5. Enter the report code data element description associated to the code entered in the Description field.
  6. Select the data type from the Data Type drop-down list.
  7. Enter the Banner table that contains the value of the Banner field.
  8. Enter the Banner value that is mapped to the reporting code in the Banner Value field.
  9. Save your changes.

    Create the validation data for the selected reporting code group.

  10. Repeat the procedure from step 1 to step 9 to define validation data for other SVASFAC fields, such as ES, SS, and PG.

Copy SWF scenario records to another

Use this procedure to copy an SWF scenario record to another.

Procedure

  1. Access Faculty Standard Workload Form (SVAFSWF) page.
  2. In the key block, enter the faculty ID in the Faculty ID field.
  3. Enter the term code in the Term field.
  4. Enter the scenario number in the Scenario field.
  5. Select Next Block.
  6. Enter the scenario number of the faculty ID to be copied in the From Scenario field.
  7. Enter the scenario of the faculty ID to which the scenario are to be copied in the To Scenario field.
  8. Click Copy.

Maintain faculty member standard workload details

Use this procedure to allow administrative users to maintain a faculty member’s standard workload details such as SWF summary and assigned complimentary hours.

Procedure

  1. Access the Faculty Standard Workload (SVAFSWF) page.
  2. In the key block, enter the faculty ID in the Faculty ID field.
  3. Enter the term code in the Term field.
  4. Enter the scenario number in the Scenario field.
  5. Select Next Block.
  6. In the Detail tab of the base block, enter the details related to the subject and course.
  7. In the Complementary Hours Assigned block, enter the details related to the complementary hours assigned to the faculty ID entered in the key block.
  8. Save your changes.
  9. Go to the Summary tab to view the summary of the details related to the subject and course details related to the faculty member in the key block.
  10. In the Summary tab, if desired, you can change the assigned hours and save your changes.

Perform SWF enrollment auditing

SWF enrollment audit is a two-step procedure. First, you must create a new SWF scenario for all eligible SWFs with the assigned CRN and actual enrollment (class size) and secondly, you must convert the new scenario of a SWF to be an active SWF revision if desired.

About this task

Use the following procedure to execute the SWF enrollment audit process.

Procedure

  1. Access the Faculty Standard Workload Form (SVAFSWF) page.
  2. In the key block, from the Options menu select the SWF Enrollment Audit Process item.
  3. Enter or select the term code in the Existing Term field in the Update CRN and Class Size window.
  4. Select Run.
    Note: If there are any errors or warnings, go to SWF Process Errors and Warnings (SVASERR) page to view detail messages of the term code.

    After you execute the SWF enrollment audit process and decide to replace the existing SWF in effect with the new SWF scenario, use the following procedure to make the enrollment audited SWF an active revision.

  5. Access Faculty Standard Workload Form (SVAFSWF).
  6. In the key block, use the Summary button to search and select the enrollment audited SWF scenario of a faculty member.
  7. Select Next Block.
  8. From the Options menu select the Activate Enrollment Audited SWF item.

Set up SWF security

Use this procedure to set up system access for SWF users as administrators, deans, and associate deans.

Procedure

  1. Access FGAC Business Profile Validation (GTVFBPR) page and enter following details:
    1. Enter the business profile codes in the Code field.
      SWF_ADMINISTRATOR, SWF_SUPERVISOR_SCHOOL, SWF_SUPERVISOR_DEPT.
    2. Enter description for each code in the Description field.
    3. Save your records.
  2. Access FGAC Business Profile Assignments (GOAFBPR) page.
    1. Select your SWF business profile from the LOV in the key block.
    2. Select Next Block.
    3. In Fine Grained Access User ID field enter the user who is assigned to the business profile.
    4. Save your changes.
    5. Repeat step 1 and step 2 for other SWF business profile user assignments.

    All users of the above business profiles must also exist in the Enterprise Access Controls (GOAEACC) page.

  3. Access SWF Access Control (SVRSACC) page and enter the following details:
    1. Select the desired SWF business profile from the LOV in the key block.
    2. Select Next Block.
    3. Select the Include all college code check box if the business profile in the key block has the privilege to access all institution-wide SWF records in the system.
      Select the Read only for all college code check box if business profile in the key block has the read only access to all institution-wide SWF records.
    4. To assign specific college or school to the business profile, enter the specific college code.

      For the business profile to access all departments in the college, leave the Department Code field as blank.

    5. To assign a specific department to the business profile, enter the college code and the department code.
      Select the Read only check box to give the above business profile a read only access to the college code and the department.
    6. Save your changes.

Create .csv file

The final stage of SWF is to export the data to an external document. This process allows you to export the extract data to a flat file document for final validation outside of Banner using the SWF software or for submission.

Procedure

  1. Access Universal Viewer (GKAPUNV) page.
  2. Enter the seven-character name of the export table, such as, SVRSWFR in the Table Name field.
  3. Use the Filter Column and Filter Value fields to filter the data.
    For example, you can filter for a particular process or a rule set.
  4. Select Next Block.
  5. Double-click in any cell of the CLOB column.
  6. Enter the following string in the Fields field:
    SVRSWFR_PROCESS LIKE 'SWF_DATA_EXTRACT' AND SVRSWFR_RULESET LIKE 'SWF_DATA_RULESET' AND SVRSWFR_RULE LIKE 'SWF_DATA_EMPL'
  7. Enter the name of the directory to which the file will be exported in the Directory Name field.
  8. Enter the name of the exported flat file in the Filename field, ensuring that the file extension is .csv.
  9. Click Export Column Data.

Move third party faculty data to a Banner baseline table

There are two tables to hold third party data that includes external faculty member data and external course data.

It is assumed that you have uploaded your file to the standard location on your job/sub server. This can be done using the Banner GJAJFLU process or your preferred method.

The SIPNBFC process should be run with these parameters:

Number Parameter Value
01 file type F
02 file name <name of the file you uploaded>
03 delete existing records Y to delete existing records; N to preserve existing records
04 run mode A for Audit; U for update
If N is chosen for delete existing records, the process will:
  • produce an error message and skip to the next input record if the input term and pidm match an existing record
  • insert the record if the input pidm matches an existing record but the term doesn't match
  • insert the record if the input pidm doesn't match an existing record

Input file format

The faculty file is a comma-separated file with these fields provided in this order (maximum field length shown in parentheses):
  • BANNER ID (9)
  • PIDM (8)
  • TERM CODE EFFECTIVE (6)
  • LAST NAME (60)
  • FIRST NAME (60)
  • MIDDLE NAME (60)
  • STATUS (2)
  • STATUS DATE (11)
  • EMPLOYMENT STATUS (4)
  • CATEGORY (6)
  • PROGRAM GROUP (2)
  • SERVICE STATUS (2)
  • SERVICE STATUS DATE (11)
  • EMPLOYEE GROUP (1)
  • LOCATION (3)
  • COLLEGE CODE (2)
  • COLLEGE DESCRIPTION (30)
  • DEPARTMENT CODE (4)
  • DEPARTMENT DESCRIPTION (30)
  • SCHEDULE IND (1)

Update SWF status to Completed with MDUU

The MDUU process, SWF_STATUS_CHANGE is used to update the SWF faculty members status from signed or finalized (five days after the SWF delivery date if it is not signed by the faculty member) to completed.

Procedure

  1. Access Process Tree Execution (GKAPEXE) page.
  2. Select SWF_STATUS_CHANGE process code in the Process Code field in the key block.
  3. Go to Execution tab.
  4. Enter the term code of the SWFs for the Term Code parameter in the Parameter Value field.
  5. Select Execution Mode and Exception Mode as desired.
  6. Select either Run Now or Run from Jobsub as desired to execute the process.
  7. Follow the instructions as they appear to continue.

Hide overtime options on SVAFSWF page

Use this procedure to hide non-default overtime option fields if desired in the Signature Information section of the Faculty Standard Workload Form (SVAFSWF) page.

About this task

This procedure prevents the user from selecting other overtime options than the default overtime hours on SWF.

Procedure

  1. Access Data Display Mask Rules (GORDMSK) page.
  2. Enter SVAFSWF in the Object field, then go to the next block.
  3. In the base block, delete any existing records.
  4. Navigate to the record of SVRGWFB in the Block field and SVRGWFB_OT_HRS_IND in the Item field.
  5. Select the Conceal check box to hide the overtime hours indicators; or select the Visible check box to display the overtime hours indicators on SVAFSWF.
  6. Select All Users check box to apply this rule to all users, or enter a business profile in the Business Profile field to apply this rule to a group of users who belong to the business profile.
  7. Click Save.

Define reading week and holidays

Use this procedure to define reading week and holidays.

Procedure

  1. Access Schedule Exclusion Rules (SSAEXCL) page.
  2. Enter the calendar year in the Year field.

Examine MDUU rules for process: SWF_DATA_EXTRACT

Use this procedure to examine the delivered MDUU rules for the process: SWF_DATA_EXTRACT – Extract data from SWF tables.

About this task

This process contains rules to extract reporting data from the existing SWF records. The rules are constructed with SQL statements. However, you can customize the SQL statements. These SQL statements use the functions contained in SVKMDUU database package. The rules are as follows:
  • SWF_DATA_EMPL - Extract Employee identification details.
  • SWF_DATA_SWFC - SWF Course assignment information.
  • SWF_DATA_SWFW - SWF Weekly summary details.
  • SWF_DATA_SWFY - SWF Academic year total information.

Procedure

  1. Access Business Rules Builder (GKRRSQL) page.
  2. Enter query for SWF_DATA_EXTRACT in the Process Code field and SWF_DATA_EMPL in the Rule Code field. Or, use Summary to enter the above query.
  3. Go to the Rule Data section.
  4. Examine the SQL statement.
  5. Click Start Over.
  6. Repeat these steps to examine the SQL statements for rule codes of SWF_DATA_SWFC, SWF_DATA_SWFW and SWF_DATA_SWFY.

Execute SWF Data Extract process

Use this procedure to extract reporting data from SWF tables and save the data in the working table (GKRPWRK) by running the SWF_DATA_EXTRACT process.

About this task

The process rules (SWF_DATA_EMPL, SWF_DATA_SWFC, SWF_DATA_SWFW and SWF_DATA_SWFY) for the SWF_DATA_EXTRACT process is grouped in the rule set SWF_DATA_RULESET.

Procedure

  1. Access Process Launch (GKAPPLN) page.
  2. Select SWF_DATA_EXTRACT in the Process Code field.
  3. Select SWF_DATA_RULESET in the Rule Set field.
  4. Under the Process Launch Parameter tab enter the value of each parameter.
  5. Run the process.

Format extracted reporting data

This procedure is to execute process SWF_DATA_EXTRACT to format the previously extracted data in the .csv format and save the results in SVRSWFR table.

Procedure

  1. Access Process Tree Execution (GKAPEXE) page.
  2. Select SWF_DATA_EXTRACT in the Process Code field.
  3. Under the Execution Tree Set-up tab make sure every tree branch has an Enabled status, that is, a check sign is shown.
  4. Under the Execution tab enter the parameter value for each parameter.
  5. Run the process in the RUN/EXECUTION section.

Export formatted data to text files

Use this procedure to export the formatted reporting data in the .csv format from SVRSWFR table to an Oracle directory.

About this task

The user must have sufficient access to the Oracle directory.

Procedure

  1. With the resulting data from the procedure in Format extracted reporting data, go to the Export tab.
  2. Enter SVRSWFR in the Table Name field.
  3. Select the Oracle directory to save the files.
  4. Enter the condition statement for each output file one at a time in the Condition(s) field.
    A sample statement for the EMPL file can be:
    SVRSWFR_PROCESS LIKE 'SWF_DATA_EXTRACT' AND SVRSWFR_RULESET LIKE 'SWF_DATA_RULESET' AND SVRSWFR_RULE LIKE 'SWF_DATA_EMPL'
  5. Enter the file name, for example, EMPL.csv in the File Name field.
  6. Click Export Table to export the data to the specified file.
  7. Repeat step 4 to step 6 for each output file.
