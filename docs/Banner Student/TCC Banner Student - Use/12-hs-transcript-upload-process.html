Troubleshooting

Troubleshoot data processing issues

During routine operation the user may encounter data processing issues that were caused by factors such as file error, middleware or TCC Student.

Follow the recommended procedures below to determine the cause of the error and suggested steps for resolution. These instructions encompass processing from the time the file is received from the UT Speede server until the transcript is stored in the TCC Student temporary tables.

The incoming transcript file is required for further processing. Absence of the file will cause processing to stop.

Additional notes

In case of messages or errors, review the above table and perform steps to diagnose or resolve the problem. If additional assistance is needed contact the Ellucian Customer Support Center and submit a Service Request.

Before submitting an SR the following checklist should be completed:

  • Verify all TREx related patches and releases are installed. Following are helpful tips:
    • Register for the TCC Student Commons as all patches and releases are announced in that community.
    • Check the Student Product Release Matrix for a listing and compare to the releases at your institution.
      • Obtain a list of TCC software installed at your institution using either GZITCCV or GZRTCCV.
      • Obtain a list of TCC software available by going to the TCC Student Commons and click on the following links:
        • Find It Fast → Product Release Matrix for Student
        • Product Release Matrix
        • Click Open
        • Click the tab titled TCC_BannerStudent. Included is a list of all software patches and RTEs.
      • Compare the list of TCC software installed at your institution to the list of TCC software available.
  • Errors appear on both the SZAEHTA Review Results tab and on the GZIERRS form. A purge of the transcript in the temporary tables using either the Electronic HS Transcript Activity page (SZAHETA) or the Electronic HS Transcript Purge process (SZREHPG) will remove the messages from viewing on GZIERRS.
  • If errors are found in the LOG file indicating a date format that is not valid (ORA-01480: trailing null missing from STR bind value) the issue may be with the format of the transcript file. If the post EDI.Smart file is transferred to a Linux machine the format of the file may need to be modified to ensure it is in UNIX format. A command such as dos2unix can be used to convert the file to UNIX format.
  • File Format - The file must be in ASCII format with no Carriage Returns (CR) at the end of each record. The format required may be referred to as UNIX line endings or UNIX (LF).

Troubleshoot data load to TCC Student temporary tables

If an issue is encountered during the data load to the Banner temporary tables an informational message is written to the GZRERRS table which is viewable through the General Errors Inquiry form (GZIERRS).

This same message is viewable through the Electronic HS Transcript Activity page (SZAEHTA) on the Review Results tab. Following are examples of common messages written by the HS Transcript Load process (SZREHSL) during the temporary table load along with recommended resolution steps.

When viewing these messages using the form SZAEHTA on the Review Results tab the Document ID is included in the bottom section of the form in the Doc Seq # field and the incoming file name is included in Key Value 11.

7oy49gh8o Transcript NOT Loaded Invalid HEA1 found –

-or-

8mt02gh8o Transcript NOT Loaded Unsuccessful Load - Error in processing line –

The expected first record of the transcript was not found or an invalid key word was found in the first 4 characters of a record.

This transcript will not load to the temporary tables in Banner.

This transcript may load if the first record of this transcript is changed and HEA1 is replaced with HEAD in the received file.

The SZREHSL process will stop and not load any additional transcripts from the transcript file.

The process looks for specific key words in the first four characters of each record received. If the first four characters contain an invalid Key word, an error is indicated in the LIS file and the transcript may not load to the temporary tables.

The list of Key words includes the following:

HEAD, HDR3, HDR4, IDEN, ACAD, TR00, TR10, TR11, ASUM, ASES, CRSR, CNTE, COIN

Recommendation: Edit the transcript file and modify the keyword to match one of those listed above.

Troubleshoot data load to TCC Student permanent tables

If an issue is encountered during the data load to the TCC Student permanent tables an informational message is written to the GZRERRS table which is viewable using the General Errors Inquiry form (GZIERRS).

This same message is viewable using the Electronic HS Transcript Activity page (SZAEHTA) on the Review Results tab.

When viewing these messages using the form SZAEHTA on the Review Results tab various additional information items are included in the bottom section of the form and may be used for trouble-shooting purposes.

Following are examples of common messages written during the permanent table load along with recommended resolution steps.

Posted Message Recommended Resolution Steps
SZAEHTA Review Results tab or SZREHSP.LIS file
Document ID

Transcript Load Status

Informational Text

The actual transcript record causing this message displays immediately beneath the posted message.

Most messages contain 3 elements which are outlined below.

  • Document ID

    An identifier of this transcript in the received TREx file. This transcript number is used to search the transcript file for this particular transcript.

  • Transcript Load Status

    Indicates if the transcript will load to the temporary tables.

  • Informational Text

    Indicates the exact message, such as a missing value.
Banner Common Matching issue. Please create Person record manually. The process could not automatically assign an existing TCC Student ID or create a new TCC Student ID for this person.

Recommendation: Use the pull-down Options menu to access GOAMTCH and assign a TCC Student ID manually.
Banner - Missing Texas ID Name Type (SAAERUL HSALTIDTYPE or GTVNTYP). The SAAERUL HSALTIDTYPE rule is missing or the SAAERUL HSALTIDTYPE assigned is missing on GTVNTYP or is a value that is not valid, such as UPDATE ME is assigned.

Recommendation: Create a defined value for the HS Alternate ID on GTVNTYP and assign this value to the SAAERUL HSALTIDTYPE rule.
Banner – SAAERUL EXISTSETHNIC is not Y or N – data not used. The SAAERUL EXISTSETHNIC rule is missing or is not assigned a value of Y or N.

Recommendation: Create the SAAERUL EXISTSETHNIC rule and ensure the assigned value is Y or N.
Banner - Ethnicity Not Used. Due to the value of SAAERUL EXISTSETHNIC the Ethnic value received is not updated in TCC Student.

Recommendation: If the institution prefers to load the received Ethnic value, adjust the SAAERUL EXISTSETHNIC value to Y or N.
Banner - SAAERUL EXISTSETHNIC is not Y or N - data not used. The SAAERUL EXISTSETHNIC assigned value is not Y or N. Thus the EXISTSETHNIC rule is not used.

Recommendation: Modify the SAERUL EXISTSETHNIC rule assigned value.
Banner - Missing STVSBGI code for incoming CEEB Code (STVSBGI or SOAXREF STVSBGIH) for CEEB 440012 The incoming High School CEEB code is not defined on either STVSBGI or SOAXREF using STVSBGIH.

Recommendation: Define the incoming High School CEEB code on either STVSBGI or on SOAXREF using STVSBGIH.
