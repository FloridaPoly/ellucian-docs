Map Nation Codes

The mapping of external CAO nation codes to internal Banner nation codes must be performed before the processing cycle begins.

This mapping is used to map the values loaded from the ID19, ID20, and ID13 fields, and to store the result in the GOBINTL_NATN_CODE_BIRTH , GOBINTL_NATN_CODE_LEGAL and SPRADDR_NATN_CODE columns when an ID record is processed during the CAO process.

The mapping is defined on the Nation Code Validation page (STVNATN).

The following table lists the values needed to define the nationality mapping.

Field Name Value
Nation Code Internal Banner Nation Code
Description Internal Banner Nation Description
EDI Equiv CAO Nation Code

If the value in the ID19 or ID20 field is blank, or the processing cannot identify a valid internal nation code through the specified mapping, the internal nation code associated with the EDI Equivalent value of UN (Unknown) will be retrieved and saved instead. Therefore, this mapping should be performed before any other. If the ID19 or ID20 field value is not blank and cannot be mapped, the process will create a warning exception to flag the error before continuing with the rest of the application processing.

Define CAO Course Codes

Use the Banner Program Definition Rules (SMAPRLE) page to enter your institution's course codes.

To define the various fields of study associated with a program such as Majors, Minors, and Concentrations, use the Banner Curriculum Rules page (SOACURR).

You should also define the study paths for programs using SOACURR

CAO provides the following approaches to define CAO course codes and associate them to programs within Banner using the CAO Interface Configuration (GZVCAOI) page group codes:
  • Through CAOCOURSE: In this approach, the CAO course code is associated to a specific program in Banner which allows the system to pick the most appropriate major to be used for student applications.
  • Through a combination of CAOCOURSE, CAOMAJOR1, CAOMAJOR2, CAOMINOR, CAOCONC1, CAOCONC2: In this approach, a deeper level of associating CAO course codes with specializations within a program. For this approach, the minimum group that must be defined for a CAO Course Code is CAOCOURSE and CAOMAJOR1
Note: In both the approaches, it is important that the fields of study used follow the Banner Curriculum Rules.

Map CAO Campus Codes to CAOAS07 Group

Use the CAO Interface Configuration page (GZVCAOI) to map the CAO campus codes for your institution to the CAOAS07 group.

The AS flat file has a provision to enter AS07 values that allows institutions to translate up to three character campus codes as per CAO. In the incoming AS file, the course (AS03) is directly mapped to the campus (AS07). Example, the first five-character course code corresponds to the first three-digit code in AS07, the second 5-char course code, then corresponds to the second 3-digit code in AS07 and so on.

To map the campus code to the CAOAS07 group, do the following:
  1. Access the GZVCAOI page and insert the new record with CAOAS07 group.
  2. Enter the CAO campus code coming in AS file as External Code value.
  3. Enter required values in Code and Internal Code
Note: You can maintain more than one value. However, you must maintain the equivalent course code for the campuses (as per AS flat file).

Institutions can maintain a value for the CAOAS07 group code, only if multiple campuses exist for institutions; else the field can be left blank. If institutions decide to leave the CAOAS07 group code value as blank in the GZVCAOI page, there will be no impact to the AS file processing.

For institutions with multiple campuses, Ellucian recommends to configure the campus code in External Code for CAOAS07 to determine and process AS files for the respective campus only.

Note: CAO did not require any changes to the ID files and OF files and hence the ID and OF file processing remain as is.

The following table lists the values needed to map CAO campus codes.

Field Name Value
Group CAOAS07
External Code CAO Campus Code
Internal Code Same as Translation Code
Translation Code User defined Campus Code
The AS file processing includes the following validations.
  • If the CAOAS07 group code value is left blank, the AS file processing continues as is without any checks on the campus codes. (Best suited recommended for institutions having only one campus).
  • For incoming AS file with AS07 values, if the CAOAS07 group has campus value (one or more) in the GZVCAOI page, the AS file processing logic checks whether the incoming campus values in AS07 of AS file is configured for CAOAS07.
  • For the AS file processing logic to run without errors to create admission records in Banner, the system validates the following:
    • The campus values must exists for the CAOAS07 group in the GZVCAOI page
    • If yes, the respective courses must also be mapped appropriately in the GZVCAOI page
    • The appropriate campus values must be positioned correctly that corresponds to the course in AS file
  • For an incoming AS file with AS07 values, if the CAOAS07 group values do not match the AS07 values in AS file, the processing logic will not process the AS file. The error message appears: Transaction not loaded – CAO AS07 value is not mapped in GZVCAOI Group ‘CAOAS07’ for CAO Course Code. You can view this message in the SZAIREC page.

Define Offer Month Indicator

The Offer Month parameter is used to associate a month with the month value contained in the Offer file in fields OF08 and OF10.

The dates in an Offer file are in the format of MDD, where M is a value between 1 and 5, and DD is the day of the month. A value of 1 is considered to be the 8th month, a value of 2 is the 9th month, a value of 3 is the 10th month, a value of 4 is the 11th month, and a value of 5 is the 12th month.

The CAOMONTH parameter value is used along with the DD portion of the OF08/OF10 field and the current year to page an offer date for the decision record in the SARAPPD table.

The values in the External Code fields are the values included in the Offer file (current values are 1-5). The values in the Internal Code fields represent the months used to store decision records in the SARAPPD table. The Internal Code values can be changed to any valid month from 1-12.

If CAO introduces a new value such as 6, the only required change would be to introduce a new CAOMONTH record with an external code of 6 and the relevant month in the Internal Code field.

The indicator is defined on the CAO Interface Configuration page (GZVCAOI).

The following table lists the values needed to define the indicator.

Field Name Value
Group CAOMONTH (delivered as seed data)
Internal Code Month used to store decision records in the SARAPPD table. Possible values are as follows:
  • January
  • February
  • March
  • April
  • May
  • June
  • July
  • August
  • September
  • October
  • November
  • December
External Code Values included in the Offer file in fields OF08 and OF10 (current values are 1-5)
Translation Code Same value as the Internal Code field

Define Banner Generated Identification Numbers

Some institutions have a requirement that all correspondence, notes, results, and all records pertaining to a person are recorded against a single identity (ID) number for that person. This person will be an applicant in the first instance but might become a student/undergraduate, post-graduate or alumnus.

Other institutions require that the system generated ID be created at the point when the applicant becomes a student. Other institutions require that the system use the CAO applicant number throughout. The CAOGENERATEID group is used to define when an ID will be generated.

The Banner generated identification number is defined on the CAO Interface Configuration page (GZVCAOI).

The following table lists the values needed to define the Banner-generated identification numbers.

Field Name Value
Group CAOGENERATEID (delivered as seed data)

Only one entry for the CAOGENERATEID group is permitted.
Internal Code Possible values are as follows:

N: Institution requires that the ID be created on application

Y: CAO system will create a system generated ID on admission

C: CAO applicant number will be retained

If the value is N or Y, the CAO applicant number will be kept but the Banner value for the CAO number will be marked inactive and the system generated ID will be active.

If the value is C, the CAO number will always be active.
External Code Same value as the Internal Code field.
Translation Code Same value as the Internal Code field.

Set up to Receive Exam Files with No Results

The CAO can send an exam file containing entries with an empty results field to indicate applicants who are planning to take their exams in the near future and for which results can be expected.

The Banner CAO module can be configured to process these entries by setting up the following system variables on the CAO Interface Configuration (GZVCAOI) page:
  • CAOLOADERTYP
  • CAOEREXMYR
  • CAOERCMTT

When the CAO Interface: Data Load Process (SZPIIFT) loads an Exam file entry with an empty results field, the process checks if the exam type is included in the list defined for the CAOLOADERTYP system variable. If the exam type is included in this list, this indicates that a comment should be inserted into the Person Comment (SPACMNT) page to show that results are expected for the applicant.

The SZPIIFT process then checks that the year in the Exam file entry is the current exam year for that exam type as defined for CAOEREXMYR. If the years match, then an entry is temporarily inserted into the SPACMNT page to indicate that results are expected. The Comment Type code used to create this entry is defined, for the required exam type, in the GZVCAOI CAOERCMTT system mapping.

When the actual results arrive in a later Exam file, the transaction will have the same exam type and year but the results field will be populated. The SZPIIFT process will load the Exam file that now contains the results.

The SZPIIFT process checks if the exam type is defined for CAOLOADERTYP. If the exam type is defined for CAOLOADERTYP, and the current exam year for that exam type is defined for CAOEREXMYR, the process will remove the associated Comment Type code record from the SPACMNT page. The SZPIIFT process will then populate the Test Score Information page (SOATEST) with the valid result entries.

Define the Comment Type Code

Use this task to define the Comment Type code that will be inserted into the Person Comment page (SPACMNT) when the SZPIIFT process loads an exam file record with no exam results for the current exam year (for the exam types defined for CAOLOADERTYP).

This comment will be temporarily inserted into the SPACMNT page until a new exam file is received for the applicant where all of the following conditions exist:
  • The new entry is for an exam type for which expected results are loaded (as defined by CAOLOADERTYP).
  • The new entry is for the current year (as defined by CAOEREXMYR).

If these conditions exist, the corresponding Comment Type code entry will be deleted.

The Comment Type code must be defined on the Comment Type Code Validation page (STVCMTT). The Comment Type code must then be assigned to an exam type that has been defined for CAOLOADERTYP. The exam type is entered in the External Code field.

A CAOERCMTT entry should be created for every exam type listed for CAOLOADERTYP.

The CAOERCMTT system variable is defined on the CAO Interface Configuration page (GZVCAOI).

The following table lists the values needed to define the comment types.

Field Name Value
Group CAOERCMTT (delivered as seed data)
Internal Code Valid comment type code from the STVCMTT page.
External Code Exam type. The code must be defined in the STVTADM table.
Translation Code Same value as the Internal Code field.

Handle CAO Files

This section describes the following tasks.

Copy the CAO Files to the Banner Interface (JobSub) Directory

The CAO notifies your institution (usually by fax) that a particular file has been created and has been placed on your institution's own secure directory on the CAO computer.

The name of the file will be in the notification and will be one of the following types:
  • Identity File (ID) (Revised format ID1 with country and county codes)
  • Application Selection (AS) File
  • Exam File (EF)
  • Text File (TX)
  • Offer/Acceptance File (OF)
  • School File (SF)

The user should log in as CAO and FTP the files from the CAO to the Banner interface directory. If the user is copying ASCII files, then the user must set FTP to transmit in ASCII so that control characters do not appear at the end of lines. Likewise, if the user is copying zip files, then the user must set FTP to transmit in binary mode.

The interface directory will be the home directory for the CAO user login. This login has been set up so that all files created by this user will have file ownership permissions set so that all users could at least read the files.

Review Contents of the CAO Files

The user should review the contents of the files within the interface directory. Some institutions might want to delegate this task to technical staff. Access to the interface should be designated as 'read only' (that is, your institution's IT staff should have set the directory to be 'read only').

The following checks should then be carried out:
  • The file should contain transactions of the right type. There should not be a mix of transaction types in a file.
  • Each transaction should be on a separate line in the file.
  • If the file is a Master, Identity, or Application Selection file, the application numbers should be in ascending order.

If any of the above checks reveal errors, do not continue to load the files into Banner, but notify the IT staff immediately.

Load the CAO Files into Banner

The CAO transaction files must be loaded by the following processes, and in the indicated order.

Procedure

  1. Merge and load the ID file and AS file into a new file using the CAO Interface: Merge+Load File Process (SZPIIMG).

    Refer to Identity File (ID) and Application Selection File (AS) for ID and AS file details.

    Note: The CAO Interface: Join+Sort Files Process (SZPICAT) is seldom used because the SZPIIMG process merges and loads the ID and AS files in a single process. Institutions that receive two AS files can run the SZPICAT process to create one AS file before running the SZPIIMG process.
  2. Load the EF file using the CAO Interface: Data Load Process (SZPIIFT) with file type EF.

    Refer to Exam File (EF) for EF file details.

  3. Load the TX file using the SZPIIFT process with file type TX.

    Ensure that only the latest file is used. Do not concatenate text files.

    Refer to Text File (TX) for TX file details.

  4. Load the OF file using the CAO Interface: Data Load Process (SZPIIOF).

    Student records are created in Banner when offers and acceptances are received.

    Refer to Offer/Acceptance (OF) for OF file details.

  5. Load the SF file using the CAO Interface: Load Schools Process (SZPIISF).

    The SZPIISF process should only be run one time in a year.

    Refer to School File (SF) for SF file details.

Check for Duplicates and Validation Errors

After the data has been created from the uploaded files, the CAO module will indicate if there were errors and anomalies such as potential duplicate records.

After running each upload process, a check should be made for exceptions by doing the following:
  • Check the data in the CAO Transaction Exception Maintenance (SZAIREC) page, and accept the necessary data.
    Note: The SZAIREC page must be checked, and any outstanding issues resolved, before and after every load process. Any pre-existing duplicate or mismatch errors for the same person are removed before the latest duplicate or mismatch error is added into SZAIREC.
  • Review the process log file (users might require assistance from IT staff to do this).

Process Withdrawn Applications

Use this task to automatically set the status to Withdrawn for CAO applications that are no longer included in files received from the CAO.

About this task

Running the SZPIIMG process will clear out any existing data from the Automatic Application Withdrawal Table (SZRWDAP) and will re-populate it with excluded application entries.

Note: The SZPIIWA process should be run only after full CAO ID/AS files are loaded, and it should not be run after loading mini files.

Procedure

  1. Merge and load the ID file and AS file into a new file using the CAO Interface: Merge+Load File Process (SZPIIMG).
  2. Produce a list of applications that will be included in the withdrawal processing by running the CAO Auto Withdrawal Process (SZPIIWA), being sure to set the Run Mode parameter to Audit.
  3. Update the applications and set the status to withdrawn by setting the Run Mode parameter to Processing for the SZPIIWA process.

Manage Applicants and Applications

This section describes the following tasks.

Update Applicant and Application Data

When the CAO data loads are run, General Person, Admissions, Test Score, and General Student records will be inserted or updated in the Banner database.

After the data from the CAO has been checked and loaded into Banner, the following pages can be used to manage applicants and applications.

Page Name Use
SZAIIOT View/add/change ratings, and view decisions.
SZARXPR View/add/change ratings or supplemental scores for all of the applications of a single applicant.
SZARMAS View/add/change ratings or supplemental scores for multiple applications for a selected program and term.
SPAIDEN View/change address details.
SPAPERS View/change personal details.
SPATELE View/change telephone details.
SAAADMS View/change admissions details.
SAADCRV View admissions decision details.
SGASTDN View/change general student details, after an applicant has accepted an offer.
SOATEST View examination results of an applicant.
SOAHSCH View/change previous school details.
SOAQQIA View/add/change the applicant qualifications data sent by the CAO in the QQI/FETAC/NCVA file.
SOASUPL View/change supplemental application details.
SPACMNT View/add/change comments.

Add or Modify an Applicant's Ratings and Supplemental Scores

The Irish Institutes CAO Rating (SZAIIOT) page, Irish Institutes CAO Rating Express Entry (SZARXPR) page, and Irish Institutes CAO Rating Mass Entry (SZARMAS) page can be used to add or modify ratings or supplemental scores for an applicant.

Each page records the ratings and supplemental scores as test scores. The value in the Type field will determine if the data goes to a Ratings file or a Supplemental Scores file.

Create the Ratings or Supplemental Scores Files

If an institution has created ratings or supplemental scores for an applicant, the CAO must be notified within the time allowed. The RF Download Process (SZPIIRS) creates Ratings and Supplemental Scores (RF) files for applicants, which can then be sent to the CAO.

This process only downloads for first year applicants.
