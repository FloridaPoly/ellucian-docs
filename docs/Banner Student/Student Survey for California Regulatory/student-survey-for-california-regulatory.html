Student Survey for California Regulatory

California community colleges' vocational / career technical education programs depend heavily on the Carl D. Perkins Vocational Technical Education Act (VTEA) dollars as their major funding source.

The Perkins fund allocation is based on regulatory MIS report data submitted by the college to the state at the end of EVERY academic term. To report student info in the regulatory MIS report to the state, the college needs to collect certain self-identifying info items from students each academic term, and store in the student information system (SIS).

A survey is presented to each student to gather the self-reported student information to cover VTEA and other California Regulatory (MIS Student Special Populations, AB 1504 Student Representation Fee opt-in opt-out and AB 2248 Cal Grant notification).

Prerequisites

You must meet the following prerequisites to set up the Student Survey before students and administrators can access its functionality and features in Ellucian Experience.

Banner

  1. You need to have district codes correctly associated with campus in STVCAMP.
  2. You must have an API user that has access to the following resources:
    • persons
    • person-filters
    • person-hold-types
    • person-holds
    • ca-economically-disadvantages
    • ca-import-mass-special-term-data
    • ca-import-mass-student-institutional-requirements
    • ca-import-mass-workforce-innovation-opportunity-act
    • campus-codes
    • district-division-codes
    • enrollment-status-control
    • registration-additional-fees
    • general-student-curricula
    • student-term-enrollment-bases
    • term-codes
    • process-submission-control
  3. That user is required in the configuration of platform components. For more information on how to create API users see: Create and Authorize a Banner User to Enable Proxy API calls for Ethos Integration.
  4. You must have the Registration Additional Fees Control Rule configured (SFAAFEE) for the used term.
  5. You need to configure a HOLD in STVHLDD that prevents student registration.
  6. You need to have a population selection. For more information about this, go to: How to build a population selection. This population is required to schedule tasks in Intelligent Processes.
  7. Make sure the UTC offset is correctly configured, this is required by Intelligent Processes, see: Configure the UTC offset and timezone.

Audiences Lists

The Audience Lists card enables you to create lists that you can use to send communications to a targeted population. You build an audience in Ellucian Communicate based on populations created in your ERP using the Banner Population Selection.

Enable audience lists if you are going to be working with dynamic populations and recurrence.

For more information about it, see: Audience List.

Audience Lists need configuration before using the recurrent schedule feature for the Student Survey.

Ellucian Communicate needs access to:

  • Banner Integration API (person-filters).
  • Banner Student API.
  • Banner Business Process APIs (process-submission-control).

You need to make sure that the application that use an API key, has access to the previous resources. For more information about this, see: Create the ethos applications for Communicate.

Set up roles and users

  1. Navigate to Ellucian Experience Setup → Permissions → Audience Lists
  2. Enable the following permissions:
    • For Audience Queries for the administrator role:
      • Create: Create an audience list
      • Read: View audience list
      • Update: To view audience list details
    • In Static Audiences for the administrator role:
      • Read: View audience list history
    • Audience Members for the administrator role:
      • Static: To view added or total members
    • Configuration for the administrator role:
      • Administer
  3. Click Save.

For more information, see: Grant Audience List permissions.

Create Actions

Continue with the creation of the needed actions.

Procedure

  1. Navigate to Ellucian Experience dashboard
  2. Click the Applications icon, and select Intelligent Processes.
  3. In the Intelligent Processes Workflows page, select Actions in the navigation panel.
  4. On the All Actions page, click + New button.
  5. On Action Detail, enter an action name, for example: Obtain term details.
    With that name, in the field code, a unique code is generated, and it is needed to import the workflow.
  6. Then, enter a description, for example: Obtain term details given a certain code.
  7. On Pipeline Name, enter a unique name for the pipeline, for example: term-details.
  8. On API Key enter the key from the previously configured application. Refer to the next step for guidance on how to obtain the API key:
    1. Open a new browser tab and enter to Ellucian Ethos Integration → Applications → All Application tab, select the application you configured in the step Add the integration package to application in the prerequisites, then, in the API Keys tab you will find the key, click on the copy button.
  9. Click Save to save your action.
  10. Click Publish.
  11. Repeat the process three more times, each for one of the pipelines required. Here's a table with the details for each pipeline:

Action Name Description Unique Code Pipeline Name
Obtain term details Obtain term details given a certain code OBTAINTERMDETAILS term-details
Obtain district details Obtain district details from records of a given student ID OBTAINDISTRICTSDETAILS student-district-details
Create survey records Create the corresponding records from the data collected in the survey CREATESURVEYRECORDS student-survey-records
Add additional fees Create the additional fees ADDADDITIONALFEES survey-registration-additional-fees
  1. Click Save and Publish.

Results

When entering the pipeline details, all the parameters that the pipelines requires are brought up; the user does not have to modify anything.

The four actions should be visible in the All Actions list.

For more information, see the step 2 of the: Create actions

Create a New Job for the Pipeline

After the workflow has the right permissions, you need to create a new job for it.

Procedure

  1. Navigate to Ellucian Experience dashboard. → Integration Packages.
  2. Select the package Student Survey Package.
  3. Select the pipeline student-survey-trigger and click on New Job.
  4. Fill the parameters:
    1. For Ethos API Key, use the one from the Ethos Application previously created.
    2. For Term Code, use the desired term you want students to receive the survey.
    3. For Workflow ID, go to Intelligent Processes in another tab, and select More Options on the Student Survey API workflow and select Settings; here, copy the Workflow ID and paste it in that field in the Job Parameters section.
    4. Under Job Run Details, select the option Triggered by Event and setup the notifications you need.
  5. Click Save.

Test the Student Survey

Now its time to test if the Student Survey works properly.

After the schedule has been executed and the workflow has been assigned, you can see that a task has been allocated, and that is the Student survey, now, to validate it:
  1. Log in as a student to the Experience dashboard.
  2. In the right side panel you now see that a task has been assigned and that is the survey.
  3. Answer the survey with a test data.
  4. Click Next and continue with the survey until you see the Submit button.
  5. Click the Complete Form Task button to finish the survey.

After the completion of the Student Survey, you can see the responses in the following pages in Banner: MIS Special Term Data (SVAMIST), Student Institutional Reporting Requirements (SGAUSDF) and Workforce Innovation and Opportunity Act (WIOA) Data (SVAWIOA). If the student opt-in for additional fees, you can validate in Registration Additional Fees (SFAEFEE).

Note: The Student Survey configuration needs to be completed only one time. After that, you only need to complete the steps to Configure the workflow and Configure the schedule each time you want to release it.

Review Workflow Errors

The Errors report helps you to view the workflow errors page in Ethos Integration. You can then select the Errors, Warning, or Info tab for more error information.

  1. Open Ellucian Ethos Integration and hover on Reports.
  2. In the drop down menu, click on Errors.
  3. In the Errors tab, you can see the history about errors.
  4. Click the info icon to open the details pop up.
    You can see the error details, for example:
    • Date / Time
    • Severity
    • Application / Platform Component / Packages
    • Response code
    • Resource ID
    • Description
    • Details
    • Correlation ID

Also, you can see the error details in Ellucian Intelligence Processes.

  1. Log on to Experience with the user name and password of the role with access to the Workflow designer (Administrator)
  2. In the dashboard navigate to the Applications icon, the Applications menu should be displayed, select Intelligent Processes.
  3. Select Workflow Runs.
  4. From the list of workflow runs, you can see the date and time, name, and the status of them. Click on one element that has the status of Error.
  5. On the detailed page, in the right section, scroll down and click View Error.
  6. In the pop up, you can review the details of the error.
You can also see the details when a Student Survey ran with errors when it was scheduled:
  1. Click the button to go back to Intelligent Processes.
  2. Select Workflow.
  3. From the list, select Student Survey - Template to enter the Designer.
  4. In the upper section Student Survey - Template, click the button to display the drop down.
  5. Select Schedules.
  6. You can see the list of the survey schedules and the occurrences that failed.

For more details about the code, see: Use error reporting and View and manage workflow runs.

Add Items to the Survey

In case it is necessary to add new elements to the survey, follow these steps.

  1. Before making any modifications, create a backup of the survey and the workflow, to ensure data integrity and avoid accidental data loss.
  2. Add the additional questions or sections your institution requires.

    To learn more about the items that can be added to the forms, see: Enter form details.

  3. To connect the new item, a serverless API must be developed to store the information collected from the added item. It is important to know the Banner API endpoints that the new pipeline will use.

    For more information on the steps to follow on how to develop a serverless API, see: Create a serverless API.

  4. After the pipeline has been tested locally, it needs to be added as an additional step into the workflow as an action. It's recommended to add it after the existing objects.

    To know how to develop an action item, go to: Create action.

This process will have to be repeated every time that Ellucian releases a new version of the form and the workflow.
