Release 9.3.42 and 8.29

The Banner ASCGEN 9.3.42 and 8.29 release includes regulatory updates.

ECAF Course Resolution Enhancement

Updated the ECAF (Engagement Course Activity File) framework to resolve course data from SMAPFPA as the primary source, with fallback logic to SKADRCO for backward compatibility.

Course maintenance has been transitioned to the SMAPFPA page, making the SKADRCO reference outdated. This update ensures that students whose course data exists in SMAPFPA are processed correctly through ECAF.

Key features of this enhancement include:

  • Primary course resolution from SMAPFPA
  • Fallback to SKADRCO if course not found in SMAPFPA
  • Updates to SOPECAF, SKPECAF, and SOPICAF processes
  • Enhanced support for ERM customers using SMAPFPA for course maintenance

This enhancement addresses PE0008332 in the Ellucian Customer Center.

Student Status Derivation Logic for Mid-Term Citizenship and Mixed Funding

The student status derivation logic in SKVUFEE is enhanced to handle complex fee type determination scenarios, including mid-term citizenship changes and mixed funding arrangements (CSP/Full-Fee).

This enhancement addresses scenarios such as residency status changes mid-term (shifting from international fees to domestic full-fee and potentially CSP), faculty decisions to apply CSP to selected units only (creating mixed charging within a term), and Student Learning Entitlement (SLE) limits where CSP subsidy is capped and students who exhaust their entitlement must be charged full fees for additional units.

Key features of this enhancement include:

  • Four new rate codes introduced in SKARVAL and SKARMAP:
    • RATE-INT-DEFERRED: International students changing citizenship mid-term entitled to HECS-HELP
    • RATE-INT-UPFRONT: International students changing citizenship mid-term entitled to CSP upfront fees
    • RATE-FEE-DOM-DEFERRED: Fee-paying students with faculty approval to receive HECS-HELP
    • RATE-FEE-DOM-UPFRONT: Fee-paying students with faculty approval to receive CSP upfront fees
  • Modified SKVUFEE package to include new filter criteria using existing skktcsi.fn_check_deferred_exist function
  • Unit-level attribute support for CSP eligibility and SLE exhaustion tracking
  • Accurate fee type determination for government reporting and student billing

This enhancement addresses PE0008345 in the Ellucian Customer Center.

Enhanced SKKJSON package

The SKKJSON package has been upgraded to support the import of incoming VTAC application data and SEAS data into Banner ERP. This enhancement enables the package to process and load incoming records into the appropriate Banner structures, ensuring seamless handling of both new and existing applications for continued processing within Banner.

This enhancement addresses PE0008343 in the Ellucian Customer Center.

WCAG Accessibility Enhancements for SKASYSC and GKAADIV pages

Banner ASCGEN pages have been enhanced to comply with WCAG 2.2 Level A and AA accessibility standards, specifically addressing keyboard navigation and screen reader support for critical device status fields on the SKASYSC (External Systems Interaction Control) and GKAADIV pages.

This enhancement resolves WCAG 2.1.1 (Keyboard) and WCAG 4.1.2 (Name, Role, Value) compliance violations, and ensures the Australian institutions provide equitable access to Banner ASCGEN functionality for all users, including those with disabilities, and supports compliance with international accessibility requirements and institutional accessibility policies.

This enhancement addresses PE0008451 in the Ellucian Customer Center.

New SFRUFEE table for ERM Integration

The new SFRUFEE table supports Australian regulatory reporting by storing student Unit of Study–level fees and loan details for ERM integration.

Ellucian created the new SFRUFEE (Student Fee Information Detail) table to support Australian regulatory reporting. This table stores student Unit of Study–level fees and loan details for downstream processing and ERM integration. The SFRUFEE table serves as the authoritative source for ERM to load Engagement-related financial data.

The SFRUFEE table has a primary key consisting of SFRUFEE_PIDM, SFRUFEE_TERM_CODE, and SFRUFEE_CRN.

Column Name Data Type Nullable Description
SFRUFEE_PIDM NUMBER(8,0) No PIDM of the student registered in the CRN and Term.
SFRUFEE_TERM_CODE VARCHAR2(6) No Term code of the student's registration.
SFRUFEE_CRN VARCHAR2(5) No CRN in which the student is registered.
SFRUFEE_UNIT_CDE VARCHAR2(12) No Unit of Study code for the registered student.
SFRUFEE_DETAIL_CODE VARCHAR2(4) Yes Detail code associated with the student fee.
SFRUFEE_DESC VARCHAR2(255) Yes Description for the fee detail code.
SFRUFEE_AOU_IND VARCHAR2(1) No Indicator for record selection (default 'N').
SFRUFEE_UPFRONT_PER_UNIT NUMBER(12,2) Yes Up-front fee amount per unit (student paid portion).
SFRUFEE_TOTAL_PER_UNIT NUMBER(12,2) Yes Total amount charged for the unit.
SFRUFEE_LOAN_FEE NUMBER(12,2) Yes Loan fee for the unit of study.
SFRUFEE_LOAN_AMOUNT NUMBER(16,2) Yes HELP or SA-HELP loan amount per unit.
SFRUFEE_RATE_CODE VARCHAR2(5) Yes Rate code associated with the registration.
SFRUFEE_DISCOUNT_AMOUNT NUMBER(16,2) Yes Discount amount applied for the CRN.

SFRUFEE_VERSION NUMBER(19,0) Yes Optimistic lock token for concurrency control (default 1).

A new Java process is created to populate the SFRUFEE table with the following functionality:

  • Reads data from the SKVUFEE and SKVURPL views.
  • Populates SFRUFEE with transformed and normalized values.
  • Sets the SFRUFEE_FEE_TYPE column to identify the originating view (FEE for SKVUFEE or RPL for SKVURPL).
  • Ensures data is refreshed based on institution load cycles.

These enhancements addresses PE0007580 in the Ellucian Customer Center.

Enhanced security for concession customer reference numbers

Ellucian enhanced the security of student concession data by implementing Masking for the Customer Reference Number field (SKRCONC_CONC_ID) on the Student Concessions (SKRCONC) table. This field stores the student's Concession Customer Reference Number used when verifying concessions with Centrelink. The new process SOPUFEE picks up data from SKVUFEE and SKVURPL and inserts into the new table SFRUFEE.

The enhancement includes:

  • Encryption of Customer Reference Numbers at rest to protect sensitive student concession data
  • Automatic decryption only during Centrelink verification processes
  • Masked display in the user interface to prevent unauthorized viewing
  • Database schema updates to support encrypted data storage
Note: Existing Customer Reference Numbers will be masked in the UI as part of the upgrade process. The Centrelink verification process will continue to function normally, with decryption occurring automatically during verification.

This enhancement addresseses PE0007667 in the Ellucian Customer Center.

Enhanced delivery location management for multiple campuses

Ellucian enhanced the Delivery Organization (SKATORG) page to support multiple campus delivery locations with automatic address population. When users select a Delivery Location from the Site Code validation table (STVSITE), all associated address details automatically populate, streamlining data entry and ensuring accuracy.

Key features include:

  • Auto-population of address fields based on site selection, including:
    • Street Name
    • Building / Property
    • Flat / Unit Details
    • City
    • State or Territory
    • Post Code
    • Nation
  • Support for Australian address formats with state/territory and postcode mapping
  • Automatic setting of default values for Effective From Date and Active status
  • Direct mapping from STVSITE validation table to delivery location fields
Note: The Effective From Date defaults to the term start date, and the Active status is automatically set to checked (true) when creating new delivery location records.

This enhancement addresses PE0007668 in the Ellucian Customer Center.

Enhanced Security for Concession ID Data

Ellucian enhanced the Concession Code Rules (SKACONC) page to protect sensitive concession identification data. The Concession ID field (SKACONC_CONC_ID)is now masked in the user interface to safeguard student concession card numbers and related identification information.

This security enhancement ensures that concession identification data is protected both at rest and during display, aligning with data privacy best practices and regulatory requirements for handling sensitive student information.

Note: Existing Concession ID values will be masked as part of the upgrade process. Users with appropriate security access can continue to enter and manage concession data through the SKACONC page, with values displayed in masked format.

This enhancement addresses PE0007668 in the Ellucian Customer Center.

Data Connect Pipeline enhancements

This release delivers a new SSAF Consumption with Rule Engine Data Connect Pipeline for the SSAF Rules evaluation process to use the GET-student-services-amenities endpoint, which allows the optional filter parameters such as studentid, termcode, program, partofterm, and ratecode. The acyrCode (academic year) and apiKey fields are required for executing the pipeline.

Upon retrieving all student records, the relevant student fields, including the insmCode (Instructional Method), EFTSL, termType, and program fields are sent to the POST-rule-engine-evaluation endpoint to determine the rule engine charge.

The pipeline, then calculates caps by comparing the sum of all TBRACCD termCode amounts with the difference between the TBRACCD value and the Rule Engine value against the Annual Charge. Validated records are subsequently posted to the TBRACCD table using the POST-student-payments endpoint.

This enhancement satisfies PE0005227.
