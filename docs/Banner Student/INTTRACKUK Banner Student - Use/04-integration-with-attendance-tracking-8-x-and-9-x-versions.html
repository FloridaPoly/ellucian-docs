Integration with Attendance Tracking 8.x and 9.x versions

Banner INTTRACKUK 8.x is version integrated with Banner Attendance Tracking 8.x version to allow institutions to monitor missed attendance of international students and display the missed contact counts to be reported to UKVI in the SKAICAS page.

Banner Attendance Tracking 8x version allows you to track the attendance of students for Courses or Events. Refer to the Banner Attendance Tracking use content for more information on how to setup tracking of students by CRN or Event.

After you have setup and started tracking international students who have a CAS application record in SKAICAS page. You can use the “Create missed contacts snapshot” procedure to snapshot ten or more unauthorized missed contacts for the student between the Program (or Visa) Start Date and Expected End Date defined for all CAS applications of the student.

The query selects students with an entry in the CAS Application Table (SKRICAS) where the CAS status is = USED who also have entries in the attendance tracking table (SKRATTR) between their program start and end dates for the following tasks.

Events linked to a missed contact event type (specified in GKAKSYS in the MISCON_EVENTTYPE parameter)

OR

Meetings linked to a missed contact CRN meeting type (specified in GKAKSYS in the MISCON_CRNMEETTYPE parameter) where a certain number of contact events or CRN meetings as specified in the GKAKSYS MISCON_EVENTNUM or MISCON_CRNMEETNUM system parameters have been missed, respectively.

To allow users to be able to use Banner Attendance Tracking 9.x and benefit from its new functionality, as of version 8.3.1 INTTRACK UK is integrated with ATTR 9.x version.

Note: Banner Attendance Tracking 9.x does not support tracking by Event anymore, as the functionality is already delivered as part of Banner Event Management 9.x version. However, INTTRACK UK 8.3.1 does not deliver integration with Event Management 9.x version.
If you are using Attendance Tracking 9.x to track attendance of international students, you can use the 9.x specific activity to retrieve attendance counts based on the following criteria:
  • Student attendance is tracked by CRN
  • The Meeting Type parameter in GKAKSYS is optional, when set, only CRNs for which correct meeting type is defined will be tracked
  • Student must have a CAS record in INTTRACK with status USED
  • Student's attendance is monitored between the Program/Visa Start date and Expected Program End Date recorded against their CAS record
If the NOTIFYABS parameter in GTVSDAX is set to not count authorized non-attendance as missed contact, those missed classes will not be included in the missed contact count for the student.

As the tracking attendance with Attendance Tracking 8.x and 9.x is supported in parallel, counts from Attendance Tracking 8.x and Attendance Tracking 9.x are displayed in separate columns in the Missed Contacts Snapshot (SKRMCON) table. However, the Total Number From Latest Snapshot field in SKAICAS adds up the counts from 8.x and 9.x for the user to see the cumulative count for a student.

For Attendance Tracking 9 integration, the Meeting Type parameter (MISCON_CRNMEETTYPE) in GKAKSYS has been made optional, when set, only CRNs for which correct meeting type is defined will be tracked.

Therefore, for migration to Attendance Tracking 9 or parallel use of Attendance Tracking 8 and 9, the following scenarios must be considered:
  • If you migrate from Attendance Tracking8 and want to use Attendance Tracking 9 only, you can either set or not set the MISCON_CRNMEETTYPE meeting parameter in GKAKSYS. Your existing ATTR 8 counts will be preserved as ATTR 9 activity inserts counts into a separate column in the snapshot table
  • If you use or migrate to Attendance Tracking 9 and do not set the MISCON_CRNMEETTYPE parameter, but decide to set it at later point; previous counts from ATTR9 will not show in snapshot table and SKAICAS anymore after you have run the activity again unless the CRNs previously tracked have the correct meeting type defined, because the activity re- queries all student records and updates counts in snapshot table each time the activity is run
  • To use Attendance Tracking 8 and 9 in parallel, you must set the MISCON_CRNMEETTYPE parameter, as it is a mandatory item in the Attendance Tracking 8 specific activity
