Error tables

This section describes the following tables.

OCAS Error Base (SVBOERR) table

This table stores the pool of error number descriptions that could be generated when editing the OCAS fields. This table is populated with a seed data script.

Errors can fall in the following categories:
  • Error at the field level
  • Error at the record level
  • Error when checking duplicate person.

OCAS Field Description Base (SVBOFLD) table

This table stores all of the different field descriptions for the OCAS fields. These descriptions can be used for many tasks, such as description of the field when errors exist, and any other situation when a description is required.

This table is populated with a seed data script.

OCAS Raw Data Ignoring Rules (SVROIGR) table

This table stores the rules for ignoring whole raw records. The SVAORME page looks at this table to validate which records can be ignored.

This table is populated with a seed data script and will not be maintained by the user.

OCAS Raw Data Error (SVRORER) table

This table records the error condition of an applicant (a record exists when an applicant gets an error in any OCAS raw data).

OCAS Field Data Error (SVRORFE) table

This table stores a record for every error that occurs at the field level. It contains all the information related to the field error per applicant in an order that can be tracked.

Validation and Rule tables

This section describes the following tables.

OCAS Common Detail (SVROCOM) table

This table stores the OCAS field labels and their valid values as defined in the OCAS documents (College Transmission Specification). This table is populated with a seed data script.

OCAS Program Campus Maintenance (SVROPRC) table

This table stores the term code and its attached OCAS program codes, the date where these programs start (in the OCAS year), the related semesters and the campus where each program is offered.

OCAS Program Schedule Maintenance (SVROPRS) table

This table stores the term, and the attached OCAS program codes, the date where the programs start (in the OCAS year) and the related semesters where the programs are being offered.

OCAS Term Maintenance (SVROTRM) table

This table stores the OCAS year and the Banner terms attached to that year.

OCAS Validation Code Rules (SVROVXW)

This table was added to store OCAS validation code rules for each OCAS validation group.

OCAS Test Code Validation (SVVOTSC) table

This table stores the types of test that can be taken by an applicant. This table is populated with a seed data script.

OCAS BSID Validation (SVVOBSI) table

This table stores the BSID codes (secondary schools in Ontario).

OCAS Campus Validation (SVVOCMP) table

This table stores the OCAS campuses where programs are conducted.

OCAS Common Validation (SVVOCOM) table

This table stores the OCAS field labels for the OCAS fields that do not have their own validation table. This table is populated with a seed data script.

OCAS Document Code Validation (SVVODOC) table

This table stores the types of supporting document. This table is populated with a seed data script.

This table stores all the valid courses for the Ontario High School.

This table stores the International Evaluation Secondary School levels that can be achieved by the applicant at a secondary school. This table is populated with a seed data script.

OCAS Sponsoring Agency Validation (SVVOSPA) table

This table stores the codes that identify the test norming groups. This table is populated with a seed data script.

This table stores the tests and related sub-tests that can be taken by an applicant.

The tests can be OCAS tests, or any other extra test. The table also stores the value for the Banner test code to which the OCAS test is equivalent. This table is populated with a seed data script.

OCAS Validation Groups (SVVOVGR)

This table was added to store OCAS validation group code records. OCAS validation groups are to group OCAS validation codes.

OCAS Eligibility/Scoring Rules tables

This section describes the following tables.

OCAS Boolean Variable Definition (SVROBOV) table

This table stores the rules that define a Boolean variable code. The Boolean variable codes can be used when setting up program eligibility rules.

OCAS Category Rules Definition (SVROCTR) table

This table stores the rules that define a category code. These rules are used to determine in which category an applicant falls. The category is one of the fields in which the program eligibility and scoring rules are based.

OCAS Eligibility Area Definition (SVROEAD) table

This table stores the rules that define an eligibility area code. The area codes are used when setting up program eligibility rules.

OCAS Eligibility Area Miscellaneous (SVROEAM) table

This table stores the eligibility area descriptions associated with each term.

OCAS Program Eligibility General Requirement Attachment (SVROEGA) table

This stores the general requirement codes attached to a particular program to be used when calculating program eligibility.

OCAS Eligibility/Scoring Equivalency Group (SVROEGP) table

This table stores a group code and its equivalency group codes.

OCAS Eligibility General Requirement Definition (SVROEGR) table

This table stores the rules that define a general requirement code. The general requirement codes are used when defining the program eligibility rules.

OCAS Program Eligibility Formula Definition (SVROELF) table

This table stores the formula used when calculating the program eligibility for an applicant. The formula is composed of one or more area codes that are attached to the corresponding OCAS program for which the eligibility will be calculated.

OCAS Eligibility/Scoring Group Definition (SVROESG) table

This table stores the rules that define a group code. The group codes are used when setting up areas in program eligibility and scoring rules.

OCAS Institutional Testing Requirement (SVROITS) table

This table stores the institutional testing requirements for a particular program to be used when calculating program eligibility.

OCAS Numeric Variable Definition (SVRONUV) table

This table stores the rules that define a numeric variable code. The numeric variable codes can be used when setting up program scoring rules.

OCAS Scoring Area Definition (SVROSAD) table

This table stores the rules that define a scoring area code. The area codes are used when setting up program scoring rules.

OCAS Program Scoring Formula Definition (SVROSCF) table

This table stores the formula that will be used when calculating the program scoring for an applicant. The formula is composed of one or more area codes that are attached to the corresponding OCAS program for which the score will be calculated.

This table stores the OCAS Boolean variable codes.

OCAS General Requirement Validation (SVVOGRE) table

This table stores the OCAS general requirement codes.

Eligibility/Scoring Output tables

This section describes the eligibility/scoring output tables.

The following tables were previously used for eligibility/scoring output but are now obsolete (although they have not been removed from the database):
  • OCAS Alternate Program Summary Output (SVROAES) table
  • OCAS Alternate Program Total Score (SVROALS) table

OCAS Alternate Program Header (SVROALH) table

This table stores the following information.

  • Connection between the regular program and its corresponding alternate program for which the eligibility and scoring was used during OCAS alternate program calculation.
  • The summary of the eligibility checking for an alternate program whether or not an applicant met the eligibility requirements for the alternate program. This is after results were calculated for general requirements, institutional testing and formula.
  • The total score per applicant for an alternate program obtained when adding the scores per area.

OCAS Program Eligibility General Requirement Output Summary (SVROEGM) table

This table stores the summary of the eligibility checking when evaluating general requirements.

The table stores whether an applicant did or did not meet the whole set of general requirements (summary of the general requirement codes). The table stores one record per applicant, program, year, category, term, start date, semester and stage.

OCAS Program Eligibility General Requirement Output (SVROEGO) table

This table stores the results of the eligibility checking for the general requirements. The records are stored per applicant, program, year, category, term, start date, semester, general requirement code and stage.

OCAS Program Eligibility Output Summary (SVROELI) table

This table stores the following information.

  • Summary of the eligibility checking after evaluating all requirements, which means after results were calculated for general requirements, institutional testing and formula.
  • Whether an applicant met or did not meet the whole set of eligibility requirements.
  • One record per applicant, program, year, category, term, start date, semester and stage.

OCAS Program Eligibility Formula Output Summary (SVROELM) table

This table stores the summary of the eligibility checking when evaluating the formula. The table stores whether an applicant did or did not meet the whole formula (summary of the areas). The table stores one record per applicant, program, year, category, term, start date, semester and stage

OCAS Program Eligibility Formula Output (SVROELO) table

This table stores the results of the eligibility checking per area. The records are stored per applicant, program, year, category, term, start date, semester, eligibility area code and stage.

OCAS Detail Course/Test Not Used by Program Eligibility (SVROENU) table

This table stores the details of the course/test that is checked but not used by the program after running the eligibility process. The records are stored per applicant, program, year, category, term, start date, semester, eligibility area code, group code and stage.

A checked course/test is when the item belongs to a group. Courses/tests that were not defined in the eligibility rules as part of a group will not be found in this table.

OCAS Detail Course/Test Used by Program Eligibility (SVROEUS) table

This table stores the details of the course/test used by the program after running the eligibility process. The records are stored per applicant, program, year, category, term, start date, semester, eligibility area code, group code and stage.

OCAS Eligibility/Scoring Group Code Temporary (SVROGTM) table

This table stores temporary values for OCAS groups that are needed to select the student courses in eligibility, scoring and alternate processing.

OCAS Institutional Testing Requirement Output Summary (SVROITM) table

This table stores the summary of the eligibility checking when evaluating institutional testing requirements.

The table stores whether an applicant did or did not meet the whole set of institutional testing requirements (summary of the tests). The table stores one record per applicant, program, year, category, term, start date, semester and stage.

OCAS Institutional Testing Requirement Output (SVROITO) table

This table stores the results of the institutional testing requirements for a particular program after program eligibility has been calculated.

OCAS Program Total Score (SVROPTS) table

This table stores the total score per applicant obtained when summing the scores per area. The records are stored per applicant, program, year, category, term, start date, semester and stage.

OCAS Program Scoring Formula Output (SVROSCO) table

This table stores the results of the scoring calculation per area. The records are stored per applicant, program, year, category, term, start date, semester, scoring area code and stage.

OCAS Detail Course/Test Not Used by Program Scoring (SVROSNU) table

This table stores the details of the course/test that is checked but not used by the program after running the scoring process. The records are stored per applicant, program, year, category, term, start date, semester, scoring area code, group code and stage.

A checked course/test is when the item belongs to a group. Courses/tests that were not defined in the scoring rules as part of a group will not be found in this table.

OCAS Detail Course/Test Used by Program Scoring (SVROSUS) table

This table stores the details of the course/test used by the program after running the scoring process. The records are stored per applicant, program, year, category, term, start date, semester, scoring area code, group code and stage.

OCAS Transaction Processing tables

This section describes the OCAS transaction processing tables.

OCAS Applicant Alert (SVROAAL) table

This table records the detail of alerts per applicant when processing an OCAS applicant through all of the phases. Some alert codes will be added by the system when processing the application; however the user will be able to add codes per applicant as needed.

OCAS Alert Code Rule (SVROALC) table

This table stores the alert codes and the groups to which they are attached. This table is populated with a seed data script.

OCAS Transaction Processing Popsel (SVROCAT) table

This table records the Popsel of the applicants that are processed by the SVPOCAT process.

Various processes use this table to read the population that will be processed and to write back the status of the processing (Y-processed, NULL-not processed yet). Every process will update the corresponding indicator to Y when the process is finished successfully for the applicant.

Some of the processes that use this table are: SVPOTBC, SVPOACC, SVPOELI, SVPOSCR and SVPOADM. These processes use this table when run with the Use SVPOCAT popsel parameter set to Y.

OCAS Transaction Processing Exception Reporting Detail (SVROCER) table

This table records the exception reporting conditions of an applicant when processing the OCAS transaction records.

OCAS Transaction Letter Control (SVROTLC) table

This table stores the transaction codes that have a letter attached, which are detected when processing transactions.

This table is filled by query, using a seed data script. The table must be maintained by the user because the letter code is specific to each institution.

OCAS Transfer Transcript Report Temporary (SVROTRN) table

This table is used internally by the OCAS Transfer Transcription (SVPOTRN) process for reporting purpose. The data in the SVROTRN table will be deleted or inserted by a SVPOTRN job.

OCAS Alert Group Validation (SVVOALG) table

This table stores the alert group codes. This table is populated with a seed data script.

OCAS Transaction Processing Exception Reporting Validation (SVVOCER) table

This table stores the exception reporting codes, which can be generated when processing Process transaction records. This table is populated with a seed data script.

Control tables

This section describes the Control tables.

OCAS Control (SVROCTL) table

This table stores the fields that control the way to process the OCAS data. Only one record is stored in this table. All of the fields stored in the one record define the institution’s way of processing OCAS data.

OCAS Student Attribute Crosswalk (SVROSAX) table

This table stores the OCAS student attribute crosswalk data.

OCAS Term Control (SVROTCT) table

This table stores some critical fields to control the OCAS data processing per term such as the following.

  • OCAS year for which the OCAS control values are being used
  • Term code for which the OCAS control values are being used
  • Equal consideration date (month and day)
  • Replicate rule indicator to indicate whether the rules replication (SVPORPL) process has been run or not. Values can be Y-Process has been run till the last level of replication, N-Process has not been run till the last level of replication.

Miscellaneous tables

This section describes the following miscellaneous tables.

Release Tracking Solution Centre (GVRVERS) table

This table tracks the release numbers of a Canadian localization. This table is used for all Canadian localizations.

OCAS Alternative Programs (SVROALP) table

This table stores the alternative program(s) attached to an OCAS program. A record exists for every alternate program that an OCAS program has.

OCAS Course Crosswalk (SVROCXW) table

This table stores the crosswalk values between the Ontario High School courses and the Banner courses.

OCAS Extra Course Data (SVROECD) table

This table stores other courses taken by the applicant at the institution or externally but are not included in the OCAS file.

OCAS Extra Test Data (SVROETD) table

This table stores other tests written by the applicant in the institution or externally but not included in the OCAS file.

OCAS Program Exclusion (SVROPEX) table

This table is used for entering the programs (by term) that will be excluded from being used in a particular process.

For example, programs that need to be excluded from being reported in the OCAS ENROLLMENT FILE that is sent back to OCAS. These programs can be articulated programs, collaborative programs, etc. However, this table can also be used for excluding any program from being considered in a specific task.

Note: This table is not currently used, but will be used in the future.

OCAS Report Temporary (SVRORPT) table

This table temporarily stores some records that are reported in a special order at the end of certain processes. There is no Primary Key in this table. The table may contain as many records as required per applicant.

OCAS Student Attribute Crosswalk (SVROSAX) table

This table stores the student attributes attached to every semester where OCAS programs are offered. These attributes will be inserted in the Banner Admission tables when an acceptance of the applicant is processed (when a CC-Y is received).

Replication tables

This section describes the Replication tables.

OCAS Term Start Date Replication Rule (SVRODRR) table

This table stores the start dates when a term starts for a given Replication year, and the subsequent start date and term for the next year.

This data is used when replicating rules per year and term. The subsequent start date for a given start date of a term must be known, otherwise it is not possible to generate term rules for a new year where the start date is part of the key.

All start dates cannot be assumed to be the same (e.g., date could fall in a weekend), so adding “a year” cannot be used as a generic rule for deducting the equivalent start date for the next year.

OCAS Term Replication Rule (SVROTRR) table

This table stores the terms for a given OCAS year and their subsequent term for the next year.

This data is used when replicating rules per year. The subsequent term for a given term must be known, otherwise term rules cannot be generated for a new year.

OCAS Option Zero Term Start Date Replication Rule (SVROZRR) table

This table is used to store the start dates for when the OCAS Rules Replication (SVPORPL) process is run with the Replication Option parameter set to 0.

This table is identical to the SVRODRR table, the difference is that the SVRODRR table is used when the OCAS Rules Replication (SVPORPL) process is run with the Replication Option parameter set to 2.

OCAS Rank/Offer/Acceptance tables

This section describes the OCAS Rank/Offer/Acceptance tables.

OCAS Error Detail for Offer Data File (SVROEDO) table

This table is used to store the data contained in the Error (EC) records of the error file that is sent by OCAS to the colleges.

The error file relates to an offer file that was submitted by the college to OCAS. Every error file contains zero or more EC records.

OCAS Error Header for Offer Data File (SVROEHO) table

This is used to store the data contained in the Batch Header (BC) record of the error file that is sent by OCAS to the colleges and contains the offer errors.

Those offers were transmitted before by the colleges to OCAS in an OC file. Every error file contains one BC record only, which is loaded into the SVROEHO table.

OCAS Offer Data Files Tracking (SVROFIT) table

This table is used to track the Online Confirmation (OC) files produced by the OCAS Offer Data File Generation (SVPOOCF) process. OC files are offer files that contain OC records.

A record will be inserted into this table by the SVPOOCF process every time that the process generates a new OC file.

OCAS Offer (SVROOFR) table

This table stores and manages the applicant offers.

OCAS Offer Tracking (SVROOFT) table

This table is used to track all transactions that affect offer data. A new table is required for tracking all transactions that affect the offer data.

The SVPOCAT, SVPORNK, SVPODMU, SVPOSIP, SVAOCAS and SVAOQOP objects will insert and update a record in this table when offer records are affected.

A new OC record will be inserted into this table when changes occur for the following fields:
  • SVROOFT_OFFER_ACTIVE_DATE (from the SVAOQOP page, and SVPODMU and SVPORNK processes)
  • SVROOFT_OFFER_EXP_HARD_DATE (from the SVAOQOP page, and SVPODMU and SVPORNK processes)
  • SVROOFT_OFFER_EXP_SOFT_DATE (from the SVAOQOP page, and SVPODMU and SVPORNK processes)
  • SVROOFT_OFFER_STATE (from the SVAOCAS and SVAOQOP pages, and SVPOCAT, SVPORNK, SVPODMU, and SVPOSIP processes)
  • SVROOFT_LATE_ADMIT (from the SVAOCAS page).

OCAS Offer Group Rule (SVROOGR) table

This table stores the rules that define the offer group codes.

OCAS Program Offer Rule (SVROPOF) table

This table stores the rules that manage an offer queue.

OCAS Program Offer Groups (SVROPOR) table

This table stores the maximum number of seats per offer group for a program.

OCAS Ranking Temporary (SVRORAT) table

This table stores the temporary data generated by the SVPORNK process when sorting the population for getting the ranks. The results of this table are removed at the end of the SVPORNK process.

OCAS Ranking (SVRORNK) table

This table stores the results of the ranking process and the relevant data used to generate the ranking. This table will be populated or cleaned as many times as the SVPORNK process is run.

This table has an important field (SVRORNK_QUEUE_STATUS) that shows if the queue values are real or virtual. When the status is real, the ranking results have been passed to the final queue tables (SVROOFR, SVROWLQ) and the queue fields in the SVROCCC table have been updated. When the status is virtual, the queue table are not affected because the ranking process was run as a trial.

When data has been inserted into the queue tables (SVROOFR, SVROWLQ), and the queue fields in the SVROCCC table have been updated, the data stays the same regardless of whether or not the SVPORNK process was run with the Trial Run parameter set to Y.

OCAS Offer Status VS Offer State Rule (SVROSVS) table

This table is used to map the offer status to the offer states required in an offer file. Seed data was delivered for the SVROSVS table.

OCAS Waitlist Queue (SVROWLQ) table

This table stores and manages the applicant waitlists.

The data inserted into this table is from the following sources:
  • SVPORNK process when run with the Trial Run parameter set to N
  • SVPOCAT process
  • Manual entry through the OCAS Queue Operation (SVAOQOP) page.

OCAS Course Property 1 Validation Table (SVVOCP1)

This table is used to store the valid values for Course Property 1, which will be like an attribute attached to a course.

The property is attached to a course regardless of the applicant to which the course is related. Course Property 1 can be used for representing any concept. It can be completely different between institutions.

For example, course MAT4AC can have DMAT as Property 1, which means the course MAT4AC is offered by the Department of Mathematics. Other courses may have MAT (Math subject), which means that the subject of the course is MAT.
