Statistics Canada PSIS Institution Program Data Capture (SVAIPTB) page

Use this page to enter additional program related data required by PSIS. The page includes the PSIS Program Data, Entry Data, OJT Data, Provincial Data, and Multiple Institution Data blocks, which are used to capture data.

Statistics Canada requires that one record be created for each program offered by the institution during the reporting cycle.

Note: The Program Definitions Rules (SMAPRLE) page in the CAPP module of Baseline Banner Student must be set up before beginning the process of gathering program information. A combination of the degree and major are approved by Statistics Canada to determine the program ID.

PSIS reporting requires the total number of credits needed to graduate from a program. The SMAPROG page contains a field for this purpose. However, a field is also included with the PSIS project because entering the total credits on the SMAPROG results in the value being used to calculate eligibility to graduate. For those institutions using this method, the PSIS field (SVRIPTB_PROG_CRED) is available to accept data directly through the page or with a SQL script (not provided).

Attach all program IDs to individual student SGASTDN records.

A program is required on the SMAPRLE page so that a program ID can be attached to a student’s SGASTDN record. After the Program fields on the SMAPRLE page have been populated, the program must be attached to the student's record in the SGASTDN page for the reporting cycle.

Note: After the SMAPRLE and SGASTDN records are set up with program IDs, it is not possible to change the program IDs or SMAPRLE records without changing the SGASTDN records. Careful thought must be given regarding the concatenation of major and degree.

Institution Program and More Tabs

The Institution Program (IP) file is an inventory of the programs offered by your institution. Provide one IP record for each of your programs.

There is a logical link between the IP file and the Student Program (SP) file. The SP file contains a record for each combination of student and program. Each program code reported on SP must be present on IP.

If you have students taking non-credit courses or taking credit courses without seeking a formal credential, create a non-program record on the IP file containing a name in element IP2000 such as NONPRGM, to which these students can be assigned on the SP file. One non-program record should suffice for all students taking non-credit courses or taking credit courses without seeking a formal credential.

Institutions that store their program data with separate fields for degree and major(s) may be able to report just the degree code in element 2000 and the student's major(s) in elements 5015-5017 on the SP file. For example, if all BA programs have the same duration, credit requirement, provincial funding code, entrance requirements, OJT components etc, then you could report only one IP record for all BAs, with element 2000 equaling BA, and then show the different majors on the SP records of individual students. But, if some of the BA programs have different durations or credit requirements, then you must provide separate IP records for them. In these cases, you could combine the degree code and the major(s) in element 2000 of the IP and SP records.

Some programs award two credentials. Report one IP record, not two, in these cases. The joint credential is reported in elements 2011 and 2016.

For apprenticeship programs, provide one IP record for each year or level of the program.

For the Final (full-year) report, describe all the programs offered during the twelve months beginning on your start date. For the Preliminary (fall) report, you can report all the programs for the twelve months if the information is available at the time of the Preliminary report; if not, report the programs from your start date to the end of your fall term.

The SMRPRLE and SVRIPTB tables are the driving tables used to select the program records for the reporting cycle. If multiple institutions share a common database, then the institution code is used in selecting the appropriate records for populating the SVRESIP table.

The input parameters are supplied by job submission. Process every record in the SMRPRLE table.
