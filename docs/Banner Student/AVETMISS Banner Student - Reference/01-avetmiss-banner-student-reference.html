Identity Verification Document Details (GKAVDOC) page

Use the GKAVDOC page to enter or display details about a person's identity verification documents.

Identity verification document details are needed to get a successful response from CreateUSI or BulkUploadRetrieve requests but can be deleted when a Unique Student Identifier (USI) is successfully retrieved from the USI Registry.

Clients will be able to control whether identity verification document information is purged when a CreateUSI or BulkUploadRetrieveA response is received where the Result is either Success or MatchFound, using the GKRVDOC-PURGE system parameter on the Report System Parameters (SKARSYS) page.

The GKRVDOC-PURGE will only operate correctly if it has a single value. The valid values are:
  • A = If the value is 'A' then ALL records will be purged from GKRVDOC for the PIDM when a Success or MatchFound Result is returned in a CreateUSI response or a BulkUploadRetrieve response. This means that even if the person has more than one record on GKRVDOC, then even the records that we not used by the CreateUSI request or the BulkUpload request will also be purged.
  • P = If the value is 'P' then only the Primary record will be purged from GKRVDOC for the PIDM when a Success or MatchFound Result is returned in a CreateUSI response or a BulkUploadRetrieve response.
  • N = If the value if 'N' then no records will be purged from GKRVDOC
If the value is anything else - then no records will be purged from GKRVDOC

If the Result in the CreateUSI response or BulkUploadRetrieve response is Failure, then no records will be purged from GKRVDOC for the relevant person regardless of the value of the GKRVDOC-PURGE system parameter.

Reporting Locations Mapping (SKARLOC) page

Use the SKARLOC page to map delivery locations to campuses using a variety of factors to vary the delivery location depending on the student’s instructional and locational circumstances.

This page offers a more flexible delivery location mapping and allows you to nominate delivery locations based on combinations of the other elements, such as, delivery location, campus, and instructional method. This will allow you to register students under a “home” campus for institutional reporting or funding allocation purposes, but report those students (depending on their physical location or delivery method) under a different delivery location identifier for AVETMISS purposes.

Key block

Use this section to specify the organisation ID, term code, and reporting collection code for which you want to nominate delivery locations.

Different sets of rules can be set up for different sub-organisations (using a different organisation ID) or reporting collection even using campuses or delivery locations belonging to other rule sets, if desired.

Field Description
ID Organisation ID.
Name (untitled) Name associated with the organisation ID.
Term Term code.
Report Collection Report collection code.

Base section

Use this section to map the details specified in the Key block.

Field Description
From Term Term from which the delivery location mapping data is valid.

If you are defining data for the first time, the value in this field defaults to the term entered in the Key block.

If you are defining data for a later term than has already been defined, the value in this field defaults to the most recent term before the Key block term and for which data has been defined. You can change the code using the Maintenance button.

If you are defining data for an earlier term than has already been defined, the value in this field defaults to the term entered in the Key block.
Maintenance Click this button to either copy all delivery location mapping data for the selected ID and term to a new term or to end the organisation information record at the term in the Key block.

If a record exists for a prior term, then the Maintenance button will be enabled. If you click the Maintenance button an options window will open, displaying two options. If you click End Term, the To Term field will be updated with the value from the Key block term. If you click Copy Term, the From Term field will be updated with the value from the Key block term, and this new record will be saved.
To Term Last term until which the delivery location mapping data is in effect.

If you are defining data for the first time, the value in this field defaults to the maximum term code in STVTERM (typically term code 999999 (the end of time)).

If you are defining data for an earlier term than has already been defined, the value in this field defaults to the most recent term for which data has been defined and is after the term entered in the Key block. If you are defining data for a later term than has already been defined, the value in this field defaults to the maximum term code in STVTERM.
Delivery Location Delivery location code for reporting purposes.
Campus Student campus code. (For reporting purposes, typically the campus of a registration, although SKARLOC in itself does not refer to any registration data).
Instructional Method Instructional method code.
Student Location Student location code.

This code is not a baseline code, but a code internal to SKARLOC used to distinguish interstate or off-shore students.
Active Check box used to specify whether this record is active.

Additional Study Path Data (SKASTSP) page

Use the SKASTSP page to enter data for a student, effective term and study path that cannot be entered in any existing Banner fields.

With this page, you can:
  • Enter a funding eligibility key for a student and study path, in an effective term.
  • Enter an associated course ID for a student and study path, in an effective term for a student who has transitioned from superseded program to a replacement program.
  • View a calculated value for the program unique supervised hours for a student and study path, in an effective term.
  • Enter an override value for program unique supervised hours for a student and study path, in an effective term.
  • View a calculated value for program supervised teaching activity completion date for a student and study path, in an effective term.
  • Enter an override value for program supervised teaching activity completion date for a student and study path, in an effective term.

Key block

Use this section to specify the ID, effective term and study path for which you want to enter or display additional study path data.

Field Description
ID ID of the student.
Untitled Name associated with the ID of the student.
Term Effective term for the additional study path data record.
Study Path Study path for the student and effective term.

Study Path window

Use the Study Path window to enter the student study path details.

Additional Study Path Data section

Use the Additional Study Path Data section to enter or display additional study path data for the ID, effective term. and study path in the Key block.

Field Description
From Term Term from which the term is effective.

If there is an existing record for the student and study path and the user enters a term in the key that is later than the effective term of the existing record, then this field will be enabled and the cursor will navigate to this field. Users will either need to copy the record to the new effective term or rollback and change the term in the key.

If there is an existing record for the student and study path and the user enters a term in the key that is earlier than the effective term of the existing record, then this field will be disabled and will be populated with the value from the Term field in the key. The user will be able to create a new record that will be effective from the key Term up to the previously existing record.

If there is no existing record for the student and study path, this field will be disabled and will be populated with the value from the Term field in the key. The user will be able to create a new record that will be effective from the key Term until the end of time.
To Term Last term until which the term is effective.

If there is an existing record for the student and study path and the user enters a term in the key that is later than the effective term of the existing record, then the value displayed in the To Term field will be '999999'.

If there is an existing record for the student and study path and the user enters a term in the key that is earlier than the effective term of the existing record, then the value displayed in the To Term field will be the effective term of the existing record.

If there is no existing record for the student and study path, then the value displayed in the To Term field will be '999999'.

Users will not be able to navigate to this field.
Maintenance (button) Click this button to either copy all the study path data for the selected ID and term to a new term or to end the study path record at the term in the Key block.

If there is an existing record for the student and study path and the user enters a term in the key that is later than the effective term of the existing record, then the Maintenance button will be enabled. Users will either need to copy the record to the new effective term or rollback and change the term in the key.

If there is an existing record for the student and study path and the user enters a term in the key that is earlier than the effective term of the existing record, then the Maintenance button will be disabled. The user will be able to create a new record that will be effective from the key term up to the previously existing record.

If there is no existing record for the student and study path, then the Maintenance button will be disabled. The user will be able to create a new record that will be effective from the key term until the end of time.

The unique supervised hours value must be five characters in length.
