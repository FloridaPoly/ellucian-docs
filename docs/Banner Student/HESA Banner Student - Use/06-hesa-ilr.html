HESA ILR

This document discusses the Individualised Learner Record (ILR) feature that is available for Banner HESA.

Note: This 9x version corresponds to the Banner HESA 8.22 release version.

As of 2019, HESA has decided to stop the service it was offering to Higher Education Institutions (HEI) which involved generating the ILR files from information supplied to them in the Student returns.

The ESC_ILR process tree is used for reporting of Apprenticeship Standards students to the Education and Skills Funding Agency (ESFA). Institutions are expected to create a cohort on the HESA Cohort page (SKAHCOH) and then assign the students that need to be reported to the regulatory body.

Institutions can execute the ESC_ILR process tree using the Execution Tree Execution (GKAPEXE) page.

The snapshot, extract, and export activities are delivered under ESC_ILR process tree. Like in the past, institutions can customize these activities to meet their own business needs.

Note: It is important that institutions with any customized MDUU activities listed already under the ESC_ILR process, must take a backup of the activities before running the ESC_ILR.sql script. When the script is run successfully, the activities can be copied back under the same process.

Record dummy Banner Program/HESA course

HESA have advised that a programme ‘wrapper’ course is included in the HESA Student return, with COURSEAIM as Z99. They have also advised that the following details to be included.

  • Course title (CTITLE)
  • Course identifier (COURSEID)
  • Reduced course return indicator (REDUCEDC)
  • Course Subject

This will require the creation of Banner Program records in SMAPRLE, SKASPRI and SKAPMYR pages, so that a dummy HESA course can be included in the HESA return. HESA have confirmed that they expect to see this course in the ILR Generation Student return.

The dummy HESA course must also have a Mode of Study 98 – Mode not applicable and available in the Program Modes tab of the SKASPRI page.

Programme Wrapper Instance creation

This section discusses the creation of the programme wrapper instances.

Component/Learning Aim Instance

Banner HESA currently creates an instance automatically when a general learner record is created in baseline Banner. This instance can be used as the Component Learning Aim instance in the Student return.

The Aim Type for this instance should be set to three. If the student is gaining additional qualifications as part of the Apprenticeship Standard, then the information must be recorded as additional instances in Banner HESA, each with the relevant LARS code provided in Engagement.ENGAIM. These codes will normally be created when the second curriculum is created on the General Learner Record for the additional qualification.

LearningDeliveryFAM and Engagement entities are required for the Component Learning Aim Instance.

Programme Wrapper Instance

HESA have advised that a programme ‘wrapper’ Instance is also required in the Student return for Apprenticeship Standards students requiring an ILR generation. This will need to be created manually in the SKAHINS page using the New Instance button. The programme ‘wrapper’ Instance can be linked to the same curriculum record as the existing Component Learning Aim instance.

The programme‘wrapper’ Instance will also need to have the following fields:
  • Aim Type (Instance.AIMTYPE)= 1
  • FEStudent Marker (Instance.FESTUMK) = 5
  • Mode ofStudy (Instance.MODE) = 98
LearningDeliveryFAM,Engagament and ApprenticeStandardFinances entities are required for the programme‘wrapper’ instance. These can be recorded in the SKAHIEN page. The Engagement must have the Engagement Aim field set to ZPROG001.

Ensure that you add the relevant learner information in the SKASPIN page.
