Structured Progression

Banner Student 9.3.29 and 8.26 introduces Ellucian Structured Progression, which is a solution to calculate the grades of students using calculations and rules in Banner Student. The solution allows for step-by-step progression recommendations and course award classification recommendation to be calculated.

In Banner Student, the rules include logic about compensation, student contribution, allowable deferred credit, and so on. This logic, when employed in the calculation process, assists in determining whether a student is eligible to progress or receive an award. The rules also provide the flexibility to specify weightings applicable to each academic level, and the discounted credit (allowed), when calculating the result for a student.

Structured Progression Rules and Calculators

Use the Structured Progression Mapping (SHASPAW) page to map the compensated grades, define condoned grades, the deferred grades, and establish the rules for the Course Eligibility Mapping and Compensated Rules Mapping.

Grade Mapping

You can use the Compensated grades and Deferred grades tabs in the Grade Mapping rules section to map the Compensated Grade and Deferred Grade. Use the Grade Mapping rules section to map the Compensated Grades and define a list of grades, that are, Compensated grades and Deferred Grades.

Compensated Grade Rules

You can specify the number of credits that can be compensated at each level, so that the award rules can make sure that only the right amount of compensated credits and marks are included in both the stage and overall program GPA calculations. You can use these later with both the progression and award classification calculations when the SHPPGAW job process is run. For example, if you consider the grades 35-39 to be eligible for compensation, you can offer a compensated grade 35C - 39C for each individual grade from 35-39.

Note: It is not possible to generate more than one compensated grade for the same level and term combination.

In addition, you can specify a change reason code based on each used grade when running the SHPPGAW job process. Auto compensation is verified, and if the student falls within the specified range, the quality points are awarded.

Condoned Grade Rules

You can specify which grade codes to consider as condoned grades for your institution. Condoned grades are manually assigned to the students during grades review. Therefore, the student’s GPA is calculated considering the Condoned grades and their quality points.

Deferred Grade Rules

You can specify which grade codes to consider as deferred grades for your institution. Deferred grades are manually assigned to the students. Therefore, the student’s GPA is calculated considering the Deferred grades and their quality points.

Course Eligibility Mapping

Use the Course Eligibility Mapping tab to identify courses that are not eligible to be compensated or condoned. You can also tag courses as mandatory courses that you need the student to take, which you can use to calculate the student’s Overall GPA. For a specific term, program, or area, define the Subject and Course, and clear the Course Compensated, or Course Condoned or both check boxes, or select the Required for Overall GPA check box.

Compensated Rules Mapping

Use the Compensated Rules Mapping to determine the number of credits that can be used to compensate in a stage. The page contains many attributes, and when evaluating the auto-compensation logic on SHPPGAW process, the field precedence is checked as defined on the SOAXREF page for the Label = FIELDPRE, and a suitable rule is picked to assign the compensated grade to students.

Optionally, you can also provide the values for Minimum Stage GPA and Minimum Earned Hours for a stage. For example, if the Allowed Compensated Credits is 25, and the Minimum Stage GPA is 40, the student must achieve a Minimum Stage GPA of 40 to be compensated.

If a student does not meet the Minimum Stage GPA either/or Minimum Earned Hours. then the compensated grades will not be evaluated, and assigned to the student. You can define the hierarchy of the attributes in the SOAXREF page, where the Label = FIELDPRE. You can define the priority of the attributes in the Banner Value column.

Structured Progression Rules

Use the Structured Progression and Awards Rules (SHASPAR) page to define rules for the stage progression, the overall GPA calculation and the award classification for a student. SHASPAR rules reflect on the Structured Progression Process (SHPPGAW).

There are rules criteria that allow you to define a set of rules for a particular level and term. You can create rules for a specific effective term, degree, or a program, and a rule number is automatically associated to the rules. After you set the rules in the Rules Criteria, you can define the Progression Rules, the Overall GPA Rules and the Award Classification Rules.

Progression Rules

You can define a progression decision against each rule, with a priority order to loop the students. Depending on the priority order, the application verifies if the student meets the rules criteria. If there is no match for the student in Priority Order 1, then the application checks for Priority Order 2, and, so on, until the student matches the rules criteria. For each stage you can specify an outcome in the Progression Outcome Description column to build the rules for the student, to achieve the outcome.

In the Stage Details you can view the selected priority order in the Progression Rules section. The section displays the high and the low credits to be achieved by the student. Every rule has a range, and as an Admin you can specify the Allow Compensated Grades, the Condoned Grades and the Deferred Grades. You can provide values for the Minimum Stage GPA to display in the SHASPAW page, the credits needed to pass at first attempt, and select the check box for the Mandatory Courses Met.

Select the Mandatory Courses Met check box, for the application to check the Required for Overall GPA column in the Course Eligibility Mapping tab on the SHASPAW page, if you want the courses to be calculated in the GPA. For more information on the Progression Outcome calculations, see Progression Outcome Assessment in the Sitio de documentación de Ellucian.

If the rules in the Rules Criteria do not meet your requirement, you can create a new rule. These rules are associated with the rule numbers. You can define the priority order for the rule, and the best credits to be considered weighed at a percentage value. In the Course Qualification Level Rules, you can select the level to select the courses.

Structured Progression Process (SHPPGAW)

Use the SHPPGAW process to calculate the structured progression and awards for a specific Student ID or a set of Student IDs that are linked to a Committee Code, based on the selected Evaluation Term.

See the Banner Student CAPP content in Banner Student Use in the Sitio de documentación de Ellucian for details on CAPP and compliance process.

The process performs the following functions:

  • Creates, automatically, the, compliance request on the Compliance Request Management (SMARQCM) page, and runs the compliance process.
  • Evaluates the stage GPA, and automatically calculates the compensated grades for the student.
  • Runs the progression process based on Committee Code or Individual Student ID.
  • Evaluates, automatically, the Overall GPA of a student who meets all the requirements of the program, including the General Requirements and the Non-Course Requirements.
  • Evaluates a student's final Award classification based on their Overall GPA.
  • Evaluates the student Trailing Courses for each stage and updates the new trailing courses columns within the Stage Progression Assessment (SHRSPSG) table with the appropriate values on each run. The process performs the following functions.
    • Selects the compliance request number created for the stage.
    • Determines the compliance request number and checks the current stage areas and previous stages areas to obtain the stage required credits and stage earned credits for a student.
    • If the Stage Required Credits are not equal to the Stage Earned Credits, it is an indication that there are trailing courses for a stage.
    • If Stage Required Credits are equal to the Stage Earned Credits, it is an indication that there are no trailing courses for a stage. Accordingly, the newly added trailing columns on the Stage Progression Assessment (SHRSPSG) table will be updated for the current and its previous stages.

Automated Compliance Process

The process creates the compliance request and then runs the compliance process for the students while processing for the progression outcome.

Create a compliance request for a student

When you enter the Evaluation Term on the SHPPGAW process, the same Evaluation Term value is entered in the Compliance Request Management (SMARQCM) page. Similarly, when you enter the Origin Code in the SHPPGAW process, the value of Origin Code is entered in the Origin Code field in the SMARQCM page. These origin codes are defined on the Originator Code Validation (STVORIG) page. The value AUTO is the default for the parameter when running the job process. If the value AUTO is not defined on the STVORIG page, then the job process aborts and an error message appears in the .log file.

The default parameter codes are defined in the Compliance Defaults Option Validation (STVDFLT) page. You must define the rule for the default code in the Compliance Default Parameters (SMADFLT) page. The value BATCH is the default for the parameter when running the job process. If the value of the BATCH is not defined on STVDFLT, or if no rules exists for the value on the SMADFLT page, then the job process aborts and an error message appears in the .log file.

When the compliance request is created from the process, the information from the Program and Major information on SMARQCM page are taken from the active and current curriculum for the student. As there can be multiple Majors, Concentration and Minors linked to a student curriculum record, the compliance request is automatically created from the SHPPGAW job process. The process only considers two Majors, two Minors, four Concentration records attached to a Major and one Independent Concentration record for the student.

  • If the job process is run for Committee Code = C, then all the students linked to the committee code on the Committee Student Population Definition page (SHACSPD) are processed, the compliance requests are created, and the compliance process is run.
  • If the job process is run for Committee Code = S and Student ID is provided, then the compliance requests are created for the student, and the compliance process is run.
  • You can view the result of the compliance process on the Compliance Results Inquiry (SMICRLT) page against the compliance request number created while running the SHPPGAW job process.
  • If there are any errors running compliance request for a student, then an error message appears in the .lis file within the SHPPGAW job process.

Stage GPA Rounding Logic

You can define the rounding logic and the number of decimal places used in the student Stage GPA calculations.

A rounding logic is created within the Structured Progression Process. It evaluates the rules setup within the GPA Display Rules (SHAGPAR) page, and then truncates the Stage GPA for the student before it stores the rules on to the intermediate table.

On running the SHPPGAW job process, the rules setup on the SHAGPAR page are checked and the relevant rules are selected based on the Overall GPA rules, the Level GPA, or Campus GPA rules setup.

The job process checks the Overall Term Selection option buttons in SHAGPAR to specify the term code on which the GPA rules are considered. The three options are:

  • Use student's first term
  • Use student's last term
  • Use most recent display rule

Use student's first term

When you select the Use student's first term option button, the student's first term code is selected and checked against the rules defined in Overall GPA Rules section for less than or equal to the Evaluation term code that was defined while running the SHPPGAW job process.

Example:

If the student has registrations for the 202101 and 202102 terms, the rules setup in the Overall GPA Rules section in SHAGPAR are shown in the following table.

Term GPA Display Rule Display Number Quality Points Display Rule Display Number
202101 Truncate (T) 1 Round (R) 1
202102 Truncate (T) 2 Round (R) 2
202103 Truncate (T) 3 Round (R) 3
  • When the option group Use student's first term is selected, and the student's first term 202101 is selected and compared to check any rules setup for term = 202101.

Level GPA and Overall GPA Assessment

Assessment of Level GPA and Overall GPA.

Note: The Level GPA without any conditions, that is, considering all the courses credits without any Credits or weight (%) logic is not evaluated or stored in the intermediate table.

The Level GPA described on this page is purely based on the Credits and Weight (%) logic, and it is used to derive the Overall GPA for a student.

Pre-Requisites

Level GPA, overall GPA and Award Classification are only considered in the job process if the student fulfills all program requirements, that is, General Requirements, Non-Course Requirements. Level GPA is the pre-requisite to calculate Overall GPA.

Level GPA and Overall GPA Calculation

To calculate the Overall GPA, you must calculate the Level GPA for individual levels (Level 4, Level 5, and so on) based on the Credit and Weightage rules setup on the Overall GPA tab in SHASPAR page. Define the credits to consider from each level on the Overall GPA tab. Consider courses from the CAPP for the student and cover the following functions.

  • Student Adjustments to the program and its courses
  • Student Repeated courses for a program
  • Student transfer courses

The SHPPGAW process considers the course credits for a student from CAPP based on the following order:

  • Check for the precedence, that is, courses taken by a student are marked as Required for Overall GPA on the Course Eligibility Mapping tab in the SHASPAW page. If found, consider the credits for Required for Overall GPA courses based on the students highest grades.
  • Consider the remaining courses credits for a level based on the highest grades till the number of credits match with the Credits to Consider value in Overall GPA Rule > Credit/Weight Rules > Credits to Consider field in the SHASPAR page.

The process calculates the Level GPA for each levels individually after getting the credits, considering the Credits and Quality points for each course within a level or multiple levels. Each of the individual Level GPAs are stored in an intermediate table, or if you consider clubbing multiple level credits, then the modules are considered from both the levels and the GPA is evaluated and stored on the intermediate table.

On getting the GPAs for all the individual levels or clubbed levels for a program, multiply the respective GPA values with its weightage (%) defined in Overall GPA Rule > Credit/Weight Rules > Weight(%) field in the SHASPAR page. Add all the weighted individual level or clubbed levels GPAs to get the Overall GPA for the student.

Note: You can club the Credits and Weights for multiple levels. For example, you can define a rule to take 90 credits from Level 5 and Level 6, and weightage 60% from Level 5 and Level 6. Accordingly, the Level GPA calculation considers the credits and weight.

Automated Compensated Grades

The Structured Progression (SHPPGAW) process includes logic about automated compensation grades. This logic, when employed in the progression outcome calculation, assists in determining a compensated grade (that is, earned credits) for a student course for which a student does not achieve a passing grade.

Prerequisites

  • On the Structured Progression and Awards Mapping (SHASPAW) page, set up compensated grades in the Grades Mapping tab in the Compensated Grade Rules section.
  • On the SHASPAW page, define the compensated credits limit for each stage in the Compensated Rules Mapping tab.
  • On the SHASPAW page, list the courses that are not eligible for compensation in the Course Eligibility Mapping tab with the Course Compensated check box cleared, that is, Course Compensated equal to N.
  • Run the SHPPGAW process for a stage with the Assess Compensated Grades? parameter set to Y.
Job process logic

Running the job process for Automated Compensated grades is based on logic.

  • When you run the SHPPGAW job process for Automated Compensation calculation, all the courses that a student takes for a stage are considered as eligible for compensation, unless you have defined the courses on the SHASPAW page. On the SHASPAW page, you define courses in the Course Eligibility Mapping tab with the Course Compensated check box cleared, that is, Course Compensated equal to N.
  • When you run the SHPPGAW process, the logic should determine the list of courses taken on CAPP by a Student ID or set of Student IDs linked to a Committee Code for a stage number.
  • Based on the matching rules and SOAXREF precedence configurations defined for a Label = FIELDPRE, the job process should select an appropriate rule for compensation.
  • When you have defined the rule, the job process should check if the Minimum Stage GPA either/or Minimum Earned Hours is defined for the rule. If defined, the job process should verify the following criteria:
    • If a student does not meet the Minimum Stage GPA either/or Minimum Earned Hours, then the process does not evaluate and assign compensated grades to the student. An error message appears in the .lis file against the student.
    • If a student meets the Minimum Stage GPA either/or Minimum Earned Hours condition, then the job process should evaluate the compensated grades for a student as defined in the Compensated Grade Condition section.
  • If the Minimum GPA either/or Minimum Earned Credits field values are not defined for a rule, then the job process should evaluate the compensated grades for a student as defined in Evaluate compensated grades by compensated grade conditions.
Evaluate compensated grades by compensated grade conditions

The job process evaluates the compensated grade for a student considering the various conditions that you set up on the SHASPAW page.

Procedure

  1. Check if any course has already been assigned manually with a Compensated Grade but marked as not eligible for compensation.
    On the SHASPAW page and in the Course Eligibility Mapping tab, the Course Compensated check box must be cleared, that is, Course Compensated equal to N. Then, the process will not evaluate the compensation grade for the student and will display an error message in the .lis file against the student.
  2. Check if any course has already been marked with Compensated grades.
    On the SHASPAW page and in the Grades Mapping tab in the Compensated Grade Rules section, check the Compensated Grade field against the student courses taken and its grades for a stage.
  3. The process decides the next steps, based on the results of the previous step:
    • If yes, consider the course credits for which the compensated grade exists, and equate to the credit’s limits set up in the Allowed Compensated Credits field for a stage number in the Compensated Rules Mapping tab on the SHASPAW page.
    • If no, continue performing this procedure.
  4. Check if any course that the student has taken for a stage has been marked as not eligible for compensation.
    On the SHASPAW page and in the Course Eligibility Mapping tab, the Course Compensated check box must be cleared, that is, Course Compensated equal to N. Then the process will not consider the courses for a student for compensation credits or for Compensated Grades assignment.
  5. To determine the courses that are eligible for compensated grades assignment, compare the courses' grades with the grades defined.
    The courses are defined on the SHASPAW page, within the Grade Code field in the Grades Mapping tab in the Compensated Grade Rules section.
  6. Define the courses that can be compensated that will be equivalent to the credits limit defined.
    Credits limit is defined on the SHASPAW page, in the Compensated Rules Mapping tab and in the Allowed Compensated Credits field.

    Then, update the compensated score to the course on the Student Course Maintenance (SHATCKN) page for the student.

    • After the courses that are eligible for compensation are determined based on the preceding steps, the new Compensated Grade and the Grade Change Reason are added to the SHRTCKG table in the Grades section on the SHATCKN page, with an incremental sequence number against the respective course for a student.
    • The Grade Change Reason Code will be defined on the SHASPAW page in the Grades Mapping tab, in the Compensated Grade section and in the Grade Change Reason field.

      For example:

      Table 1. Student courses and grades for a stage
      Course Credits Grade
      CRS1 10 35
      CRS2 20 32
      CRS3 30 38
      CRS4 20 80
      CRS5 20 95
      CRS6 20 67

      In the Student courses and grades for a stage table, if the CRS1 course, the CRS2 course, and the CRS3 course are eligible for compensated grades and the Allowed Compensated Credits limit is set to 20 credits, then:

      1. Based on the highest grades, the CRS3 course takes the first precedence. However, as the CRS3 course is a 30-credit course, you can compensate only 20 credits. No partial compensation is allowed.
      2. Based on the highest grade, the CRS1 course takes second precedence. As the CRS1 course is a 10-credit course, the course will be marked with the compensated grade on SHATCKN.
      3. Based on the highest grade, the CRS2 course takes next precedence. As the CRS2 course is a 20-credit course, you are left with only 10 credits. The CRS2 course will not be compensated.
