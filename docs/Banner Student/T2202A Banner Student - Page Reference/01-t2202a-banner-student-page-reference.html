T2202A Reporting pages.

Ancillary Fees Detail Code (SVAANCI) page

The SVAANCI page is used to process the account receivable detail codes of ancillary fees as part of the tuition tax credit calculation and reporting. These detail codes must be T2202A eligible. This page is applicable for tax year 2014 and later.

Copy Tax Year window

Select Copy from the Options menu to copy the detail codes from one tax year to another.

Charitable Donation Definition (SVACHAR) page

The SVACHAR page is used to process the detail codes of charitable donations for T2202As. The information about any charitable donations made by a student must be captured and printed on the T2202A.

The SVACHAR page will capture the detail code that holds this information. SVACHAR checks that a valid detail code was entered, and that the tax type is not T2202A eligible.

Any amounts entered on this page will be displayed on the T2202A Taxation (SVATAXC) page, and will print on the T2202A. The amounts will be split over multiple tax years on the same basis as TTC using the WTP for a particular term. The page will not look for the residual amount as is done for the TTC in the final year of a multi-year term.

Records that exist in the SVBTAXC table cannot be deleted or updated from this page.

Use this section to enter the tax year and charitable donation detail codes that you want to process and print.

Field Description
Tax Year Valid tax year between 1950 and 2999.
Charitable Donations Detail Codes Valid detail code for the charitable donation. The detail code cannot have a tax type code that is T2202A eligible.

Enrollment Status Code Rules Definition (SVAESTS) page

Use the SVAESTS page to track enrollment statuses that affect T2202A qualifying months for student calculation rules. The tuition tax credit calculation will still be completed.

Only enrollment status codes that are specified on SVAESTS are included in the qualifying months and HWE time calculations. An entry must exist in the SVRESTS table for all enrollment status codes that are to be included in the tax calculation. Those that are missing from SVRESTS will be ignored. Records that exist in the SVBTAXC table cannot be deleted or updated from this page.

Federal Reporting Year Rules (SVAFRYR) page

Use the SVAFRYR page to track terms that affect T2202A processing for a given tax year. The page is also used to calculate the percentage split of fees for student calculation rules.

The T2202A Calculation Q.M.-TTC (SVPTAXC) report calculates the percentage distribution of the tuition tax credit for each term for each student using CRN calculation rules in the T2202A reporting year. A record is inserted into the SVRFRYR table for each valid term of a given T2202A reporting year. This includes the start and end dates of the term.

An entry must exist in the SVRFRYR table for all terms that are to be included in the tax calculation. Those that are missing from the table will be ignored. If you enter a term code where the date range on the Term Code Validation (STVTERM) page does not fall into the tax year, an error is displayed.

You cannot delete a term record if the term has been used in SVBTAXT for the tax year.

HWE Rules (SVAHWER) page

Use the SVAHWER page to develop and maintain the rules applicable by term for individual institutions. The rules determine the selection of student records (SGBSTDN and SGRSATT), registration records (SFRETRM), and course records (SFRSTCR) for calculation of qualifying months.

Qualifying full-time and part-time months are calculated based on HWE rules set up on SVAHWER. If no rules are defined, an error report is created listing the student, the appropriate CRNs, and their attributes.

When you copy a term using the Copy option on the Option menu, the rule is saved to the HWE Student Calculation Rules (SVBHWSC) table. When the Copy Term option is used, the dates used for the new term will always be the term dates as defined in the STVTERM table regardless of if the original dates have been overridden.

Student Rules

Any student who matches the criteria set up in the exclusion rules will be excluded when calculating the qualifying months for that particular term.

The TBRACCD records are processed for eligible tuition fees. If more than one field is populated, the student must match all the criteria to be excluded. For example, if the major is equal to Art and the student attribute is equal to MD1, only students with both of these would be excluded. Art students with student attributes other than MD1 would not be excluded.

After a student passes by all the exclusion rules, the process checks to see if there are any matching student calculation rules. If more than one field is populated, the student must match all the criteria to be processed.

The number of HWEs for full-time or part-time as listed on SVATAXL in the Full-time Hours per Week or Part-time Hours per Week fields will be used to calculate qualifying months for the entire term.

Only students with enrollment status codes defined on SVAESTS are processed for qualifying months using the SVAHWER rules. Qualifying months and tuition tax credits are mostly independent of each other. The Tuition Tax Credit (TTC) for multi-year terms uses the ATP and HWE calculation to determine the split of the TTC over the tax years. Even if a student or CRN is excluded by the exclusion rules, the process checks to see if there is any eligible TTCs for that particular term.

The student rules consist of the Student Exclusion Rules section and the Student Calculation Rules section.

CRN Rules

If a particular student does not match any of the student rules, then the CRN Exclusion and Calculation Rules blocks are used to process the applicable CRNs in which the student was registered.

Only students with registration codes defined in the SVARSTS page are processed for qualifying months using the rules on SVAHWER.

To be considered a full-time month, the CRNs (HWEs) must be greater than or equal to the full-time limit defined on the SVATAXL page, and last for at least three consecutive weeks. If a student is full-time for even one day in a month, they will get that month as a full-time month.

To be considered a part-time month, the CRNs (HWEs) must be greater than or equal to the part-time limit defined on the SVATAXL page, and last for at least three consecutive weeks. A student must have a minimum of twelve hours in a month to be considered part-time. Students withdrawing early from a CRN, where they were eligible for part-time months, will receive credit for the month from which they withdrew even if the twelve hour minimum was not reached.

Any CRN that matches the criteria set up in the exclusion rules will be excluded when calculating the qualifying months for that particular term. The TBRACCD records are processed for eligible tuition fees. If more than one field is populated, the CRN must match all the criteria to be excluded. For example, if the course level is equal to UG, and the section attribute is equal to FS, only students with both of these would be excluded. Course levels of UG with section attributes other than FS would not be excluded.

After a CRN passes by all the exclusion rules, the process checks to see if there are any matching CRN calculation rules. If more than one field is populated, the student must match all the criteria to be processed.

Student Calculation Rules section

These rules process students with characteristics that require qualifying months that would not be easily calculated with the CRN calculation rules, such as a group of students who receive an extra month for pre-course work done outside of the CRN dates, or graduate students who are registered with no CRNs.

The values in the From Date and To Date fields are used by the T2202A Calculation Q.M.-TTC (SVPTAXC) and TL11x Calculation Q.M.-TTC (SVPTAXU) processes when they are run for time status mode 1 (Use the latest time status SFBETRM). If the processes are run for time status mode 2 (Use the effective time status SFRTHST), the processes use the value in SFRTHST_TMST_DATE to determine the start date and end date for the periods that are separated by the time statuses within the term.

Calculation Rules
  • Eligible tuition and fees are captured in the student account records (TBRACCD) using detail codes for charges and payments with the T2202A tax indicators as defined on the TTVTAXT page.
  • Eligible charge detail codes (such as tuition) and ineligible payment detail codes (such as exemptions) are defined on the TSADETC page and used in fee assessment and payment processing.

    Tax credit = sum (eligible charge amounts - eligible charge balances) - sum (eligible exemption amounts).

  • The weighting used for WTP is based on the ATPs (the percentage of the CRN that falls within the tax year) and the HWEs (number of hours/week equivalent) for the appropriate CRNs.
  • An HWE is calculated by multiplying the appropriate unit (credit, billing, contact, meeting hour/week) by the factor that matches the rule for that particular CRN.
  • The WTP for a term equals the sum of all (ATP * HWE)/the sum of the HWEs.

Example

Rules can be built to calculate five full-time qualifying months for all students that are in campus three and have a major of JOUR, even if the term and registration records were only for four months, or no registration existed at all. This would not affect the qualifying months for JOUR students in other campuses.

CRN Calculation Rules section

The CRN Calculation Rules process the students’ courses and the HWE for each eligible course. Then, the HWEs determine the qualifying months and the tuition tax credit.

You can build unique calculation rules for students in the same CRN but who have different attributes.

CRN Calculation Rules
  • Each CRN, which a student is registered in or has withdrawn from (status must be on SVARSTS,) in a term has a HWE calculated based on the rules for that term.
  • HWE is calculated by multiplying the appropriate unit by the factor that matches the rule for that particular CRN.
  • The unit (for HWE calculations) can be the credit hour, billing hour, contact hour, or meeting hour.
  • The factor is the number of hours per week to which one unit is equivalent.
  • The default is the number of hours per week to default for a CRN if the unit value is zero or null.

Example

Suppose a school has two colleges. For college A, all CRNs are based on credits where a one semester course is worth .5 credit hours, and a standard course has three hours associated with each half-credit. For college A, the unit is credit hours, the factor is six, and the default is three.

For college B, all CRNs are based on contact hours where one contact hour is worth one HWE. Then for college B, the unit is contact hours, the factor is one, and a default of four is assumed.

If you build a rule using Meeting Hours MT and assume that would use the SSRMEET dates, but had set check section dates on SVARSTS, then SVAHWER checks the rule to see if SVARSTS is set to Meeting/Section. A message is displayed that the dates in use are the section dates. If meeting dates are required, you need to change the option on SVARSTS.

Releve 8 Taxation (SVAREL8) page

The SVAREL8 page is used to maintain current and historical data for each student for the tax year. This page is initially populated by the SVPREL8 process.

Processing Options

Go to the Option menu to access the available processing options.

Print

The Print option runs the SVRREL8 process. When this option is selected, the system displays a message asking whether to proceed with the print or cancel.

If you select Yes, the system runs SVRREL8 and, when the run is completed, displays the following message: SVRREL8 processing is completed. Please review data to see if the page is printed. Check log file in case of fatal errors. When you select OK, the base section is cleared, and you are returned to the Key block. After the process has run successfully, you can perform a Go button function to display the data.

For 2007, this option sets the value for Box B to the tuition amount printed on the Relevé 8 (RL-8) and populates the Government Sequential Number field. If the RL-8 slip has previously been printed with a Box B amount different from the current total amount of the tuition and examination fees, this option will create an amended record.

For 2008 or later, the values of Boxes B and C are calculated before printing because they are reported in the XML file.

For 2007, the following apply:
  • If the record status is O (original) during printing, the “Code du relevé” box will contain “0“.
  • If the record status is A (amended) during printing, the “Code du relevé” box will contain “1”.
For 2008 or later, the following apply:
  • If the record status is O (original) during printing, the “Code du relevé” box will contain “R”s.
  • If the record status is A (amended) during printing, the “Code du relevé” box will contain “A”.
  • If the record status is D (deleted) during printing, the “Code du relevé” box will contain “D”.

If both the program and degree codes are null in the associated SVBTAXC record for a student in the specified tax year, the system will not print an RL-8 slip for the student, and the following message is displayed: Unable to print Releve8 page because the student has no program and degree associated with in SVBTAXC table.

Note: After a record is printed, you can no longer make any changes. To make changes after a record is printed, you must select the Create New/Recalculate option.
For the year 2008 or later, the report checks that the following conditions exist before the RL-8 information can be printed in a flat file:
  • RL-8 records were printed in an XML file
  • XML validation status is either blank or Valid

For years before 2008, the report does not need to check if RL-8 records were printed in an XML file.

Recalculate

Select the Recalculate option to run the SVPREL8 process for the student, which replaces the data in the current sequence number. This option can only be selected if the Print Date field is Null.

When the Recalculate option is selected, the cursor is returned to the Key block. The user must wait a moment to allow the SVPREL8 process to recalculate the data, and can then return to the Base section to see the updated data.

Create New/Recalculate

Select Create New/Recalculate option to run the Calculation of Releve 8 (SVPREL8) process, which determines if a new record is generated or if existing data is recalculated in the SVBREL8 table.

T2202A Based Terms Priority Rules Maintenance (SVATPRI) page

Use the SVATPRI page to set up the priorities for terms that have the same start date for a given tax year.

The priorities entered on this page are used by the T2202A Calculation Q.M.-TTC (SVPTAXC) and TL11x Calculation Q.M.-TTC (SVPTAXU) processes to select the right program/degree from the SGBSTDN table.

It is also used by the web pages and printing processes to select the right campus from SVBTAXT table. The priority provides the ability to determine which term to select when two or more term codes share the same start date (STVTERM). For web pages and printing processes, the campus is chosen depending on the term code with the latest start date in SVBTAXT. The address associated with the campus on SVAINAD or GUAINST is printed. The value for the Mode Same Start Date Terms field on the Education/Tuition Amount Limits (SVATAXL) page is used by the processes to determine if the priorities are used.

If the value is 1 (Use maximum term code) for the Mode Same Start Date Terms field, when any of the following processes or web pages are run, the values on SVATPRI will not be used and the term with the higher term code will be selected:
  • SVPTAXC
  • SVPTAXU
  • SVRTXLP
  • SVRTXLU
  • SVRREL8
  • Printable T2202A page (bwvktt22.P_PrintT2202A)
  • Printable Quebec Form page (bwvktt22.P_PrintQuebec)
  • Printable Relevé 8 page (bwvkrel8.P_LaunchReleve8)
  • Pre-2007 Printable Relevé 8 page (bwvkrel8.P_LaunchReleve8_Prior07)

If the value is 2 (Use term:registration/priority) for the Mode Same Start Date Terms field, select the term based on the student’s registration, the priority of the term, or both.

  • For the SVPTAXC and SVPTAXU processes, setting the indicator to 2 causes the logic to look at the Student Course Registration Repeating (SFRSTCR) table first, and if more than one such term is registered, it then looks at the priority defined in SVATPRI.
  • For web pages and printing processes, setting the indicator to 2 causes the term-campus to be chosen from SVBTAXT, depending on the priority of the terms defined in SVATPRI.

If the term being processed (from the SFBETRM or TBRACCD table) for a student matches an effective term code in the SGBSTDN table, the process will select the matching SGBSTDN record regardless of the value selected for the Mode Same Start Date Terms field.

In other words, if an exact match occurs, the process does not check any other SGBSTDN records, and does not check the registration information for the student in SFRSTCR or the priority set up for the year in the SVATPRI table.

If an exact match does not occur, the process will choose the SGBSTDN record that has the effective term with the closest start date before the start date of the term (from the SFBETRM or TBRACCD table) being processed. If two or more effective terms exist with the same start date in SGBSTDN table, the process will check the value for the Mode Same Start Date Terms field to decide which SGBSTDN record to select.

If data is retrieved from the SVRTPRI table, and all of the terms have the same priority, the process will select the SGBSTDN record that has the maximum effective term code among the terms that have the same priority.

A check is done to disallow the use of this page if an ID/tax year combination already exists. When a record is created on this page, the SVBTAXC_EXCEPTION_LOCK is set to Y. If an exception record is viewed on the SVATAXU page, none of the fields can be updated from that page.

The SVATXRP page allow institutions to define the reporting periods for T2202A reporting. Institutions can define up to four reporting periods and can associate an unlimited number of terms to a particular reporting period.

All terms defined in the SVAFRYR table must be present in this page. The terms defined here are validated against the SVRFRYR table for the same tax year.

Associated Terms section

Use this section for terms associated with this reporting period.

Field Description
Associated Term to Reporting Period Terms associated with this reporting period.

A multi-year term can be associated with a reporting period in each tax year. An unlimited number of terms can be associated with a reporting period. For most institutions with non-concurrent terms, the institution can define the reporting periods to closely match their term dates.

Institutions can associate a term code with multiple reporting periods using this block. For example, the term that starts in May and ends in August and spans through July, can report the proportionately redistributed tax credit amount, ancillary amount, claimable amount, charitable amount and the number of months in the following two reporting periods:

  • From May to June
  • From July to August

In other cases, institutions who integrate third-party data with T2202A, a term may span over the entire 12 months of the year. In such scenarios, the term can be associated with all the reporting periods of the year.

The claimable amount (which is proportionately redistributed) and the number of months of a term can be reported in multiple reporting periods as defined by month.

The List of Values (LOV) (SVRFRYR) for this field only lists the term codes of the same tax year as that in the key block, so that the term code defined for other tax years cannot be entered in this block.

At the time of saving the term record,
  • If the term code is already associated with another reporting period, then a dialogue window displays with the following warning message:

    Term exists in other reporting period of current tax year. Do you want to continue to add the term to this period?

  • If the date range of this term code is also outside the reporting period months, then the subsequent warning message is displayed:

    Term Dates are not within the period. Do you want to continue?
