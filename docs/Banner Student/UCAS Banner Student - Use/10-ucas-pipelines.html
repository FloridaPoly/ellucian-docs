UCAS Pipelines

You can use UCAS pipelines in Banner.

The following is the list of tasks that you need to complete to setup UCAS pipelines:

  • Setup Banner Ethos API access
  • Setup GUACONF
  • Setup Ethos Application
Important: Ellucian recommends that you implement the following system configuration updates:
  • Ensure sufficient database tablespace when downloading large datasets from UCAS using DC pipelines.
  • Firewall update:
    • Update firewall configurations as per the security requirements
    • Some of the customers have observed an affecting issue even after their IP addresses were whitelisted. To address this issue, Ellucian recommends you to add the https://prod-eu-west-1-integration-service-files.s3.eu-west-1.amazonaws.com URL to the IP whitelisting section and ensure to include in the outbound firewall rules
  • Transaction Timeout configuration:
    • Update the banner.transactionTimeout setting to 600 seconds
    • Update banner_configuration.groovy script in both Integration API and Shared Configuration
  • Validate the Crosswalk and Pipeline configuration:
    • Implement validation process to identify and remove trailing spaces in: * Crosswalk configurations (during creation and copying operations) * Pipeline name configurations
    • Eliminate (systematically) the trailing spaces to avoid configuration errors
  • SYSTEMD working directory fix:
    • Error Message: {"errors":[{"code":"Global.SchemaValidation.Error","description":"Errors parsing input JSON.","message":"UcasXml.xml"}]}
    • Issue: When Tomcat is started as a systemd service, Linux may not identify the current shell's working directory. If the working directory is not set in the systemd unit file, the service starts in the root directory (/). However, Tomcat does not have the write permission to the directory location. Hence, Tomcat fails to create the temporary UCAS XML file.
    • Fix: Add the working directory for Tomcat in systemd configuration files and restart the Tomcat services to solve this issue.

Data connect requirements

Setup Banner Ethos API access

Assign the applicable Banner security objects to users who need access to a particular resource.

About this task

Setup is required for XML pipelines to work as expected.

Procedure

  1. Access the Oracle/Banner Security Maintenance (GSASECR) page to allocate the security object (API_UCAS_XML) at the user level.
  2. Verify whether the user has access to the BAN_GENERAL_API_C security class, as it is necessary for Experience and Data connect.

Set up GUACONF

Modify the configuration values in the GUACONF page.

Procedure

  1. Navigate to the GUACONF page in the Application Navigator and enter BAN_STU as the Application ID.
  2. Select the Configurations tab.
  3. Change the ucas-xml-interface parameter value to Data Connect. The default value for WINC users is WINC.

Setup Ethos Application

Before you begin to download UCAS XML data through Data Connect, create a proxy application for the ucasxmlset resource in the UCAS Xml Proxy page.

Create UCAS Services Resource application

In Ellucian Ethos Integration, you must create an application that owns resources.

Before you begin

Ensure the following:
  • Access to Ellucian Ethos Integration. For more information and requesting access, see Ellucian Ethos Integration requests.
  • You are using the EU environment.
  • Whitelist the IP addresses to avoid issues of firewall restricting requests while adding the resources. See IPs to whitelist for the list of IP addresses.
  • You will require the base URL of Ethos Integration API.

Procedure

  1. Log in to Ellucian Ethos Integration.
  2. On the Ethos Integration header bar, click the gear button and select the environment where you want to perform this procedure.
  3. On the Ethos Integration header bar, click APPLICATIONS.
  4. On the Create New App tab, click MANUALLY.
  5. On the Add Application dialog box, clear the check boxes, and click CONTINUE.
  6. On the Application Details page of the wizard, enter the following information, and then click Next.
    Field Entry
    Application name Enter a unique name for this application. For example, ucas Services Resource.

    Ensure that the name uniquely identifies this application. When you need to select an application elsewhere in the Ethos Integration user interface, you need to use the name to select the correct application.
    Description (Optional) Enter a description of this application. For example, ucas Services Resource.
  7. On the Add Subscriptions page of the wizard, click Skip.

    A message appears as ucas Services Resource has been successfully added!.

  8. Click View Application.
  9. Click to open the Owned Resources tab and perform the following:
    1. Select Authentication Type as Basic Authentication.
    2. In the Base URI field, enter the base URL of the Ethos Integration API.
    3. Click the save icon next to the Base URI field.
    4. Click Add Resources to manually configure them.
      Note: Do not click Auto-Configure Resources to automatically configure them.
    5. Select Add A Custom Resource and then click Next.
    6. In the Add Owned Resource (Custom) dialog box, enter the following resource names in the Resource Name field, and then click Add.
      Resource Name Description
      ucasxmlset UCAS XML Data
      ucaslink-mcds-transactions MCDS Data
      ucaslink-transactions Personal Statements Data
      ucas-application-transactions-details UCAS Transaction Details Page/Card
      ucas-transaction-statuses Transaction Status from UCAS to Recruit
      ucas-update-job-statuses Transaction Status from UCAS to Recruit
Create UCAS Services Proxy application

The application record contains basic information about UCAS Services proxy application and how it interacts with Banner through Ethos Integration.

Before you begin

The Add Application wizard will prompt you for the user name and password for a user account that supports proxy API requests. Before running the wizard, create the user account.

About this task

  • Ethos applications for the Banner Integration API, which is part of setting up Banner in Ethos Integration.
  • An Ethos application for UCAS Services proxy application process, which you will create using the procedure mentioned in the following step-by-step procedure.

Procedure

  1. On the Ethos Integration header bar, click the gear button and select the Ethos environment where you want to perform this procedure.
  2. On the Ethos Integration header bar, click Applications.
  3. On the Applications page, click Add Application.
  4. In the Add Application dialog box, do the following:
    1. Select Manually.
    2. Select Configure REST API proxy.
    3. Click Continue.
  5. On the Application Details page of the wizard, enter the information described below and click Next.
    Field Entry
    Application name Enter a unique name for this application.

    Example name: UCAS Service Proxy

    Ensure that the name uniquely identifies this application.

    When you need to select an application elsewhere in the Ethos Integration user interface, you will use the name to select the correct application.
    Description (Optional) Enter a description of this application.
  6. In the Add Source Applications page of the wizard, set up proxy API requests:
    1. Click Add Source Application to open the Add Source Application dialog box.
    2. In the Source Application field, select the Ethos application (UCAS Services Resource) that you created for Banner.
    3. Enter the user name and password for the Banner user account that supports proxy API requests.
    4. In the Select a resource field, select any Ethos resource to which that user account has permissions in the ERP.
      You can select any resource for which you granted that user account permissions in the ERP. For example, persons. Ethos Integration uses that resource to validate the user credentials by confirming that the user account has access to at least one resource in the ERP. After the credentials are validated, the application will have access to all resources for which the user account has been granted permissions.
    5. Click Add.
    6. Click Next.
  7. Click View Application if you are ready to configure app-specific settings, or click Back to Applications if you want to just create the app now and configure settings later.

Before you begin

If there are any existing ucasXml crosswalks, delete them, and then, create a new crosswalk as ucas.

About this task

The following procedure is applicable only for SaaS customers who use Data Connect.

Procedure

Run the UCAS XML LINK pipelines

Run the UCAS XML Pipelines.

About this task

This procedure is only for SaaS customers who use Data Connect.

Procedure

  1. Access Ethos Experience and log in with the credentials of the tenant where you've configured the UCAS.
  2. Select UCAS XML LINK from Integration Packages, select the pipeline for which you need to run the job.
  3. Click New Job and enter the parameter details as required for the job run.
  4. If you want to schedule a job, update the Job Run Details section.
    This runs the same job with the same set of parameters based on a time schedule chosen while creating the job.
  5. Enter the following pipeline parameters:
    1. Ethos API Key for the Proxy app
    2. User Id
    3. Password
    4. User Id2
    5. Password2
  6. Enter the following job parameters:
    Job Parameter Description
    Personal Id The personal id to extract records only for a particular applicant record.
    Since Date The date as of when the records have to be fetched for the corresponding UCAS GET endpoint.
    Note: Manual Job 'Since Date' Parameter Behavior Issue ISSUE DESCRIPTION: When executing a manual job for the first time, the system correctly honors the 'Since Date' parameter and imports records using this specified value as the 'LastUpdated' timestamp. However, during subsequent executions of the same manual job, the system exhibits inconsistent behavior: The 'Since Date' parameter is no longer respected, regardless of whether it is modified or remains unchanged The system defaults to using the current date and time as the 'LastUpdated' value instead of the configured 'Since Date' This forces users to create a new manual job for each execution to achieve the desired behavior

    This is an expected behavior.
    ERP As these pipelines are running for Ellucian, this is defaulted to Ellucian.
    Multi Institution Allows you to select the first institution or second institution.
  7. Click Save.
    Ellucian recommends that you note the following information.
    • Ethos Api Key, User Id, Password, User Id2, and Password2 are the persistent parameters in the pipeline.
    • Date picker is available for Since Date Job Parameters while creating new job for UCAS XML LINK pipelines.
    • Maximum Concurrency value is set to 1 in the Advanced options, while creating new job for UCAS XML LINK pipelines. Ensure that the Maximum Concurrency slide bar under the Advanced Options section remains as the default value for all pipelines.
    • When you run the pipeline for the first time, entering the Since Date job parameter is mandatory when there is no Personal Id job parameter.
    • When you enter the Personal Id, the system will not consider the Since Date job parameter to download/upload data from UCAS to Banner.
    • For the Multi Institution parameter, if you select the first inst in crosswalks, the values from the userIdMap, passwordMap, and institutionCodeMap mapping will be used. If you select the second inst in crosswalks, the values from the userIdMap2, passwordMap2, and institutionCodeMap2 mapping will be used. The Multi Institution parameter allows you to use two institutions to download the UCAS data.
    • Following are the ways to handle a few error scenarios in the UCAS XML LINK pipelines.
      • Batching of 200,000 records for getUCASApplicantStatus per API call to stop running into ORA-31186: Document contains too many nodes error.
      • In the Xml-link UCAS Applicant Data SET pipeline, handled false positive error even though pipeline is successful.
      • In Xml-link UCAS Reference Data GET pipeline, removed deprecated end points getReferenceParentalOccupations and getReferenceParentalOccupations2010.
      • In Xml-link UCAS Results GET pipeline, Xml-link UCAS Units GET and Xml-link UCAS Results Match GET pipelines,

        Batching of 200,000 records per api call to stop running in to error ORA-31186: Document contains too many nodes.

Reset UCASXML password

Reset the UCASXML password using the updatePassword end point.

Before you begin

Before you reset the password, ensure that you verify any UCAS end point, for example, getUCASApplicantActivity using current password, which is shown in the passwordMap parameter in the Crosswalks pane.

Procedure

  1. In the Integration Packages page, click UCAS XML LINK.
  2. In the List of Crosswalks pane, select the ucas (vo.0.57) option.
    The password that you see in the passwordMap parameter in the Crosswalks pane is used as the current password for the UCAS end points to fetch data from HEP1/HEP2 link.
  3. To reset password, under the UCAS XML LINK packages list, select the Xml-link UCAS Password SET option and click New Job.
  4. In the Edit Job page, enter the job name in the Basic Details section.
  5. Enter a new password and confirm your password in the Job Parameters section for which you want to reset the password.
  6. From the ERP drop-down list, select Banner or Quercus.
  7. Click Run Now in the Job Run Details section.
  8. Select Max Concurrency as 1 and maximum available value for HTTP Request Timeout in the Advanced Options section.
  9. Select Enable Diagnostic Log, if you require a log.
  10. Click SAVE.
    After the job run is successfully complete, view the status as Succeeded.
    Note the following:
    • This password change pipeline updates the password for the HEP1/HEP2 UCAS link after the pipeline runs successfully.
    • You can test the new password by opening any UCAS end point, for example, getUCASApplicantActivity in your browser using the new password. You can view the data for the end point.
    Possible error messages that you may encounter when running the Xml-link UCAS Password SET pipeline.
    • After resetting the new password and when you try to access the endpoints data with the old password using the browser/ERP, the system will not display the end point data and will display the (HEI0007) Incorrect userId/password error message.
    • When the New Password and Confirm New Password does not match, the job terminates with a failure status and displays the (HEI0014) Your confirmation password is different to your password error message in the View Errors section.
    • When you use an password that is not valid and which does not confirm to password standards to update the New Password and Confirm New Password fields, the job terminates with a failure status and displays the (HEI0017) Your password must consist of mixed case letters and numbers with no consecutive characters message in the View Errors section.

Schedule MCDS pipelines

Lists the scheduling MCDS pipeline process.

Pipeline 1 Scheduling

  • Schedule Pipeline 1 to run at the required interval (for example, every 12 hours).
  • Ensure that the Pipeline 1 is the first pipeline to execute in the sequence.

Pipeline 2 Scheduling

  • After the first successful run of Pipeline 1, schedule Pipeline 2 to run at the same interval as Pipeline 1 (for example, every 12 hours).
  • Ensure that the timing of Pipeline 2 execution aligns with the completion of Pipeline 1 and specified duration.

Failure Handling

If Pipeline 1 succeeds but Pipeline 2 fails:
  • Create a new scheduled job for both Pipeline 1 and Pipeline 2.
  • Set the Since Date parameter for the new Pipeline 1 job to match the last successfully run creation date of Pipeline 1 to ensure data consistency.

You can see the summary of the data download in UcasTransactionsDetails Experience Card with Input: JobRunId of the UCAS MCDS pipeline 1 successful completed Job.

If the summary of the data download are not available for successful completed Job, look for the File COUNT ZERO FROM UCAS.txt with the text No records to process : count is 0 from UCAS. This indicates that there are no updates or new data from UCAS since the last successful run/since date.

SOPPSMT Java Process

To resolve Personal Statement processing failures involving high‑volume datasets, a new Java process has been introduced as a workaround.

The new process accepts Personal Statement data as file input and performs the necessary updates.

Note:
  • The new DC pipeline UCAS Interim Personal Statement Pipeline 2 (version 1.0.0) generates a text file with personal statement data.
  • File name is based on the Job Run ID. File contains Personal Statement data.
  • Transfer this text file to Oracle directory before you run the java process SOPPSMT.
  • As per the prior procedure, run the DC pipeline UCAS Interim Personal Statement Pipeline 2 (v1.0.0) following the completion of UCAS Personal Statement Pipeline 1.

The Java process requires the following input parameters:

  1. Oracle Directory Name:

    Oracle directory where the input file is stored and must be pre-configured and accessible by the process.

  2. File Name:

    Name of the input file containing Personal Statement data, and it must include the .txt extension.

    Example: 69ce2d5f80082cbf8a746e9d.txt

  3. Run Mode:

    Defines how the process behaves.

    • Audit mode – validates and reports data without making updates
    • Update mode – applies Personal Statement changes to the system

DM Import Pipeline (1.0.0 version)

Retrieves applicant documents from UCAS for a given admissions cycle and institution and writes to S3. The pipeline submits a supplemental data job and writes the response for downstream processing.

This pipeline generates a file named POST_SUPPLEMENTAL_DATA_JOBS_RESPONSE.txt, which contains the supplemental data job ID and its status. Initially, the status will be NOTSTARTED.

The generated job ID is then used in the DM Import Status Pipeline to check the job status. When the status changes to DOWNLOADED, it indicates that the documents have been successfully downloaded to S3.

Job Parameter Required Description
multiInstitution Yes Select institution (1 or 2)
cycleCode Yes Admissions cycle year (for example, 2027)
lastUpdated No Only retrieve documents updated after this date/time. Ignored if lastUpdatedOverride is true. Defaults to the submission time of the most recently completed job.
lastUpdatedOverride No If true, returns all documents for the cycle regardless of last updated date. Default: false
sectionId No Filter by document section
categoryId No Filter by document category
personalId No Comma-separated list of personal IDs (must match count of applicationSchemeCode)
applicationSchemeCode No Comma-separated application scheme codes (must match count of personalId)
requestorId No Identifier of the requestor submitting the job

Application Review Centre (ARC) Self Service changes

A new Document section has been introduced in ARC. When the Fetch Documents button is selected, documents associated with the Personal ID are retrieved, and their metadata such as Document ID, Document Name, Document Type, and Document Category is displayed in Self-Service. Selecting the hyperlink in the Document ID field opens the corresponding document in the browser or initiates a download.
