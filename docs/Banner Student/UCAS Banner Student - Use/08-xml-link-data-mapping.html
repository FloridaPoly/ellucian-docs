UCAS Widening Participation (WP) data

In recent years, Higher Education (HE) providers have identified additional groups of students who can benefit from flagging their circumstances with their providers.

As part of widening access and participation for students, and ensuring greater efficiency for HE providers, UCAS collects and shares this information during the application submission. The Banner UCAS application downloads and stores the widening participation information for each applicant for the institution’s use.

Manage WP data

Institutions can download the widening participation answers for each applicant from the SKAUHPR page by running the available new XML Link operations from UCAS. You can view the Widening Participation data for applicants in the Person Social Economic Identity Details GOAPSID page.

Before you begin

Ellucian delivers a rule for WP data that you can view in the GKAKSYS page for the UCAS system. The *K – WP system parameter rule is available for institutions to a value from the Values LOV, before downloading data. Institutions must have a valid value for the HESACOUNTRY parameter setup for the HESA system in the GKAKYSY page.

For your Social Economic Identity Report (based on the HESACOUNTRY value setup), you should add the Social Identity codes for the UCAS Widening Participation fields to the report template from the GOASETP page. This allows you to view the Social identity codes for the Widening Participation fields in the GOAPSID page.

With the UCAS_SEID social economic identity report, institutions can see the UCAS WP social economic identifiers that are displayed already. Along with the UCAS_HESACOUNTRY report, the UCAS data is loaded to the UCAS_SEID report for the GOAPSID page, by the UCAS packages.

Note: As Recruit currently looks up the HESACOUNTRY report in GOAPSID to display the UCAS WP fields on its pages, data is loaded to both the HESA_COUNTRY and UCAS_SEID social economic identity reports, respectively. After Recruit makes changes to display the WP data from the UCAS_SEID report, with a future release for Banner, the WP data will always be loaded only to the UCAS_SEID social economic identity report, and not the HESA_COUNTRY reports.

  1. Access the UCAS Data Processing (SKAUHPR) page.
  2. From the Web Service Process drop-down list, select the xml-link UCAS applicant data Get methods(Executable) option.

    • getUCASApplicantRefugeeAsylumSeekerStatus
    • getUCASApplicantServedInArmedForces
    • getUCASApplicantCaringResponsibilities
    • getUCASApplicantFreeSchoolMeals

  5. Click Run Now.
  6. Navigate to the Banner Control window.
    The system displays the *K record type data in the RE (Received) status
  7. Optional: Use the Filter option to sort and search for a particular applicant.
  8. Go to the Tools menu, and click Load All Applicants or Load Single Applicant option.
    The system displays the *K record type data in the PM/PR (Processed with Message/Processed) statuses.

    If there is a missing reference data for Widening Participation, the *K records are processed the PM status message.   9. Access the Person Social Economic Identity Details (GOAPSID) page.
