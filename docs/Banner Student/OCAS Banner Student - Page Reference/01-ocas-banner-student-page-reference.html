OCAS Banner Student page reference

Identifies the functionality and parameters of the reference pages contained in the Ontario College Application Services (OCAS) software.

The Ontario College Application Services (OCAS) Centre collects and processes information for all first-year students applying to a full-time program at a college in the province of Ontario, Canada.

This page reference documentation supports the latest available version of . To review documentation for earlier versions, click Previous Versions on the navigation bar at the top of the page, and then download the file associated with the version you need. There is a Reference document for that version in the downloaded zip file.

Use the GVIVERS page to display the release numbers of a Canadian localization. This page is used for all Canadian localisations. The data is queried from the GVRVERS table.

OCAS Applicant Assignment to Administrator (SVAOAAA) page

Use this page to filter the applicants assigned to a primary OCAS administrator.

The administrator/applicant relationship is used ensure administrators can only access the data for the applicants that have been assigned to them. This restriction will be applied for all the OCAS forms that handle application numbers.

An applicant’s first program choice is considered when they are assigned to an administrator through the OCAS Data Processing Process (SVPOCAS), and is for balancing purposes only (balancing ensures that all administrators have approximately the same number of applicants).

There are two ways to assign an administrator to an applicant are:
  • Using SVPOCAS, which is done when AC/CC records exist for the applicant.
  • Using the OCAS Data (SVAOCAS) page, when the page automatically assigns an administrator to the applicant when AC data is saved (a CC record is not required to assign an administrator from SVAOCAS).

The only way to change the secondary administrator for an applicant is to assign a secondary administrator to the corresponding primary administrator in the OCAS Administrator Re-Assignment (SVAOARA) page. This assignment affects all of the applicants related to the primary administrator not just one specific applicant.

This page also displays if an applicant has critical alerts. Applicants with alerts in the SVROAAL table are listed first on the page. The applicants with alerts are listed in the following order:
  • Records are listed in descending order from the most recent date to the oldest date (SVROAAL_INSERT_DATE)
  • Records where the Action Required check box is selected will be listed first
  • Records where the Alert Cleared check box is cleared will be listed before records that have the Alert Cleared check box selected

Base section

Field Description
OCAS Applicant Number Application number that is assigned to the primary administrator. The applicant must exist in the SVRORCC or SVROCCC table. The applicant could exist in only the SVROCCC table if entered manually from SVAOCAS.
Program Code Applicant’s first program choice. Display only.
Secondary OCAS Administrator Banner ID and Name Secondary administrator. Display only.
Alerts Check box used to indicate whether the applicant has critical alerts.
Action Required Check box used to indicate whether the existing alert(s) require an action from the user.
Alert Cleared Check box used to indicate whether the alert has been cleared, which means that the alert has been corrected.

OCAS Applicant Alert (SVAOAAL) page

Use this page to filter and enter the alert codes attached to an applicant.

Only U (User) type alert codes can be entered. An alert requires administrator intervention. Alert codes attached to S (System) type groups are filter only.

The records are listed in descending order with the most recent alert at the top.

OCAS Administrator Change (SVAOACH) page

Use this page to change the primary and secondary administrator for an individual applicant. To use this page, you must be a valid and active OCAS administrator on the OCAS Administrator Definition (SVAOADM) page and be assigned to the selected applicant.

Note: You can use the OCAS Administrator Re-Assignment (SVAOARA) page to change the primary and secondary administrator for a whole population.

Primary Administrator section (untitled)

This section is used to change the primary administrator. Select Change Primary Administrator ID from the Options menu to access this section.

Secondary Administrator section (untitled)

This section is used to change the secondary administrator. Select Assign/Change Secondary Administrator ID from the Options menu to access this section.

The secondary administrator does not need to have authorization to handle a particular program. A secondary administrator can be assigned to an applicant without verifying whether or not the administrator exists in the SVROAPA table for the applicant's programs.

The secondary administrator has to be different than the primary administrator. Because a secondary administrator is being assigned to help the primary with their tasks, it does not make sense to assign a secondary administrator with the same ID as the primary administrator.

OCAS Administrator Definition (SVAOADM) page

Use this page to enter the person who is a valid OCAS administrator.

Filter Rules

The following details the data that an administrator can update, view, or both according to values in the indicator fields.

Admissions Role Super User Result
Selected Selected The administrator can update OCAS data, and can also view applicants on the SVIOWRK page.
Selected Cleared The administrator can update OCAS data only for applicants for whom they are the primary or secondary administrator, or for applicants who have a program that the administrator can handle according to the SVROAPA table. The administrator can also see applicants on the SVIOWRK page who have programs to which the administrator was associated on the SVAOAPA page.
Cleared Cleared The administrator cannot view or update an applicant from the OCAS forms (SVAORER, SVAOCAS, and so on), but can see applicants on the SVIOWRK page who have programs to which the administrator was associated on the SVAOAPA page.

Base section

Field Description
Active Only active administrators can be assigned to an applicant.
Admissions Role Check box used to indicate whether the administrator has an admissions role, which means that the administrator can modify OCAS data.
Super User Check box used to indicate whether the administrator has super-user privileges. A super-user administrator can update applicant data in any OCAS page that uses an application number.
Eligibility/Scoring with Final Grades Check box used to indicate whether an administrator can run the following processes with the Final Grades Only parameter set to Y:
  • OCAS Eligibility Calculation Process (SVPOELI)
  • OCAS Score Calculation Process (SVPOSCR)
  • OCAS Alternate Program Calculation Process (SVPOALT)

Application Form Tracking per Applicant (SVAOAFA) page

Use this page to track application forms that are in the process of being filled in by applicants applying for admission through OCAS Self-Service.

An applicant might have multiple records in this page, as a new record will be created any time the applicant changes their applicant type for the same year (for example, from Transfer to International). Multiple records for the same applicant can be active only if the value for the Number of Application Forms Indicator on the Web Application tab of the OCAS Control (SVAOCTL) page is M.

Applicant Form per Applicant section

Use this section to display the basic data for the applicant number, application page code, year, and applicant type combination specified in the Key block. You cannot insert records in this section, but you can add a comment to an existing record.

General Status Sub-tab

This sub-tab displays the general status information about the application.

Field Description
Status Status of an application page submitted through the OCAS Web Application. Valid values are as follows.

Complete: The application page has been completed and is ready to be reviewed by the admissions officer. All the data has been pushed from the temporary tables to the permanent tables.

In-progress: The application page is in process of being completed by the applicant, after the applicant completes the basic sections (Personal Information, Mailing Address, and Available Programs) and an OCAS application number has been assigned.

Submitted: The application page has been submitted after the applicant has complete all sections.

Payment Pending: The applicant has not yet paid the admission fees.

Duplicate: The system has identified one or more possible duplicates for this applicant.
Activity Check box used to indicate whether this application page and applicant type combination is active. If your institution allows applicants to apply only to a single application page per year (that is, the value for the Number of Application Forms Indicator on the Web Application tab of SVAOCTL is S), the applicant will have only one record active for the OCAS year in this table.
Payment Check box used to indicate whether payment has been received for the application.
Duplicate Check box used to indicate whether potential, unresolved duplicate records exist for this applicant.

If this check box is selected, you can click Duplicate to access the OCAS Duplicate Person (SVAODUP) page, which you can use to resolve the duplication.

Evaluating an Applicant’s Eligibility

To be eligible, an applicant must match all of the criteria defined for the eligibility rules such as general requirements, institutional testing and the eligibility formula (eligibility areas). The OCAS Eligibility Calculation Process (SVPOELI) is used to evaluate if an applicant is eligible.

A general requirement can be evaluated right away or when final grades are received.

Institutional testing is evaluated right away, which means that the applicant will be eligible only if the test has been completed.

One or more eligibility areas compose an eligibility formula. To be eligible, the applicant must satisfy each one of the eligibility areas. Eligibility areas are defined on the OCAS Eligibility Area Definition (SVAOEAD) page.

Calculating an Applicant’s Scoring

The final goal when running the OCAS Score Calculation Process (SVPOSCR) is to calculate the score that an applicant has regarding a program.

The score is a numeric value that is obtained by adding the partial scores obtained in every scoring area resulting in the total score for the applicant’s program. Scoring areas are defined on the OCAS Scoring Area Definition (SVAOSAD) page.

  • The combination of target term, program, semester, and campus must exist and be active in the SVROPRC table.
  • The record must exist in the SVROPOR table for the source term, program, semester, and campus combination.
  • The totals of the source seats, CC-Y and offers of the program offer rules must match with program offer group totals.

If all those condition are met, then the copy process checks if the combination of target program, term, semester and campus exists in the SVROPOF table. The copy process can still be cancelled at this point. If the combination does not exist, the process creates a new SVROPOR record for all offer groups, or for a specific offer group for the combination of target program, term, semester and campus.

OCAS Queue Operation (SVAOQOP) page

Use this page to manage the movement of applicants between queues (offer, waitlist, refusal).

When an applicant is assigned to a queue for the first time (offer, waitlist or refusal), the eligibility output is frozen. The applicant’s stage is set to Offer Processed for all of the eligibility output records that the applicant has for the corresponding program. Further movement between queues of the same program (for example, from offer to waitlist or to refusal) will not cause the stage to be changed as long as the value was Offer Processed.

In order to execute some of the queue options, which update applicant information in/or between queues, the applicant program should be active, otherwise a warning is displayed requesting that OK be clicked to clear the screen.

This page will not execute any queue task where the program is inactive at the applicant program level. A program that is inactive at the general level but active at the applicant program level (SVROCCC_STATUS = A) will not be processed.

An applicant is assigned a conditional offer if the value of the Eligibility Final Indicator field on the Eligibility-Scoring subtab of the Program tab in SVAOCAS is P. This occurs when the applicant is moved to the offer queue from another queue.

Offers are stopped when there is no place available and when the user stopped the offer. The Stop Offers indicator and number of available offers are checked to determine if the offer should be stopped. The page will ask for confirmation so the user can still process the offer even if no place is available or offers have been stopped.

If the Online Confirmation Indicator field on the OCAS Control (SVAOCTL) page has a value of Y, SVAOQOP creates a record when any of the following tasks are performed:
  • Applicant was deactivated in the OFFER queue (Offer State changed)
  • Applicant was reactivated in the OFFER queue (Offer State changed)
  • Applicant was moved from OFFER to WAITLIST queue (Offer State changed)
  • Applicant was moved from OFFER to REFUSAL queue (Offer State changed)
  • Applicant was moved from OFFER to NO-QUEUE (Offer State changed)
  • The OCAS DUE DATE changed for the applicant(s) (Offer OCAS Soft/Due Date changed)
  • Applicant(s) was (were) moved from the WAITLIST to the OFFER queue (Offer Hard Date, Offer OCAS Soft/Due Date, Offer State changed)
  • Applicant was moved from the REFUSALS to the OFFER queue (Offer Hard Date, Offer OCAS Soft/Due Date, Offer State changed)
  • Applicant was moved from the NO-QUEUE to the OFFER queue (Offer Hard Date, Offer OCAS Soft/Due Date, Offer State changed)
  • Any other option was selected in Offer Queue section that modifies fields that are relevant for the OC file.

When executing any task that will be followed by the insertion of a record into the SVROOFT table, the page will verify there is a valid value for any SVROOFT field that is not null. If a valid value is missing, the page will not insert a record into the SVROOFT table. A new record must be inserted in the SVROOFT table so that the data can be sent back to OCAS in an Offer file. Records will be always inserted in to SVROOFT table, but never updated.

This page will insert or update records in the Banner baseline tables that handle concurrent curricula data. After data has been inserted or updated in the Banner Admissions tables (SARADAP/SARAPPD) or the Banner Student table (SGBSTDN), the records will also be inserted or updated in the SORLCUR and SORLFOS tables.

  • Ignore the whole record, or ignore one or more fields with an error
  • Fix error fields by changing the original value to the corrected value
  • Fix error fields by inserting a missing value in a validation page
  • Ignore a field

When correcting errors at the field level, the Error Status field for the corresponding record is set to null.

Ignore Records

To ignore records with errors, it must be done at the record level even if the error(s) are at the field level.

Ignoring a record means that the entire record is not considered during transaction processing. The user must enter I in the Status field and then run SVPOCAS to change the Error Status field to I for the corresponding field(s) of the record.

Note: The AC record is an exception. An AC record with errors cannot be ignored. The record can be fixed or some error fields can be ignored but the entire record cannot be ignored. The reason is because the AC data is used to update the General Person data in Banner.

When correcting errors at the record level, the SVRORER_INTER_REC_DEP_IND column is set to null for the corresponding record.

Ignore Fields

Another option to clean up errors is by ignoring the field that has the error condition, which allows the remaining fields in the record to still be used.

This applies to some fields that are not relevant for making decisions so the user may not want to invest time fixing them. Fields that are involved in decisions or are part of the key cannot be ignored. These fields must be fixed or part of an ignored record.

Fields that are ignored have a value of Y in the Ignore Field Error field on the OCAS Fields Description (SVAOFLD) page.

When correcting errors for the duplicate PIDM condition, the OCAS Duplicate Person (SVAODUP) page is available from the Duplicate Person Form option. SVAODUP displays all of the possible duplicate PIDMS. The user has to pick the PIDM that is correct or discard all of them if not valid (in this case, a new PIDM is created). The record of the chosen PIDM will set SVRODUP_USED_IND to Y and the remaining PIDMs will be set to N (all the records could be set to N in the case where none are valid).

In the case where the chosen PIDM has a different address type than the one defined as the default for OCAS processing in the SVROCTL table, the process will insert all new records using the SVROCTL types into the General Person tables, copying the OCAS information available at that moment (AC record) using the SVROCTL address type, telephone type, and so on.

When the applicant birth date has an error in the OCAS file, the default birth date is used when inserting the General person record in Banner. You must correct this date using Banner baseline forms.

Note: SVAODUP clears the duplicate error condition after the user makes a decision (that is, selects one of the listed PIDMs or creates a new PIDM).

After all the changes have been saved, run SVPOCAS to clean up the error status. This process can be called from Launch OCAS Data Process option.

OCAS Program Property Validation (SVVOPP1) page

Use this page to manage the data for the OCAS Program Property, which will be like an attribute attached to the applicant's program. The Program Property can be used for representing any concept, and can be completely different between institutions.

For example, an applicant applying to a NURS program (Nursing) may have FMED (Faculty of Medicine) as Property 1, however another institution may say that the NURS program has FIRSTIME as Property 1, which means that the applicant is applying to that program for the first time.

Web Section Code Validation (SVVOSTN) page

Use this page to enter or display the codes used for web sections on web application page pages.

Web section codes are used for defining the structure of a web application page’s page. Web sections can be associated with multiple web application forms. Values for pre-defined questions are delivered for this page as seed data.

Field Description
Section Type Indicator for the type of section. Values are as follows:

Pre-Defined: This section is system required. The contents of the section are provided as seed data.

User-Definable: This section is defined by your institution. This value is automatically populated for sections added by your institution.
Basic Indicator Check box used to indicate whether the section is part of the basic information that must be obtained for the system to work properly when processing the web application page.

This check box cannot be cleared for the personal information, mailing address, and available programs sections.

Sections for which this check box are selected are the only ones that will be displayed when an applicant first creates a new application. After the applicant saves the application, these sections will be displayed along with all others specified for the applicant type when the applicant accesses the application page in the future.
