Sample Scenarios - SVRTXLU

A list of sample scenarios as examples of possible ways that an institution can set up T2202A.

Scenario 1: Multiple terms

You use the Federal Reporting Year Rules (SVAFRYR) page to track terms that affect T2202 processing for a tax year. The following table lists five sample terms that could exist in the 2010 tax year. Terms 200910 and 201011 overlap two tax years.

Term Description Start Date End Date Percent Fee
200910 2009-2010 Academic Year 01-SEP-2009 31-AUG-2010 60
201011 2010-2011 Academic Year 01-SEP-2010 31-AUG-2011 40
201020 Winter 2010 04-JAN-2010 30-APR-2010 100
201030 Summer 2010 10-MAY-2010 25-JUN-2010 100
201110 Fall 2010 06-SEP-2010 24-DEC-2010 100

Term 200910 is part of the tax years 2009 and 2010. The fee percent is 60 because term 200910 covers only 60% of the year 2010.

Similarly, term 201011 is part of the tax years 2010 and 2011. The fee percent is 40 because term 201011 covers only 40% of the year 2010.

Scenario 2: Full-time/part-time hours

You use the T2202A Education/Tuition Amount Limits (SVATAXL) page to define the number of hours that are considered full time and part time at the tax year level.

If the value in the Full-time Hours per Week field is 9, then any student registered in a minimum of nine hours of classes per week will be considered full-time. If the value in the Part-time Hours per Week field is 3, then any student registered in a minimum of three hours of classes per week will be considered part-time.

Scenario 3: Enrollment status

You use the Enrollment Status Code Rules Definition (SVAESTS) page to track enrollment statuses that affect T2202 qualifying months for student calculation rules. The tuition tax credit calculation will still be completed.

Only enrollment status codes that are specified on SVAESTS page are included in the qualifying months and HWE time calculations. An entry must exist in the SVRESTS table for all enrollment status codes that are to be included in the tax calculation. Those that are missing from SVRESTS will be ignored.

The following table shows an example of a simplified SVAESTS setup.

Enrollment Status Code Description Default Early Exit
AW Administratively Withdrawn   X
EL Eligible to Register X  
RS Reinstated X  
WS Withdrawn   X

In this example, if the Default option button is selected for the enrollment status codes of EL (Eligible to Register) and RS (Reinstated), students with the status codes of EL and RS, who are captured using student rules, will be processed using the term start and end dates.

Furthermore, if the Early Exit option button is selected for the enrollment status codes of AW (Administratively Withdrawn) and WS (Withdrawn), students with the status codes of AW and WS will be processed using the term start date as the start date and the enrollment status date as the end date.

Scenario 4: Registration status

You use the Registration Status Code Rules Definition page (SVARSTS) to define your registration status codes. Only registration status codes that are specified on SVARSTS are included in the various qualifying months and HWE time calculations.

The following table shows an example of a simplified SVARSTS setup as it would appear in the Default Registration Status Code Rule block.

Registration Status Code Description Schedule Rules Section Dates Meeting Section Early Exit
AW Administratively Withdrawn       X
DE Distance Education X      
RE **Registered**     X  
RW **Web Registered**   X    

For registrations with a registration status code for which the Early Exit option button is selected, the system uses the registration status date as the end date. You would use this setting for withdrawals, such as AW in the example.

For registrations with a registration status code for which the Meeting Section option button is selected, the system uses the CRN meeting times, or if no meeting times have been defined, it uses the CRN start and end dates. You would use this setting for “regular” courses, such as RE in the example.

For registrations with a registration status code for which the Section Dates option button is selected, the system uses the section start and end dates. You would use this setting for courses that have set dates, such as RW in the example.

For registrations with a registration status code for which the Schedule Rules option button is selected, the system uses the rules you define in the Registration Status Code Exception Rules Based on Schedule Type block. The following table show an example of a setup for a distance education (DE) course.

Schedule Type Description Open Entry Open Exit Section Dates Meeting Section
B Lab   X  
C Lecture/Lab   X  
D CCN Distance Learning X    
L Clinic     X

The Section Dates and Meeting Section option buttons work the same in this block as in the Default Registration Status Code Rule block.

For registrations that have open start and end dates, such as distance learning courses, you would select the Open Entry/Open Exit option button. For registrations with this setting, the system tracks each student’s particular start and end dates.

Scenario 5: Student rules

You use the HWE Rules page (SVAHWER) to set up your student exclusion and calculation rules. The system first identifies student records to be excluded, then uses the calculation rules to determine all the matching records. Any student record that matches the criteria set up in the exclusion rules will be excluded when the qualifying months for the term are calculated.

For example, to exclude from calculation any students who are not enrolled for credit, you would enter NC (Non-Credit) in the Student Level field on the Student Exclusion Rules tab.

When a student record passes all the exclusion rules, the process checks to see if there are any matching student calculation rules. If more than one field is populated, the record must match all the criteria to be processed.

The rules defined on the Student Calculation Rules tab work with the status codes defined on the Enrollment Status Code Rules Definition page (SVAESTS). The system processes records with characteristics that require qualifying months that would not be easily calculated with the CRN calculation rules (for example, a group of students who receive an extra month for pre-course work done outside of the CRN dates, or graduate students who are registered with no CRNs).

Note: Student rules should be used only if the CRN data in the database does not adequately reflect the student's time in studies. It is recommended that you build your CRN rules first and use student rules only in circumstances where it is absolutely necessary.

For example, you could have a diploma (DIPL) degree that runs past the end date (April 30, 2010) of the 201002 term. The student calculation rules could be set up to extend the end date for student records with a diploma degree, as shown in the following table.

Rule Number Degree Code Student Time Status Full/Part-time Students Number of Months From Date To Date
5 DIPL FT F 8 0110 0410
10 DIPL PT P 4 0110 0410

As shown in this example, students who have a degree of DIPL and who are either full-time or part-time (as defined by the FT and PT values in the Student Time Status field) will have qualifying months calculated for January 2010 to August 2010.

The Full/Part-time Students field is used to indicate if the student will be calculated as a full-time or part-time. When the field has a value of F, then the SVPTAXC/SVPTAXU processes will refer to the values in the Full-time Amount and Full-time Hours per Week fields on the SVATAXL page for the tax year. When the field has a value of P, then the SVPTAXC/SVPTAXU processes will refer to the values in the Part-time Amount and Part-time Hours per Week fields on the SVATAXL page for the tax year.

Any students without a degree of DIPL will have the qualifying months calculated as defined by the CRN rules.

Scenario 6: CRN rules

You use the HWE Rules page (SVAHWER) to set up your CRN exclusion and calculation rules. The system first identifies CRNs to be excluded, then uses the calculation rules to determine all the matching records. Any CRN that matches the criteria set up in the exclusion rules will be excluded when calculating the qualifying months for that particular term.

If a student record does not match any of the student exclusion and calculation rules, the CRN exclusion and calculation rules are used to process the applicable CRNs in which the student was registered. Only records with registration codes defined on the Registration Status Code Rules Definition page(SVARSTS) are processed for qualifying months using the rules on SVAHWER.

For example, to exclude from calculation any records for non-credit CRNs, you would enter NC (Non-Credit) in the Course Level field on the CRN Exclusion Rules tab.

When a CRN passes by all the exclusion rules, the process checks to see if there are any matching CRN calculation rules. The CRN calculation rules process the students’ courses and the HWE for each eligible course. Then, the HWEs determine the qualifying months and the tuition tax credit.

The following table show how you might set up calculation rules for college A and college B.

Rule Number College Unit Factor Default
5 College A CR 6.0000 1.00
10 College B CT 1.0000 4.00

Let’s say that many of your CRNs are based on credits (CR) where a one-semester course is worth .5 credit hours (as defined by a value of .5 in the Credit Hours field on SSASECT). In the example above, rule # 5 tells the system to multiply the credit value (.5) of CRNs for college A by 6 so that a one semester course will grant the student 3 HWEs for that course. If a CRN has no value in the Credit Hours field, then the default value of 1 will be used as the credit hours value when calculating the HWE value, therefore resulting in an HWE value of 6.

For college B, all CRNs are based on contact hours where one contact hour is worth one HWE. In the example above, college B, the unit is contact hours (CT), and the factor is 1 for rule #10. If a CRN has a value of 5 in the Contact Hours field on SSASECT, then a student would be granted 5 HWEs. If a CRN has no value in the Contact Hours field on SSASECT, then the default value of 4 will be used as the contact hours value when calculating the HWE value.

Scenario 7: Meeting times

In this scenario, meeting times are used extensively because they were determined to be the best method for equating weekly hours. The meeting times for this CRN overlap. The SVPTAXC process treats each meeting time like a mini-CRN allowing for each meeting time to calculate its contribution toward the HWE for the dates covered. In this example, sample CRN 8915 has multiple meeting times, and each time slot has its contribution assigned to its own sequence, which is used to determine each month's qualification toward part- or full-time qualifying months.

With specific calculation

In this scenario, the following situations occurred in order for the specific calculation to be used:
  • The Specific Calc when MT for PT m parameter was set to Y when the SVPTAXC process was run.
  • The student met the CRN calculation rules in the SVAHWER page.
  • The student is in one of situations that are described in cases for specific calculation section listed in the part-time months calculation chapter of this document.
  • At least one of the Days of the Week check boxes was selected on the Meeting Time block on the SSASECT Form for a CRN in a term that the student has registered.
A student taking CRN 8915 will qualify for part-time status for the months of January and February as January in 2002 has 17.005 hours, and February has 15.005 hours. See the table below for a break down of how the hours were calculated for each month using the specific calculation.

The specific calculation uses the following logic.

The HWE multiplied by the number of days when a student is scheduled to attend a class in a week divided by the total number of days marked in the student meeting record.

For example, for Meeting Time 2 in Week 1, the HWE is 3. Classes are set to meet Monday, Thursday and Friday of each week, but because the week starts on Tuesday, January 1, the student only attends classes on Thursday, January 3 and Friday January 4. Therefore, the calculated HWE for Meeting Time 2 in Week 1 is 3 * 2/3 = 2.

Scenario 8: Remaining balance amount

This scenario explains how the remaining balance amount is calculated. For terms that cross tax years, special processing has to take place to ensure the correct fees are attributed to each tax year. First, the fees are generally split based on the weighted percentage of the course amount when CRN rules are used, or the percentage of the term that falls within the tax year when student rules are used. However, this can be affected by changes to the student record from one year to the next within a term (for example, institutions that have one term that spans from September 2009 to May 2010 where the students register in individual parts of the term). After processing the T2202 for the first tax year, the student may register and pay for additional courses. In this case, the student would now qualify for an amount that is more than the percentage that will be calculated for that term in the second tax year.

The following table show a student who registered in CRNs 1112, 1113, and 1114 and paid the tuition charge in October 2009. In this example, these courses ran until May 30, 2010. The total charge for these courses was $1530.00. In January 2010, this student registered in an additional CRN 1115 that only runs from January to May of 2010. This course cost an additional $170.00.

CRN Registration Date Paid Date Tax Year Paid Tuition Charge
1112 15-OCT-2009 23-OCT-2009 2009  
1113 15-OCT-2009 23-OCT-2009 2009  
1114 15-OCT-2009 23-OCT-2009 2009  
Total: $1530
1115 04-JAN-2010 04-JAN-2010 2010  
Total: $170

For tax year 2009, the student receives a Tuition Tax Credit (TTC) of $765 which is half of the fees paid for the first three courses.

However, in the 2010 tax year, an additional $170.00 has been added. When the process calculates the split for the term (half of the total fees paid of $1700), the result would be $850.00. As the term end date is earlier than the tax year end date, an additional check is performed to ensure that the student has received the maximum of the calculated amount and the available amount. In this case, the student is now eligible for $1700 in total for the term. As the student only received $765 in the first tax year, the remaining balance of $935 ($765 + $170) is received in 2010. The Remaining Balance indicator is set to Y in the Student Rule Calculation Detail or CRN Rule Calculation Detail block of SVATAXC Form to indicate that calculated amount has been altered.

In much the same way that the fees are checked for the split term above, the SVBTXTP table is used to capture the proper split when the tax year for the term, which crosses more than one tax year, exists in an environment that did not use this modification. For these instances, an institution can use the SVBTXTP tables to store the amount of the TTC given to students in the prior year for terms that cross the tax year. The process will take in to account these amounts when calculating the current years TTC.
