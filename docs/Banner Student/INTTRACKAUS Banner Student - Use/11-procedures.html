Define reporting data elements

This procedure is needed only for Australian CRICOS reporting.

About this task

To map Banner data to reporting data elements, you must create activities in the MDUU. Before you can create these activities, you need to define the elements and their valid values as described in the following procedure. Element codes have been delivered for reporting elements that do not have a logical baseline Banner location and are required for CRICOS reporting.

Procedure

  1. Access the Report Element Validation (SKVRVAL) page.
  2. Define each element to be mapped.
  3. Save your changes.
  4. Access the Report Element Values (SKARVAL) page.
  5. Define the valid values for an element as follows.
    Note: You must define a separate record for each valid value for an element. For example, if an element has six valid values, you must define six records, one for each value.
    1. Create a new record.
    2. Enter the element name, as defined on SKVRVAL, in the Element Code field.
    3. Enter a valid value for the element in the Element Value field.
    4. Enter the text description associated with the value in the Description field.
    5. Select the Active check box.
    6. If the valid value is to be in use only for a limited time, enter the last date on which the value is to be used in the End Date field.
    7. Save your changes.
    8. Repeat step 5 for each valid value.

Define system parameters

There are several reporting elements where the selection of the correct data depends on specific Banner codes.

About this task

For example, to identify whether a student received a charge for their OSHC, you must query the accounts receivable tables for charges with an OSHC detail code. If you have defined OSHC as the detail code, you would assign it as the value for the OSHC system parameter. A student who has no charges with an OSHC detail code will not be included in the OSHC snapshot.

To support interconnectivity between baseline codes and INTTRACK reporting elements, a predefined set of system parameters is delivered with INTTRACK Reporting, and you must configure these parameters for use. You can modify the delivered parameters to meet your needs, or you can create new ones. Those that are required by the system are noted as such in the System Parameters section.

Only users with appropriate permissions can define or modify system parameters.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Enter the academic year code in the Academic Year field, then go to the next block.
  3. Enter the parameter for which you want to enter valid values in the Parameter field.
  4. Enter the valid value(s) for the parameter in the Value field.
    You can enter multiple values for each parameter, separated by a comma, up to 2,000 characters.
  5. If desired, enter information in the Description and Notes fields.
  6. Save your changes.

Copy system parameters to another year

System parameters are associated with an academic year. You can copy one year's parameter definitions to another, then modify the new definition as desired.

About this task

When you copy system parameter rules from one year to another, all rules are copied. System parameter rules cannot be deleted if the system required indicator is selected, but the parameter value can be updated to null. System parameter rules can be deleted after being copied to the new academic year if the system required indicator is not selected. You can copy rules forwards or backwards in time; the only restriction is that you cannot copy system parameter rules to an academic year that already has system parameter rules.

If you attempt to copy parameters to a year for which at least one parameter has already been defined, the system does not perform the copy and displays an error message.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Select the Copy Rules to New Year button.
  3. Enter the code of the academic year to be copied in the From Year field of the Copy Rules window.
  4. Enter the code of the academic year to which the definitions are to be copied in the To Year field.
  5. Select the Process Rule Copy button.
  6. If desired, modify the parameter definitions as explained in the Define system parameters section.

Build CRICOS course data

This procedure is needed only for Australian CRICOS reporting.

About this task

The following procedure explains how to build data for capture by the snapshot activity (ASC_SNA_CRICOS_COURSE) for each file when the CRICOS Course Data Reporting file is created.

Procedure

  1. Access the CRICOS Course Data (SKACRIC) page.
  2. Enter the institution ID in the ID field of the key block.
  3. Enter a program code in the Program field, or click Search to select a program.
  4. Enter the term code in the Term field.
  5. Select Next Block.
  6. Enter the course definition details in the CRICOS Course Definition window.
  7. Save the record.

    Refer to the INTTRACKAUS Reference for more information on field descriptions.

Process INTTRACKAUS data

Use this procedure to produce data for users to manage compliance reporting.

The SC_INTERNATIONAL_TRACKING process is used to produce INTTRACK data. This process contains snapshot, extract, and export activities.

The SC_INTTRACK_ATTENDANCE process is used to produce INTTRACK attendance data. This process contains snapshot, extract, and export activities.

You can control the execution of each process to run specific activities or tasks separately, or to run all tasks and activities together. However, we advise you to run each task separately, evaluating the data each time. This results in better processing times and allows you to do any data cleaning before the final data is used in any reporting.

Refer to the Banner Mass Data Update Utility Use for more information about the pages.

SC_INTERNATIONAL_TRACKING

Use this process to produce INTTRACK data. This process contains snapshot, extract, and export activities.

Procedure

  1. Access the Execution Tree Set-up (GKAPEXS) page.
  2. Enter SC_INTERNATIONAL_TRACKING in the Process Code field.
  3. Select Next Block.
  4. Customise the execution tree to meet your local requirements, for example, by changing the status of tree nodes using the Change Status button.

    If desired, you can customise the activities and add these to the execution tree, or you can create your own execution tree. If you customise the activities, you need to create local copies of the baseline activities first.

  5. Access the Process Tree Execution (GKAPEXE) page.
  6. Enter SC_INTERNATIONAL_TRACKING in the Process Code field.
  7. Select Next Block.
  8. Select the required stages on the Execution Tree Set-up window.
  9. Go to the Execution window.
  10. Enter the appropriate run-time parameters, as shown in the following table.
    Parameter name Description
    Activities for Overseas Student Health Cover data (SC_SNA_OSHC, SC_EXT_OSHC and SC_EXP_OSHC)
    Academic Year The academic year for terms that should be included in the report.
    Purge Before Populate If set to Y, target tables rows for the academic year, report period and submission combination will be purged before being re-populated.
    Report Period The report period that has been linked terms that should be included in the report, on the Reporting Calendar (SKAREPT) page.
    Submission Number The submission number that has been linked terms that should be included in the report, on the Reporting Calendar (SKAREPT) page.

    If Reporting Calendar rules have been built without using Submission, then leave this blank and it will default to 0.
    All other activities in this process tree
    Academic Year The academic year for terms that should be included in the report.
    Date since activity last run Enter a date as DD-MON-YYYY to pick up records that have met the selection criteria for an activity from the last time the activity was run.
    Purge Before Populate If set to Y, target tables rows for the academic year, report period and submission combination, that also match the value entered for 'Date since activity last run' will be purged before being re-populated.
    Report Period The report period that has been linked terms that should be included in the report, on the Reporting Calendar (SKAREPT) page.
    Submission Number The submission number that has been linked terms that should be included in the report, on the Reporting Calendar (SKAREPT) page.

    If Reporting Calendar rules have been built without using Submission, then leave this blank and it will default to 0.
  11. Change the value in the Execution Mode field to Update.
  12. Select either the Run for Jobsub or Run Now button, as desired, to execute the process.
  13. Review the results by selecting the View SQL log.
  14. Access the Universal Viewer (GKAPUNV) page to review the data generated by the process.

Create CSV reports

You can use the baseline data extract feature to create a data extract that can be used in MS Excel. The CLOB text can be converted to columns within MS Excel.

Alternatively, you can use an ODBC connection to import data directly into MS Excel. For example, you might use this feature to import the contents of the OSHC Data Extract (SKREOSH) table or the OSHC Data Export (SKRXOSH) table directly into an excel workbook.

Export CLOB column as CSV file

Use the following procedure to export the CLOB column as a csv file.

Procedure

  1. Access the Universal Viewer (GKAPUNV) page.
  2. Type the export table name (for example, SKRXESO) or select the name of the export table containing the data you want to export.
  3. Use the Filter Column and Filter Value fields to filter the data that you want to export (for example, you can filter for a particular academic year and report year combination).
  4. Select Next Block.
  5. Navigate to the CLOB column.
  6. Double-click to open the Export Data window.
  7. In the Filter field, type ORDER BY TABLENAME_SEQNO, where TABLENAME is the name of the export table containing the data you want to export, (for example ORDER BY SKRXESO_SEQNO).
  8. In the Directory field, type or select the directory where the you want the exported file to be saved.
  9. In the File Name field, type a name for the file being sure to use the .csv extension.
  10. Click Export Column Data.

    The file can be opened in Excel and will have a header row and the data will be correctly arranged in columns.

    If your data contains special characters, such as accents in student names then you will need to use the Data Import feature of Excel to ensure that Excel opens the file using the UTF-8 character set.

View CSV file in Excel

Assuming that you have Excel 2007, use the following steps to view the saved csv file data in Excel.

Procedure

  1. Open Microsoft Excel application.
  2. Click New or press CTRL+N to create a new document or open an existing spreadsheet if you want to append rows to an existing file.
  3. Click the Data tab.
  4. In the External Data group, click From Text.
  5. Locate and select your csv file.
  6. Click Import.
  7. As a first step in the Text Import wizard, as a first step, set Original Data Type to Delimited.
  8. Change the File origin to UTF-8.
    It might be listed as 65001: Unicode (UTF-8).
  9. Click Next.
  10. As a second step in the Text Import wizard, select , (comma) as the delimiter.
  11. Click Finish.
    In the Import Data box, you can select to store the data into the existing sheet, and can nominate the cell for starting the import. For a new document, this is likely to be the first cell - $A$1. For adding rows to an existing document, select the first empty cell in your document.

View INTTRACKAUS data

You can view the INTTRACKAUS extract and snapshot data using a SQL tool such as SQL*Plus or a reporting tool like Oracle Discovery. The MDUU includes a Universal Viewer to allow this data to be viewed.
