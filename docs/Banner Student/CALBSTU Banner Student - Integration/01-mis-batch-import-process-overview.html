MIS Batch Import Process Overview

Ellucian provides batch import processes that enable institutions to upload MIS reporting data for multiple students simultaneously into Banner CALBSTU.

The batch import processes address customer needs to capture student contact and services data from external systems and sources—at the point of delivery—and import that data directly into Banner CALBSTU.

Ellucian delivers the initial batch import process and any future batch import processes in Experience as a Data Connect integration package or pipeline. For details, see the Configuration requirements for batch import pipelines.

Prerequisites

Before you run any of the Banner CALBSTU batch import processes, you must apply several software upgrades.

Please ensure you have installed the minimum required versions of these products:
  • Banner CALBSTU 9.3.31
  • Banner CALBSTU 8.18
  • Banner Student 9.3.31
  • Ethos DB upgrade 9.30.0.3
  • Banner Student API 9.32.2
  • Banner Business Process APIs

Configuration requirements for batch import pipelines

Before you can run any batch import process pipeline, you must complete several configuration steps in Banner and Experience.

  1. Create a Banner user. For details, see Create a Banner user.
  2. Set up user permissions in Banner.
    • For SVAMIST, follow this procedure: Set up user permissions in Banner using GOAFBPR
    • For SVANEED, follow this procedure: Set up user permissions in Banner using GSASECR
  3. Configure permissions in Experience. For details, see Set up user permissions in Experience.
  4. Assign permissions to users for Data Connect Integration Packages. For details, see Grant permissions in Data Connect.

Create a Banner user

You must create and admin user in Banner and assign the appropriate API permissions, to allow those users to make proxy API calls to Ethos integration.

Before you begin

Work with your database administrator for URL access to the Banner Access Management application, which is where the Banner Security pages are located.

Note: For detailed information about administering Banner Security, see Security.

Procedure

  1. Log in to Banner Access Management.
  2. Navigate to the Oracle/Banner Security Maintenance (GSASECR) page.
  3. On the Users tab, enter a User ID. For example, API_USER.
  4. Click Create.
  5. Enter a password in the Password and Verify Password fields.
  6. In the Temporary Tablespace field, select a value from the List of Values.
  7. In the Default Tablespace field, select a value from the List of Values.
  8. In the Default Role field, enter USR_DEFAULT_CONNECT as the default role.
  9. In the Profile field, select a value from the List of Values.
  10. Select the Authorize BANPROXY check box.
  11. Select the Authorize BANJSPROXY check box.
  12. Click Save to create the new user ID.
  13. Optional: To enter information that applies to the institution, click Banner Rules. Enter any appropriate information and click Save.
  14. Optional: If Banner has been configured for MEP, the user must be authorized for any VPDI contexts that will be accessed from APIs. Navigate to the Oracle/Banner VPD Security Maintenance (GSAVPDI) form. To give a user access to the institution code other than the code that is set as the system default, click the User Assignment tab and assign the appropriate values.
  15. If required, assign privileges to the Banner user.

        • AD FS - the LDAP attribute mapped to the Outgoing Claim Type of userId.

SVANEED batch import pipelines

The SVANEED batch import pipelines allow schools to import basic needs data that they would typically manually enter on the Student Basic Needs (SVANEED) page.

The SVANEED page enables schools to record and display services and support that a student received through the Basic Needs Center at the college. The SVANEED page contains eight tabs, which collect data on the following: food, housing, transportation, mental health, child care, physical health, technology, and veterans.

There is a separate package and pipeline in Experience for each tab of the SVANEED page:

Tab Package Pipeline
Food SVANEED - Food Import Process ca-mass-student-food-needs
Housing SVANEED - Housing Import Process ca-mass-student-housing-needs
Transportation SVANEED - Transportation Import Process ca-mass-student-transportation-needs
Mental Health SVANEED – Mental Health Import Process ca-mass-student-mental-health-needs
Child Care SVANEED – Child Care Import Process ca-mass-child-care-health-needs
Physical Health SVANEED – Physical Health Import Process ca-mass-student-physical-health-needs
Technology SVANEED - Technology Import Process ca-mass-student-technology-needs

When this batch import pipeline is created, it uses the Ethos API Key from the Priority Registration Services Proxy Ethos application. After a pipeline is initially configured, this Ethos API Key is persistent in all subsequent pipeline jobs that are created from the pipeline. For details, see step 11 in Create the Ethos application for the Priority Registration Services Proxy.

Note: SVANEED also has Veterans tab. The batch upload process to upload data to this tab is not available at this time. The batch upload is planned for a future release.

SGAEOPS batch import pipelines

The SGAEOPS batch import pipelines allow schools to import data from the Education Opportunity Programs and Services Page (SGAEOPS) page.

SGAEOPS is an optional form found in baseline Banner Student that allows California institutions to record and maintain information related to a the Education Opportunity Programs (EOPS) status eligibility factors, acceptance date, and financial aid eligibility for a student.

There are two pipeline jobs for SGAEOPS:
  • SGAEOPS - Import process, with the pipeline ca-import-mass-education-opportunity-programs-services
  • SGAEOPS - Eligibility Factor Batch Import, with the pipeline ca-eops-eligibility-services.

Currently SGAEOPS pipelines only allow you to import data massively to the Education Opportunity Programs and Services and Eligibility Factor sections.

When this batch import pipeline is created, it uses the Ethos API Key from the Priority Registration Services Proxy Ethos application. After a pipeline is initially configured, this Ethos API Key is persistent in all subsequent pipeline jobs that are created from the pipeline. For details, see step 11 in Create the Ethos application for the Priority Registration Services Proxy.

SVAMIST batch import pipelines

The SVAMIST batch import pipelines allow schools to import student data, required by the Special Population Data Report (SG), from the MIS Special Term Data (SVAMIST) page.

The SVAMIST page enables schools to record and display the academic programs and support services that a student received through various state- and nation-wide initiatives. The SVAMIST page contains ten tabs, which collect data on the following:
  • Justice: status of students who are or were incarcerated or part of a juvenile justice program
  • MESA/ASEM: status of students in the Mathematics, Engineering, and Science Achievement (MESA) or Achievement in a Science, Engineering status and Mathematics (ASEM) programs
  • Puente: status of students in the Puente Program, a nationwide initiative that enables educationally-underrepresented or disadvantaged students to enroll in four-year colleges and access writing, counseling, and mentoring services
  • MCHS/ECHS: status of students in the Middle College High School (MCHS) or the Early College High School (ECHS) programs
  • Umoja: status of students in the Umoja Program, a worldwide initiative to increase the number of African Americans and people of color at four-year colleges or universities and mentor future students in their communities
  • Career Advancement Academy: status of students participating in the Career Advancement Academy (CAA)
  • Foster Youth: status of students participating in Cooperating Agencies Foster Youth Educational Support (CAFYES)
  • College and Career Access Pathways: status of students participating in COLLEGE AND CAREER ACCESS PATHWAYS (CCAP)
  • Work-based Learning: status of students participating in work-based learning programs
  • A2MEND: status of students participating in the A2MEND program

After you complete the configuration steps in Banner and Experience, you must create a CSV input file that contains the data you want to batch import into the SVAWIOA page.

You must use a CSV format in Microsoft Excel for your SVAWIOA data. Make sure your file uses comma as a separator.

The CSV input file is required to run the Run SVAWIOA batch import pipeline jobs.

Run SVAWIOA batch import pipeline jobs

Set up batch import pipeline jobs in Experience to successfully import data to the SVAWIOA page.

Before you begin

This procedure shows you how to use the pipeline to import data to the "Student data ” section on the SVAWIOA page.

Procedure

  1. In the Integration Packages card on the Experience dashboard, click the SVAWIOA - SVAWIOA - Workforce Innovation and Opportunity Act Import Process package.
  2. On the Integrations Package page, under PACKAGES, click ca-import-mass-workforce-innovation-opportunity.
  3. Click + NEW JOB to access the New Job page.
  4. On the New Job page, enter settings for the job:
    Field Required? Entry
    Job name yes Enter a descriptive name for this job. If you create multiple jobs for this pipeline, you can use this name to find this job on the Pipelines page

    Example: WorkforceOpp_2024
    Import File Name yes Enter the import file name

    Example: WorkforceOpp_2024.csv

    Note: The filename cannot exceed 30 characters, which includes the .csv extension.
    Term Code yes Enter the term code from the Term Code Validation (STVTERM) page
    Note: The pipeline will not run if you don't populate all the job parameters.
  5. You can run the job one time or set up a recurring schedule. For example, during testing you might choose to run a job one time. For ongoing processing of applications, you would likely set up a schedule.
  6. If you set up a schedule for the job, and you want the schedule to end at a certain date and time, do the following:
    1. Enable the toggle switch for Setup Job Stop Date/Time?.
    2. Select the desired stop date.
    3. Enter the desired stop time in the HH:MM AM/PM format. If you leave this field blank, the stop time defaults to 11:59 PM.
  7. Optional: In the Advanced Options section of the page, modify the default settings as needed:
    1. In the Maximum Concurrency setting, specify the number of concurrent threads for this job.
      Some pipeline jobs use multiple concurrent threads for processing. Increasing the number of concurrent threads can improve processing time, but too many simultaneous threads might overwhelm the target system for the job.

      You can accept the default of 10 threads unless you are seeing performance issues. If the pipeline job is taking a long time to run, try increasing the number of threads. If you are seeing performance issues in the target system, try decreasing the number of threads.

    2. In the HTTP Request Timeout setting, specify how long this pipeline job should wait for HTTP requests to complete (in minutes).
      You can accept the default of three minutes unless a job run fails with the following error message: The request exceeded the maximum timeout of <#> minutes and was aborted. In that case, increase the timeout and run the job again.
  8. Click Save.
  9. You must click Refresh to update the status of your job.
    If a job run fails, see: Output errors.

Upload and download files within Experience

Learn how to upload and download files within the Experience.

Before you begin

To ensure that the pipeline job runs successfully and no errors occur, you must:
  • Use a CSV format for the import file
  • Include any required fields for each student record

About this task

CALBSTU customers can upload and download their CALBSTU files using the Data Connect user interface (UI) rather than the S3 and SFTP options. Customers who are set up to use the S3 and SFTP may continue to do so, but Ellucian encourages them to transition to the Data Connect UI at their earliest convenience.

Procedure

  1. Log in to Experience.
  2. From the Integration Packages card, click the name of a package.
  3. At the top of the Package page, click the Upload Supplemental File icon.
  4. Select a supplemental file from your desired location.
  5. Click the pipeline link to execute the CALBSTU batch import pipeline job.
    1. Click Edit Job Parameters icon.
    2. In the Input Filename field, enter the name of the supplemental file and click Save. The name must match the file name you uploaded.
    Note: If a job does not exist or you want to create a new job, follow the steps in the SVANEED batch import pipelines topic.
  6. When the pipeline job finishes, go to the Actions column and click the View Files icon.
  7. From the Job Run Files window, click the Download icon and then and open the output file to view the details.

Troubleshoot pipeline error messages

If a job run fails, or if you are not seeing the expected results, you can access troubleshooting information from the job runs page.

Before you begin

The user performing this procedure must have the following access:
  • A role that has been assigned to the Experience card.
  • The View or Manage permission on the integration that includes this pipeline.

Procedure

  1. If you are already on the Job page for the job run that you want to troubleshoot, skip to Step 5.
  2. On the Data Connect integration packages card on the Experience dashboard, click your integration package.
    The title of the card on your dashboard is the name specified during card configuration by an administrator at your institution. The default title is Integration Packages.
  3. On the Package page, in the table of pipelines, click the pipeline for the job you want to troubleshoot.
  4. On the Pipeline page, in the table of jobs, click the job that you want to troubleshoot.
  5. On the Job page, in the table of job runs, locate the job run you want to troubleshoot and view the summary information in that row.
    Key information for troubleshooting includes:
    Column Description
    Status Overall status of the job run.
    Errors If there are errors in the job run, a View Errors link is displayed. Click the link to see error details.
    Actions If you enabled diagnostic logs for this job run when you set up the job, a diagnostic log zip file is generated after the job runs to completion. Click the View Files icon in the Action column, and then download the diagnostic logs zip file from the Job Run Files dialog box.
    The zip file contains:
    • A plan.json file that describes the structure of the job run.
    • One or more execution log files with details about what happened during the job run. The execution logs have filenames like <job_run_id>_n_n.json

    In some cases, for example if the pipeline execution fails validation, the zip file will contain only the plan.json file, with no execution logs.

    A complex job run might generate a large number of execution log files. The zip file is capped at a maximum of 1,000 files. If the zip file from a job run contains 1,000 files, this indicates that some data from the job run is not included in the log files.

    The diagnostic logs zip file is automatically deleted seven days after the job run.
