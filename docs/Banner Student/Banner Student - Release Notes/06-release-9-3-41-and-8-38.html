Release 9.3.41 and 8.38

The Banner Student 9.3.41 and 8.38 release includes quality improvements and technical currency updates.

New Hold Information page (SGASTHD)

The Hold Information (SGASTHD) page includes a new Hold by Term section that provides comprehensive management of term-specific registration holds. This enhancement enables administrators to:

  • Create and manage term-based registration holds with individual active indicators.
  • Associate specific hold types with academic term codes for targeted enforcement.
  • Control hold activation status independently for each term-hold combination.
  • View complete hold history including both active and inactive term-based holds.
  • Maintain separation between traditional date-range holds and term-specific holds.

The Hold by Term section restricts hold validation to registration hold types only, ensuring proper enforcement during registration processes. Each hold entry specifies a single term code (no term ranges) and includes an active indicator that determines whether the hold enforces registration restrictions.

Note: Only holds with Active Indicator = Y prevent registration. Holds with Active Indicator = N remain for historical tracking without affecting student registration capabilities.

The SPRTHLD database table provides the data foundation for term-based registration holds. This table stores term-specific hold assignments and includes:

  • Student identification: Links holds to student PIDM for individual student tracking.
  • Term code: Specifies the academic term for which the hold applies.
  • Hold type code: References registration hold types defined in STVHLDD.
  • Active indicator: Controls whether the hold enforces registration restrictions (Y = active enforcement, N = historical record).
  • Release indicator: Controls whether only the system user who entered the term hold may release it (when set to Y).
  • Audit fields: Captures creation and modification timestamps with user attribution.

Registration APIs: person-holds - Enhancement of this API will be addressed with PE0007779 in a future release.

FVT/GE Reporting process (SFPGESC) enhancement

FVT/GE reporting process (SFPGESC) is enhanced so that Banner can automatically derive a student’s program withdrawal status using National Student Clearinghouse (NSC) style required-term gap logic, instead of relying only on manually entered W statuses.

Using the required-term structure from SFACPLT/SFRCPTT, the process:

  • Identifies required terms in which the student is expected to be enrolled.
  • Detects gaps when a required term has:
    • no SFBETRM record, or
    • SFBETRM but no qualifying enrolled registration (no count-in-enrollment course).

  • When such a gap follows a term with an enrolled status (F/Q/H/L/A), the process:

    • Derives a program withdrawal
    • Sets the withdrawal date to:
      • the prior required term end date for F/Q/H/L statuses, or
      • the LOA effective date for A (Leave of Absence),
    • Creates TA records when withdrawal date falls in the award year and the student received Title IV aid.

Additional rules:

  • Non-required terms (such as summer) never trigger a derived withdrawal.
  • Manual withdrawals always override the derived logic, and withdrawals for other programs are not changed.
  • CEU logic is explicitly excluded, while GE/FVT reporting is aligned with NSC calculated-withdrawal methodology.

This enhancement aligns Banner GE/FVT reporting with NSC logic, reduces manual maintenance of withdrawal statuses, and improves accuracy and compliance for unofficial withdrawals.

Course Program of Study (SFPCPOS) process enhancement

The Course Program of Study (SFPCPOS) process introduces a new parameter Include Graded and Rolled Courses (IGR) to explicitly control whether graded and rolled courses are included in CPOS processing. This enhancement enables institutions to manage on-demand Degree Works reconciliation without reprocessing completed coursework, while maintaining the ability to perform full historical re-evaluations when needed.

  • IGR = Y: Graded and rolled courses are eligible for CPOS selection and evaluation.
  • IGR = N (default): Graded and rolled courses are excluded from CPOS processing and remain frozen, protecting completed coursework from post-grade changes.

The new parameter is available through:

  • Job Submission pages for automated and scheduled SFPCPOS runs
  • Relevant UI control pages for manual CPOS execution
  • Batch processing workflows and integration scripts
Tip:
  • For routine incremental processing triggered by registration changes, use the default configuration (On-Demand = N, IGR = N) to maintain stability.
  • For Degree Works exception reconciliation without reprocessing completed work, use (On-Demand = Y with IGR = N). Reserve the combination (On-Demand = Y with IGR = Y) for scenarios requiring complete historical re-evaluation.

SFRNSLC report regulatory updates

Ellucian enhanced the National Student Clearinghouse/NSLDS Interface Program (SFRNSLC) logic to properly distinguish between required and non-required terms when reporting enrollment status and program status effective dates (PSED) to the National Student Clearinghouse. This enhancement aligns Banner with NSC continuous enrollment reporting guidance for non-required terms such as summer sessions and other non-compulsory terms.

Required vs. Non-Required Term Determination

The enhancement uses the Required Terms Rule (SFACPLT) to determine whether a term is considered required for a student’s academic program.

  • Required terms are those explicitly defined in the SFACPLT rule for the applicable curriculum.
  • Non-required terms are any academic terms that are not listed in the applicable SFACPLT rule.

SFRNSLC evaluates the student’s primary, current, and active curriculum record and applies the weightiest matching SFACPLT rule to determine term classification.

Processing Logic for Required Terms

For terms identified as required, SFRNSLC continues to use existing logic, including:

  • Required-term gap detection
  • Program status determination
  • PSED calculation rules

There are no changes to existing required-term behavior.

Processing Logic for Non Required Terms

For terms not defined as required in SFACPLT, SFRNSLC applies updated logic aligned with NSC guidance:

  • The student’s actual enrollment status (FT, HT, LTHT, 00) is reported for the non-required term.
  • Skipped or LTHT/00 non-required terms do not create required-term gaps.
  • PSED for the next required term is preserved unless a sustained increase in status occurs.
  • Non-required term decreases do not reset required-term PSED

Centric Periods support

The enhancement supports institutions using Centric Periods = Y. Time status derivation continues to use Centric Period logic when enabled, and required vs non-required term classification is still determined through SFACPLT. Required-term logic remains unchanged

Example scenario:

  • Spring (Required term per SFACPLT): Student enrolled full-time with PSED of January 10, 2025.
  • Summer (Non-Required term – not listed in SFACPLT): Student enrolled Less Than Half-Time (LTHT).
  • Fall (Required term per SFACPLT): Student enrolled full-time.

When SFRNSLC is run for the summer term:

  • Summer status is reported as LTHT based on actual enrollment..
  • Summer PSED reflects the summer effective date.
  • No required-term gap is created.
  • Required-term PSED continuity is preserved.

When SFRNSLC is run for the fall term:

  • Required-term logic applies.
  • If no sustained status increase occurred, PSED reverts to the most recent required term where status changed.
  • Continuous enrollment is maintained per NSC guidance.

Configuration requirements

To use this enhancement, institutions must configure the Required Terms Rule (SFACPLT) for each applicable academic program.

  • Define required academic terms (for example, Fall and Spring).
  • Do not list non-required terms (for example, Summer) in the rule.
  • Ensure rules are properly aligned with institutional academic policies and NSC reporting requirements.

If no matching SFACPLT rule exists for a student’s curriculum, SFRNSLC defaults to existing required-term processing behavior.

Additional Notes

  • No Banner code changes were made related to NSC warning codes (292, 1861–1866, 1901–1906); these are generated and managed by NSC.
  • Existing withdrawal and graduation logic remains unchanged.

This enhancement addresses PE0004344 in the Ellucian Customer Center.
