2024 Releases

Release 9.3.36 and 8.33

The Banner Student 9.3.36 and 8.33 release includes quality improvements and technical currency updates.

Enhancement to support the Assembly Bill (AB1111)

A new page Course Alias Usage Rules page (SCACARL) is introduced in Banner Admin to support the AB1111 - Common Course Numbering legislation. Use this page to control the Course Alias field v/s the Course field configuration in your institution.

This enhancement addresses PE0004633 in the Ellucian Customer Center.

Anonymous Grading updates

The Anonymous Grading Controls section is removed from the Academic History Control (SHACTRL) page. The dependencies on the SHBANGD fields are removed from the student-anonymous-grading-registered business event and from the svq_anonymous_grading view.

The relevant controls were the length of the anonymous grading ID, whether used to generate IDs by section or by term or to generate separate Midterm IDs and regardless if grade adjustments were used. Controls are moved to the Anonymous Grading settings page in Ellucian Experience.

Anonymous Grading is an Experience SaaS solution, the anonymous ID generator will be available in Experience.

Note: All Banner feature updates related to Banner Anonymous Grading are in support of a future Ellucian SaaS Solution.

This enhancement address PE0005157 in the Ellucian Customer Center.

Clock Hours to Credit Hours Conversion enhancements

This release includes enhancements that enable the conversion of clock hours to credit hours to support accurate financial aid disbursements based on credit hours. The Basic Course Information (SCACRSE) page includes a new Clock Hour field. When you set the Clock Hour field to Y, the Schedule (SSASECT) page will dynamically calculate Credit Hours and Billing Hours based on Contact Hours for clock hour courses.

Process enhancements

  • The Advisor Assignment Process (SGPADVA) is enhanced to delete or end a single advisor, or all advisors depending on a specific Advisor Type.

    This enhancement addresses PE0005176 in the Ellucian Customer Center.

  • A new parameter Outcome Record Required is introduced in the Transcript Population Creation Process (SHRTPOP), which allows the user to set the parameter to N, so that the students in the population selection do not need to have a SHADEGR record. By default the valid value of the parameter is Y.

    This enhancement addresses PE0005314 in the Ellucian Customer Center.

Generate transcripts for multiple levels

The Transcript Request (SHARQTC) page is enhanced with a new Level section for users to enter up to 10 level codes for a multiple level transcript request.

A Level Option radio group is added so that when users make requests, they can indicate whether the request is a Single Level, Multiple Levels, or All Levels request.

The Level Option (SHTTRAN_LEVEL_OPTION_CDE) field automatically updates for any existing records, as follows:

  • Any existing records with AL as the Level code has the Level Option set to A - All Levels.
  • All other existing records will have the Level Option set to S - Single Level.

There is no change in the existing functionality, and the transcript requests for a single level, or for all levels will continue to work correctly even if the Level Option field is not populated. Any existing customer methods of populating the SHTTRAN table for single level or all levels transcript requests will continue to work, similar to eTranscript requests. This enhancement does not change the eTranscripts.

For more information, see the Transcript Request section in Banner Student Page Reference.

This enhancement address PE0004504 in the Ellucian Customer Center.

Release 9.3.35.1 and 8.32.1

The Banner Student 9.3.35.1 and 8.32.1 release includes US Regulatory updates to meet Gainful Employment/FVT reporting needs.

New section for Financial Value Transparency / Gainful Employment

The September 2024 Banner releases bring the Gainful Employment processing within Banner up to the new regulations.

The Department of Education has renamed the regulations to “Financial Value Transparency / Gainful Employment” (also known as FVT/GE). Ellucian has implemented both the “Financial Value Transparency” and “Gainful Employment” in the Banner pages and processes, and has retained the original (shorter) designation of “Gainful Employment” (also known as, GE).

Direct any questions about the regulations to the appropriate government agency.

Overview of processing

The FVT/GE regulations include reporting both details about students and high-level information about programs. These are two separate reports.

Ellucian has enhanced the existing configuration/rules page so that institutions can enter information for both of the reports on this single page. Ellucian continues the practice of isolating the GE configuration from other Banner Student configuration because of the dependency on the Federal regulations.

For both reports, Ellucian anticipates that an institution will:
  • enter the configuration and rules.
  • run the appropriate process (student or program) to write the data to the table.
  • use the appropriate administrative page to review and possibly update the data.
  • repeat the above steps until satisfied with the data.
  • run the same process to extract the data from the table to create the comma separated value (.csv) file
  • submit the file to the National Student Clearinghouse (NSC)

The two report processes are independent; an institution can choose to work on one process, or work on both processes simultaneously.

Standard versus Transitional processing

For this reporting year, institutions will need to choose if they are following the “Standard” or the “Transitional” method. Depending on this choice, the institution will need to report student data for different years and with different populations. Ellucian is providing a job/sub parameter to enable you to control the students included in the files Banner generates. The following tables provide more detailed information.

Banner generates, verifies, and independently submits the files for the various years. You can process the files in any order.

For institutions choosing the “Standard” method, see the following table:

Award year Student population Job/sub parm 12
2023 – 2024 All students A
2022 – 2023 Graduated and withdrawn students for all programs G
2021 – 2022 Graduated and withdrawn students for all programs G
2020 – 2021 Graduated and withdrawn students for all programs G
2019 – 2020 Graduated and withdrawn student for all programs. G
2018 – 2019 Graduated and withdrawn student for all programs. G
2017 – 2018 Graduated and withdrawn student for all programs. G
2016 – 2017 Graduated and withdrawn student for qualifying graduate programs. Q

Banner uses the standard parameter for the “write to file” part of the process. Banner writes all students to the table during the initial step of writing to the file.

For institutions choosing the “Transitional” method, see the following table:

Award year Student population Job/sub parm 12
2023 – 2024 All students A
2022 – 2023 Graduated and withdrawn students for all programs G

Again, Banner uses the transitional parameter for the “write to file” part of the process. Banner writes all students to the table during the initial step of writing to the file.

You can now filter the students in the SFRGEFM table to see only the population you need to verify for the ultimate file creation. Do not worry that more students are written to the table than are included in the .csv file Banner generated. This is expected behavior. You can use the standard filter to ignore the data that the file creation step ignores.

Use of “Batch ID”

The previous GE solution within Banner used the concept of a “batch ID”. Whenever SFRGEED was run to create data in the SFRGEFM table, Banner generated a one-up “batch ID” and attached it to the newly created records. The batch ID number was included in the .lis file.

This batch ID could be used when reviewing data on SFAGEFM. It was also an optional parameter when creating the output file and for any data purging (using SFPGEED).

Ellucian is continuing the use of the “batch ID” concept. There are separate sequences for the student data (which SFPGESC generates) and the program data (which SFPGEPC generates).

Student Distinctions

The previous GE regulations made a distinction between “enrolled” and “graduated or withdrawn” students. The current regulations continue this distinction. The record type field provides codes to easily distinguish these types of students.
  • AA stands for "Annual Amount". AA records are current enrollment records.
  • TA stands for "Total Amount" TA records are graduated or withdrawn records.

The AA and TA codes also let you know which of the financial cost fields should be populated.

Configuration and Rules

Ellucian is using the existing configuration and rules from the previous versions of Gainful Employment; some entries require you to supply additional information to fully use the new reports. As your institution inserts or updates a row, Bannerchecks the entry for the current mandatory/optional status. However, existing rows that are not updated will not be explicitly flagged. It is the institution’s responsibility to make all such updates.

New page:

Gainful Employment Program File Maintenance (SFAGEPM) page

This administrative page enables your institution to review generated program records. Your institution can insert, update, or delete records.

Updated pages:

Gainful Employment Program Rules (SFAGECR) page

Ellucian has enhanced the Curricula tab to enable you to specify additional characteristics for a curriculum. For the most part, the program report process uses the fields in the lower section.

Some fields that were previously optional are now mandatory when a row is inserted or updated. An example is credential length. If these fields are not completed before running the reports, then the students or programs will be missing this information. Ellucian has continued the use of allowing an institution to specify by major, CIP code, degree code, level code, program, or a combination of these fields.

Ellucian also enhanced the Detail Codes tab to enable an institution to specify additional categories for a detail code.

Ellucian did not:
  • change the Books/Supplies/Equipment Allowance tab.
  • change the OPEID tab.
Ellucian has added:
  • the Residency Tuition Status tab to enable an institution to cross-walk their student residence code values (which are maintained on the Residence Code Validation (STVRESD) page) to the tuition status values the regulation provides.
  • the Housing/Food Allowance tab to enable an institution to specify component codes to identify “housing and food” components.
There are two blocks on this tab:
  • Aid Year Budget block – Use this block to enter aid year budget component codes from the Budget Component Validation (RTVCOMP) page.
  • Period Budget block – Use this block to enter period budget component codes from the Period Component Validation (RTVPBCP) page.
The Housing/Food Allowance tab is not enabled when Banner Financial Aid is not in use.

Gainful Employment File Maintenance (SFAGEFM) page

The SFAGEFM administrative page enables an institution to review generated student records. You can insert, update, or delete records. Ellucian has enhanced this page to accommodate the new fields in the student report.

This enhancement addresses PE0004338 in the Ellucian Customer Center.

New processes

Gainful Employment Student Creation (SFPGESC) process

The SFPGESC process creates student report records which Banner stores in the SFRGEFM table. After reviewing, you can run this process again to create the file to submit to the NSC.

NSC has indicated that they will need your file named in this format: 6 digitOPEID_AwardYear.csv

For example, 001234_20222023.csv

Banner will not be using this format, so institutions will be responsible for renaming the file before submitting it.

Gainful Employment Program Creation process (SFPGEPC)

The SFPGEPC process creates program report records which Banner stores in the SFRGEPM table. After reviewing, you can run this process again to create the file to submit to the NSC.

Note: The NSC specs say to produce a row for each NSC/NSLDS program, which would be a combination of CIP code + credential level. Ellucian is producing a row for the combination of OPEID + CIP code + credential level.

Unchanged process

Gainful Employment Purge Report (SFPGEED) process

Ellucian did not change the SFPGEED process. You can run it to delete records from the student report (SFRGEFM) table.

Deprecated process

Gainful Employment Report (SFRGEED) process

The SFRGEED process previously did all of the processing for the student report table and for the subsequent files. Due to the extensive updates to the regulations, Ellucian determined that it would be better to deprecate this process and to provide a new streamlined process.

Pending new process

Gainful Employment Program Purge (SFPGEPP) process

Due to time constraints, Ellucian will not be able to provide a purge process for the program report data with this initial release, although the release will contain foundational work. Ellucian will provide this process in a future release.

New tables

Residency Tuition Status (SFRGERT) table

You can use the SFRGERT table to store the crosswalk from student residence code values to the tuition status for the regulation.

Housing and Food Allowance – Aid Year (SFRGEAF) table

You can use the SFRGEAF table to store the Aid Year budget component codes for Housing and Food allowances.

Housing and Food Allowance – Period (SFRGEPF) table

You can use the SFRGEPF table to store the Period budget component codes for Housing and Food allowances.

Program report data (SFRGEPM) table

You can use the SFRGEPM table to store program report data.

Updated tables

Ellucian updated the following tables:

Curricula configuration (SFRGECR) table

You can use the SFRGECR table to store configuration and rules around curricula.

Detail code configuration (SFRGEDR) table

You can use the SFRGEDR table to store configuration and rules around detail codes.

Student report data (SFRGEFM) table

You can use the SFREFM table to store student report data.

  1. the student's degree from the Degrees and Other Formal Awards (SHADEGR) page
  2. the degree code validation from the Degree Code Validation (STVDEGC) page

If an institution adds more degree codes or award categories, they will have complete control on NSC values that get reported. Ellucian will not provide a degree award category code for the newly supported Credential NSC category. Institutions will need to enter their local value on STVACAT and propagate it appropriately. Texas Connection Consortium (TCC) enhancement

The studbpr_baninst1_drop_083000.sql script dropped all TCC packages from the baseline database for non-TCC institutions.

Ellucian used the following criteria to ensure that the script deleted only TCC objects and that it did not delete institution-created objects or non-TCC objects:
  • Object has a Z as the second character
  • Release number matches the specific delivered release number
  • Code contains text specific to the TCC delivered DBPROC
  • Institution is non-TCC client

As a best practice, Ellucian recommends verification following the installation of a release.

This enhancement addresses PE0003334 in the Ellucian Customer Center.
