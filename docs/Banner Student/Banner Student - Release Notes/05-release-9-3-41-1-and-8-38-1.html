Release 9.3.41.1 and 8.38.1

The Banner Student 9.3.41.1 and 8.38.1 release includes quality improvements and technical currency updates.

Support for Banner 8 Self-Service has ended

As of January 1, 2026, Banner 8 Self-Service has moved out of Sustaining Support and has entered End of Support.

For detailed information on support statuses, please review our Support Assurance Policy.

Enhanced character validation for NSC/NSLDS enrollment reporting

The Clearinghouse Extract Report (SFRNSLC) process is enhanced to accept all ASCII characters, matching the specifications set by the National Student Clearinghouse (NSC). This enhancement resolves data accuracy issues caused by the previous limitation that stripped special characters, including the forward slash (/) commonly found in addresses.

The field validation logic now permits the following ASCII special characters in addition to alphanumeric characters:

Character Category Characters
Basic punctuation ! " # $ % & ' ( ) * + , - . /
Comparison and syntax : ; < = > ? @
Brackets and underscores [ \ ] ^ _ `
Braces and pipes { | } ~

This enhancement provides the following benefits:

  • Improved data accuracy - Addresses and other text fields are now transmitted to NSC and NSLDS without character loss, ensuring data integrity
  • Compliance with NSC specifications - Banner field validation now matches NSC's character acceptance standards
  • Enhanced address handling - Forward slashes and other punctuation marks commonly found in addresses (such as apartment designations like "Apt 1/2") are preserved
  • Reduced manual intervention - Eliminates the need for workarounds or manual corrections when special characters are required in reporting data

This enhancement addresses PE0007870 in the Ellucian Customer Center.

New Order and Session identification fields in SHARQTC

To improve visibility and troubleshooting for electronic transcript processing, the SHARQTC form now displays additional identifiers:

  • The SHARQTC Transcript Request section now displays Order ID and Session ID as read-only fields in the Electronic Transcript Status section.
  • The transcripts-request Banner ERP API (GET) response now includes Order ID and Session ID.

These identifiers helps users quickly associate transcript requests with eTranscripts orders and more easily troubleshoot processing issues (including orders that may remain in RG (Ready to Generate) status), reducing the need for backend queries and minimizing unnecessary order cancellations.

This enhancement addresses PE0007983 in the Ellucian Customer Center.

Australian TCSI compliance enhancements

Program and curriculum mapping capabilities are enhanced to support Australian Tertiary Collection of Student Information (TCSI) compliance reporting requirements. These enhancements add new data capture fields and improve curriculum mapping accuracy for Australian institutions.

Program data enhancements:

The Program and Field of Education Application (SMAPFPA) page is enhanced with the following capabilities:

  • Program Alias field to store alternate program identifiers (TCSI codes) used for regulatory reporting
  • Standard Program Duration field to capture the expected completion timeframe for programs
  • Program-level Field of Education data block for capturing TCSI-specific education classification data
  • Special Interest Course data block for documenting specialized course details
  • Reorganized page layout with Help Type and Indicative Fee information moved to tabbed sections
  • Corrected course of study type data sourcing to use SORCRST validation table
  • Improved navigation for Application ID, Transaction Date, and Status fields

Curriculum mapping enhancements:

The Curriculum Mapping (SOACMAP) page is enhanced with the following fields to improve mapping accuracy:

  • SITE: Dynamically populated from STVSITE validation table. Auto-fills when one site is defined, provides selection list when multiple sites exist, and displays validation message when no sites are mapped to the campus
  • Operation Type: Fixed list of values field for categorizing curriculum operation types
  • Course Specialisation: Read-only field automatically populated from the CIPC code associated with the selected major, ensuring consistent specialization data
  • TCSI Code: Automatically populated from the Program Alias maintained in SMRPFPA, ensuring consistent regulatory reporting identifiers

Database changes:

The following database objects are added or modified to support these enhancements:

  • SKRPOFR table modified to add SKRPOFR_CIPC_CODE column for storing program specialization codes derived from the CIPC code of the selected major
  • SORPFOE table added to store Program Field of Education detail for TCSI reporting
  • SORPSPL table added to store Program Special Interest Course detail
  • SMRPFPA table modified to add SMRPFPA_PROGRAM_ALIAS and SMRPFPA_PROGRAM_DURATION columns for program alias and standard duration data

These enhancements address PE0007993 and PE0007998 in the Ellucian Customer Center.

Section-level attributes support for Degree Works integration

The Banner and Degree Works integration payload is enhanced to include section-level data (attributes & part of term). This enhancement enables Degree Works to perform more accurate prerequisite evaluation by considering section-specific metadata in addition to course-level information.

This enhancement provides more precise prerequisite validation during student registration, reducing registration errors and the need for manual overrides. The feature was implemented in conjunction with performance improvements to the Banner/DegreeWorks integration (PE0008170).

This enhancement addresses PE0007316 in the Ellucian Customer Center.

SMRPFPA UI Layout Enhancement for Australian TCSI Compliance

The Program and Field of Education Application (SMRPFPA) page layout is enhanced to support Australian TCSI compliance reporting requirements. This enhancement adds new data capture fields and reorganizes the page layout for improved usability.

New fields added:

  • Standard Program Duration - A mandatory free-text field that captures the expected completion timeframe for programs. This field is located in the Course and Qualification Details area and supports Australian regulatory reporting requirements for program duration data.
  • Institution Program Alias - A free-text field that stores alternate program identifiers (TCSI codes) used for regulatory reporting. This allows institutions to maintain separate display names and reporting codes for programs.

The bottom section of the SMRPFPA page is restructured to clearly separate two data blocks as distinct tabbed sections:

  • HELP TYPE DATA tab - Contains Higher Education Loan Program type information
  • INDICATIVE FEE DATA tab - Contains indicative fee information

This enhancement addresses PE0007997 in the Ellucian Customer Center.

Gainful Employment and Financial Value Transparency reporting label enhancement

The Gainful Employment and Financial Value Transparency (FVT/GE) reporting processes are enhanced to improve clarity of the void indicator field display. This enhancement affects the SFAGEFM and SFPGESC processes:

The decoded display text for the invalidate indicator field when set to Y is changed from the generic Y to the more descriptive label Invalidate existing record. This provides clearer information about the action that will be performed when this indicator is enabled.

This enhancement addresses PE0007297 in the Ellucian Customer Center.

Student type program update correction (SHRTYPE)

A data integrity issue affecting the Student Type Update (SHRTYPE) page is corrected in this release. The issue caused incorrect program assignments to be saved for future terms when updating student type information.

This correction ensures that program data is accurately maintained across term boundaries when processing student type changes on the SHRTYPE page. The fix applies to both Oracle and PostgreSQL database environments.

This defect addresses PD0030915 in the Ellucian Customer Center.

Person Holds Ethos API enhancement

The person-holds Ethos API is enhanced to support term‑based registration holds stored in SPRTHLD, in addition to the existing person‑level holds in SPRHOLD

The Person Holds Ethos Integration API is enhanced from version 6.1 to version 16.0, adding support for term-based registration holds. This enhancement extends the API capabilities to support more granular hold management at the term level.

This enhancement requires Common DB Upgrade 9.42.1 and Student API 9.41.1.

This enhancement addresses PE0007779 in the Ellucian Customer Center.

Faculty Grade Entry gradebook component grade correction

An Oracle database error that occurred when updating component grades in the Faculty Grade Entry (FGE) Gradebook is corrected. The correction includes admin page modifications to prevent the error condition.

This correction applies to both Banner Student and Banner Faculty Self-Service.

This enhancement addresses CR-000141263 in the Ellucian Customer Center.

DegreeWorks integration performance improvement

Performance is improved for the Banner and DegreeWorks integration by removing a fixed 2-second processing delay on integration calls. This change affects the Review Registration Approve Menu (SFRRGAM) page and other DegreeWorks integration points.

The improvement reduces overall transaction time for DegreeWorks data exchanges, enhancing the user experience during student registration and degree audit processes.

This enhancement addresses PE0008170 in the Ellucian Customer Center.

FVT/GE reporting enhancement

The Gainful Employment Student Creation (SFPGESC) process is enhanced so that withdrawn students are included in the FVT/GE Student Level (TA) output when they have any Title IV‑eligible disbursement within the reporting aid year, even if the disbursement is posted after the withdrawal date.

The enhanced population selection logic now determines withdrawn‑student eligibility based on Title IV‑eligible disbursements within the reporting aid year, regardless of whether the disbursement is posted before or after the withdrawal date. This aligns with Federal Gainful Employment and Financial Value Transparency reporting guidance, which permits institutions to process R2T4 and Post‑Withdrawal Disbursements (PWD) after withdrawal while maintaining student eligibility for FVT/GE reporting.

This enhancement provides the following benefits:

  • Improved reporting compliance - Supports complete and accurate FVT/GE reporting in accordance with Department of Education (ED) and NASFAA guidance.
  • Comprehensive withdrawn‑student capture – Includes withdrawn students who received Title IV‑eligible aid within the reporting aid year, even when the only qualifying activity is a post‑withdrawal disbursement.
  • Accurate post‑withdrawal disbursement handling – Properly recognizes Post‑Withdrawal Disbursements (PWD) and R2T4 adjustments within the reporting aid year, regardless of posting date relative to the withdrawal date.
  • Reduced under‑reporting risk – Prevents eligible withdrawn students from being excluded from federal FVT/GE reporting.

This enhancement applies to withdrawn students only. Graduated student inclusion rules and AA record logic remain unchanged. Student inclusion is based on Title IV‑eligible disbursements attributed to the reporting aid year, and not on a 45‑day post‑withdrawal window.

This enhancement addresses PE0007299 in the Ellucian Customer Center.

Business Process API for Admissions Application Rating

A new admissions-rating-application-ratings v1.0.0 BPAPI is introduced for the Application Rating section on the Admissions Rating (SAARRAT) page, enabling programmatic management of admissions rating configurations.

The GET, POST, and PUT request methods are supported.

The new BPAPI for Application Rating allows institutions to:

  • GET SARRRAT records with filter support (for example, rating code, effective term, status, institution-defined qualifiers) using search criteria such as PIDM, APPL_NO, TERM_CODE, and AROL_PIDM
  • POST new SARRRAT records with full validation (required fields, term validity, code validation, uniqueness rules)
  • PUT updates to existing SARRRAT records while enforcing the same constraints and behavior as the Banner UI

The API follows Banner's existing security model, supports audit tracking, and ensures consistent outcomes across UI and API workflows. All endpoints enforce the same validation, permissions, and business rules that run when the staff performs Application Rating operations manually, preserving audit-ability without bypassing existing integrity checks, effective-dating, or entity/MEP restrictions.

Key benefits:

  • Enables faster, less error-prone maintenance of admissions rating tables at scale
  • Improves integration capability with admissions platforms and workflow tools

This enhancement addresses PE0007216 in the Ellucian Customer Center.
