Self-Service

Banner AVETMISS includes Student Self-Service Web pages to allow students to provide their Unique Student Identifier (USI).

If real time USI processing is enabled for self-service, then students can verify their USI in real time. There is no provision for students to request a USI from within Student Self-Service. Information text is included to direct students to the USI Portal to request a USI, including a hyperlink to the USI Portal.

This chapter describes the template Web pages as delivered. These descriptions are used to help you modify the delivered pages to meet your institution's needs.

Web Menu

The Student Records Menu provides the Unique Student Identifier link for Banner AVETMISS which is used to provide the USI for verification.

USI tasks

This chapter explains the procedures and Self-Service Web pages used to verify a Unique Student Identifier (USI).

Provide and verify a USI

Use the following step-by-step procedure to provide and verify a Unique Student Identifier.

Procedure

  1. Access Student Self-Service.
  2. From the Student Records menu, click Unique Student Identifier.
  3. On the Unique Student Identifier page (ASC_USI), type the USI in the Unique Student Identifier field.
  4. Click Continue.

Results

If real time processing is enabled for Self-Service, then this will trigger the following procedures to verify the USI.
  • If the USI was successfully verified, then the USI Successfully Verified page (ASC_USI_SUCCESS) will be displayed.
  • If the USI was not verified, then the USI Not Verified page (ASC_USI_FAILURE) will be displayed.
  • If there was a problem connecting to the USI registry, then the Cannot Connect to USI system page (ASC_USI_FAULT) will be displayed.

If real time processing is not enabled for Self-Service then the student will be taken to the next step in the institution's enrolment process, or they will be returned to the Student Records menu.

USI Web pages

The Unique Student Identifier process is composed of the Self-Service Web pages discussed in this section.

Unique Student Identifier (ASC_USI)

Use this page to do the following.

  • Enter a unique student identifier for verification.
  • Access the USI Portal through a hyperlink.

If real time USI processing is enabled for self-service, then students can verify their USI in real time. There is no provision for students to request a USI from within Student Self-Service.

Note: Students can also access this page directly by typing the Web page link in the address bar.

Updates to Banner

This page will insert a record into the Additional ID Verification table (GKRADIV) as follows.

Field Name Description Value
GKRADIV_ADID_CODE ID Type USI
GKRADIV_ADDITIONAL_ID Additional Identification The value entered by the student in the Unique Student Identifier field
GKRADIV_CONSENT Verification Consent Y
GKRADIV_CONSENT_DATE Consent Response Date The current system date
  • If real time USI processing is not enabled for self-service, then there will be no further updates to Banner.
  • If real time USI processing is enabled for self-service, then VerifyUSI processes will be triggered
  • The process will check that it is possible to retrieve the institution's Organisation code for inclusion in the VerifyUSI web service request.
  • If the institution's Organisation code cannot be retrieved:
    • A new VerifyUSI request transaction record will be inserted into the Transactions Data table (SKRTRNS) with a status message indicating that the Organisation code could not be retrieved.
    • The student will be navigated to the Cannot connect to USI System page (ASC_USI_FAULT).
  • If the institution's Organisation code can be retrieved, the process continues and now checks that a VerifyUSI request can be created for the student.
  • If it is not possible to create a VerifyUSI request for the student:
    • A new VerifyUSI request transaction record will be inserted into the Transactions Data table (SKRTRNS) with a status message indicating that the VerifyUSI request could not be created.
    • The student will be navigated to the Cannot connect to USI System page (ASC_USI_FAULT).
  • If it is possible to create a VerifyUSI request for the student:
    • A new VerifyUSI request transaction record will be inserted into the Transactions Data table (SKRTRNS).
    • A new VerifyUSI request record will be inserted into the Request Collector table (SKRRQST).
    • The VerifyUSI MDUU activity runs to gather data for the student's verifyUSI request.
    • The data from the VerifyUSI MDUU target table (SKSVUSI) is used to compile a VerifyUSI request xml.
    • The VerifyUSI request web service message is sent.
    • The VerifyUSI response web service message is received.
    • The VerifyUSI response XML is unpacked and parsed in a target table (SKXVUSI).
  • If the USI has been successfully verified:
    • The status of the request transaction record in SKRTRNS is updated to SUCCESS.
    • The status of the request record in SKRRQST is updated to SUCCESS
    • The status of the request record in SKSVUSI is updated to SUCCESS
    • The status of the additional identification record in GKRADIV is updated to VALID.
    • The status date for the additional identification record in GKRADIV is updated to the current system date.
    • The verification date for the additional identification record in GKRADIV is updated to the current system date.
    • A record is inserted into the Additional Identification table (GORADID) for the student as follows:
      Field Name Description Value
      GORADID_ADID_CODE ID Type USI
      GORADID_ADDITIONAL_ID Additional Identification The value entered by the student in the Unique Student Identifier field
    • A record is inserted into the Student Transaction Data table (SKRSTRN) for the student and request.
    • The student is navigated to the USI Successfully Verified page (ASC_USI_SUCCESS).
  • If the USI has not been successfully verified:
    • The status of the request transaction record in SKRTRNS is updated to COMPLETE.
    • The status of the request record in SKRRQST is updated to COMPLETE
    • The status of the request record in SKSVUSI is updated to COMPLETE
    • The status of the additional identification record in GKRADIV is updated to the value of the USIStatus field in the VerifyUSI response. Depending on whether the USI itself is valid or not, this value could be VALID, INVALID or DEACTIVATED.
    • The status date for the additional identification record in GKRADIV is updated to the current system date.
    • A record is inserted into the Request Exceptions table (SKREXPT) for the student and request.
    • The student is navigated to the USI Not Verified page (ASC_USI_FAILURE).
  • If there was some error which prevented the process from reaching completion:
    • The status of the request transaction record in SKRTRNS is updated to SOAPFAULT and any error message is populated into the SKRTRNS_STATUS_MESSAGE field.
    • The status of the request record in SKRRQST is updated to SOAPFAULT
    • The status of the request record in SKSVUSI is updated to FAILED
    • The status of the additional identification record in GKRADIV is updated to FAILURE.
    • The status date for the additional identification record in GKRADIV is updated to the current system date.
    • A record is inserted into the Request Exceptions table (SKREXPT) for the student and request.
    • The student is navigated to the Cannot connect to USI System page (ASC_USI_FAULT).

Buttons/icons on this page

This page contains the following buttons/icons.

Button/Icon Action
Continue If real time USI processing is enabled for self-service, then the process will attempt to send a VerifyUSI request and receive a VerifyUSI response.

If the USI is successfully verified, goes to the USI Successfully Verified page (ASC_USI_SUCCESS).

If the USI is not successfully verified, goes to the USI Not Verified page (ASC_USI_FAILURE).

If there is a connectivity issue or other fault in sending the request, goes to the Cannot connect to USI System page (ASC_USI_FAULT).

If the student clicks the Continue button without providing a USI, goes to the USI Exempt page (ASC_USI_EXEMPT).

If the student is exempt from providing a USI or already has a verified USI, returns to the Student menu (twbkwbis.P_GenMenu?name=bmenu.P_StuMainMnu).
Cancel If the student is not exempt from providing a USI and the USI is not verified, goes to the USI Exempt page (ASC_USI_EXEMPT).

If the student is exempt from providing a USI or already has a verified USI, returns to the Student menu (twbkwbis.P_GenMenu?name=bmenu.P_StuMainMnu).

USI Successfully Verified (ASC_USI_SUCCESS)

This page will be displayed when real time USI processing is enabled for self-service and the student's USI has been successfully verified in real time.

Note: When a student tries to type this Web page link in the address bar to directly access this page, the following error message will be displayed: You are not authorized to access the requested page.
Web page fields

This page contains the following fields.

Item Description/source information
First Name First name of the student.

If the student has a name record with the name type of USI, the first name of that record will display here, even if it is an alternate identification record. Otherwise the current first name will display. The first name cannot be changed.
Last Name Last name of the student.

If the student has a name record with the name type of USI, the last name of that record will display here, even if it is an alternate identification record. Otherwise the current last name will display. The last name cannot be changed.
Date of Birth Displays the student's date of birth.

The date of birth cannot be changed.
Unique Student Identifier Displays the verified Unique Student Identifier and cannot be changed.
Verification Status Displays the status of a verified USI which will be VALID and cannot be changed.
Verification Date Date when the USI was verified and cannot be changed.

Item Description
External Systems Interaction Control (SKASYSC) page Set up controls for Unique Student Identifier processing on the USI tab.
Organisation Definition (SKATORG) page Ensure that the organisation saved on the USI tab of SKASYSC has a valid Training Organisation ID.
Report System Parameters (SKARSYS) page Use this page to enter or display system parameters for use in USI processing.

If you want to enable real time USI verification in self-service, the USI-REAL-TIME system parameter should have a value of either S (Self-Service) or B (Both pages and self-service).

USI Not Verified (ASC_USI_FAILURE)

This page will be displayed when real time USI processing is enabled for self-service and the student's USI has not been successfully verified in real time.

Note: When a student tries to type this Web page link in the address bar to directly access this page, the following error message will be displayed: You are not authorized to access the requested page.
Web page fields

This page contains the following fields.

Item Description/source information
First Name First name of the student.

If the student has a name record with the name type of USI, the first name of that record will display here, even if it is an alternate identification record. Otherwise the current first name will display. The first name cannot be changed.
Last Name Last name of the student.

If the student has a name record with the name type of USI, the last name of that record will display here, even if it is an alternate identification record. Otherwise the current last name will display. The last name cannot be changed.
Date of Birth Displays the student's date of birth.

The date of birth cannot be changed.
Unique Student Identifier Displays the verified Unique Student Identifier, but can be changed so that the student can make corrections and attempt to verify it again.
Error Message Error message. The message displayed to the student is a concatenation of the exact results received in the VerifyUSI response.
  • If the USI is a valid USI on the USI Registry but the Last Name provided by the student does not match the record for that USI on the USI Registry, the result message will be: USI Status: Valid, Last Name Status: NoMatch, First Name Status: Match, DOB Status: Match
  • If the USI is a valid USI on the USI Registry but the first name provided by the student does not match the record for that USI on the USI Registry, the result message will be: USI Status: Valid, Last Name Status: Match, First Name Status: NoMatch, DOB Status: Match
  • If the USI is a valid USI on the USI Registry but the date of birth provided by the student does not match the record for that USI on the USI Registry, the result message will be: USI Status: Valid, Last Name Status: Match, First Name Status: Match, DOB Status: NoMatch
  • If the USI is a valid USI on the USI Registry but the single name provided by the student does not match the record for that USI on the USI Registry, the result message will be: USI Status: Valid, Single Name Status: NoMatch, DOB Status: Match
  • Similarly, if the USI is a valid USI on the USI Registry, but both parts of the name or part of the name plus the date of birth do not match the record for that USI on the USI Registry, the result message will show that the USI itself is valid but that some or all of the Name and Date of Birth fields have a NoMatch status.
  • If the USI is not a valid USI on the USI Registry, then the result message will be one of the following message, depending on whether the student has a first name and last name or a single name:
    • USI Status: Invalid, Last Name Status: NoMatch, First Name Status: NoMatch, DOB Status: NoMatch
    • USI Status: Invalid, Single Name Status: NoMatch, DOB Status: NoMatch
