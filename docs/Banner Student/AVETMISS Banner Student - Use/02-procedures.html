Define reporting data elements

To map Banner™ data to reporting data elements, you must create activities in the Banner Mass Data Update Utility (MDUU).

About this task

For the purposes of AVETMISS reporting, the activities required to produce each file will be documented in separate specifications for each file. Before you can create these activities, you need to define the elements and their valid values as described in the following procedure. Element codes have been delivered for reporting elements that do not have a logical baseline Banner location and are required for AVETMISS reporting.

Procedure

  1. Access the Report Element Validation (SKVRVAL) page.
  2. Define each element to be mapped.
  3. Save your changes.
  4. Access the Report Element Values (SKARVAL) page.
  5. Define the valid values for an element as follows.
    Note: You must define a separate record for each valid value for an element. For example, if an element has six valid values, you must define six records, one for each value.
    1. Create a new record.
    2. Enter the element name, as defined on SKVRVAL page, in the Element Code field.
    3. Enter a valid value for the element in the Element Value field.
    4. Enter the text description associated with the value in the Description field.
    5. Select the Active check box.
    6. If the valid value is to be in use only for a limited time, enter the last date on which the value is to be used in the End Date field.
    7. Save your changes.
    8. Repeat 5 for each valid value.
    Refer to Banner AVETMISS Online Help to read more information about pages and field descriptions.

Map external codes to Banner codes

You can map external codes, such as those used for Main Language other than English Spoken at Home, to baseline codes for cases where a baseline code is too short or where using the AVETMISS values in a baseline page is not appropriate.

About this task

When the AVETMISS reporting process is run, the snapshot activities insert raw data from baseline fields, and then the extract activities run relevant data through this mapping table.

For example, the AVETMISS reporting element Main Language other than English Spoken at Home Identifier uses four-character Australian Standard Classification of Languages (ASCL) codes. The Banner Native Language field is only three characters in length, but it is a logical place to capture the data. The Client file snapshot activity therefore uses the Banner field to populate the Main Language data element. The Client file extract activity then transforms each Banner value to the matching ASCL value, as defined on the Report Elements Mapping (SKARMAP) page.

Procedure

  1. If you have not previously defined the data element to be mapped, define it as explained in the Define reporting data elements section.
  2. Access the Report Elements Mapping (SKARMAP) page.
  3. Enter the academic year code in the Academic Year field, then go to the next block.
  4. Enter the column name of the Banner baseline field to be mapped in the Banner Field field.
  5. Enter the Banner baseline value to be mapped in the Banner Value field.
  6. Enter the reporting element code to be mapped to the baseline field in the Element Code field.
  7. Enter the reporting element value to be mapped to the baseline value in the Element Value field.
  8. Save your changes.
  9. Repeat 4 through 8 for each mapping.

Copy external code mappings to another year

External code mappings are associated with an academic year. You can copy one year's mappings to another, then modify the new mapping as desired.

About this task

When you copy mapping rules from one year to another, all rules are copied, and you can delete any rules that no longer apply. You can copy rules forwards or backwards in time; the only restriction is that you cannot copy mapping rules to an academic year that already has mapping rules. If you attempt to copy mappings to a year for which at least one mapping has already been defined, the system does not perform the copy and displays an error message.

Procedure

  1. Access the Report Elements Mapping (SKARMAP) page.
  2. Select the Copy Rules to New Year button.
  3. Enter the code of the academic year to be copied in the From Year field of the Copy Rules window.
  4. Enter the code of the academic year to which the definitions are to be copied in the To Year field.
  5. Select the Process Rule Copy button.
  6. If desired, modify the mappings as explained in the Map external codes to Banner codes section.

Define system parameters

There are several reporting elements where the selection of the correct data is dependent on specific Banner codes.

About this task

For example, to report a student's postal address, you must specify an address type code from the Address Type Code Validation (STVATYP) page. If you have defined MA as the address type code to signify 'mailing address,' you would assign MA as the value for the POSTAL_ADDR_TYPE system parameter. When this system parameter is used in reporting, it will return data for address types of MA. If a student does not have a MA address, then no address data will be reported for that student on reports using the POSTAL_ADDR_TYPE parameter.

To support interconnectivity between baseline codes and AVETMISS reporting elements, a predefined set of system parameters is delivered with AVETMISS Reporting, and you must configure these parameters for use. You can modify the delivered parameters to meet your needs, or you can create new ones. Those that are required by the system are noted as such in Seed Data section.

Only users with appropriate permissions can define or modify system parameters.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Enter the academic year code in the Academic Year field, then go to the next block.
  3. Enter the parameter for which you want to enter valid values in the Parameter field.
  4. Enter the valid value(s) for the parameter in the Value field.
    You can enter multiple values for each parameter, separated by a comma, up to 2,000 characters.
  5. If desired, enter information in the Description and Notes fields.
  6. Save your changes.

Copy system parameters to another year

System parameters are associated with an academic year. You can copy one year's parameter definitions to another, then modify the new definition as desired.

About this task

When you copy system parameter rules from one year to another, all rules are copied. System parameter rules cannot be deleted if the system required indicator is checked but the parameter value can be updated to null. System parameter rules can be deleted after being copied to the new academic year if the system required indicator is unchecked. You can copy rules forwards or backwards in time; the only restriction is that you cannot copy system parameter rules to an academic year that already has system parameter rules.

If you attempt to copy parameters to a year for which at least one parameter has already been defined, the system does not perform the copy and displays an error message.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Select the Copy Rules to New Year button.
  3. Enter the code of the academic year to be copied in the From Year field of the Copy Rules window.
  4. Enter the code of the academic year to which the definitions are to be copied in the To Year field.
  5. Select the Process Rule Copy button.
  6. If desired, modify the parameter definitions as explained in Define system parameters.

Build organisation data

The following procedure explains how to build data for capture by snapshot activities for national AVETMISS and Victorian VET files which rely on organisation definitions to derive the correct data. Examples of such files include the Training Organisation NAT0010, Delivery Location NAT00020 and Enrolment NAT00120 files.

Procedure

  1. Make sure that all your training and employer organisations are defined as non-person records on the Identification (SPAIDEN) page.
  2. Make sure that all your organisation contact people are defined as person records on the Identification (SPAIDEN) page.
  3. Create your institution's organisation definition record for each training and employer organisation and effective term as follows.
    1. Access the Organisation Definition (SKATORG) page.
    2. Enter the ID of the non-person organisation in the ID field.
    3. Enter the term code in the Term field.
    4. Enter your institution's organisation details in the Organisation Definition window.
    5. Save the record(s), and select Next Block.
    6. View your sub-organisation details in the Sub-Organisation window.
    7. Save the record(s), and select Next Block.
    8. Enter your organisation contact details in the Organisation Contacts window.
    9. Save the record(s), and select Next Block.
    10. Enter your institution's delivery location details in the Delivery Location window.
    11. Save the record(s).

Build student statistical data

The following procedure discusses to save student statistical data to various existing tables through a single data-entry page. Administrators, who are responsible for data entry and reporting, can capture data for several statutory reporting elements in one location.

Procedure

  1. Access the Student Statistical Details (SKAENRL) page.
  2. In the Key block, specify the student ID for which you want to enter data who has a general student record with at least one learner curriculum.
  3. In the Biographical Details tab, enter the following details of the student specified in the key block:
    1. In the Address Details block, enter the student's address details.
    2. In the Biographical details block, enter the student's biographical details.
    3. In the Demographic details block, enter the student's demographic details.
  4. In the Additional Details tab, enter the following details of the student specified in the key block:
    1. In the High School Details block, enter the student's high school details
    2. In the Prior Education Details block, enter the student's prior education details
    3. In the Disability Details block, enter the student's disability details, if any.
    4. In the Statistical Details block, enter the student's school education statistic details.
    5. In the Unique Student Identifier block, enter the students' USI details.
    6. In the Medical Details block, enter the student's medical details.
  5. Save the record.

Set up controls for Unique Student Identifier

The following procedure explains how to set up the controls used for requesting and verifying Unique Student Identifiers.

Procedure

  1. Access the External Systems Interaction Control (SKASYSC) page.
  2. Select the USI tab.
  3. Enter the ID of the non-person for your training organisation in the ID field.
  4. Optional: Enter the organisation's Australian Business Number in the Australian Business Number field.
  5. Enter a prefix for USI requests in the Request ID Prefix field.
  6. If document verification should be required by default for all CreateUSI or BulkUpload requests, select the Document Verification Required Default check box.
  7. The value in the Maximum Number of Records in Bulk Verify Request field and Maximum Number of Records in Bulk Upload Request fields will default to 500, but can be changed.
  8. Enter a number of hours in the Number of Hours Before Sending Bulk Upload Retrieve field.
  9. Enter your local institution URL for the VerifyUSI java program in the VerifyUSI https URL field.
  10. Enter your local institution URL for the BulkVerify java program in the BulkVerify USI https URL field.
  11. Enter your local institution URL for the CreateUSI java program in the CreateUSI https URL field.
  12. Enter your local institution URL for the BulkUpload java program in the BulkUpload https URL field.
  13. Enter your local institution URL for the BulkUploadRetrieve java program in the BulkUploadRetrieve https URL field.
  14. Enter the code for the process that gathers data for a VerifyUSI request message in the VerifyUSI Process field.
  15. Enter the code for the process that gathers data for a BulkVerify request message in the Bulk VerifyUSI Process field.
  16. Enter the code for the process that gathers data for a CreateUSI request message in the CreateUSI Process field.
  17. Enter the code for the process that gathers data for a BulkUpload request message in the BulkUpload Request Process field.
  18. Enter the user name of the user that will be authenticated on your local Apache Tomcat or WebLogic web server when USI web services are run.
  19. Enter the password for the user that will be authenticated on your local Apache Tomcat or WebLogic web server when USI web services are run.
    Note: This password is stored as an encrypted string.
  20. Save the record.

Build person identity verification document data

The following procedure explains how to create identity verification document data for students when you use either the CreateUSI web service or the BulkUpload web service to request a USI on their behalf. Identity verification document data is not needed if you will only use the VerifyUSI or BulkVerify webservices.

Procedure

  1. Access the Identity Verification Document Details (GKAVDOC) page.
  2. Enter the ID of the student in the ID field of the key block.
  3. Select Next Block.
  4. Enter the type of document in the Document Type field.
    Records will default to Active and Primary. Other data entry fields will be enabled or disabled depending on the selected document type.
    Note: The Primary record for identity verification indicator will be checked by default but only one record can be the Primary record. If you are entering details of more than one document for the person, clear the Primary record for identity verification indicator for each non-primary record before saving it.
  5. If the selected document type is BIRTH, do the following.
    1. Enter the registration number in the Document Event Registration Number field.
    2. Enter the certificate number in the Document Certificate Number field.
      Note: If the certificate is from South Australia and was printed after 1 November 1999, or is from the Australian Capital Territory and was printed after 1 May 2002, or is from the Northern Territory and was printed after 1 July 1999, then, the certificate number is required.
    3. Enter the code for the Australian state or territory in which the birth was registered in the Document Event State field.
    4. Enter the date on which the birth was registered in the Document Event Registration Date field.
    5. Enter the date on which the certificate was printed in the Document Print Date field.
    6. Save the record.
  6. If the selected document type is CITIZEN, do the following.
    1. Enter the stock number from the document in the Document Certificate Number field.
    2. Enter the acquisition date from the document in the Document Event Date field.
    3. Save the record.
  7. If the selected document type is DESCENT, do the following.
    1. Enter the acquisition date from the document in the Document Event Date field.
    2. Save the record.
  8. If the selected document type is DRIVER, do the following.
    1. Enter the licence number from the document in the Document Certificate Number field.
    2. Enter the code for the Australian state or territory of the licence in the Document Event State field.
    3. Save the record.
  9. If the selected document type is IMMICARD, do the following.
    1. Enter the ImmiCard number from the document in the Document Certificate Number field.
    2. Save the record.
  10. If the selected document type is MEDICARE, do the following.
    1. Enter the Medicare Card Number from the document in the Document Certificate Number field.
    2. Enter the card expiry date in the Document Expiry Date field.
    3. Enter the person's individual reference number in the Medicare Individual Reference Number field.
    4. Enter the colour of the card in the Medicare Card Colour field.
    5. Enter this person's first name line from the Medicare card in the Name Line 1 field.
    6. Enter this person's second name line from the Medicare card in the Name Line 2 field.
    7. Enter this person's third name line from the Medicare card in the Name Line 3 field.
    8. Enter this person's fourth name line from the Medicare card in the Name Line 4 field.
    9. Save the record.
  11. If the selected document type is PASSPORT, do the following.
    1. Save the record.
    2. Access the International Information (GOAINTL) page.
    3. Enter the ID of the student in the ID field of the key block.
    4. Select Next Block.
    5. Access the Passport tab
    6. Enter the Passport number in the Passport Number field.
    7. Enter the passport country of issue in the Nation of Issue field.
    8. Save the record.
  12. If the selected document type is VISA, do the following.
    1. Save the record.
    2. Access the International Information (GOAINTL) page.
    3. Enter the ID of the student in the ID field of the key block.
    4. Select Next Block.
    5. Access the Passport tab
    6. Enter the Passport number in the Passport Number field.
    7. Enter the passport country of issue in the Nation of Issue field.
    8. Save the record.
    9. If the visa was issued by an agency that is not actually a country (for example, United Nations agency), then access the Visa tab.
    10. Enter a visa type in the Visa Type field.
    11. Enter the visa issuing agency in the Visa Issuing Authority field.
    12. Save the record.

Build data to request a Unique Student Identifier

The following procedure explains how to record data for students when you will use either the CreateUSI web service or the BulkUpload web service to request a USI on their behalf.

About this task

If real time processing is enabled for use in Banner pages, then this will trigger the CreateUSI web service when the record is saved.

Note: When using real time processing to request a USI on behalf of a student, it is necessary to complete all other relevant data entry before accessing the Additional ID Verification page including entering details of the person's identity verification documents. If any data items are missing, this will result in either an error in sending the request or in errors in the response message.

If real time processing is not enabled for use in Banner pages, the data will be saved in several tables, including a request collector table and will be included in the next scheduled run of the BulkUpload web service.

Procedure

  1. Access the Additional ID Verification (GKAADIV) page
  2. Enter the ID of the student in the ID field of the key block.
  3. Select Next Block.
  4. Enter the additional ID Type in the ID Type field.
    For USI processing, the value is USI.
  5. Select the Given option from the Verification Consent group.
  6. Enter the person's preferred method of being contacted by the USI Registry in the Preferred Contact Method field.
  7. Ensure that the Yes option is selected for the Document Verification Required group.
  8. Save the record.
    If real time processing is enabled for Banner pages, your screen will freeze for a few seconds while the data is gathered, the request message is sent, the response message is received and processed, and the status of the record is updated.

Correct Unique Student Identifier request and verification errors

The following procedure explains how to find more details about any errors received when a USI creation or verification request is not successful.

About this task

Sometimes, the error would have been returned in a response message and sometimes it will have prevented the request message from being sent.

Procedure

  1. Access the Request Exceptions (SKAEXPT) page.
  2. Enter the ID of the student in the ID field of the key block.
  3. Select Next Block.
  4. Scroll through the records or execute a query to only view the records where the system is USI.
  5. To access the message details window, click Edit on the Message field.
    The message will provide information about the corrections that need to be made. You may need to correct data on one or more pages, such as the Identity Verification Document Details (GKAVDOC) page or address, phone number, date of birth or email address details on the Identification (SPAIDEN) page.
  6. When the cause of the error has been fixed, access the Additional ID Verification (GKAADIV) page.
  7. Enter the ID of the student in the ID field of the key block.
  8. Select Next Block.
  9. Change the date in the Consent Response Date field.
  10. Save the record.

Results

If real time processing is enabled for Banner pages, your screen will freeze for a few seconds while the data is gathered, the request message is sent, the response message is received and processed, and the status of the record is updated.

Copy reporting calendar rules

Reporting calendar rules are associated with an academic year and report collection. With the copy reporting calendar rules option, you can do the following.

About this task

  • Copy one year's rules to another year for the same report collection
  • Copy one report collection's rules to another report collection for the same year
  • Copy rules from one year and report collection to a completely different year and report collection
  • After the rules have been copied, modify the new rules as desired
  • Only rules that have the Copy Indicator checked are copied
  • Copy rules forwards or backwards in time
    Note: If you attempt to copy report calendar rules to a year and report collection for which at least one rule has already been defined, the system will prompt you to confirm that you want to overwrite existing rules for that new year and this report collection.

Use the following procedure to copy reporting calendar rules.

Procedure

  1. Access the Reporting Collection Calendar (SKAREPT) page.
  2. Enter the academic year in the Academic Year field.
  3. Enter the report collection code in the Report Collection field.
  4. Select Copy Rules.
  5. Enter codes in the correct fields, depending on the kind of copy that you want to make:
    1. If you are copying rules to a new year for the same report collection, then enter the code of the academic year to which the rules are to be copied in the Copy rules to new year and same report collection field.
    2. If you are copying rules to a new report collection for the same year, then enter the code of the report collection to which the rules are to be copied in the Copy rules to same year and new report collection field.
    3. If you are copying rules to a new year and a new report collection, then enter the code of the academic year to which the rules are to be copied in the Year field of the Copy rules to new year and new same report collection section and enter the code of the report collection to which the rules are to be copied in the Report Collection field of the Copy rules to new year and new same report collection section.
  6. Select Copy that is next to the field where you entered an academic year or a report collection.
  7. If desired, modify the new rules as explained in Create reporting calendar rules.

Set the reporting calendar rules copy indicator

Specific reporting calendar rules will only be copied if the Copy indicator for that rule is checked.

About this task

The Copy indicator can be checked and unchecked for each individual rule, or you can use the Set Copy Indicator field and the Process Copy Indicator Setting button to update the Copy indicator for all of the rules for the Academic Year and Report Collection in the key block.

Use the following procedure to set the reporting calendar rules copy indicator.

Procedure

  1. Access the Reporting Collection Calendar (SKAREPT) page.
  2. Enter the academic year in the Academic Year field.
  3. Enter the report collection code in the Report Collection field.
  4. Select Next Block.
  5. If you want to update the Copy indicator to cleared for all the rules displayed, select Process Copy Indicator Setting.
  6. Save your changes.
  7. If you want to update the Copy indicator to be selected for all the rules displayed, select the Set Copy Indicator field, then select Process Copy Indicator Setting.
  8. Save your changes.

Build student contract data

The following procedure explains how to build data for capture by snapshot activities which rely on AVETMISS course definitions to derive accurate data. Examples of such files include the Course NAT00030 and Enrolment NAT00120 files.

Procedure

  1. Create your institution's organisation definition records for each training and employer organisation and effective term on the Organisation Definition (SKATORG) page. Refer to Build organisation data for complete information about defining your organisation.
  2. Make sure that all your students are registered in course sections on the Course Registration (SFAREGS) page or in the Registration Query (SFAREGQ) page.
  3. Define student contract records as needed for each student and term on the Student Contract Details (SKATCND) page.
    The following procedure explains how to build a student contract data.
    1. Access the Student Contract Details (SKATCND) page.
    2. Enter the ID of the student in the ID field of the key block.
    3. Enter the term code in the Term Code field of the key block.
    4. Select Next Block.
    5. Enter the code or ID of the student's contract in the Contract ID field.
    6. Optional: Enter any external student ID associated with this student and this contract in the External Student ID field.
    7. Optional: Enter any external student ID associated with this student and contract in the External Student ID field, for example an ID from an interstate training authority.
    8. Optional: Enter the code of the interstate training authority associated with this student and contract in the Interstate Training Authority field.
    9. Enter the start date of the contract according to the local state authorising agency in the State Authority Start Date field.
    10. Enter the ID of the training organisation for this student and contract in the Training Organisation field.
    11. Enter the ID of the employer organisation for this student and contract in the Employer Organisation field.
    12. Enter the code of the type of contract in the Contract Type field.
      The Contract Status initially defaults to 00, you will be able to change it to a more appropriate code after the record is saved. The contract status date defaults to the current system date and can be changed.
    13. Enter the code of the student's program in the Program field.
      If you click the List/LOV icon, the Program Validation window will open. This window displays the student's active, current, learner curriculum records. If you select a record it will populate the Program and Study Path fields. The study path (key sequence) associated with this student and program will default into the Study Path field.
    14. Enter the start date of the student's contract in the Contract Start Date field.
    15. Enter the expected end date of the student's contract in the Contract End Date field.
    16. Enter the number of months that the contract is expected to take in the Nominal Duration field.
    17. When the contract is finished, enter the termination date according to the local state authorising agency in the Contract Termination Date field.
    18. Enter the code of the employment arrangement for this student and contract in the Employment Type field.
    19. Enter the Australian and New Zealand Standard Industrial Classification (ANZSIC) code for this student and contract in the ANZSIC field.
    20. Enter the Australian Standard Classification of Occupations (ASCO) code for this student and contract in the ASCO field.
    21. Select the appropriate option from the Full or Part Time group.
    22. If the student is still at school and this is a school-based contract, select the School Based check box.
    23. If the student has received credit for requirements of this contract, select the Credit check box
    24. If the student is an existing worker at the employment organisation, select the Existing Worker check box.
    25. Save your record.
    26. Optional: Navigate to the Contract Status field and update the status of the contract.
      The Contract Status Date field details will be cleared and you will need to provide a valid date for the contract status.
    27. Save your record.

Launch MDUU processes faster

You can launch the MDUU execution package in a faster and efficient way, which in turn, helps you to run activities and processes faster. From the Process Tree Launch (GKALNCH) page, you can directly access the GKAPEXE page from the Options menu.

Before you begin

You will need to access the GKAPEXE page to enable and disable nodes and compile the process tree before returning to the GKALNCH page to execute the enabled activities of the selected process.

About this task

Use the following procedure to utilise the process launch page.

Procedure

  1. Access the Process Tree Launch (GKALNCH) page.
  2. In the Process Code field of the key block, click the drop-down list or press F9 on the keyboard to view the existing process codes in the LOV.
    The pop-up window displays the process codes to for which you have access.
  3. Use the Options menu to navigate to the Process Execution (GKAPEXE) page.
  4. The selected process code will be in the Process Code field, so select Next Block.
  5. Enable and disable activities as required.
  6. Click Compile Tree.
  7. Exit to return to the GKALNCH page.
  8. Select the mode of execution.
  9. Select the exception mode.
    You can select the action applied when an exception is met during the process run. This field is enabled only when the execution mode is AUDIT.
    Note: When the execution mode is UPDATE, the exception mode will be 'Log and Abort' and cannot be changed.
  10. Select Next Block.
    Use the Process Execution block, to view the runtime parameters for the activities of the selected process in the key block and also based on the nodes that are enabled and compiled in the GKAPEXE page.
  11. In the Process Execution block, enter the parameter details for which you want to run the processes.
  12. Click Run Now to run the process selected in the key block.
  13. To mark a process run as finished for any node of the current process that has the status of being run by the current user, click Mark All Nodes as Not Running.

    You can use this button to reset the End Date field value after a failure. In some cases, such as after a loss of database connection during an execution, the End Date field is not updated when the execution is completed. This button allows you to mark, for the current user, all activities as not running.

    This button updates the end date NULL values without verifying whether the activities are effectively running or not.

  14. Select the Process Log page option from the Options menu to navigate to the GKARLOG page to view the log details of the activities that were executed. If there are any run time errors while processing, the error message will be displayed in the page.
