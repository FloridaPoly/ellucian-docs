TACfile details

This section provides more information about the files used by and generated by Banner TAC.

Related concepts
  • Functions and features

SATAC files

Each SATAC file uses an imported file processing activity to load SATAC data to staging tables within the Banner Mass Data Update Utility (MDUU).

For example, the SATAC Applicant File is loaded into the External Table for SATAC Application File (SATACAPPL).

For SATACAPPL, the following entries must be made on the Data Import window of the Process Rules Engine Execution Tree Set-up (GKAPEXS) page.

External Table Name SATACAPPL
Directory Name Name of the directory where the file is stored. Your database administrator can supply this if you do not have the information.
File Name XX_appl.txt, where xx represents the two-character value that SATAC uses to identify your institution.
Record Delimiter NEWLINE
Fields SATAC_APPL_DATA (1401)
Field Delimiter FIXEDLENGTH()

Refer to SATAC file import definitions for more information about the files used by each SATAC file.

The following tasks are carried out during this process:
  • Import files and extract data from them
  • Define the mappings for the imported data columns
  • Initialise the import
  • Populate the import
  • Increment the import
  • View the import
  • Update baseline and ASC tables with the imported data.

Load files from SATAC

The activities to load SATAC files move the data from the external tables to the MDUU staging tables.

For example, for files received from SATAC, the loading activities are contained in the ASC_SATAC_LOAD process, under the ASC_SATAC_IMPORT task.

For example, the ASC_SATAC_APPL process will move the data for each section from the external table for SATACAPPL to each column in the MDUU staging table SATAC Applicant Details (SKRSAPP) table.

All of the activities in the ASC_SATAC_LOAD process can be run in either audit mode or update mode.

Detailed information is written to the log file and can be viewed on the Process Log (GKARLOG) page. This information shows the number of records loaded to each table and the number of records that could not be loaded, which can be helpful when you are loading records to Electronic Admissions (EA) tables.

If the actual process was able to run to completion, the system displays a process completed successfully message on the Process Tree Execution (GKAPEXE) page, even if a review of the log in the Process Log (GKARLOG) page shows that there are specific errors for some records. This is because the message on GKAPEXE is about whether or not the process aborted, not about the specific actions within the process.

Refer to Loading files from SATAC for more information about the specific activities for SATAC.

Match SATAC course codes to Banner programs

The activities in this processing step are used to match SATAC course codes to Banner programs and curriculum rules.

The activities refer to data that has been built on the Program Offering (SKAPOFR) page.

For each TAC there is a matching activity to populate the TAC Course Match (SKRTACM) table with records when a match is found for the applicant's TAC course. There is also an error checking activity that populates the TAC Match Error (SKRTACE) table when the applicant's TAC course cannot be matched to a curriculum rule.

Refer to Matching SATAC course codes to Banner programs for more information about the specific activities for SATAC.

Load to Electronic Admissions

The ASC_SATAC_EALOAD activity used in the Loading to EA step of the process populates baseline EA tables with the data from the MDUU staging tables.

The ASC_SATAC_EALOAD activity uses several functions and can be run in audit mode or update mode and produces a detailed log in GKARLOG.

Run baseline process to match, verify, and load process

The Electronic Application Verify/Load (SARETMT) process must be configured by your institution to ensure that the electronic admissions routines run properly.

SARETMT is a batch process that is used to match, verify, and load admissions applications received electronically. The process uses the matching algorithm that is used for the Electronic Prospect Match (SRRSRIN) process and the Common Matching Entry (GOAMTCH) page. The Electronic Application Process (SAAEAPS) page is used to process electronic applications that are placed in suspense or error status by the SARETMT batch load process.

You must build your own common matching rules. Refer to the Banner General Common Matching Use for information about common matching, the electronic application verify and load process, and the electronic application process page before attempting to load data from Electronic Admissions tables into the baseline production tables.

Seed data is delivered with Banner TAC, but it is recommended that you review and configure EA. Refer to the "Admissions" chapter of the Banner Student Use for detailed information about configuring Electronic Admissions.

Post load activities

The post load activities step includes tasks and activities to populate the baseline production tables, after the match, verify and load process has been completed successfully.

The information updated by the post load activities is not normally modified by the baseline EA push process. It is, however, necessary to update these Banner tables primarily for statutory reporting purposes.

Note: Ensure that you have the correct values built on baseline validation tables for each field updated by the post load activities.

Refer to Post load activities for SATAC files, Load additional data to baseline tables for UAC processing for UAC files, and Load additional data to baseline tables for VTAC processing for VTAC files for more information about the specific activities for each TAC load activity.

Provide reconciliation data to SATAC

The activities used to provide reconciliation data to SATAC include tasks and activities to produce the SATAC reconciliation file, ready for export to SATAC.

Refer to Providing reconciliation data to SATAC for more information about the specific activities for each SATAC data reconciliation.

User profiles for running processes

This feature uses profile-based security to restrict processes to specific authorised users.

This helps your institution decide whether to implement this feature of MDUU.

The following table describes each profile name and the process name associated with it.

Profile Name Process Name Process Description
SATAC_DATA_LOAD ASC_SATAC_LOAD Determines who can run SATAC data load reports.
SATAC_DATA_POSTLOAD ASC_SATAC_POSTLOAD Determines who can run SATAC data postload reports.
SATAC_DATA_RECONCILE ASC_SATAC_RECONCILE Determines who can run SATAC data reconcile reports.

This section describes a number of related activities.

UAC Load Process (SOPLUAC)

The UAC Load Process (SOPLUAC) is used to parse several UAC files to insert the data into the existing UAC staging tables

This process will parse the following UAC files to insert the data into the existing UAC staging tables.

  • Application file (applic),
  • Offer file (offer),
  • Offer Notes file (offnote),
  • Preferences file (pref)
  • Qualifications file (qual).
.

When executing the process, the supported UAC files need to be placed in the appropriate directory in Banner

Refer to Loading files from UAC for more information about the specific activities for UAC load.

The activities used in this step of the process populate baseline EA tables with the data from the MDUU staging tables.

For example, the ASC_UAC_SABNSTU activity populates the baseline Electronic Admissions (SABNSTU) table.

Each activity uses a function that updates specific processing flags on the staging tables so that no record is loaded into Electronic Admissions more than one occurrence.

VTAC files

This section describes a number of related activities.

Register the VTAC file as an external table

After the VTAC D1 file has been loaded to a directory that MDUU can access, users can run this activity to register the file as an external table.

Users need to provide the filename, including the file extension, when they run the activity.

If the file extension, (for example,.txt) is not provided, then the external table will not be registered and an error message will be written to the TAC External Table Log (SKRTLOG) table.

Users can view records on SKRTLOG using the Universal Viewer (GKAPUNV) page.

The data in the external table is only temporary and will be purged when the user loads and registers a VTAC file for the next round. This means that a VTAC file for one round needs to be processed at least as far as VTAC staging tables before a VTAC file for the next round is registered. The activity to register the VTAC file as an external table is contained in the ASC_VTAC_LOAD process, under the ASC_VTAC_REG_TABLE task.

Load files from VTAC

The activities to load VTAC files move data from the external tables to the MDUU staging tables.

For example, for files received from VTAC, the loading activities are contained in the ASC_VTAC_LOAD process, under the ASC_VTAC_IMPORT task.

For example, the ASC_VTAC_DATA activity loads the data for each section from the external table for the VTAC Data File (VTAC) to each column in the MDUU staging table VTAC Data (SKRVTAC) table.

Note: When the activity is run, even though there is only a single file received from VTAC, the single file is split into several staging tables, which moves data from the external table to MDUU. This splitting of the single file is done to improve performance.

Refer to Loading files from VTAC for more information about the specific activities for VTAC.

Refer to Matching VTAC course codes to Banner programs for more information about the specific activities for VTAC.

Load to baseline Electronic Admissions tables

The ASC_VTAC_EALOAD activity used in the loading to EA step of the process populates baseline EA tables with the data from the MDUU staging tables.

The ASC_VTAC_EALOAD activity uses several functions to populate the electronic admissions tables. You can run the activity in audit mode and update mode. Audit mode will not update the database. Both run modes produce a detailed log that can be viewed in GKARLOG.

The only records loaded to Electronic Admissions tables will be those matched preferences that are receiving an offer.

Refer to Load to baseline Electronic Admissions tables for VTAC processing for more information about the specific activities for each VTAC file.

Load additional data to baseline tables

The activities used to load additional data to baseline tables populate baseline production tables and ASC tables with data that could not be processed by the Electronic Admissions routines.

For example, the ASC_VTAC_SARAPPD activity populates the SARAPPD table with an offer decision for each of the student's preferences that has been matched to a Banner program, loaded to electronic admissions tables and pushed into the Admissions Module in baseline Banner.

Refer to Load additional data to baseline tables for VTAC processing for more information about the specific activities for VTAC.
