Define system parameters

There are several elements where the selection of the correct data depends on specific Banner codes.

About this task

To support inter connectivity between baseline codes and TAC elements, a predefined set of system parameters is delivered with Banner TAC, and you must configure these parameters for use. You can modify the delivered parameters to meet your needs, or you can create new ones. Those that are required by the system are identified as such in the System Parameters section.

Only users with appropriate permissions can define or modify system parameters.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Enter the academic year code in the Academic Year field, then select the Go button.
  3. Enter the parameter for which you want to enter valid values in the Parameter field.
  4. Enter the valid value(s) for the parameter in the Value field.
  5. You can enter multiple values for each parameter, separated by commas, up to 2,000 characters.
  6. If desired, enter information in the Description and Notes fields.
  7. Save your changes.

Copy system parameters to another year

System parameters are associated with an academic year.

About this task

You can copy one year's parameter definitions to another, then modify the new definition as desired. When you copy system parameter rules from one year to another, all rules are copied. System parameter rules cannot be deleted if the system required indicator is checked, but the parameter value can be updated to null. System parameter rules can be deleted after being copied to the new academic year if the system required indicator is unchecked.

You can copy rules forwards or backwards in time; the only restriction is that you cannot copy system parameter rules to an academic year that already has system parameter rules.

If you attempt to copy parameters to a year for which at least one parameter has already been defined, the system does not perform the copy and displays an error message.

Procedure

  1. Access the Report System Parameters (SKARSYS) page.
  2. Select Copy Rules to New Year.
  3. Enter the code of the academic year to be copied in the From Year field of the Copy Rules window.
  4. Enter the code of the academic year to which the definitions are to be copied in the To Year field.
  5. Select Process Rule Copy.
  6. If desired, modify the parameter definitions as explained in the Define system parameters section.

Build program offering data

The following procedure explains how to build the program offering data.

Procedure

  1. Access the Program Offering (SKAPOFR) page.
  2. Click the Search for the Program field to select a program code that has a valid curriculum rule number.
  3. Click Search for the Major field to select a major that has been attached to the base curriculum rule selected for the program.
  4. Enter the academic year code in the Academic Year field.
  5. Select the Go button.
  6. Enter the necessary program offering data in the Program Offering window.
  7. Save the record.

Import TAC files

The VTAC Offer (D1) file is now too large to be imported using the method outlined in this procedure and a separate MDUU activity has been created to register the VTAC Offer (D1) file as an external table.

About this task

The SOPLUAC process is used for loading UAC data to staging tables and so this step is no longer needed for UAC files. For detailed information on importing the VTAC Offer (D1) file and registering the VTAC external table, refer to the "VTAC file details".

The following procedure explains how to import the files generated by SATAC, and the VTAC Abridged Offer (D2) file.

Procedure

  1. Save the TAC files to the appropriate directory.

    Your Database Administrator can do this for you.

  2. Access the Execution Tree Set-up Page (GKAPEXS).
  3. Enter the process code in the Process Code field, then select the Go button.
  4. Ensure that the activities under the relevant import task are enabled as per the following table.
    Type of TAC data Task Code
    SATAC ASC_SATAC_IMPORT
    VTAC ASC_VTAC_LOAD
  5. Customise the execution tree to meet your institution's requirements.

    For example, you can change the status of the tree nodes using the Change Status. If desired, you can customise the activities and add these to the execution tree, or you can create your own execution tree. If you customise the activities, you need to create local copies of the baseline activities first.

  6. Go to the Import section.
  7. Enter the name of the external table in the External Table Name field.

    The following table shows some examples.

    Type of File External Table Name
    SATAC Application SATACAPPL
    VTAC Abridged Offer (D2) Data VTACD2
  8. Enter the directory where the import file is located, as shown in the following table, in the Directory Name field.
  9. Enter the file name to be imported in the File Name field.
  10. Enter NEWLINE in the Record Delimiter field.
  11. Enter the correct field string, as shown in the following table, for the file in the Fields field.
    Type of file Field String
    SATAC Application SATAC_APPL_DATA (1401)
  12. Unless you are using a VTAC Abridged Offer (D2) file, enter FIXEDLENGTH() in the Field Delimiter field.

    If you are using a VTAC Abridged Offer (D2) file, then it will be a delimited file and will not be fixed length.

    Refer to File Processing for more information on the values for each import file.

    Note: If you have registered this external table before, you must select the Drop the external table if it exists check box.
  13. Click Register File.
  14. Access the Process Tree Execution Page (GKAPEXE).
  15. Enter the process code in the Process Code field, then select the Go button.
  16. Select the required stages on the Execution Tree Set-up window.
  17. Go to the Execution window.
  18. Enter values for the parameters, if necessary.
  19. Specify the desired execution mode as follows.
    • If you want to check the number of records that will be processed, enter Audit in the Execution Mode field.

      In Audit mode, the process will not insert records into the tables.

    • If you want to insert records into the tables, enter Update in the Execution Mode field.
  20. Select either the Run for Jobsub or Run Now, as desired, to execute the process.
  21. Review the results by selecting the View SQL log.

Match TAC course to Banner programs

The following procedure explains how to match TAC course codes to Banner programs and curriculum rules. UAC course matching is executed using the SOPPTAC process.

Procedure

  1. Access the Execution Tree Set-up Page (GKAPEXS).
  2. Enter the process code, as shown in the following table, in the Process Code field.
    Type of course Process Code
    SATAC ASC_SATAC_LOAD
    VTAC ASC_VTAC_LOAD
  3. Select the Go button.
  4. Ensure that all the activities under the match task, as shown in the following table, are enabled.
    Type of course Task Code
    SATAC ASC_SATAC_COURSE_MATCH
    VTAC ASC_VTAC_COURSE_MATCH
  5. Customise the execution tree to meet your institution's requirements.

    For example, you can change the status of the tree nodes using Change Status. If desired, you can customise the activities and add these to the execution tree, or you can create your own execution tree. If you customise the activities, you need to create local copies of the baseline activities first.

  6. Access the Process Tree Execution Page (GKAPEXE).
  7. Enter the process code in the Process Code field, then select the Go button.

    For example, for matching SATAC courses to Banner programs, the process code is ASC_SATAC_LOAD.

  8. Select the required stages on the Execution Tree Set-up window.
  9. Go to the Execution window.
  10. Enter values for the parameters, if necessary.
  11. Specify the desired execution mode as follows.
    • If you want to check the number of matches and match errors that will be processed, enter Audit in the Execution Mode field.

      In Audit mode, the process will not insert records into the tables.

    • If you want to insert records into the tables, enter Update in the Execution Mode field.
  12. Select either the Run from Jobsub or Run Now as desired, to execute the process.
  13. Review the results by selecting the View SQL log.

Results

Load Electronic Admissions data

The following procedure explains how to process the TAC data from the staging tables into Electronic Admissions tables. UAC data is loaded to Electronic Admissions tables using the SOPPTAC process.

About this task

If the applicant has more than one preference, and one preference is successfully matched to a curriculum but the other preference is not matched, none of the applicant's data will be loaded to the Electronic Admissions tables. Data will be loaded only if both preferences are successfully matched to a curriculum.

Procedure

  1. Access the Execution Tree Set-up Page (GKAPEXS).
  2. Enter the process code in the Process Code field, then select the Go button.
  3. Ensure that all the activities under the Electronic Admissions task, as shown in the following table, are enabled.
    Type of data Task Code
    SATAC ASC_SATAC_EA_LOAD
    VTAC ASC_VTAC_EA_LOAD
  4. Customise the execution tree to meet your institution's requirements, for example, by changing the status of tree nodes using Change Status.

    If desired, you can customise the activities and add these to the execution tree, or you can create your own execution tree. If you customise the activities, you need to create local copies of the baseline activities first.

  5. Access the Process Tree Execution Page (GKAPEXE).
  6. Select the Go button.
  7. Select the required stages on the Execution Tree Set-up window.
  8. Go to the Execution window.
  9. Enter values for the parameters, if necessary.
  10. Enter Update in the Execution Mode field.
  11. Select either the Run for Jobsub or Run Now, as desired, to execute the process.
  12. Review the results by selecting the View SQL log.

    If the applicant has more than one preference, and one preference is successfully matched to a curriculum but the other preference is not matched, none of the applicant's data will be loaded to the Electronic Admissions tables. Data will be loaded only if both preferences are successfully matched to a curriculum.
