Europe INTTRACKUK - Processes and Reports

Banner INTTRACKUK delivers processes and reports for institutions.

Student Graduation Data Update (SORGCAS) process

The SORGCAS process generates the Graduates CAS XML bulk upload file that you use to report the CAS Numbers for graduate students (also known as Graduates Notifications) through the existing Bulk Data Transfer function to the Home Office.

To include the CAS Numbers for students in the SORGCAS report, institutions should meet the following criteria.
  • Students should be graduates with the respective Outcome records that exists in the SHADEGR page with an Outcome Status, provided the Awarded Indicator field is set to Awarded for the Outcome Status. Therefore, it is important that the outcome status used in the SHADEGR page should have the Awarded Indicator field set to Awarded in the STVDEGS page.
  • Institutions should define the Level for every Degree Code. For every outcome record in the SHADEGR page, the Degree Code applied should have an attributed Level in the STVDEGC page. Else, the SORGCAS process cannot print the CAS Numbers in XML report as required. System parameter to define the degree levels for reporting is available with the institutions.
  • Based on the seed data that Ellucian provides, institutions can view the CAS_GRADUATE_LEVEL_CODE parameter in the Configurations window of the GUACONF page. Institutions can enter the required level codes as a string separated by ‘,’ (commas).
  • Institutions can define any number of level codes which are validated against the Level (STVDEGC_DLEV_COD) for the respective Degree Codes as defined in the STVDEGC page. For example, BA, MA, MS, etc.
  • The Graduate Requirements section in the SKAICAS page should not be null. To ensure that the student is eligible to study in the UK, the Type and Date Obtained fields are available in the SKAICAS page, where institutions can enter the type of proof collected from students, and the date the document of proof was collected by the institution.
    Note: CAS Numbers for students with values in the Type and Date Obtained fields are necessary for SORGCAS reporting. If Type or Date Obtained fields are NULL for the CAS applications, the CAS Numbers will not qualify for SORGCAS reporting.
  • CAS statuses for the SORGCAS reporting are defined in the CAS_STATUS parameter in the Configurations window of the GUACONF page. (The CAS_STATUS parameter is visible when the you run the seed data.). You can enter any number of values as a string separated by ‘,’ (commas) for the parameter.
    Note: The SORGCAS process extracts only the CAS Numbers for the respective values that you enter for the CAS_STATUS parameter to print the Graduates CAS XML. Example: CLOSED, ASSIGNED, USED, etc.
  • Every institution can have their own processes to qualify a CAS number to the Graduates CAS XML file. Institutions have the discretion to override the SORGCAS applied inbuilt validations for every CAS application. To override the SORGCAS applied validations, click the Graduate Return Override check box for CAS applications in the SKAICAS page.
  • When institutions select the Graduate Return Override check box (SKRICAS_GRAD_RETURN_OVERRIDE = ‘Y’), the CAS number qualifies for printing in the Graduates CAS XML output file.
  • When institutions select the Graduate Return Override check box, the SORGCAS process prints the CAS Number in the XML output does not validate the following:
    • Outcome record exists
    • Awarded indicator is set to Awarded for the Outcome Status
    • Institution-defined degree levels for the CAS_GRADUATE_LEVEL_CODE parameter in the GUACONF page
    • Graduate Requirements entered in the SKAICAS page
    • Institution-defined CAS statuses for the CAS_STATUS parameter in the GUACONF page
    Note: When the institution attempts to override an application in a CAS Status that is not specified in the CAS_STATUS parameter range, the user sees a warning message in the SKAICAS page to alert the user that the application being overridden is not in the range of defined CAS statues. This alert prevents the institutions from overriding the application.

    After the CAS Number for an application is printed in the XML output for the SORGCAS process and the Graduate CAS History is populated for CAS application, (that is SKRICAS_GRAD_CAS_BATCH_TYPE, SKRICAS_GRAD_CAS_BATCH_DATE, and SKRICAS_GRAD_CAS_BATCH_NAME), you cannot update the status of the Graduate Return Override option.

    You can update the status of the check box only if the SORGCAS process has not printed the CAS Number in any of the SORGCAS batch outputs.

The SORGCAS process uses the following parameters while execution.

Last Run Date Yes Enter Y to generate report from last run date or N for user defined dates.
Note: The Last Run Date parameter is based on the latest date that the process fetches from the SKRIEIB_BATCH_DATE column for Batch Type Graduates CAS Report.
Y or N
From Date No Enter the date from which CAS reporting for graduates should begin. Date
To Date No Enter the date to specify the end date for CAS reporting for graduates.
Note: The From Date and To Date parameters are based on the SHRDGMR_ACTIVITY_DATE column. Based on the input date range, the SORGCAS process looks up for records in the SHRDGMR table. The process considers the outcome records that are created within the date range.
 Date
Run Mode Yes Enter A for Audit Mode or U for Update Mode. U or A
Batch Name No Batch name (without file extension) of report generated to regenerate a report. Enter the Batch name
Oracle Directory Name Yes The Oracle directory name where file is created. Enter the Oracle directory name
Ellucian recommends that you note the following:
  • Set the default value of the Last Run Date field to N. After the first run for SORGCAS process, you can choose to run the SORGCAS process from the last run date (last activity date for SORGCAS) by setting this value to Y. When you set the Last Run Date field to Y, the SORGCAS process does not consider the From Date, To Date, and Batch Name field values.
  • You should populate the From Date and To Date fields with dates when the Last Run Date field value is N. This allows the SORGCAS process to extract the CAS Numbers for the specified date range and not batch name.
  • Use the Batch Name field to regenerate an XML that is already generated. To regenerate an XML, enter the exact same batch name again. You can re-run the process for a batch name, provided you enter the values for the required fields such as Last Run Date and Run Mode. However, the process will not consider the dates specified.
  • To view the sorgcas.xml file that you generated, go to the directory you specified in the Oracle Directory Name parameter for the SORGCAS process and search for the file with the run number. Alternatively, you can download the file using the GKAODFT page, which is the recommended approach for file downloads for Oracle SaaS clients.
  • The sorgcas.log file records the error logging, in case of any errors. The sorgcas.lis file records the parameter values that you enter for the process execution.

Run the SORGCAS process

Steps to run the SORGCAS process and generate the sorgcas.xml output file.

Procedure

  1. Access the Process Submission Control (GJAPCTL) page.
  2. Enter SORGCAS in the Process field.
    You can also directly enter the SORGCAS process name in the home page to access the GJAPCTL page where the process value is already displayed for you.
  3. Navigate to the data block.
  4. Enter Database in the Printer field to generate the output in the job submission directory.
  5. Enter the parameter values as required.
  6. Navigate to the Submission block to submit the details entered.
  7. Click Save.
    The system generates and displays the Sequence Number.
  8. Access the Saved Output Review (GJIREVO) page to view the sorgcas.lis, sorgcas.log.
  9. Alternatively, click the Related menu and select the GJIREVO page to view the output files.
  10. You can enter the number in the Number LOV or select the required output file name from the Number LOV.
  11. Access the Oracle directory that you entered to view the sorgcas.xml file.
    Oracle SaaS users can download the XML using the GKAODFT page.

    The following are the steps to download the SORGCAS XML file using the GKAODFT page.

  12. Access the Oracle Directory File Transfer (GKAODFT) page.
  13. Go to the Download File window.
  14. Select an Oracle Directory Name from the LOV for the Oracle Directory field. (same as the oracle directory name you provided in the parameter to run the SORGCAS process).
  15. Click the File Name field that displays the list of values for your to select your file.
  16. In the File Name field, click the LOV to view the List of Files (GURODFT) window.
  17. In the GURODFT window, enter the run number in the Criteria field to view the results depending upon your search criteria.
  18. Select the file from search results.
  19. Click Download File.
    The system displays the file downloaded to your downloads folder on your system
