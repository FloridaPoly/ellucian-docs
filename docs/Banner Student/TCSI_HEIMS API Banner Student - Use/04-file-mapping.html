File mapping

In the succeeding tables, the files are cross-mapped with Banner pages and fields that they source data from, for HEP or VET or both.



Note: SHATRNS is used for the Unit Enrolment packet only where recognition of prior learning (RPL) for units of study are recorded as transfer credit in the Transfer Credit (SHATRNS) page. The student data is recorded in the TCSI Unit Enrolment packet if the value for the RPL_IN_SHATRNS system parameter is set to 'Y'.

course-applications file mapping

Table showing the file mapping for course-applications.

The student will be included in the course applications file if they do not have an admissions application in baseline admissions (SAAADMS page, SARADAP table) where there is no application source in the Background Institution/Source table that is a value listed for the TAC-SOURCE-LIST system parameter.

This prevents applicants from being picked up if they are TAC applicants.

The selection of records is also limited based on the application date, Commonwealth supported place, and first study period. The TCSI-APP-FROM-DATE and TCSI-APP-TO-DATE system parameters allow records to only be selected if the application date is between the dates recorded in each parameter. There can only be one date for each parameter.

The TCSI-APP-SECTOR-CDE system parameter allows students to be included in the Course Application packet if they have at least one record for a Commonwealth-supported place (and even then, only if they fit other criteria of being a direct undergraduate applicant, within the application date range for the first study period)

The STVTERM_FA_TERM field is used to identify the first study period. Only those terms with the value 1 in this field will be used when evaluating records for inclusion in the Course Applications packet.

The TAC_APPS_OFFERS_PREF_GET_ACAD system parameter gets the basic details of course application using GET-UID API method for the academic year that you enter in the parameter.

Specialisations that are reported to AVETMISS, but link to a single TCSI Course Admission have their unit enrolment records reported correctly.

The TCSI reporting logic refers to these as Modular Programs to keep them separate from the TCSI concept of Course Specialisations. The unit registrations connect to each separate study path and are linked to the study path sequence of the original TCSI course admission using the TCSI Course Code link.

The SOPHBDP process includes logic to process the Modular Programs records based on the value of the MODULAR-PROGRAMS-EXIST system parameter for the report year. If the MODULAR-PROGRAMS-EXIST = Y, the system executes the logic when the SOPHBDP process is run for Unit Enrolment. If MODULAR-PROGRAMS- EXIST = N, the system does not execute the logic.

TCSI considers two unit registrations to be the same if the Unit of Study Code and Unit of Study Census Date are the same. This means that if a student is registered in one Banner CRN, and that is reported to TCSI and then the student changes to a different CRN for the same unit of study with the same census date, do the following:
  • Ensure that the old, dropped CRN is deleted from the student's registration.
    • If the student selects the 'Delete from registration' action in self-service registration, then the record will be deleted from registration and will only exist in the registration audit table.
    • If the student selects some other drop code, then the registration status will need to be updated to DD (Drop/Delete) and the record physically deleted from the registration record. It will still exist in the registration audit table
  • Ensure that the new CRN is registered correctly and has the same census date
  • Run SOPHBDP to update values - for example, perhaps the campus has changed
  • If data has changed in a way that needs to be reported to TCSI, run SOPHEIM to PATCH the existing Unit Enrolment record
  • Any CRN that has NOT been reported to TCSI and is dropped on or before the census date, will not get reported to TCSI at all, even if it has not been deleted from the student's registration record.
