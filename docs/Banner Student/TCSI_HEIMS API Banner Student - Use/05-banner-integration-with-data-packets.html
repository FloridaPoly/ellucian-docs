courses-of-study integration

See the table for methods and options associated with the courses-of-study endpoint.

API endpoint Description
Method Option
POST ^ Registration of one or more new courses of study offered by the provider.
GET ^ Request information of all active courses of study offered by the education provider.
GET :uid Request information with the use of the uid option returns data for a particular item that has a unique identifier associated with it.

When used with the courses-of-study endpoint, this becomes the courses_of_study_uid.

When used with the courses-of-study endpoint, this becomes the courses_of_study_uid.

When used with the courses-of-study endpoint, this becomes the courses_of_study_uid.

It removes the course of study record with the specific unique identifier.

students integration

See the table for methods and options associated with the students endpoint.

API endpoint Description
Method Option
POST ^ Reporting one or more new student records with DE.
POST :uid/citizenships Capture details of a new citizenship for an existing student.

If the student has multiple citizenship rows in the Bulk Extract (SOTBCIT) table that have not been posted to TCSI, the one with the lowest surrogate ID will be posted with the Student POST.

That record gets a citizenship effective from date that is the same as the TCSI system date on the day it is successfully posted, so it will be immediately PATCHED to change the effective from date to the date stored for the record in SOTCIT.

After that, the remaining citizenship rows for the student will be POSTED in ascending order, starting with the next lowest surrogate ID. It is expected that institution will maintain changes to student citizenship correctly so that the effective from dates for the records will not overlap.
