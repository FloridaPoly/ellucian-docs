SKKREPT functions

Several Australian products use the same functions, including HEIMS/TCSI, and are in the SKKREPT package.

FN_ADDR_LOC

The FN_ADDR_LOC function returns address details as either a city or a DEEWR-codified location, for either the earliest record or latest record in SPRADDR, as specified in the arguments passed to the function.

fn_addr_loc
(SKBRSYS_PARAM_NAME,
 SPRADDR_PIDM,
 SKBRSYS_ACYR_CODE, 
 p_loc_city,
 p_min_max) 
(SKBRSYS,
 Student_PIDM,
 Academic year,
 Location/City,
 Earliest/Latest record)

If the Location/City parameter is left null in the arguments, the function checks for an address record type (using spraddr_atyp_code) passed to the function as the first argument (that is, it checks for matching values for that address type on SKBRSYS).

If that address type is found on SPRADDR for that student, and if the nation code of the address (spraddr_natn_code) matches the home nation code in SKBRSYS (for the parameter HOME-NATN), the function concatenates A and the address postcode (spraddr_zip).

If the address' nation code is not within the home nation, the function concatenates X and the address' nation code (spraddr_natn_code).

Specifying MIN in the earliest/latest record parameter causes the function to retrieve the minimum address sequence number (spraddr_seqno), and specifying MAX causes it to retrieve the maximum address sequence number.

If the Location/City parameter is specified as LOC, the function returns the city of the address (spraddr_city) rather than the postcode. No modification of the city name occurs. It is returned exactly as it is found on spraddr_city.

F_BUSINESS_DATE

The F_BUSINESS_DATE function is used when calculating census dates to return a date for a CRN that is not a weekend or public holiday (business date).

The F_BUSINESS_DATE function is also used when evaluating whether a student who is eligible for a VET FEE-HELP loan has passed the legislated cooling-off period between enrollment and submission of a request for a VET FEE-HELP loan.

F_BUSINESS_DATE 
(p_date_in,
 p_acyr_code,
 p_reg_census_ind)

First, the function checks whether the input date (p_date_in) is a weekend by using the new WEEKEND system parameter value in SKARSYS for the current academic year (p_acyr_code).

If the p_reg_census_ind parameter value is C and if the WEEKEND parameter value in SKARSYS is NULL, the WEEKEND check is not performed.

If the p_reg_census_ind parameter value is E and the WEEKEND parameter value in SKARSYS is NULL, the WEEKEND check assumes that the WEEKEND parameter value is SAT,SUN (Saturday and Sunday).

If the input date is part of a weekend, the first output date will be the next business day after the weekend.

The next step is to check whether that first output date is a public holiday.

For the holiday check, the PUBLIC-HOLIDAY-USAGE parameter value in SKARSYS for the academic year (p_acyr_code ) is used to determine whether the holiday check is required.

The PUBLIC-HOLIDAY-USAGE parameter check is based on the academic year of the term code selected on the ASC_ECAF_SELECT_PROGRAM page.

Date checking against rules in SSREXCL is based on the year of the date that is passed to the function. For the enrollment check it is a year of either SFRSTCA_ADD_DATE or TBRACCD_ENTRY_DATE. For the census date check it is the year of the calculated census date.

When a public holiday is recorded for a year on the Schedule Exclusion Rules form (SSAEXCL), this function recognises the public holiday regardless of the part of term.

The public holiday check is able to be used when working out census dates and when checking whether a student requesting a VET FEE-HELP loan has been enrolled for sufficient time to be able to make that request.

If the p_reg_census_ind value is C and the PUBLIC-HOLIDAY-USAGE value in SKARSYS is CENSUS, or if the p_reg_census_ind value is E and PUBLIC-HOLIDAYUSAGE value in SKARSYS is ECAF, the holiday check is done and the appropriate business date is returned.

If the PUBLIC-HOLIDAY-USAGE value in SKARSYS is NULL, the holiday check is not performed.

F_GET_CENSUS_DATE

The F_GET_CENSUS_DATE function returns the census date for the student in the unit of study based on the actual start date and the duration of the unit of study (CRN).

F_GET_CENSUS_DATE 
(p_start_date_in,
 p_end_date_in,
 p_acyr_code_in)

For calculating the census date, the CENSUS_DATE_PERCENTAGE parameter value for the academic year of the term of the CRN is used to determine what percent of the total duration is considered to be the census date.

The number of days between the actual start date (p_start_date_in) and the actual end date (p_end_date_in) is calculated.

The CENSUS_DATE_PERCENTAGE parameter value is used to determine the census days count.

The census days count is added to the actual start date to determine the actual census date.

The F_BUSINESS_DATE function is used to determine whether the calculated census date is a holiday or a weekend and the appropriate date is returned.

If a nominal census date has been retrieved for the student and CRN, but that date goes beyond the end date of the CRN, the calculated census date will be used instead.

F_CENSUS_DATE_FOR_SSBSECT

The F_CENSUS_DATE_FOR_SSBSECT function returns the census date to be inserted into the Census One Freeze Date (SSBSECT_CENSUS_ENRL_DATE) field for traditional CRNs.

F_CENSUS_DATE_FOR_SSBSECT 
(p_crn_in,
 p_term_code_in)

It is used in the ST_SSRMEET_INSERTSKRAREG_AS trigger and is called to get the census date when a student registration does not exist and when changes are made to the SSRMEET (Section Meeting Times Repeating Table) record.

It gets the correct academic year value for the term code of the CRN, then it calls the F_GET_START_DATE,F_GET_END_DATE and F_GET_CENSUS_DATE functions to determine the actual start date, actual end date, and census date for the traditional CRN and term code, and returns the census date.

F_GET_END_DATE

The F_GET_END_DATE function returns the actual end date of the unit of study (CRN) based on the CRN and TERM_CODE for both OLR and traditional CRNs.

F_GET_END_DATE 
(p_term_code_in,
 p_crn_in,
 p_end_date_in,
 p_no_units_in)

For OLR CRNs, the function returns the completion date value from SFRAREG.

For traditional CRNs, the following steps are used to determine the actual end date if the value for the CENSUS-USE-SSRMEET system parameter is Y for the academic year of the term of the CRN:
  • The function gets the maximum end date from SSRMEET (MAX(SSRMEET_END_DATE)) for the CRN and term code.
  • If the maximum end date from SSRMEET is null, it gets the part of term end date from SSBSECT (SSBSECT_PTRM_END_DATE) for the CRN and term code, and that date is returned as the actual end date.
  • If the maximum end date from SSRMEET is not null, it gets the list of DAYS defined in SSRMEET and determines whether the maximum end date from SSRMEET DAY is in the DAYS list. If so, it returns that date as the actual end date.
  • If the maximum end date from SSRMEET DAY is not in the DAYS list, it gets the previous date from SSRMEET that is in the DAYS list and returns that date as the actual end date.

If the value for the CENSUS-USE-SSRMEET system parameter is some other value, including blank or null, or if the CENSUS-USE-SSRMEET system parameter does not exist for the academic year of the term of the CRN, the function gets the part of term end date from SSBSECT (SSBSECT_PTRM_END_DATE) for the CRN and term code, and that date is returned as the actual end date.

F_GET_START_DATE

The F_GET_START_DATE function returns the actual start date of the unit of study (CRN) based on CRN and TERM_CODE for both OLR and traditional CRNs.

F_GET_START_DATE 
(p_term_code_in,
 p_crn_in,
 p_start_date_in,
 p_no_of_units_in)

For OLR CRNs, the function returns the start date value from the baseline Additional Registration (SFRAREG) table.

For traditional CRNs, the following steps are used to determine the actual start date if the value for the CENSUS-USE-SSRMEET system parameter is Y for the academic year of the term of the CRN.
  • The function gets the minimum start date from SSRMEET (MIN(SSRMEET_START_DATE)) for the CRN and term code.
  • If the minimum start date from SSRMEET is null, it gets the part of term start date from SSBSECT (SSBSECT_PTRM_START_DATE) for the CRN and term code, and that date is returned as the actual start date.
  • If the minimum start date from SSRMEET is not null, it gets the list of DAYS defined in SSRMEET and determines whether the minimum start date from SSRMEET DAY is in the DAYS list. If so, it returns that date as the actual start date.
  • If the minimum start date from SSRMEET DAY is not in the DAYS list, it gets the next date from SSRMEET that is in the DAYS list and returns that date as the actual start date.

If the value for the CENSUS-USE-SSRMEET system parameter is some other value, including blank or null, or if the CENSUS-USE-SSRMEET system parameter does not exist for the academic year of the term of the CRN, the function gets the part of term start date from SSBSECT (SSBSECT_PTRM_START_DATE) for the CRN and term code, and that date is returned as the actual start date.

FN_SD_ADDRESS

The FN_SD_ADDRESS function checks if the last six characters of p_string are POSTAL. If so, it gets the SKBRSYS_VALUE corresponding to the SKBRSYS_PARAM_VALUE= 'POSTAL_ADDR_TYPE' and for passed SKBRSYS_ACYR_CODE.

The function also checks if the last three characters of p_string are RES. If so, it gets the SKBRSYS_VALUE corresponding to the SKBRSYS_PARAM_VALUE='RESIDENTIAL_ADDR_TYPE' and for the passed SKBRSYS_ACYR_CODE.

fn_sd_address 
(SPRIDEN_PIDM,
 P_STRING,
 SKBRSYS_ACYR_CODE)
 (Student PIDM,
 address type,
 SKBRSYS academic year)
Condition Outcome
The p_string value is SPRADDR_STREET_LINE1_POSTAL or SPRADDR_STREET_LINE1_RES The function returns a corresponding SPRADDR_STREET_LINE1
The p_string value is SPRADDR_STREET_LINE2_POSTAL or SPRADDR_STREET_LINE2_RES The function returns a corresponding SPRADDR_STREET_LINE2
The p_string value is SPRADDR_CITY_POSTAL or SPRADDR_CITY_RES The function returns the corresponding SPRADDR_CITY
The p_string value is SPRADDR_STAT_CODE_POSTAL or SPRADDR_STAT_CODE_RES The function returns the corresponding SPRADDR_STAT_CODE

F_GET_NOMINAL_CENSUS_DATE

After the census date is calculated, the F_GET_NOMINAL_CENSUS_DATE function retrieves the first nominal census date that is on or after the calculated census date. Nominal census dates should be recorded on the Report Element Values (SKARVAL) page for the CENSUS-DATE element code.

Ellucian expects that nominal census date values may be different for each institution so no seed data is delivered for SKARVAL. However, the CENSUS-DATE element code is delivered as seed data for the Report Element Validation (SKVRVAL) page.

If there is not sufficient data in SKARVAL for the function to be able to retrieve a nominal census date, then the calculated census date is used.

This function is used only if the value of the USE-NOMINAL-CENSUS system parameter is Y. If the value of the USE-NOMINAL-CENSUS system parameter is any other value, including blank/null, or if the USE-NOMINAL-CENSUS system parameter does not exist for the academic year of the term of the CRN, then the calculated census date is used.

If the USE-NOMINAL-CENSUS system parameter is set to Y, the function calculates the nominal census dates for all CRNs in terms for the corresponding academic year, whether the CRNs are Open Learning Registration CRNs or traditional CRNs using parts of term.

SKKTCSI functions

Functions that are only used for TCSI/HEIMS processing are in the SKKTCSI package.

FN_CHECK_AGGREGATED_ELIGIBLE

The FN_CHECK_AGGREGATED_ELIGIBLE function checks whether the student is eligible for Aggregated Award and returns Y or N, based the parameter values that you provide. Value Y implies that the student is eligible for Aggregated Award and N implies that the student is not eligible for Aggregated Award.

FN_CHECK_AGGREGATED_ELIGIBLE
(p_org_pidm,
 p_stud_pidm,
 p_course_code, 
 p_program,
 p_min_max 
(p_acyr,
 p_degc,
 p_key_seq)

The function checks whether the student record exists in the bulk table and is already reported to TCSI. Also, the function checks if the student’s degree record exists and matches with the Aggregated Award eligibility system parameters.

FN_CHECK_DEFERRED_EXIST

The FN_CHECK_DEFERRED_EXIST function checks whether students have any deferred amount that exists for any unit of study in same census date.

FN_CHECK_TBRACCD_DETAIL

The FN_CHECK_TBRACCD_DETAIL function retrieves detail codes based on system parameters.

FN_CHECK_TBRACCD_DETAIL
((p_detail_code,,
 p_acyr_code)

The function checks whether the detail code (p_detail_code) of a transaction on a student’s account is listed for specific system parameters for the academic year (p_acyr_code). It returns Y if the detail code is listed and N if it is not.

The function checks for the following system parameters for values:
  • AMOUNT_PD_HECS
  • TOTAL_AMOUNT_HECS
  • FEE_HELP_LOAN_FEE
  • AMOUNT_PD_FEE
  • TOTAL_AMOUNT_FEES

FN_FETCH_CENSUS_DATE

The FN_FETCH_CENSUS_DATE function gets the census date for a unit of study.

FN_FETCH_CENSUS_DATE
(p_pidm,
 p_term_code,
 p_crn, 
 p_crn,
 p_ptrm_code 
(p_report_year)

The function returns a DATE value based on the parameters that you provide. If the value for Part of Term (p_ptrm_code) is null, the function returns the skrareg_calc_census_date column value. If Part of Term is not null, and the institution is a Non-University, the function returns the ssbsect_census_enrl_date column value. Otherwise, the function returns the sobptrm_census_date column value as the census date.

FN_GET_CATALOG_TERM_CODE

Returns the catalog term for the student’s learner curriculum and uses it to extract the correct value for Provider Type and BOTP indicator from the SKADRCO page.

FN_GET_CATALOG_TERM_CODE
((p_pidm,,
p_report_year,
p_lcur_program,
p_lcur_key_seqno)

The function returns the catalog term for the student’s latest active, current, learner curriculum associated with their study path where the term code of the curriculum is earlier than or equal to the latest term in the reporting year.

FN_GET_PROVIDER_TYPE

Returns the provider type for the student’s study path.

FN_GET_PROVIDER_TYPE
(p_pidm,
 p_program,
 p_term, 
 p_key_seqno,
 p_rate_code 
(p_stsp_resd_code,
 p_stdn_resd_code)

If the student’s program is in the SKADRCO page with the provider type of 'HEP', then the system returns the value of 'HEP'.

If the student’s program is in the SKADRCO page with the provider type of 'VET'

AND the HELP type for that program is either 'V' (VET FEE-HELP) or 'L' (VET Student Loan)

AND the student’s citizenship code matches a value for the VFH-CITZ-ELIGIBILITY system parameter for the reporting year

AND either the student’s residency code on their study path or their residency code on their general learner record matches a value for the ECAF_RESD_ELIGIBLE system parameter for the reporting year

THEN the system returns the value of 'VET'.
