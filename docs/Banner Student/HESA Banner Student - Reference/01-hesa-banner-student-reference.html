Student Cohort (SKACHRT) page

The SKACHRT page can be used to view any cohort, not just a cohort created by the Process Rules Engine. For HESA processing for the Student Record of 2007/08 and later, use the HESA-specific HESA Cohort (SKAHCOH) page, which allows maintenance of HESA instance data by cohort.

When the GKPPSQL process is used to execute a rule set that creates a cohort, this page is used to view, update, add, and delete records in the cohort.

A record can be added to the SGRCHRT table if the person (ID) has a student record with a term code that is less than or equal to the term code in the Key block.

A record can be deleted from the SGRCHRT table if the effective term in the Key block equals the value in the Effective Term field in the Base section.

A record can be updated if the effective term in the Key block equals the value in the From Term field in the Base section. In this case, only the Inactive check box and Reason field may be updated.

SKACHRT does not allow a user to end a cohort. This must be done in the Additional Student Information (SGASADD) page.

Base section

Use this block to enter the student cohort details.

Field Description

Inactive If this check box is selected, a value must be entered in the Reason field.
Reason Reason that the Inactive check box was selected. A value must be entered in this field if the Inactive check box is selected.
Study Path Sequence number of the study path.

HESA Destination of Leavers (SKADL11) page

Use this page to enter or display HESA DLHE questionnaire data for a reporting period. This page displays information for reporting periods 2011/12 and later.

For reporting periods up to and including 2010/11, use the HESA Destination of Leavers (SKADLHE) page. The page uses the HESA Destination of Leavers Table (SKRDL11).

The contents for the lists of values for the relevant fields are defined on the UCAS Field Descriptions (SKAUFDS) page and the HESA Student System Data Maintenance (SKASSDT) page. An MDUU processing task to populate these based on the HESA definitions is provided in the ESC_HSD_LOV_DL11 task of the ESC_HSD_LOV process tree.

The page follows the format of HESA's “Destinations of Leavers from Higher Education” survey page. Because the page is designed to match the questionnaire, field descriptions are not provided, except for the Section F tab, which includes user-customisable fields.

A number of fields on the page are not returned to HESA, but are provided to allow you to record institution-specific fields or to assist with the recording of coded values. These include:
  • Q9 Employer ID field on the Section B (2-13) tab, which allows you to record a non-person ID (SPAIDEN) with a respondent’s employer
  • Date of Phone Call 1 - 3, Element 1 - 6, and Comment fields on the Section F/Institution Reporting tab

HESA Destination of Leavers (SKADLHE) page

Use this page to view HESA DLHE questionnaire data from a previous reporting period. This page displays information for the 2010/11 reporting period.

For reporting periods 2011/12, use the HESA Destination of Leavers (SKADL11) page, and use the HESA Destination of Leavers from Higher Education (SKADLHO) page for earlier reporting periods. This page will not be updated in future releases because it is retained in the system solely for viewing historical data.

The page follows the format of the DLHE questionnaire from HESA. The page uses the SKRDLHE table.

The fields do not have an exact one-to-one relationship with the DLHE questions. Some fields are completed using more than one question. Other questions are linked to multiple fields in the return. In most cases, users will be able to enter the leavers’ responses and have Banner translate them to HESA codes, however, this is not possible for a small number of fields. Human intervention is required to code these fields, notably the SIC and SOC codes. The user must enter the code directly or select the value from a List of Values. Valid values for these fields are provided in SKVSSDT as seed data.

There are a number of core questions in the questionnaire. If core questions are not completed, the response is not valid and the leaver cannot be returned to HESA. Some core questions are core for all respondents, some are core if the respondent is in employment, and some are core if the respondent is undertaking further study. There are core questions for part-time leavers and QTS leavers. The core fields are 001-011, 033, 036, and 048-050.

The SKADLHE record can be saved even if the record is incomplete. However, any attempt to save the record will generate the following warning message: WARNING: This record is incomplete. NULL values will be stored for incomplete questions. Do you want to save this record? After the record is saved, any entered values are stored, and default null values are stored for all other fields except in the case where this violates a validation requirement for fields that can be filled using automatic completion rules. Fields that cannot accept a default value will remain null. The Survey Status field will automatically be saved with a code of IN (Incomplete).

For example, values can be entered for the following questions not required by HESA:
  • Name of Employer
  • Employer ID
  • Region of Destination

The region of destination is automatically derived from the postcode of the employment location. These fields are located on the Section B Questions 3-9 section.

The page offers automatic navigation between sections. Alternatively, the user can navigate to the various sections using the options displayed on the page. The responses between fields are validated according to HESA coding rules, and appropriate warning messages are provided when necessary. Fields are automatically completed based on the previous responses, according to the HESA coding rules.

Field Description
Return to Regulator Check box to indicate if the institutions wants a specific HESA data to be included as a part of the Data Future returns.

Venue Type Type of the venue being returned to HESA.
