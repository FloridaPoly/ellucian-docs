Overview

The Adult Migrant English Program (AMEP) is a national settlement program that provides English language tuition for eligible migrants and humanitarian entrants to Australia, who do not have functional English language skills.

The Department of Immigration and Citizenship (DIAC) manages AMEP.

Functions and features

The AMEP module draws information from Banner AMEP tables and pages, in addition to tables and pages added specifically for the AMEP functionality.

The AMEP module is made up of various steps and processes. These are organised as follows.

  • Set up the AMEP Module: Procedures and pages are used to define elements, values, and processes that are required to produce the AMEP extract.
  • Collect and Record Data: Supplemental procedures and pages are used to enter and review any data required for AMEP compliance that might not have already been entered elsewhere in Banner.
  • Create the Return: Extract and Report Generation procedures and pages are used to create and view the data snapshot and extract. This step has three stages: snapshot process, extract process, and export process.
  • View Data: The Process Rules Engine Universal Viewer is used to view the data produced by the snapshot and extract processes.

Although the AMEP reporting software is delivered with defaulted configuration, many of the functions and processes can be tailored to your institution. For example, if the institution records each AMEP assessment as a separate unit or module, instead of using gradable components from Electronic Gradebook, this can be remapped so the AMEP extract will refer to the grade codes instead of the component marks.

Note: Configuring the AMEP module requires knowledge of the underlying database tables and is usually carried out with the assistance of technical staff within the institution or Professional Services.

System parameters

A set of default system parameters is delivered with the AMEP module.

These parameters are used to configure the AMEP system. Use the Report System Parameters (SKARSYS) page to configure this data to the specifics of your implementation. Appropriate permissions are required to modify these pages. Refer to System Parameters for details.

AMEP Eligibility Process

The AMEP Eligibility Process allows you to evaluate whether an applicant is entitled to enter an AMEP program.

About this task

Each applicant is given a score in each of the following skill areas, using the International Second Language Proficiency Rating (ISLPR):
  • Listening
  • Reading
  • Speaking
  • Writing
    Note: Each skill is given a score between 0 and 5. Each applicant's scores are recorded in Banner. Then, the Admissions Decision Rules and the Process Rules Engine is used to determine whether the applicant is eligible for AMEP tuition.
With this process, you will be able to perform the following functions:

Procedure

  1. Organise students into AMEP streams
  2. Record each applicant's scores
  3. Calculate automated decisions based on the user-defined rules.
    To accomplish these functions, a new process code has been created on the Business Rule Process Code Validation (GKVSQPR) page and a parameter code has been attached to these process codes on the Business Rule Process Parameters (GKRSQPA) page.
    Note: The process uses the Process Rules Engine (process, rule sets, and rules features) to execute these functions.

Processing data collection

This release provides the data reporting and extract functionality to meet the needs for AMEP Reporting.

The AMEP module uses rule sets in the Banner Mass Data Update Utility (MDUU) to generate the snapshot, extract, and export files for the return. Seed data has been delivered to enable you to begin designing your return process.

To understand how the returns are built, you must understand the process, task, and activity elements of MDUU. Refer to the Banner Mass Data Update Utility Use content for a complete explanation of tasks and activities, and how these elements work to support AMEP reporting requirements.

This document uses the following key terms.

  • Process: This represents a set of tasks sharing a common business area. The MDUU security allows you to associate users and user classes to a given process. If this functionality is activated, only users assigned to a given process will be able to execute this process.
  • Task: This is a set of activities that is carried out as part of a process, such as taking a snapshot of data from the original data sources and gathering them in more synthetic (eventually generated) tables.
  • Activity: This is a processing element that is carried out as part of a task, such as a data copy, or a data transformation. An activity updates a single table and can be reused in several tasks.

The typical top-level process flow for AMEP reporting is shown below.



Snapshot processing

Snapshot processing populates snapshot data from baseline tables, but could also be configured to use ASC tables, locally developed tables, and tables from third-party applications.

The process allows selected target tables in the snapshot data structure to be populated. It has the capability to refresh (remove and insert) or update (add new rows and update existing rows) the snapshot.

The structure of the snapshot tables is maintained by the MDUU under a schema called MDUUREP. (Refer to the MDUU Use for more information.)

When running the snapshot, you can select which snapshot tables to populate. You can also purge the selected snapshot tables before re-inserting rows.

This process allows you to do the following:
  • Create snapshot data
  • Define the column mappings for the snapshot
  • Define the rules to generate the snapshot population
  • Initialise the snapshot
  • Populate the snapshot
  • Increment the snapshot (add or remove records without refreshing the snapshot from scratch)

Extract processing

Extract processing populates the extract based on snapshot data and, where necessary, it transforms the snapshot data into the format needed for the extract.

The process allows selected target tables in the extract data structure to be populated. It has the capability to refresh (remove and insert) or update (add new rows and update existing rows) the extract.

This process allows you to do the following:
  • Create extract data
  • Define the column mappings for the extract
  • Define the rules to generate the extract population
  • Use expressions or functions to derive values based on the contents of the snapshot
  • Initialise the extract
  • Populate the extract
  • Increment the extract (add or remove records without refreshing the cohort from scratch)

Export processing

This process populates the export based on extract data. The process allows selected target tables in the export data structure to be populated. It has the capability to refresh (remove and insert) or update (add new rows and update existing rows) the export.

This process allows you to do the following:
  • Create export data
  • Define the mappings for the CLOB export column
  • Define the rules to generate the export population
  • Initialise the export
  • Populate the export
  • Increment the export (add and remove records without refreshing the cohort from scratch)
  • View the export
  • Create a text file from the export data

File details

Information is included about the files generated for AMEP.

AMEP Enrolments File

The following table describes the activities for this file.

Activity Type Activity Name Description
Snapshot ASC_SNA_AMEP_ENROL This activity pulls data from several baseline tables to select the students enrolled in AMEP programs, for an effective term. The activity populates the AMEP Enrolments Data Snapshot (SKRSAME) table and uses PIDM, program, CRN, component ID, and effective term as populate keys.
Extract ASC_EXT_AMEP_ENROL This activity pulls data from the AMEP Enrolments Data Snapshot (SKRSAME) table to populate the AMEP Enrolments Data Extract (SKREAME) table. The activity uses PIDM, program, CRN, component ID, and effective term as populate keys.
Export ASC_EXP_AMEP_ENROL This activity pulls data from the AMEP Enrolments Data Extract (SKREAME) table to populate the AMEP Enrolments Data Export (SKRXAME) table. This activity pulls all the data elements into one CLOB field per record, and also contains an Effective Term field, so that several data returns can be kept in the same table.

AMEP Status Changes File

The following table describes the activities for this file.

Activity Type Activity Name Description
Snapshot ASC_SNA_AMEP_STATUS This activity pulls data from several Banner baseline tables to select students in AMEP programs who have enrolment status codes that are not "EL". The activity populates the AMEP Status Data Snapshot (SKRSAMS) table and uses PIDM, program, CRN, component ID, and effective term as populate keys.
Extract ASC_EXT_AMEP_STATUS This activity pulls data from the AMEP Status Data Snapshot (SKRSAMS) table to populate the AMEP Status Data Extract (SKREAMS) table. The activity uses PIDM, program, CRN, component ID, and effective term as populate keys.
Export ASC_EXP_AMEP_STATUS This activity pulls data from the AMEP Status Data Extract (SKREAMS) table to populate the AMEP Status Data Export (SKRXAMS) table. This activity pulls all the data elements into one CLOB field per record, and also contains an Effective Term field, so that several data returns can be kept in the same table.

Procedures

Includes descriptions of admissions eligibility and other reporting procedures.

Assess admissions eligibility

The following procedure explains how to access and select the applicants who are entitled to AMEP tuition.

Procedure

  1. Access the Process Launch (GKAPPLN) page.
  2. Enter ASC_AMEP_ASSESS in the Process Code field.
  3. Enter AMEP_SELECT in the Rule Code field.
  4. Enter the effective date in the Effective Date field.
  5. Select the Go button.
  6. Enter Update in the Execution Mode field.
  7. Enter the mode of exception in the Exception Mode field.
  8. Enter the parameter value in the Parameter Value field.
  9. Click Run Now.
    Note: Use ASC_AMEP_UPDATE and DELETE_GKRPWRK rule codes to update AMEP decisions and to delete GKRPWRK records, respectively.

Report student enrolments

The ASC_AMEP_REPORTING process code contains snapshot, extract, and export activities for AMEP files.

Procedure

  1. Access the Process Tree Execution (GKAPEXE) page.
  2. Enter ASC_AMEP_REPORTING in the Process Code field.
  3. Select the Go button.
  4. Customise the execution tree to meet your local requirements, for example, by changing the status of tree nodes. (Refer to the Banner Mass Data Update Utility Use for more information.)
    If desired, you can customise the activities and add these to the execution tree, or you can create your own execution tree. If you customise the activities, you will need to create local copies of the baseline activities first.
  5. Select the required stages on the Execution Tree Set-up window.
  6. Go to the Execution window.
  7. If necessary, enter values for the parameters.
  8. Select either the Run for Jobsub or the Run Now button, as desired, to execute the process.
  9. Review the results by selecting the View SQL log.
  10. Access the Universal Viewer (GKAPUNV) page to review the data generated by the process.

Results

The following target tables are updated for the AMEP enrolment reporting activities:
  • AMEP Enrolments Data Snapshot (SKRSAME) table
  • AMEP Enrolments Data Extract (SKREAME) table
  • AMEP Enrolments Data Export (SKRXAME) table

Create flat file returns

The final stage of AMEP reporting is to export the data to an external document. This process allows you to export the extract data to a flat file document.

Procedure

  1. Access the Universal Viewer (GKAPUNV) page.
  2. Enter the seven-character name of the export table (for example, SKRXAME) in the Table Name field.
  3. Use the Filter Column and Filter Value fields to filter the data (for example, you can filter for a particular academic year or term).
  4. Select the Go button.
  5. Double-click in any cell of the CLOB column.
  6. Enter the name of the directory to which the file will be exported in the Directory Name field.
  7. Enter the name of the exported flat file in the Filename field, ensuring that the file extension is .txt.
  8. Click the Export Column Data button.
