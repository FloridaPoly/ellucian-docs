Central Applications Office pages.

CAO Interface Configuration (GZVCAOI) page

Use the GZVCAOI page to enter and maintain the CAO Interface-specific validation, crosswalk and configuration values held in the GZVCAOI table.

The GZVCAOI page entries are usually used in one of two ways for CAO.
  • System parameter value. In this case, one entry is usually entered for the Internal Code field. The values entered for the External Code and Translation Code fields should be the same as the value in the Internal Code field. The Sequence (sequence number) field is normally not used, and the value is set to 1.
  • Mapping entries. In this case, the system derives a value for the Internal Code field based on the value in the External Code field, which is usually received from the CAO.

    Usually, more than one entry exists for each potential external value (for example, CAOCOURSE, which maps the CAO course codes to internal program codes).

    The Sequence (sequence number) field is normally not used, and the value is set to 1. The CAOCOURSE entry is an exception because the Sequence field is used to identify a course category (that is, 1 = Degree, 2 = Diploma).

    The Translation Code fields should be the same as the value in the Internal Code field.

Field Description
Internal Code Specific code relationships for Banner concepts.
Sequence Internal sequence number that provides either a hierarchy or positional identifier.
Group High-level group of rows of data (Internal Codes) that are categorized together to provide multiple entries for a single concept.
Description Description of the concept.
Reporting Date Reporting date. This field is usually not used in CAO.
External Code If the Group Code is a system variable, then the value for this field is the same as the Internal Code field. If the Group Code is a mapping entry, then the value for this field is usually a value received from the CAO, which needs to be mapped to a Banner value (held in the Internal Code field).
Translation Code Field that returns translated values. The value for this field is usually the same as the Internal Code field.
System Requirements Indicates whether the row is system required. System required codes cannot be deleted.
User User who created or last modified the record.
Activity Date Date the record was created or last modified.

Irish Institutes CAO Rating (SZAIIOT) page

The SZAIIOT page is used to create the outgoing Rating and Supplemental transactions. The page is also used to view decisions received from the CAO following the receipt of Offer/Acceptance transactions.

The SZAIIOT page can be used to add or modify ratings or supplemental scores for an applicant. A rating or supplemental score cannot be entered for an application that has been withdrawn.

The page records the ratings and supplemental scores as test scores. The value in the Type field will determine if the data goes to a Ratings file or a Supplemental Scores file.

Key block

Use this block to specify the applicant details for whom you want to to create the outgoing Rating and Supplemental transactions.

Field Description
ID Applicant’s identity.
Term Term code. The value automatically defaults to the term code specified on the GZVCAOI page for the CAOTERMCODE group.

Base section

Use this section to enter the outgoing Rating and Supplemental transactions for the applicant details specified in the Key block.

Field Description
Group Code Group code, as derived from the ID01 field. An example of the group codes for 2000 are as follows:

A - Numbers beginning 000, 0025-0029, 003, 004, 005, 006, 007

B - Numbers beginning in the range 0090-0094

C - Numbers beginning 008

D - Numbers beginning 0095

The CAO decides the range of numbers, which define the group codes for every year.
Principal School Principal institution from the ID10 field on the Identity transaction.

Rating Information section

When a record is created in this section, the page will identify any unsatisfied checklist items (that match the request type for the selected test code) for the applicant, and will update the received date on the checklist item.

Field Description
Test Test code. The LOV for the test code will include records from the STVTESC page where the value in the MIS field (STVTESC_MIS_CODE) is SR.

If only one valid test code exists, this value will automatically be the default value in the Test field. If more than one applicable value exists, the user must select an appropriate test code from the LOV.
Date Taken Date on which the test was taken.
Type Type of test. The LOV for the test type will include records from the STVTADM page where the value in the Internal Code field (STVTADM_CODE) is S or R.

If only one valid test type exists, this value will automatically be the default value in the Type field.

Alternatively, if an entry exists in the GZVCAOI page for the CAOCHRTTEST group where the value in the External Code field matches the applicant's group code, the Type field will default to the Internal Code value. This default can be overwritten.

If no default exists, the user must the select the appropriate test code from the LOV.
Score Rating awarded to the test followed by the ranking number to be applied if the applicants' scores are equal.

The maximum length of the value that can be entered in this field is determined by the value entered in the Internal Code field on the GZVCAOI page for the CAOSCORELENGTH group.
Rank Ranking number, which is used to differentiate between more than one applicant with the same score.

The maximum length of the value that can be entered in this field is determined by the value entered in the Internal Code field on the GZVCAOI page for the CAORANKLENGTH group.

The value for the Rank field is automatically set as follows:
  • If the value for the Type field is R, then:

    If the Score value is outside the limits defined for the GZVCAOI CAOMINSCORE and CAOMAXSCORE groups, then the value for the Rank field will be set to zero. The value in the Rank field can then be modified.

    If the Score value is within the limits defined for the GZVCAOI CAOMINSCORE and CAOMAXSCORE groups, then the value for the Rank field will be set to that of the existing CAO rank, or a random number if that value is zero or null. If the value for the CAORANKOVR group is Y, then the value in the Rank field can be updated, otherwise the field cannot be updated.

  • If the value for the Type field is S, then:

    The value for the Rank field will be set to zero. If the value for the CAORANKOVR group is Y, then the value in the Rank field can be updated, otherwise the field cannot be updated.
Term Term code. The value automatically defaults to the term code specified on the GZVCAOI page for the CAOTERMCODE group.
Released Indicates whether the ratings information has been written to the Ratings File (RF) for return to the CAO. If this check box is selected, ratings information cannot be changed.

CAO Transaction Exception Maintenance (SZAIREC) page

Use the SZAIREC page to view the details of potential duplicates, anomalies and exceptions in the data received from CAO. Data.

Data received from these transactions will not be loaded into Banner until the user has verified that the data is accepted by clicking the Load Transaction or Load All Transaction of Current File and Exception Type button. The SZAIREC page must be checked, and any outstanding issues resolved, before and after every load process.

Details window

Use the Details window to specify the details of potential duplicates, anomalies and exceptions in the data received from CAO Data.

If the user has selected all possible matches, the transaction load package is called with the Duplicate Processing flag set to FALSE (that is, duplicate matching is not performed). If successful, the system removes the exception row.
ID, MF A No action, except to remove the exception from the page.
ID, MF A No action, except to remove the exception from the page.

All E Calls the transaction load package. If successful, the exception row is removed.
AS, OF S No action except to remove the exception from the page.

Duplicate Applicant section

When the exception type is D (duplicate) or M (mismatch), this section is displayed on the Analysis tab. This section displays the applicant who is a possible duplicate or mismatch.

An applicant has an exception type of M when the duplicate checking has found an existing record with the same Personal Public Service (PPS) number, but where the gender or the date of birth are different.

Original Applicant section

When the exception type is D (duplicate) or M (mismatch), this section is displayed on the Analysis tab. This window displays the existing applicants who may be a match to the incoming applicant. The user can view the details, and accept or reject the applicants.

The user can scroll through each original Banner student, and then clear the Check check box of original applicant with which the student from the CR transaction should be matched, and then click the Merge or Recategorise button to process the duplicate or mismatched application details. To load the applicant as a non-duplicate, the user should click the Load Current Transaction button. Any transactions where the Load Current Transaction button is not clicked will be rejected.

Field Description
ID ID of the possible original applicant.
Check Indicates whether the selected ID is a match to the duplicate applicant.
Last Name Last name of the possible original applicant.
First Name First name of the possible original applicant.
Middle Name Middle name of the possible original applicant.
Address Address of the possible original applicant.

The address that is displayed is determined by the value entered in the Internal Code field on the GZVCAOI page for the CAOADDRORDER group.
Date of Birth Date of birth of the possible original applicant.
Sex Gender of the possible original record applicant.
Postcode Postcode of the possible original record applicant.
Telephone Telephone number of the possible original applicant. The value is from the most recent SPRTELE record for the given applicant, based on the address type, address sequence number and default CAO telephone type.
SSN Social security number of the possible original applicant. The value is from the SPBPERS record.
Recategorise Renumbers the original applicant CAO ID with the CAO ID of the duplicate applicant.

The CAO divides its applicants into the following groups: Leaving Cert, GCSE, EU and Other. The CAO may assign another ID number to an applicant if the applicant's group has changed. Banner must be updated with this new number and this number is used to obtain the application cohort group.
Merge Merges the duplicate applicant to the original applicant.

Incorrectly Formatted Address section

When the exception type is "A" (address format problem), this section is displayed on the Analysis tab. This section displays the applicant who is a possible duplicate or mismatch.

This section displays the address exactly as it has been formatted on the Address Information section on the SPAIDEN page.

If necessary, the user can change the format of the address without switching to SPAIDEN.

Banner populates address and country fields from the CAO data using the following method:

If the CAO address is four or less fields, the information is placed into the Address fields and City field on the SPAIDEN page.

The country code is populated with the data mapped from ID13.

Field Description

Sequence Number Internal sequence number that is assigned to each address type associated with the ID. Display only.
From Date Date from which the address type is active or inactive for the ID. If the field is blank, the address type is effective. Display only.
To Date Date to which the address type is active or inactive for the ID. If the field is blank, the address type is effective. Display only.
Address Three lines of the street address as it is displayed on the Address Information section on the SPAIDEN page for the address type associated with the ID.
City City as it is displayed on the Address Information section on the SPAIDEN page for the address type associated with the ID.

Application Ratings section

The Application Ratings section lists all of the existing ratings for the application selected in the Application section. Records can be created, updated or deleted in this section.

Ratings information cannot be created or updated if the application status is withdrawn. When a rating has been returned to the CAO (SORTEST_RELEASE_IND = Y), the entry cannot be modified or deleted.

In addition, when a new record is created, the page will identify any unsatisfied checklist items for the applicant, which match the request type for the selected test code, and will update the received date on each item.

Field Description

If only one valid test code exists, this value will automatically be the default value in the Test field. If more than one applicable value exists, the user must select an appropriate test code from the LOV.
Date Taken Date on which the test was taken. The default value is the system date but this can be changed.
Type Type of test. The LOV for the test type will include records from the STVTADM page where the value in the Internal Code field (STVTADM_CODE) is S or R.

If only one valid test type exists, this value will automatically be the default value in the Type field.

Alternatively, if an entry exists in the GZVCAOI page for the CAOCHRTTEST group where the value in the External Code field matches the applicant's group code, the Type field will default to the Code value. This default can be overwritten.

If no default exists, the user must the select the appropriate test code from the LOV.
Score Rating awarded to the test followed by the ranking number to be applied if the applicants' scores are equal.

The maximum length of the value that can be entered in this field is determined by the value entered in the Internal Code field on the GZVCAOI page for the CAOSCORELENGTH group.
Rank Ranking number, which is used to differentiate between more than one applicant with the same score.

The maximum length of the value that can be entered in this field is determined by the value entered in the Internal Code field on the GZVCAOI page for the CAORANKLENGTH group.

The value for the Rank field is automatically set as follows:
  • If the value for the Type field is R, then:

    If the Score value is outside the limits defined for the GZVCAOI CAOMINSCORE and CAOMAXSCORE groups, then the value for the Rank field will be set to zero. The value in the Rank field can then be modified.

    If the Score value is within the limits defined for the GZVCAOI CAOMINSCORE and CAOMAXSCORE groups, then the value for the Rank field will be set to that of the existing CAO rank, or a random number if that value is zero or null. If the value for the CAORANKOVR group is Y, then the value in the Rank field can be updated, otherwise the field cannot be updated.

  • If the value for the Type field is S, then:

    The value for the Rank field will be set to zero. If the value for the CAORANKOVR group is Y, then the value in the Rank field can be updated, otherwise the field cannot be updated.
