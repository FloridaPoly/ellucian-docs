PSIS Banner Student use

Banner PSIS is a Canadian-specific product to help institutions meet reporting requirements of Statistics Canada on enrollment.

The Post Secondary Student Information System (PSIS) captures enrollment information at all Canadian post-secondary institutions for each twelve-month period. Institutions are required to report detailed information about their programs, course offerings and student enrollment.

PSIS is also designed to track students throughout their academic careers. A PSIS National Student Number (NSN) is used to link historical enrollment data from the previous survey. This process is used to build a comprehensive view of student flows within Canadian institutions and across provinces.

PSIS elements are reported using seven flat files in two categories, Institutional Data and Student Data. The Institutional Data files are used to store data about the institution and its programs (metadata). Student Data provides demographic information for all enrolled students.

Depending on specific provincial reporting requirements, your institution might only input required data elements. A number of provinces have central agencies to which the schools report. The agency assumes the responsibility of reporting the PSIS data on behalf of the institutions to Statistics Canada.

For more information about PSIS, go to the Statistics Canada web site at http://www.statcan.gc.ca/.

Terminology and acronyms

Learn about the terms and acronyms used in PSIS.

Terms

The following tables describes the terms used in Banner PSIS.

Term Description
Final Report The final report covers the twelve month period from the start date to the end of the following winter term. The final report is due on July 15th.
Institution Code Values supplied by Statistics Canada. Includes a two-digit province code, the three- digit institution code, and the three-digit college code.
Metadata The metadata is the institutional data compiled when the program and course offerings are finalized.

Generally, the three metadata files (ID, IP, and IC) are transferred to Statistics Canada during the fall term or as early as the summer.
Preliminary Report A preliminary report covers the period from the start date to the end of the fall term (usually in December).

The report starts on the day after the end of the Winter session, and ends on December 31st.

The preliminary report is due on January 15th.The preliminary report obtains a quick view of the fall activity in Canada to meet early reporting responsibilities.

Assumptions

Successful use of PSIS depends on the following conditions and assumptions.

  • A fundamental assumption is to keep the programming logic as simple as possible, and use the areas of Banner that best fit the corresponding PSIS elements.

    For example, the IP file is populated with program data from the SMRPRLE and SMBPGEN tables. This requires that some institutions revisit their setup procedures.

  • Avoid duplication of data at all costs.
  • All programs are defined in the SMRPRLE table.
  • One program code (for example, NONPRGM) for a non-program is used to capture students doing non-credit work, one-time courses, and so on (any non-official program).
  • For apprenticeship programs, Statistics Canada requires that each year have a separate program ID.
  • GTVSDAX and SVAXWLK are used to crosswalk internal values to PSIS values, unless a validation table exists with PSIS pre-defined values, such as province codes (STVSTAT) and PSIS nation codes (STVNATN).
  • Report only catalog courses in the IC file. Report schedule sections in the SC file. For a course with lecture, lab, and other sections, report only the lecture section. For pure lab courses, report only the lab section.
  • PSIS allows a section to be offered in multiple delivery modes. In the SC file, the course delivery mode could be derived from schedule type (SSRSCHD) or from attendance method (STVACCT) when only one delivery mode is checked. For multi-mode delivery, there is a need to introduce multiple schedule delivery types and map them through the SVRXWLK table to section attribute codes (SSRATTR) for delivery type.
  • Use the SCBCRSE records to populate the IC file.
  • In the GUBINST table, the GUBINST_CENTURY_PIVOT field is used by the PSIS processes to determine in what century a year belongs. The PSIS default value is 28 if the pivot field is Null. Year “28” and forward (28 - 99) correspond to the previous century, “19”. Years before “28” (00 - 27) are associated with the current century, “20”. Ensure the Century Pivot value is sufficiently low to account for the student population’s age.
Note: If your institution is not using the program ID concept in Banner, an extensive setup effort is required before you can use PSIS. A few institutions have made modifications to Banner baseline to incorporate the concept of program tracking. This issue requires these schools to act accordingly.

Institutional data

Institution, program, and course information is categorized to allow classification.

This operation allows accurate comparisons of enrollment and graduate information within and among institutions and across provinces. Institutional data consists of the following.

  • Institution Description (ID) file - Describes the institution.
  • Institution Program (IP) file - Describes programs offered at the institution.
  • Institution Course (IC) file - Describes courses offered at the institution.

Student data

Student files contain specific records for all students enrolled at any time during the reporting cycle. Programs and courses (credit and non-credit) are also taken into consideration.

File abbreviations are used to identify Student Data as it appears in the first column of the record layouts. The Student Data files consist of the following:

  • Student Data (SD) file - Describes the student
  • Student Program (SP) file - Describes the student’s program.
  • Student Course (SC) file - Describes the student’s courses.

PSIS reporting and due dates

The seven PSIS files are submitted twice per year, as a preliminary report and a final report. Record layout is identical for the two reporting cycles.

The start date for both reporting cycles is the day after the end of the institution’s previous winter term (usually a date in April, May or June). The preliminary report covers the period from the start date to the end of the fall term (usually in December). The final report spans the entire twelve- month period from the start date to the end of the following winter term.

The preliminary report is due on January 15th. The final report is due on July 15th. This method provides Statistics Canada with a thumbnail view of fall activities across Canada. The final report acts as a complete picture for the entire reporting year.

Although the preliminary report is not due until January 15th, institutions are encouraged to provide their institutional data (three metadata files) when program and course offerings are finalized. Generally, this information is transferred during the fall term or as early as the summer.

Statistics Canada also requests an electronic version of individual institutional academic calendars, where available. These tools help to classify programs and courses before receiving the actual student data in January. The period between the end of the final report and the July 15th date provides time to finalize administrative records. For example, most students will have completed their year's course work and graduated before the institution creates the PSIS files.

Some elements are collected on behalf of provincial ministries of education. The provincial authorities supply the code sets and instructions in these cases.

StatisticsCanada provides a pre-screening program to the institutions to assist in checking the validity of the data reported on their PSIS files.
