Eliminate Between-File Errors Parameter

If the Eliminate Between-File Error parameter is set to Y, then the data will be removed in the following cases:

  • The process will check that there is at least one course record (SC record) in the SVRESSC table where the combination of Instit(SC1025), RepStartYear(SC1000), StudID(SC4000) is the same as the combination of Instit(SP1025), RepStartYear(SP1000), and StudID(SP4000) in the SVRESSP table, when the value for ProgEndStat (SP5100) is not 04 (Graduated from program).

    If a matching course does not exist, then the program records are deleted from the SVRESSP table, and the following message is printed in the control report: x number of records deleted from SVRESSP table (SP4000_c).

  • The process checks if any of the course's start and end dates fall within the period dates to be reported in the ID file, where the combination of CourPer(SC1035) and CourSubPer(SC1036) is the same as the combination of Period (ID1035) and Sub_period (ID1036).

    If one of the following scenarios is true, then the course record is deleted from the SVRESSC table, and the following message is printed in the control report: x number of records deleted from SVRESSC table (SC1035_b):

    • ( (CourStart (SC6020) > EndDate (ID1055))

      OR

      (CourStart(SC6020) = EndDate (ID1055) AND CourStart (SC6020) <> CourEnd (SC6021)) )

    • ( (CourEnd (SC6021) < StartDate (ID1045))

      OR

      (CourEnd(SC6021) = StartDate (ID1045) AND CourStart (SC6020) <> CourEnd (SC6021)) )

  • The process will verify all of a student’s courses against all of their programs. A course does not have to fit the date of a specific program but must fall within the dates of all programs, especially if a student has more than one SP record.

    The process verifies a student’s courses as follows:

    1. Get all SP records that exist with SP1000 || SP1025 || SP4000 = SC1000 || SC1025 || SC4000
    2. Calculate the minimum (ProgStart (SP5010)) of all programs for the same StudID
    3. Calculate maximum (ProgEnd (SP5090)) of all programs for the same StudID
    4. If one of the following scenarios is true, then the course record is deleted from the SVRESSC table, and the following message is printed in the control report: xnumber of records deleted from SVRESSC table (SC6020_W):
      • (CourStart (SC6020) <= minimum (ProgStart) - 5 days

        OR

        (CourStart> maximum (ProgEnd) when ProgEnd <> Blank) )

      • (CourEnd (SC6021) <> Blank AND CourEnd <= minimum (ProgStart) -5 days

        OR

        (CourEnd> maximum (ProgEnd) when ProgEnd <> Blank))

  • The process will check if a student’s SD file has at least one SP record in the SVRESSP table where the combination of Instit(SD1025), RepStartYear(SD1000), StudID(SD4000) is the same as the combination of Instit(SP1025), RepStartYear(SP1000), and StudID(SP4000) in the SVRESSP table.

    If a matching record does not exist, then the student SD record is deleted from the SVRESSD table, and the following message is printed in the control report: x of Records deleted from SVRESSD table (SD4000_a).

  • For a student course (SC) record to exist, there must be an equivalent student description (SD) file. Therefore, the process will check the SVRESSD table to ensure there is a combination of Instit(SD1025), RepStartYear(SD1000), StudID(SD4000) that matches the combination of Instit (SC1025), RepStartYear(SC1000), and StudID(SC4000) in the SVRESSC table.

    If a matching record does not exist, then the student SC record is deleted from the SVRESSC table, and the following message is printed in the control report: x Number of Records deleted from SVRESSC table (SC4000_a).

  • For a student transfer (ST) record to exist, there must be an equivalent student description (SD) file. Therefore, the process will check the SVRESSD table to ensure there is a combination of Instit(SD1025), RepStartYear(SD1000), StudID(SD4000) that matches the combination of Instit(ST1025), RepStartYear(ST1000), and StudID(ST4000) in the SVRESST table.

    If a matching record does not exist, then the student ST record is deleted from the SVRESST table, and the following message is printed in the control report: x Number of Records deleted from SVRESST table (ST4000_a).

PSIS Extraction Process (SVPESIS)

This process populates the extract tables for PSIS reporting. The tables that are populated by this process are SVRESID, SVRESIP, SVRESIC, SVRESSD, SVRESSP, SVRESSC, and SVRESST.

The SVPESIS process can use generic procedures to insert data in or exclude data from the PSIS report. These procedures are blank but can be changed to include the user’s local code to solve a particular way to calculate one or more PSIS elements for the PSIS tables. If no code is added to the generic procedures, the SVPESIS process defaults to the PSIS values.

Open Learning Registration (OLR)

This process can capture registration data for CRNs created with the Open Learning Registration (OLR). Registration data for OLR is stored in the Additional Registration Information Table (SFRAREG).

For ID (Institution Description) records, the process looks at the value in the SVRIDTB_PTRM_CODE field. If the value is null, the process will do the following:

  • Search all of the OLR courses from the Academic History tables and Registration tables for current reporting year and institution.
  • Make sure all of the students to be processed are members of a population selection (GLBEXTR table) set by the user.
  • Get the term code, the earliest start date of the courses, and the latest end date of the courses for the term.
  • Insert the following ID records into the SVRESID table:
    • Period (ID1035) = the above term code
    • Sub-Period(ID1036) = NULL
    • StartDate(ID1045)= Earliest course start date of this term
    • End Date(ID1055)= Whichever date is earlier: latest end date for OLR courses for the term, or the StartDate(ID1045) plus 370

For SC (Student Course) records, the process looks at the Student Course Registration Repeating Table (SFRSTCR) for each CRN to determine if the part-of-term code (SFRSTCR_PTRM_CODE) is null.

  • If the value is not null (current registration method), then the CRN is processed in the normal way except for a small change needed to correct the end date reported when the student has withdrawn after the withdrawal date (SVRIDTB_WITHD_DATE) for the term. When the student has withdrawn after the withdrawal date (SVRIDTB_WITHD_DATE) for the term, the registration status change date (SFRSTCR_RSTS_DATE)is reported for the course end date (SVRESSC_COURSE_END_DATE).
  • If the value for the part-of-term code (SFRSTCR_PTRM_CODE) is null (OLR), then the CRN is processed using the dates in the SFRAREG table when the registration status change date (SFRSTCR_RSTS_DATE) has a registration code where the Count in Enrollment check box is selected (STVRSTS_INCL_SECT_ENRL= Y) on the STVRSTS form.

    When the registration status change date (SFRSTCR_RSTS_DATE)has a registration code where the Withdrawal Indicatorcheck box is selected (STVRSTS_WITHDRAW_IND= Y) on the STVRSTS form, the CRN will only be included if the registration record (SFRAREG_EXTENSION_NUMBER= 0) has a current registration date (SFRAREG_RSTS_DATE) that is less than the registration status change date (SFRSTCR_RSTS_DATE). Otherwise, the start and completion dates for the CRN will be the earliest value for the registration start date (SFRAREG_START_DATE) and the latest value for the completion date (SFRAREG_COMPLETION_DATE), respectively, where the registration code (SFRAREG_RSTS_CODE) has a selected Count in Enrollment check box (STVRSTS_INCL_SECT_ENRL= Y) on the STVRSTS form. If the OLR courses are beyond one report year, then the course end date (SVRESSC_COURSE_END_DATE) is set to the report start date (SVBESIS_RPT_START_DATE+ 730).

The original registration record has an extension number of 0, and a RSTS code of RE. The RE RSTS code has a selected Countin Enrollment check box (STVRSTS_INCL_SECT_ENRL= Y) on the STVRSTS form, therefore the dates associated with extension number 0 are valid. Extension numbers 1, 3 and 5 have a RSTS status code of EE. The Countin Enrollment check box is not selected on the STVRSTS form for the EE RSTS code, therefore the dates associated with these records are not considered valid. Extension

numbers 2 and 4 have a RSTS code of RX. The Count in Enrollment check box is selected on the STVRSTS form for the RXRSTS code, therefore the dates associated with these records are considered valid.

The original registration record (extension number 0) has the earliest start date (15-SEP-04), which will be used as the course start date (SVRESSC_COURSE_START_DATE). While extension number 5 has the latest completion date (22-MAY-05), the dates associated with the EERSTS code are not considered. Therefore, the course completion date (SVRESSC_COURSE_END_DATE) is 30-APR-05 from extension number 4. In this example, CRN 5002 would be reported from 15-SEP-04 to 30-APR-05. If the date of 30-APR-05 is greater than the report start date (SVBESIS_RPT_START_DATE) plus 730, then the CRN end date will be the report start date (SVBESIS_RPT_START_DATE) plus 730.

Fill SVRICTB with Defaults Process (SVPICDV)

This process is used to populate the SVRICTB table with current courses as defined on the course catalog (SCACRSE), and with default values for all PSIS fields. The SVRICTB table provides data for SVAICTB.

This process is optional, and can be used as an alternative to or in conjunction with entering data into SVAICTB.

This process should be run only one time with the F process type, and this should be done right after installing PSIS. After that, the report should be run only with the Y process type.

Manual entry of institution codes (on the SVRICIN table) is required if multiple institutions are supported.

Parameters Required? Description Values
Course Credit Unit Yes Yes Value used to define credits granted.
Process Type Yes Indicates whether the process is to be run to fill SVRICTB with defaults when the project is installed or to fill SVRICTB with yearly defaults.
  • F: Fill SVRICTB with defaults when the project is installed
  • Y: Fill SVRICTB with yearly defaults

Fill SVRSPTB with Defaults Process (SVPSPDV)

This process is used to populate the SVRSPTB table with all student related programs for the terms in SGBSTDN in the PSIS reporting year.

If there are no programs related in those terms, the process selects the most recent student related program from the SGBSTDN table. Additionally, default values are included for all PSIS fields for each student (registered/graduated) record created during the Population Selection.

The SVRSPTB table provides data for the SVASPTB form. This process is optional, and can be used as an alternative to or in conjunction with entering data into the SVASPTB form.

This process should be run only one time with the F process type, and this should be done right after installing PSIS. After that, the report should be run only with the Y process type.
