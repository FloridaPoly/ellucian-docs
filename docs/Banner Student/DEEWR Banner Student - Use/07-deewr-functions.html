DEEWR Functions

This chapter describes functions used by Banner DEEWR activities.

Commonwealth Assistance Notices (CAN)

Functions used by CAN activities are in the SKKDEWR package.

F_GET_CAN_SAHELP_INST_NAME

This function is used in the ASC_CAN_SA_HELP activity and returns the institution name for SA-HELP students for Commonwealth Assistance Notices.


SKKDEWR.f_get_can_sahelp_inst_name(:ACADEMIC_YEAR, :REPORT_PERIOD, :SUBMISSION, sorlcur_pidm, NULL, NULL, sorlcur_site_code, sorlcur_term_code, sorlcur_camp_code, SORLCUR_KEY_SEQNO)

The function uses the campus code of each CRN to determine a delivery location for each CRN, and then finds the organisation attached to each delivery location.

The function finds records on the Location Mapping Rules (SKARLOC) page where the campus code matches the campus of the CRN. The mapping rules must be for the DEEWR-SA-HELP-LOCATION report collection and for an academic year that is valid for the term of the CRN.

If there is only one rule for the matching campus code, and if on that rule on SKARLOC both Instructional Method and Student Location are blank - then the matching Delivery Location code has been found.

If there are multiple rules for the matching campus code, then this means that there are rules where Instructional Method or Student Location are not blank.

The Instructional Method on SKARLOC is compared first to the Instructional Method of the CRN (on SSASECT) and if that is blank, then the Instructional Method on SKARLOC is compared to the Session of the CRN (also on SSASECT). If the Session of the CRN is also blank, then the Instructional Method on SKARLOC is compared to the Session on the student's study path (SGRSTSP), and if that is also null, to the Session on the student's general learner record (SGBSTDN).

If there are multiple rules for the matching campus and instructional method, then the Student Location is used to select the correct Delivery Location for this student and CRN.

If the student has a student attribute and if that student attribute is in the string of values for the STUDENT_LOCATION system parameter and if the student's record on SGASADD is for a term code that is effective for this CRN, then the function retrieves the Location code where the Student Location matches the student's attribute.

If the student's attribute does not match a rule on SKARLOC, or isn't listed in the STUDENT_LOCATION system parameter, or if the effective term of the student attribute is for a later term than the CRN, or if the student does not have any student attributes - then the function compares the student's Site Code with the Student Location value from SKARLOC.

First, the function compares the Site Code from the LEARNER curriculum with the Student Location value. If a match is found, then that Delivery Location Code is used. If the Site Code on the LEARNER curriculum is null or does not match any Student Location, then the function compares the Site Code on SGBSTDN (viewed on the first tab of SGASTDN) to the Student Location value. If a match is found, then that Delivery Location Code is used.

If there is not a row for the matching campus and instructional method where student location is blank - then the function is not able to find a matching delivery location on SKARLOC and will now look at SKRTDLV (the table behind the Delivery Locations tab on the SKATORG page).

When the function looks on SKRTDLV, if there is a record that is effective for the term of the CRN where the campus code matches the campus of the CRN, then the Delivery Location code of that record is returned.Delivery location codes are all associated with a training organisation (non-person) PIDM, either on SKARLOC or on the Delivery Location tab of SKATORG.

If all of the retrieved delivery locations are attached to the same training organisation, then the legal name of that organisation, as recorded on SKATORG is returned as the institution name.

The function uses the SKATORG record that is effective for the term of the student's registration.

If the retrieved delivery locations are attached to different training organisations on SKARLOC, then the function will use the organisation that is associated with the delivery location on the Delivery Locations tab of SKATORG, and will retrieve the legal name of that organisation.

F_DEEWR_E306_HEP_CODE_OD

This function is used in the ASC_HEP_SNA_OD_FILE activity to retrieve the E306 Higher Education provider code.


skkdewr.f_deewr_e306_hep_code_od(sorlcur_pidm, sorlcur_term_code, :academic_year, :report_period, :submission, sorlcur_camp_code, saradap_sess_code, sorlcur_seqno, saradap_site_code)

The function uses the campus code of the admissions curriculum to determine the delivery location and then finds the organisation attached to that delivery location, to then retrieve the additional ID for that organisation that has an additional ID type that matches the HEP_CODE system parameter.

The function finds records on the Location Mapping Rules (SKARLOC) page where the campus code matches the campus of the curriculum. The mapping rules must be for the DEEWR-APP-LOCATION report collection and for an academic year that is valid for the term of the admissions application.

If there is only one rule for the matching campus code, and if on that rule on SKARLOC both Instructional Method and Student Location are blank - then the matching Delivery Location code has been found.

If there are multiple rules for the matching campus code, then this means that there are rules where Instructional Method or Student Location are not blank.

The Instructional Method on SKARLOC is compared to the Session of the admissions application. If there are multiple rules for the matching campus and instructional method, then the Student Location is used to select the correct Delivery Location for this student and curriculum.

If the student has a student attribute in admissions and if that student attribute is in the string of values for the STUDENT_LOCATION system parameter and if the student's admissions attribute record is for a term code that is effective for this admissions application, then the function will retrieve the Location code where the Student Location matches the student's attribute.

If the student's attribute does not match a rule on SKARLOC, or isn't listed in the STUDENT_LOCATION system parameter, or if the effective term of the student admissions attribute is for a later term than the admissions application, or if the student does not have any student admissions attributes - then the function compares the student's admissions Site Code on SARADAP with the Student Location value from SKARLOC.

If a match is found, then that Delivery Location Code is used.

If there isn't a row for the matching campus and instructional method where student location is blank - then the function is not able to find a matching delivery location on SKARLOC and will now look at SKRTDLV (the table behind the Delivery Locations tab on the SKATORG page).

When the function looks on SKRTDLV, if there is a record that is effective for the term of the admissions application where the campus code matches the campus of the curriculum, then the Delivery Location code of that record is returned.

Delivery location codes are all associated with a training organisation (non-person) PIDM, either on SKARLOC or on the Delivery Location tab of SKATORG.

The function uses the SKATORG record that is effective for the term of the student's registration and uses the PIDM of that record to retrieve the additional ID (from the GORADID table) where the additional ID type matches the value listed for the HEP_CODE system parameter, using the system parameter record where the academic year matches the academic year of the admissions application term.

This function is used in the ASC_HEP_SNA_OD_FILE activity to retrieve the E559 course campus post code.

The function uses the campus code of the admissions curriculum to determine the delivery location, and then uses the delivery location address to provide a valid course campus postcode.

The function finds records on the Location Mapping Rules (SKARLOC) page where the campus code matches the campus of the curriculum. The mapping rules must be for the DEEWR-APP-LOCATION report collection and for an academic year that is valid for the term of the admissions application.

When the function looks on SKRTDLV, if there is a record that is effective for the term of the admissions application where the campus code matches the campus of the curriculum, then the Delivery Location code of that record is returned.

If the delivery location has a nation code in its address that matches a value listed for the HOME-NATN system parameter, then the postcode is concatenated with the letter A (e.g. A2000).

If the delivery location has a nation code in its address that does not match a value listed for the HOME-NATN system parameter, then the nation code is concatenated with the letter X (e.g. X8104).

If a value for course campus postcode cannot be determined, the function returns a value of "99999."

This function is used when calculating census dates to return a date for a CRN that is not a weekend or public holiday (business date).

The function is also used when evaluating whether a student who is eligible for a VET FEE-HELP loan has passed the legislated cooling-off period between enrolment and submission of a request for a VET FEE-HELP loan.

First, the function checks whether the input date (p_date_in) is a weekend by using the new WEEKEND system parameter value in SKARSYS for the current academic year (p_acyr_code).

When a public holiday is recorded for a year on the Schedule Exclusion Rules (SSAEXCL) page, this function recognises the public holiday regardless of the part of term.

The public holiday check is able to be used when working out census dates or when checking whether a student requesting a VET FEE-HELP loan has been enrolled for sufficient time to be able to make that request.

  • If the maximum end date from SSRMEET is null, it gets the part of term end date from SSBSECT (ssbsect_ptrm_end_date) for the CRN and term code, and that date is returned as the actual end date.
  • If the maximum end date from SSRMEET is not null, it gets the list of DAYS defined in SSRMEET and determines whether the maximum end date from SSRMEET DAY is in the DAYS list. If so, it returns that date as the actual end date.
  • If the maximum end date from SSRMEET DAY is not in the DAYS list, it gets the previous date from SSRMEET that is in the DAYS list and returns that date as the actual end date.

If the value for the CENSUS-USE-SSRMEET system parameter is some other value, including blank/null, or if the CENSUS-USE-SSRMEET system parameter does not exist for the academic year of the term of the CRN, the function gets the part of term end date from SSBSECT (ssbsect_ptrm_end_date) for the CRN and term code, and that date is returned as the actual end date.

F_GET_START_DATE

This function returns the actual start date of the unit of study (CRN) based on CRN and TERM_CODE for both OLR and traditional CRNs.


F_GET_START_DATE (p_term_code_in, p_crn_in, p_start_date_in, p_no_of_units_in)

For OLR CRNs, the function returns the start date value from the baseline Additional Registration (SFRAREG) table.

For traditional CRNs, the following steps are used to determine the actual start date. If the value for the CENSUS-USE-SSRMEET system parameter is Y for the academic year of the term of the CRN, the following steps are used to determine the actual start date.

  • The function gets the minimum start date from SSRMEET (MIN(ssrmeet_start_date)) for the CRN and term code.
  • If the minimum start date from SSRMEET is null, it gets the part of term start date from SSBSECT (ssbsect_ptrm_start_date) for the CRN and term code, and that date is returned as the actual start date.
  • If the minimum start date from SSRMEET is not null, it gets the list of DAYS defined in SSRMEET and determines whether the minimum start date from SSRMEET DAY is in the DAYS list. If so, it returns that date as the actual start date.
  • If the minimum start date from SSRMEET DAY is not in the DAYS list, it gets the next date from SSRMEET that is in the DAYS list and returns that date as the actual start date.

If the value for the CENSUS-USE-SSRMEET system parameter is some other value, including blank/null, or if the CENSUS-USE-SSRMEET system parameter does not exist for the academic year of the term of the CRN, the function gets the part of term start date from SSBSECT (ssbsect_ptrm_start_date) for the CRN and term code, and that date is returned as the actual start date.

FN_EN_DISA_CODE

This function establishes whether a student has a disability record.


FN_EN_DISA_CODE (SGRDISA_PIDM, SGRDISA_TERM_CODE, SKBRSYS_ACYR_CODE) (Student PIDM, maximum term code on SGRDISA, SKARSYS academic year)

It takes a PIDM and a term code as arguments, and finds the latest SGRDISA record that is earlier than or equal to the term code passed in the function. If the student has no disability record, the function returns 00000000. If the student has a disability record, the function returns values as described in this section below.

If sgrdisa_disa_code starts with 0 or is null, then 00000000 is returned.

If sgrdisa_disa_code starts with 2, then 20000000 is returned.

The function gets the skbrsys_value where skbrsys_param_name is HEARING_DISABILITY, LEARNING_DISABILITY, MOBILITY_DISABILITY, VISUAL_DISABILITY, MEDICAL_DISABILITY, or OTHER_DISABILITY for the academic year that is passed as a parameter. If that skbrsys_value is present as a part of sgrdisa_disa_code, then 1 is appended to the end of sgrdisa_disa_code; otherwise, 0 is appended.

If sgrdisa_spsr_code starts with 2, then 2 is appended to the end of sgrdisa_disa_code.

If sgrdisa_spsr_code starts with anything other than 2, then 1 is appended to the end of sgrdisa_disa_code.

If sgrdisa_spsr_code is null, then 2 is appended to the end of sgrdisa_disa_code.

If sgrdisa_disa_code characters 2 through 7 are 000000, then sgrdisa_disa_code is changed to 00000000 and returned.

FN_SD_ADDRESS

fn_sd_address (SPRIDEN_PIDM, P_STRING, SKBRSYS_ACYR_CODE) (Student PIDM, address type, and SKBRSYS academic year)

F_GET_NOMINAL_CENSUS_DATE

After the census date is calculated, this function will retrieve the first nominal census date that is on or after the calculated census date. Nominal census dates should be recorded on the Report Element Values (SKARVAL) page for the CENSUS-DATE element code.

It is expected that nominal census date values may be different for each institution so no seed data is delivered for SKARVAL. However, the CENSUS-DATE element code is delivered as seed data for the Report Element Validation (SKVRVAL) page.

If there is not sufficient data in SKARVAL for the function to be able to retrieve a nominal census date, then the calculated census date is used.

This function will only be used if the value of the USE-NOMINAL-CENSUS system parameter is 'Y'. If the value of the USE-NOMINAL-CENSUS system parameter is any other value, including blank/null, or if the USE-NOMINAL-CENSUS system parameter does not exist for the academic year of the term of the CRN, then the calculated census date will be used.

If the USE-NOMINAL-CENSUS system parameter is set to Y, nominal census dates will be calculated for all CRNs in terms for the corresponding academic year, whether the CRNs are Open Learning Registration CRNs or traditional CRNs using parts of term.
