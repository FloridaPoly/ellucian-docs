Placement Advisor Maintenance (SJAADVR) page

Use the SJAADVR page to enter or display supplementary information about the advisors such as qualifications, titles, organisations, and review date.

Advisor details are term-code effective. The data is stored in the SJBADVR table.
You can do the following from this page:
  • Define multiple types for each advisor
  • Define the approval status, start date, and expiry date for each advisor type
  • Display organisations and placements assigned to an advisor at a specific term
  • Attach multiple students to this advisor
  • Display placements with which an advisor is associated and the students allocated to these placements

Placement Program and Institution Characteristics (SJAGCHR) page

Use the SJAGCHR page to enter or display program and institution characteristics. Program characteristics are inherited by all placements associated with that program. Program characteristics are term-code effective.

To enter program characteristics, enter values for the Curriculum Rule, Program, or both fields. To enter institution characteristics, leave both fields blank.

If institution characteristics have been defined, you will be asked if you want to save them as program rules when new program characteristic rules are defined in this page. Click OK to confirm. Programs will not inherit institution characteristic rules unless you have actively saved them in this way. For this reason, placements will not inherit institution characteristics if they are not stored against the program for which the placement is offered.

Placement Manual Allocation (SJAMALC) page

Use the SJAMALC page to enter or display placement allocations for students (individually or in groups).

Banner will check that each student selected has an active General Student record (that is, a record with a student status code (SGBSTDN_STST_CODE) that has the Allow Registration indicator selected on STVSTST) for the date range specified in the Key block.

Banner will check to ensure that the user has the appropriate access rights. A user who does not have the correct access rights will receive a warning message and will not be able to proceed.

You can do the following on this page:
  • Specify the student or group of students (program or cohort) to allocate manually.
  • Specify the unique batch ID from the automatic allocation process to identify a group of students to allocate.
  • Specify the date range for which you want to search for available placements to allocate to a student.
  • View existing allocations for a selected population.
  • Specify the inclusive characteristics or learning experiences required in the available placements. Reducing the number of characteristics specified will widen the search, effectively relaxing the application of the characteristic check rules.
  • Select a placement from those returned by the search and allocate it to a student.

In the Student Allocations section, a record is displayed for each date range in the weekly plan with a study type that has the placement indicator (SJVVPST_PLAC_IND) checked, for each student. Records are displayed first by student surname and then in date order. If you select to view existing allocations, these are also displayed in date order. If a student has an allocation within the first date range from the weekly plan, that same date range will also display a row without an allocation. This allows you to make additional allocations to that date range where an individual allocation does not cover the entire date range.

When the allocation is attempted, Banner checks that the program of the selected student is active in the Placement Program Requirements Maintenance (SJAPLRN) page. If the program is not active for placement allocation, no allocation is made for the selected student.

Banner searches for available placements offering the specified learning experience or characteristic in the Learning Experience and Characteristic Criteria blocks.

Available placements are those that are available to the student’s program for the allocation dates specified in the Student Allocations section. The approval status of each placement is displayed, where applicable, in addition to the maximum and optimum spaces available for the date range.

Available placements can include placements the student has previously attended. If you allocate such a placement to the student, a warning message is displayed indicating that the student has previously attended the placement. You can choose to cancel the allocation.

When a student is manually allocated, Banner completes the allocation even if there are characteristic rule failures. A warning message is displayed indicating that characteristic checks have failed and giving you the option of cancelling the allocation.

Students cannot have an allocation in the same date range as an existing allocation. An allocation in the same date range can be created only by changing the allocation date on the Vocational Placement Student Details (SJASTUD) page or using the Placement Allocation Override (SJAALOV) page.

Banner allows allocations to be made to dates in the past. A warning message is displayed giving you the option to cancel the allocation.

Banner allows allocations to be made that exceed the overall capacity, learning experience capacity, or required characteristic capacity. In each case, a warning message is displayed giving you the option of cancelling the allocation.

Banner records against the student the primary advisor associated with the allocated placement.

The allocation does the following:
  • Create a record of a student on a placement and a learning experience for specific dates
  • Initialise the attendance records for a student on a placement
  • Store the activity date and user ID, which can be viewed on SJASTUD

Successful allocations are indicated on the page.

You can search for available placements that meet the search criteria entered in the Learning Experience and Characteristic Criteria window, which is opened by double-clicking the Placement field in the base section. The placement and learning experience are returned to the Student Allocations section against the highlighted student when selected from the Available Placements section. You must then select the Include check box and save to create the allocation. When the allocation has been made, the actual allocation dates are displayed in the Student Allocations section.

Note: Manual allocation cannot handle split-primary or secondary allocations. The Learning Experience fields on the base section include only non-split primary learning experiences. The LOV for the Learning Experience field in the Learning Experience and Characteristics Criteria window allow you to select only non-split primary learning experiences.

Capacity Calculation

The capacity calculation, the value of which is displayed in the Maximum and Optimum fields, operates as follows.

  • Take the required allocation length (for example, 2 weeks).
  • Starting on first day of weekly plan, determine maximum number of available spaces against the overall maximum and optimum capacities for the required allocation slot (in this case 2 weeks).

    For example, PLAC1 has a total capacity of 6. There are 3 allocations in week 1 and 2 allocations in week two of our slot. This means that the highest number of allocations that could be made to this two-week slot would be 3, and this would be the capacity displayed.

  • Starting on the second day of the weekly plan, determine the maximum number of available spaces against the overall maximum and optimum capacities for the required allocation slot.
  • Continue to determine spaces for each two-week slot, starting on each consecutive day of the weekly plan, until the latest possible start date.
  • Take all the figures from these calculations and display the highest figure.

    The following details provide an example.

    • Weekly plan dates are 01-Jul-2007 to 28-Jul-2007.
    • The learning experience requires a two-week slot.
    • The first two-week slot has 3 spaces (starting 01-Jul and using calculation above).
    • The second two-week slot has 2 spaces (starting 02-Jul).
    • The third two-week slot has 2 spaces (starting 03-Jul).
    • And so on until there are 15 different figures, the highest of which is 3.
    • The capacity displayed in the Maximum (or Optimum) field is 3.

If the placement has learning experience capacity figures defined, these will affect the capacity displayed. The calculation is as above, but determined against the specific learning experience capacity instead of against the overall capacity, as shown in the following example.

  • PLAC2 has overall capacity of 6.
  • LEX1 capacity is 4.
  • LEX2 capacity is 2.
  • Learning experience LEX2 requires two-week slot, and the weekly plan is 2 weeks long.
  • There are already 2 allocations with LEX1 and 1 with LEX2.
  • Although the overall remaining spaces is 3, there is only 1 space left for LEX2.
  • The available capacity displayed in the Maximum (or Optimum) field is therefore 1 when attempting to allocate LEX2.

Allocated Placement Comments window

This window is used to enter comments about the student for each highlighted placement from the Attendance Tracking window. Select the Placement Allocation Comments option from the Attendance Tracking window to open this window.

This window also displays any comments entered from the Web page for the absence or made up time record.

The way in which the comments are stored is dependent up the section from which the Comments window was accessed. To return to the comments, you must access the comments from the same section as where they were entered.

  • Comments entered from the Overall Requirements section are linked to the student. The comments are stored in the SJRGCMT table.
  • Comments entered from the Allocated Placements section are linked to a specific placement allocation record (SJBPATT).
  • Comments entered from the Absence Details section are linked to a specific absence record (SJRPATT).
  • Comments entered from the Made-up Time section are linked to a specific made-up time record (SJRPATT).

Comments made against allocations, absence and made-up time will be visible in the SJAPLAC page.

Placement Characteristic Codes Validation (SJVVCHR) page

Use the SJVVCHR page to define the characteristic codes that will be used in matching students to placements during the allocation process.

This page allows you to specify whether a characteristic is a Banner column or user-defined. Each characteristic can have multiple values. You can associate characteristic values with a user-defined characteristic code on the SJACHRV page. For example, a user-defined code could be WCHA for wheelchair access.

Base section

Use this section to enter the placement characteristic code details that you want to define.

Field Description
Code Characteristic code. Banner characteristic codes have the page and field name.
Description Description associated with the characteristic code.
Banner Indicates whether the characteristic is a Banner characteristic, or a user-defined characteristic.

Selected: Banner characteristic: A characteristic derived from a Banner entity related to a student. Student Status and Fundability are examples of student-related Banner entities. These would be entered as Banner columns SGBSTDN_STST_CODE and SKBSSIN_SSDT_CODE_FUND respectively. In this case, the allocation process will match the characteristic value and the value of the Banner entity that specified when the characteristics in the Banner Column Name (SJVVCHR_BAN_ATT) field were defined. Banner characteristics can be user defined.

Cleared: User-defined characteristic: A characteristic that represents a student trait that is not supported by Banner (for example, the value of the characteristics does not relate to any of the student Banner traits). The matching here will be according to the placement characteristic value and the student characteristic value.
Characteristic Data Type Data type of the value to be assigned to the characteristic. Possible values are Banner, String, Number or Date.
Banner Column Name Column name for Banner definable characteristic codes. The value is the Banner column that would hold the value for this entity for a particular student (for example, SGBSTDN_STST_CODE). When a user enters a Banner characteristic on the SJAPLAC, SJAGCHR or SJAMALC pages, the list of possible values will be taken from the validation table for this column. In this example, the LOV would come from the STVSTST table. This field cannot be accessed if the Banner check box is not selected.
