Install ISSM Data Integration Tool

Before installing ISSM DIT, confirm that you have all the required software and it is installed on the ISSM Data Integration Tool server, which is also the ISSM server.

See ISSM Data Integration Tool server requirements for more information. After verifying, you can then download the tool from the Ellucian Customer Center website and begin installation.

Note: Uninstall older versions of ODAC before installing the new version. Install ODAC 12.2c R1 on Windows Server 2016, before installing DIT 2.0.7

Install the ISSM DIT application files

Install the ISSM Data Integration Tool application files.

Procedure

  1. Stop IIS. Open command prompt and enter iisreset/stop.
  2. Open Windows Explorer and navigate to setup.exe that you extracted from the ISSMDataIntegrationTool207.zip file.
  3. Right click setup.exe and select Run as Administrator.
  4. Click Next.
    On the License Agreement window review the license agreement in the text box, choose the I accept option.
  5. Click Next.
  6. On the Customer Information window enter your user name and organization. There is an Install this application for: option. By default this is set to Anyone who uses this computer (all users).
    Note: Do not change this setting unless you are directed to do so by customer support.
  7. Click Next.
    The default and recommended destination folder for this tool is \fsaATLAS\DataIntegrationTool.
  8. Optional: Click Change to select a different installation directory.
  9. Click Next.

    On the Database Server window enter the following information for the database:

    Database server name
    Server Name that will host the fsaATLAS database. This name should include the entire server name.
    Database Login ID
    SQL Login ID that has the privilege to install a new database on the server above.
    Database Password
    SQL Password for the user above.
  10. Click Next to install the application to the indicated directory.
  11. On the Ready to Install the Program window check the settings, and if they are correct click Install.
    If a setting is incorrect, click Back to return to the appropriate window and change the information.
    Note:
    If you get the error message Error 27506: Error executing SQL script fsa_dit120_111811.sql. Line 260, it indicates that the script file was already executed during ISSM install or upgrade process.
    • In the SQL Server database, go to the tblSystemDBChangelog table.
    • Rename fsa_dit120_111811.sql line entry to Orig_dit120_111811.sql (or any name other than the actual file name).
    • Restart the installation procedure from step 7.
  12. Click Finish when the installation of the files is complete.
    • Open the IntegrationConfig.xml from the fsaATLAS\DataIntegrationTool\XML directory.
    • Search for the entry <MappedField fsaname="VisaIssuingCntry" fsaType="Regular" externalType="Regular">VisaIssuingCntry</MappedField>
    • Replace the word VisaIssuingCntry to VisaPostCode. The modified entry should look like <MappedField fsaname="VisaPostCode" fsaType="Regular" externalType="Regular">VisaPostCode</MappedField>
    • Save the changes made to IntegrationConfig.xml file.
  13. Now the installation is complete.
    • If your source data only comes from an XML file, go to Update SMTP settings section.
    • If your source data only comes from ISSM, proceed to Edit tnsnames.ora (ISSM connections only) section.

Edit tnsnames.ora (Banner connections only)

The SQL*Net tnsnames.ora configuration file, which is distributed with ODP.NET, must have the correct information to connect to the Banner database, and be in the correct location on the ISSM Data Integration Tool server.

Procedure

  1. Navigate to the \oracledirectory\network\ADMIN directory, where oracledirectory is the directory that contains the Oracle files (for example, OraHome_1) and confirm that the tnsnames.ora file is located here:
    If the file is in the one of the directories listed above, continue to step 4 in these steps. If the file is not in this location, continue to Update SMTP Settings.
  2. Navigate to the default location of the tnsnames.ora file. By default, this location is \oracledirectory\network\ADMIN\SAMPLE.
  3. Copy the tnsnames.ora file and place it in \oracledirectory\network\ADMIN directory.
  4. Edit this file with an editor and enter the connection string and any other information necessary for connecting with the Banner Server instance.
  5. Save and close the file.

Create fsamgr user and custom field package (Banner connections only)

The fsamgr user is a Banner user who provides the ISSM Data Integration Tool with the appropriate permissions to connect with the Banner Oracle database.

Before you begin

Be sure to have the appropriate DBA access of the Banner database.

About this task

When you create a user, you must also create a package to access the Banner custom query function. Perform this process on the Banner server.

Procedure

  1. Copy the following SQL scripts from \fsaATLAS\DataIntegrationTool\Scripts\BannerScripts and place them on the Banner Oracle database server where you can access them through SQL Plus:
    • Create_Integration_User.sql
    • Custom_Query_Package.sql
    • Custom_Query_Package_Body.sql
  2. Open SQL Plus and run the Create_Integration_User.sql script to create the fsamgr user.
    The script creates a user with the default name of FSAMGR and a password prompt displays.
  3. Create the custom field package.
    Run the Custom_Query_Package.sql script.
  4. Create the body of the custom field package.
    Run the Custom_Query_Package_Body.sql script.

Update the Banner API (Banner connections only)

You must update the Banner API's if you have connections to ISSM.

About this task

To update the Banner API for Banner connections only.

The Data Integration Tool uses Banner GTVSDAX settings for Foreign and U.S. Address Types for ISSM as follows:

  • GTVSDAX Internal Code of SVSFADDR = SEVIS Foreign Address.
  • GTVSDAX Internal Code of SVSUADDR = SEVIS US Address.
  • The External Code field contains the Banner Address Type for the address that you want to have sent to ISSM.
  • You can have a hierarchy for each Address Type by creating multiple rules for each GTVSDAX Internal Code and using the sequence numbers to prioritize (no limit). The lowest sequence is looked at first. If the person doesn’t have the Address Type in the External Code field, the API should look at sequence 2 for the same Internal Code to see if they have that Address Type, and so on.
  • Mailing Address is configured in the DIT, not in GTVSDAX.

Procedure

  1. Navigate to the following directory:

    \fsaATLAS\DataIntegrationTool\Scripts\Banner Scripts\.

    Within this directory is gokp_internatl_stud1.sql.

  2. Copy this script and move it to your institution's Banner environment.
  3. Ask your Database Administrator to compile the package with this new script.

Update SMTP settings

A new feature in v1.1 Hotfix 1 sends an e-mail notification of data processing results to the registered e-mail address.

About this task

You must configure the feature to be fully functional.

Procedure

  1. Navigate to [CurrentInstallDrive]:\fsaATLAS\DataIntegrationTool folder, open both fsaATLASDataIntegrationTool.exe.config and ExtractRunner.exe.config files.
  2. Look for the following SMTP information section: 
    <smtp from="">
<network host="smtp.server.com" password="" port="25" userName="" />
</smtp>
  3. Update the SMTP information section above with your institution SMTP server information.
  4. If your institution SMTP server requires SSL connection, update the following setting to true in both files mentioned above: 
    <appSettings file="xml\commonsettings.config">
<add key="IsSSLEnabledForEmail" value="false" />
</appSettings>

    For additional information about this feature, see Work with configurations based on a Banner Database in the Config content on the Ellucian Documentation site.

Set the blank tags setting

By default, the ISSM Data Integration Tool does not send blank tag information to ISSM.

About this task

This means that if a field is blank, ISSM does not extract the information. However, if you decide that you want blank tag information sent to ISSM, then set this option to Yes.
Note: This option only works for regular mapped fields and not for custom fields in ISSM.

Procedure

  1. Open Windows Explorer, navigate to \fsaATLAS\DataIntegrationTool\XML.
  2. Open commonsettings.config in a text editor.
  3. Locate the <add key="AllowBlankTags" value="N"> setting.
  4. To allow blank tags, change N to Y.
  5. Save any changes that you make to this setting.
    The change will take place the next time you open the ISSM Data Integration Tool.
    Note: Do not make any other changes to this file without prior approval from the ISSM Support or Services group.

    You can only process the fields mapped in DIT in the Map Fields tab to ISSM. If the mapped field in DIT does not contain data in source (Banner or XML), then:

    • -- In case the AllowBlankTags = Y a tag with an empty value will be sent in the XML drop file to ISSM Campus DataLink.
    • -- In case the AllowBlankTags = N the tag will not be sent in the XML drop file to ISSM Campus DataLink.

Procedure

  1. Stop IIS. Open command prompt and enter iisreset/stop.
  2. Back up the \fsaATLAS\DataIntegrationTool directory and the fsaATLAS database.
  3. Open Windows Explorer and navigate to setup.exe that you extracted from the ISSMDataIntegrationTool207.zip file.
    Note: Before you begin the upgrade: Make a complete and current backup of the fsaATLAS\DataIntegrationTool folder and sub-directories on the ISSM server.   5. Click Next.
    On the License Agreement review the license agreement in the text box, choose the I accept option.
  6. Click Next.

  7. Click Next.

    The default and recommended destination folder for this tool is fsaATLAS\DataIntegrationTool. Click Change to select a different installation directory.

    Note: If you are changing the installation directory, make sure not to select another directory within the installation directory. For example: If your current installation directory is C:\fsaATLAS\DataIntegrationTool, then the new directory must not be within C:\fsaATLAS\DataIntegrationTool.
  8. Click Next.

    On the Database Server enter the following information for the database:

    Database server name
    Server Name that will host the fsaATLAS database. This name should include the entire server name.
    Database Login ID
    SQL Login ID that has the privilege to install a new database on the server above.

    SQL Password for the user above.

    If a setting is incorrect, click Back to return to the appropriate window and change the information.

  12. Start IIS. Open command prompt and enter iisreset/start.

Remove entries from database

To remove the entries from the database ensure there are no errors during the next DIT installation on the same server.

Procedure

  1. Open Microsoft SQL Server Management Studio.
  2. Provide the database credentials to connect to fsaATLAS database.
  3. Run the following query. 
    USE [fsaATLAS]
GO
delete from tblSystemDBChangeLog where ScriptName = 'fsa_dit120_111811.sql'
GO

    The above script removes the entry of DIT SQL scripts from the fsaATLAS database.

Delete files manually

Any files that you create or edit after the initial install of the ISSM Data Integration Tool are not automatically removed during the uninstall. If you want to remove the files, you must delete them manually.

C:\WINDOWS\Tasks\tasknames, or %windir%\tasks\tasknames. These are the scheduled configuration tasks, and will continue to attempt to run until you disable them.
