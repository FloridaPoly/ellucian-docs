Release 5.1.6

Degree Works 5.1.6 includes new functionality, improves existing functionality, resolves change requests, and more.

For more detailed information about the release, see the Degree Works 5.1.6 and Transfer Equivalency 5.1.6 release records.

General Degree Works Release Information

Overview

The central themes of Release 5.1.6 include expanding the functionality offered in the Responsive Dashboard and Transit to meet the needs of the customer base and enhancements to support Degree Works as a SaaS solution. Release 5.1.6 also meets customer satisfaction goals by delivering nearly 25 improvements and 80 problem resolutions.

This release is a MINOR release so the version has been assigned as Release 5.1.6, and it builsd on the baseline established by the previous MAJOR release, Release 5.1.0, and subsequent releases. This is a significant release in terms of the product direction, and it continues to build on the infrastructure introduced for Cloud delivery.

There are two planned service packs for Release 5.1.6. The service packs will deliver corrections to high-impact defects reported with the release and are planned for delivery on the following dates (targeted dates, subject to change):
  • 5.1.6.1 (Service Pack 1) – November 14, 2025
  • 5.1.6.2 (Service Pack 2) – January 23, 2026

Upgrade path

The Degree Works Release 5.1.6 supports a new installation or a direct upgrade path for existing customers currently on Release 5.1.4 or Release 5.1.5.

Scenario Upgrade path
I am new to Degree Works. You can install 5.1.6.
I am on 5.1.4 or 5.1.5. You can upgrade directly to 5.1.6.
  • 5.1.5 > 5.1.6
  • 5.1.4 > 5.1.6
I am on 5.1.3 or older. You must upgrade to 5.1.4 before you can upgrade to 5.1.6. Depending on your current version, intermediate updates may be necessary.
  • 5.1.3 > 5.1.4 > 5.1.6
  • 5.1.2 > 5.1.4 > 5.1.6
  • 5.1.1 > 5.1.2 > 5.1.4 > 5.1.6
  • 5.1.0 > 5.1.2 > 5.1.4 > 5.1.6

If you are on any service pack level, the upgrade path you should follow is from your base release as service packs are included in the next release. For example, if you are on 5.1.5.2 you would follow the path of upgrading from Release 5.1.5 to Release 5.1.6.

Ellucian strongly recommends institutions run on current and supported versions of our software so multiple jumps are not required when processing a new release upgrade.

Release support status

With the release of Release 5.1.6, Release 5.1.5 moves to Maintenance Support, while Release 5.1.4 moves to Sustaining Support. Release 5.1.3 moves to End of Support. Details about Ellucian Support Assurance can be found in article number 000038478.

All Degree Works versions older than Release 5.1.3 are in End of Support. If you are on one of these versions, you must upgrade to at least Release 5.1.4 before you can process Release 5.1.6.

Degree Works releases follow a rolling schedule for support. This means that with each new release, all previous releases will transition to the next support status. For example:

  • 5.1.6 is released in September 2025 with an Active status
  • 5.1.5 released in March 2025 will move to Maintenance status
  • 5.1.4 released in September 2024 will move to Sustaining status
  • 5.1.3 released in March 2024 will move to End of Support status

Degree Works hardware and software requirements

Before beginning a new installation or upgrade, be sure to verify that your Degree Works environments meet the hardware and software requirements.

Supported Hardware Architectures

For new customer installations, only the following hardware architecture and operating system configurations are supported for Degree Works servers:

  • Intel-based x86 running Red Hat Enterprise Linux 8.x (64-bit)
  • Intel-based x86 running Oracle Linux Server 8.x (64-bit)

For upgrading customers only, the following hardware architecture and operating system configurations are supported for Degree Works servers:

  • Intel-based x86 running Red Hat Enterprise Linux 8.x (64-bit)
  • Intel-based x86 running Oracle Linux Server 8.x (64-bit)
  • IBM running AIX 7.x (64-bit)
  • Sun SPARC platform running Solaris 11 (64-bit)
  • HP Integrity Platform (IA64) running HP-UX 11.x (64-bit)
Note:

Ellucian Degree Works will end support for the following operating systems with the 5.1.7 release, planned for March 19, 2026:

  • Solaris
  • HP-UX
  • IBM AIX

On-premises institutions running Degree Works on Solaris, HP-UX, or AIX must migrate to a supported Linux-based operating system before March 19, 2026 to avoid disruption.

Supported RDBMS

Degree Works Release 5.1.6 supports Oracle 19c.

Supported Ellucian Integrations

Banner customers: Release 5.1.6 requires that you are on at least Banner Student 8.33.2, which added the common course number to SHRTCKN and SHRTRCE. Degree Works processes that pull data from Banner, such as RAD30, BAN62, refreshing from the Dashboard, etc. will fail if you are on an older version of Banner Student.

RabbitMQ

Degree Works Release 5.1.6 has been tested against the following versions:

  • RabbitMQ server v3.13.1
  • RabbitMQ client v0.14.0

Java

Degree Works Release 5.1.6 requires Oracle Java Development Kit (JDK) or OpenJDK version 17 on both your classic and application servers. Do not install this release if your servers are configured for only a prior version of Java. You may have other versions of Java on these servers, but the Degree Works environments need to be able to be configured for Java 17 – the installer will not run if the correct Java version cannot be found, and the Java applications may encounter errors on deployment and during use if a prior version of Java is used.

Warning: If you are upgrading from Release 5.1.4, your classic and Java application servers must be updated to this version to update to Release 5.1.6.

GCC Compiler

Degree Works Release 5.1.6 requires GCC version 8.x.

Apache FOP

Degree Works Release 5.1.6 requires Apache FOP version 2.6 on the classic server.

OpenSSL

Degree Works Release 5.1.6 requires OpenSSL version 1.1.1, including the openssl-devel package.

Supported Browsers

Ellucian makes every effort to test and support the current versions of the following browsers at the time of a release:

  • Google Chrome
  • Mozilla Firefox
  • Apple Safari
  • Microsoft Edge

For more information, see Ellucian Global Web Browser Support Policy and Matrix.

Degree Works Enhancements

Advanced Search highlights

Improve the student search functionality in Responsive Dashboard for modernization, performance, and extensibility

The Responsive Dashboard Advanced Search has been modernized to enhance extensibility and resolve reported performance issues as described in defects PD0020040 and PD0020047.

While the user-facing functionality remains unchanged, the underlying architecture has been updated to improve maintainability and support future scalability.

Audit highlights

Improve how the best-fit algorithm prioritizes completed, in-progress, transfer and preregistered classes

To help reduce movement of completed classes to other requirements on the audit as additional coursework is added, three new flags have been added to CFG020 DAP14 which can refine the behavior of the best-fit algorithm.

Best-fit: fall-through mode defines the hierarchy the best-fit algorithm should use when deciding which classes should be removed from a rule when there are too many classes that can be applied. Options are completed/in-progress/transfer/preregistered, completed/transfer/in-progress/preregistered or no hierarchy.

Best-fit: keep class on rule with fewer options allows a class that matches multiple rules to apply to the rule with substantially fewer options (less than half).

Best-fit: max rule qualifiers check allows the auditor to check which classes are on rule Max qualifiers that are over the limit of classes/credits when there are too many classes applying to the rule. These classes will be marked as good candidates for removal from the rule.

Add a configuration to define a different default grade for pre-registered classes than in-progress classes

To help students and advisors identify which classes on an audit are pre-registered versus in-progress, a new Default Preregistered Grade field has been added to CFG020 BANNER, allowing preregistered classes to have a different grade from in-progress classes.

Allow <ECA> and <ECA-OVERFLOW> tags to be used Proxy-Advice

When using Elective Credits Allowed (ECA), the <ECA> and <ECA-OVERFLOW> tags can be Scribed in Proxy-Advice.

For example:

60 Credits
 ProxyAdvice “You need 60 credits; you have <APPLIED> credits, ”
 ProxyAdvice “you need <NEEDED> more”
 ProxyAdvice “; you are allowed to take up to <ECA> elective credits”
 ProxyAdvice “; <ECA-OVERFLOW> credits were excluded from the degree “
 ProxyAdvice “because you took too many electives.”

Exclude classes in Fall-through from counting towards residency requirements (IDEA-20541)

A new option (Q) has been added to CFG020 DAP14 Fall-through course count in the overall that will prevent classes that go to Fall-through from counting in the overall GPA and credits/classes applied calculation or any other qualifier in the starting block, such as residency requirements.

Allow customization of DWAge to look at active term, catalog term, or current term to decide the expiration of a course

A new DWAge mode flag has been added to CFG020 DAP14 that can be used to define whether the DWAge keyword looks at the student's active term, the current term, or the catalog year to calculate the age of a course. Options are:

  • Mode A: use the active term from RAD_STUDENT_MST (current behavior).
  • Mode C: determine the current term by comparing the current date to the start and end dates on the STU016 record.
  • Mode Y: catalog year from RAD_GOAL_DTL.

Exclude ECA-Overflow credits from the degree GPA calculation - only include the ECA-OK credits

A new option (E) has been added to CFG020 DAP14 Fall-through course count in the overall so that when CFG020 DAP14 Calculate elective credits allowed is enabled, fall-through ECA-OK classes count in the overall GPA and credits/classes applied calculation and all other qualifiers in the starting block. Fall-through ECA-OVERFLOW classes do not count in the overall GPA and credits/classes applied calculation nor do they count against any other qualifier in the starting block.

Banner highlights

Support Common Course Number on historical and transfer classes

For the Common Course Numbering (CCN) functionality (AB1111) required for California Community Colleges (CCC), the common course number that was effective at the time a course was taken will now display in Responsive Dashboard.

With Banner Student 8.33.2, the common course number was added to SHRTCKN and SHRTRCE. Degree Works now loads this data from the extract into the RAD_CLASS_DTL and RAD_TRANSFER_DTL.

Support different email address for Advisors who are also students

A new RAD_STAFF_EMAIL field was added to the RAD_PRIMARY_MST table to store an additional email address for users who are both students and advisors so that their advisees see their faculty email address, not their student email address.

CPA highlights

The DAP25 CPA results daemon is not successfully recovering/reconnecting after temporary database issues, sometimes leading to exhaustion of database processes

In the event of a database issue, after the issue is resolved when DAP25 next wakes to check for new audits, it will successfully reconnect to the database and do its work as expected.

Exception highlights

Allow Apply Here exceptions on Fall-through or Over the Limit sections of the audit

An Apply Here exception can now be used to move a class into the Over-the-Limit (Not Counted) and Fall-Through (Electives) sections. When using Elective Credits Allowed (ECA), the class can be applied to the ECA-OK or ECA-OVERFLOW fall-through sections.

Increase the ECA-OK Fall-through through Change the Limit

When using Elective Credits Allowed (ECA), there is now an option to allow Change the Limit exceptions to adjust the number of elective credits allowed. Changing this ECA value will cause more or fewer classes to be marked as ECA-OK and ECA-OVERFLOW in the fall-through section.

Validate DW* WITH reserved word codes

A new UCX table (SCR043) has been added to validate DW* WITH codes and also control which codes display in the drop-down in Exceptions.

This does not affect which DW* WITH codes are available to use in Scribe.

GPA Calculator highlights

Responsive Dashboard: Advice Calculator does not display the numeric grade value the same way it does in the dashboard servlet.

The Advice Calculator now properly rounds or truncates the numeric grade value to the correct number of decimals based on the dash.gpaCalculator.round and dash.gpaCalculator.decimals Shepherd settings.

Responsive Dashboard: Graduation Calculator is providing incorrect calculations

The Graduation Calculator has been fixed to provide the correct results for the GPA that is needed in the remaining credits to achieve the desired overall GPA.

Notes highlights

Ability to modify Created by field in notes functionality

Similar to the existing functionality for exceptions, the Created by and Modified by names on audit notes can be localized to display a generic name like Registrar's Office instead of the actual name of the author.

Always display create/modify details of notes in Responsive Dashboard

The created time and last modified by/date for notes in Responsive Dashboard are now always visible rather than only viewable in hover text to improve accessibility.

System highlights

Generate a unique value for batch IDs instead of using the process ID

Instead of using the Unix process ID (pid) as an identifier, RAD30, RAD32, and BAN62 now use a uniquely generated value to prevent duplicated identifiers when the pid rolls over frequently. For example:

  • RAD_BATCH_ID in hash records created/modified by RAD30 or RAD32
  • SHRSAPP_REQUEST_NO/SHRSARJ_REQUEST_NO in BAN62

Ellucian Product Rebrand for Degree Works

In this release, all Degree Works applications have been updated with the new Ellucian logo and colors.

Transfer Finder highlights

Generate the Transfer Finder PDF audit in the updated format

The Transfer Finder audit PDF has been updated to match the style of the academic audit Responsive Dashboard and the transfer audit in Transfer Equivalency Self-Service.

Transit highlights

Make BAN62 (Banner SAP Processor) multi-threaded to improve performance

BAN62 has been modified to support multi-threading to enhance performance. A new transit.ban62.workerCount Shepherd setting defines the number of concurrent BAN62 processes.

Move functionality in dapauditstoxmlfiles script to a Transit job

A new Transit job, DAP26 - Generate Audit XML files, has been introduced to replace the now deprecated dapauditstoxmlfiles script. The new job allows you to upload a text file containing a list of audit IDs in Transit, generating a zip file with individual XML files for each requested audit.

Move functionality in dapfindbadaudits script to a Transit job

A new Transit job, SYS05- Find bad audits, has been created to replace the now deprecated dapfindbadaudits script. The new job generates a report listing possibly corrupt audits by student ID, audit ID, and audit date. You also have the option to delete the bad audits that are found.

Move functionality in dapfindorphanedaudits script to a Transit job

A new Transit job, SYS06- Find orphaned audits, has been created to replace the now deprecated dapfindorphanedaudits script. The new job generates a report file with a list of audits by student ID, audit ID with old degree, and new degree believed to be orphaned. That is, these audits exist for students who have changed their degree from when the audit was generated. You also have the option to delete the orphaned audits and the associated CPA data.

Move functionality in sepshowplan script to a Transit job

A new Transit job, SYS54 - Show SEP plan, has been created to replace the deprecated sepshowplan script. You can now use Transit to find the specified plan(s) and generate a report listing of the plan data similar to the output of the sepshowplan script.

Move functionality in sepshowtemplate script to a Transit job

A new Transit job, SYS55 - Show SEP template, has been created to replace the deprecated sepshowtemplate script. You can now use Transit to find the specified template and generate a report listing of the template data similar to the output of the sepshowtemplate script.

Degree Works updates

Database Changes

The RAD_STAFF_EMAIL field was added to RAD_PRIMARY_MST.

The following fields were added to RAD_CLASS_DTL:

  • RAD_ALIAS
  • RAD_PART_TERM

The RAD_ALIAS field was added to RAD_TRANSFER_DTL.

The UCX_SCR043 table was added.

Subtractions

In Release 5.1.6
  • As part of the work done for PE0006084 (Improve the student search functionality in Responsive Dashboard for modernization, performance, and extensibility), the dap22all script has been obsoleted. To run audits on all students, please launch DAP22 through Transit or launchjob.
  • DAP21 (Extract Articulated Transfers) has been obsoleted and removed from Transit.
Upcoming in Release 5.1.7
  • The following deprecated Shepherd keys will be obsoleted:
    • ADVISIDS (use SDSTUMY instead)
    • ANYSTUID (use SDSTUANY instead)
    • SDDEPART (use ADFILTER instead)

    If you have not already switched to the replacement Shepherd keys, Ellucian recommends you start making this change as soon as possible.

  • Ellucian Degree Works will end support for the following operating systems:
    • Solaris
    • HP-UX
    • IBM AIX

    On-premises institutions running Degree Works on Solaris, HP-UX, or AIX must migrate to a supported Linux-based operating system before March 19, 2026 to avoid disruption.
