Faculty Grade Entry

The Faculty Grade Entry page is used to enter and update midterm, final, and incomplete grades, in addition to the last date of attendance and hours attended.

Components and subcomponents can be graded using grade book functionality. You can import and export grade data for students. You can also use Student Academic Review processing. The Faculty Grade Entry Self-Service page can be used in conjunction with existing pages in Banner Faculty and Advisor Self-Service 8.x.

Note: Banner 8.x Self-Service grading can co-exist with Banner Student Faculty Grade Entry 9.x grading. You should not have the same term/CRN being graded at the same time in the two systems. A term/CRN can be graded in the two systems at different points in time. For example, you could perform a Banner Student Faculty Grade Entry 9.x upload, followed by a Banner 8.x Self-Service update, followed by a Banner 9.x update, followed by a Banner 8.x administrative update, and processing should be successful.

Disable grading links in Self-Service

When using Banner Faculty Grade Entry 9.x with Faculty Self-Service 8.x, grading in Faculty Self-Service 8.x is still supported for midterm and final grading.

About this task

You must disable the menu links to the grading pages (Midterm Grades, Final Grades, Incomplete Grades Summary) in 8.x Self-Service if you no longer want to have midterm and final grading active in both systems. Disable the menu links for the following pages:
  • Mid Term Grades ( bwlkfmgd.P_FacMidGrd )
  • Final Grades ( bwlkffgd.P_FacFinGrd )
  • Incomplete Grades Summary ( bwlkincg.P_FacIncmpGrdSum )

You can also disable the menu link for the Summary Class List page ( bwlkfcwl.P_FacClaListSum ) if you choose.

You can disable one menu link at a time.

Procedure

  1. Access Banner Web Tailor.
  2. On the Web Tailor Menu ( bmenu.P_WebTailorMnu ), select Web Menus and Procedures.
  3. On the Customize a Web Menu or Procedure page ( twbkwmnu.P_OptionPgWebMain ), enter the package.procedure name of the Web page in the Search by Name field.
    Use these package.procedure names:
    • bwlkfmgd.P_FacMidGrd
    • bwlkffgd.P_FacFinGrd
    • bwlkincg.P_FacIncmpGrdSum
  4. Click Search.
  5. Select the name in the Procedure Name field.
  6. Click Copy Baseline to Local.
  7. Clear the Enabled Indicator check box.
  8. Click Submit Changes.</cmd>
  9. Repeat these steps for each menu link you want to disable.
    You may need to log out of Self-Service and log back in to see the menu changes.

Set up GTVSDAX rules

This chapter discusses the GTVSDAX rules used with Faculty Grade Entry. You need to select your settings to determine data display and to process midterm, final, and incomplete grades. Additional rules can be set up for use with electronic grade book processing in Banner Student.

This section also contains details about the MDUU rules used with grade book processing.

GTVSDAX rules used in overall Faculty Grade Entry processing

The following rules are used with Faculty Grade Entry processing.

  • GMODGRD
  • INCLUCLASS
  • MIDTERM
  • PHOTOS
  • ATTENDHRS
  • SCALELIMIT
GMODGRD rule

This rule is used to determine what grades are available for midterm and final grading.

The system looks at the setting of the rule, in addition to the student’s course level and grade mode from SFAREGS and the logic on SHAGRDE. To limit the grades available for selection in the Grade field, enter Y, N, or A in the External Code field for the Internal Code of GMODGRD on GTVSDAX.
External Code Internal Code Internal Code Sequence Number Internal Code Group Description Activity Date
Y, N, A GMODGRD N/A FACWEB Grades by Grade Mode System Date

Here are the setting choices for the GMODGRD rule.

  • Set the GMODGRD rule to Y to limit the grades available for selection to those that match the student's course level and grade mode.
  • Set the GMODGRD rule to N to limit the grades available for selection to all grades for all the course's grade modes at the student's course level.
  • Set the GMODGRD rule to A to limit the grades available for selection to all grades, for all grade modes, for the student's course level, with no regard to the course's grade modes.
INCLUCLASS rule

The INCLUCLASS rule is used to determine whether courses are displayed in the Midterm Grades and Final Grades sections of the Faculty Grade Entry page.

The display of these courses is based on the setting of the Display Class List indicator from the Term Control Page (SOATERM). This indicator is part of the faculty controls used to restrict or enable selected faculty-related actions in Banner Self-Service.

The Display Class List indicator is included to allow institutions to have the flexibility to view the student rosters in read-only mode when grading is disabled.

External Code Internal Code Internal Code Sequence Number Internal Code Group Description
Y, N

(Default value is Y)

 INCLUCLASS N/A FACWEB Include Class List Indicator
  • If the INCLUCLASS rule is set to Y, then the Display Class List indicator (on SOATERM) is used to fetch the courses and display in Midterm and Final tabs in FGE. With this rule set, even if grading is disabled and the Display Class List indicator is checked on SOATERM for a particular term, the faculty will be able to view courses and student rosters in read-only mode for that term.
  • If the INCLUCLASS rule to set to N, then, the Display Class List indicator (on SOATERM) is not used while fetching courses in Midterm and Final tabs in FGE. With this rule set, if the grading is disabled, the courses for that term will not be displayed in the Course section. Only if grading is enabled, the courses will be displayed and faculty can enter/edit student grades in the roster.
MIDTERM rule

This rule is used to restrict entry of midterm grades for students when a comment code is mapped from STVGCMT.

Only courses that have registered students with the matching comment code are displayed in the Midterm Grades section. Only students who have the matching comment code on their registration record for the CRN are displayed on the class roster for midterm grades for that CRN. If the MIDTERM rule is created, and no students in the course have the matching midterm comment code entered in SFAALST or SFASLST, the course is not displayed for grading.
External Code Internal Code Internal Code Sequence Number Internal Code Group Description Activity Date
N MIDTERM 1 GRADING Mid-Term Grade Required System Date

Here are the setting choices for the MIDTERM rule.

  • Set the MIDTERM rule to N, to display all students on the class roster for midterm grading. The midterm grade comment code is not required.
  • Set the MIDTERM rule to a value other than N (a valid, Web-enabled, grade comment code from STVGCMT), to require the midterm grade comment code on a student’s record.
PHOTOS rule

The PHOTOS rule is used to determine whether or not student photos are displayed on the Faculty Grade Entry page. This rule affects the Student Details tab in the Enter Grades section of the page for midterm, final, and grade book grades.

External Code Internal Code Internal Code Sequence Number Internal Code Group Description Activity Date
N PHOTOS N/A SS GRADING Photo Display System date

Here are the setting choices for the PHOTOS rule.

  • Set the PHOTOS rule to Y, to display student photos. If no photo is available for a student, a photo placeholder can be displayed.
  • Set the PHOTOS rule to N, to not display student photos.
ATTENDHRS rule

The ATTENDHRS rule is used to determine whether the system displays the hours attended data on the Faculty Grade Entry page. This rule affects the Enter Grades section for midterm and final grades, and the import and export grade processes used with the page.

This rule is delivered set to Y, to mirror existing 8.x functionality where hours attended data is automatically available to the user. You have the option to turn off the rule at your institution.

External Code Internal Code Internal Code Sequence Number Internal Code Group Description Activity Date
Y ATTENDHRS N/A SS GRADING Attendance Hours Display System date

The following choices are available for the ATTENDHRS rule.

  • Setting the ATTENDHRS rule to Y causes the system to display the Hours Attended field in the Enter Grades section.
  • Setting the ATTENDHRS rule to N causes the system to hide the Hours Attended field in the Enter Grades section.
  • Setting the ATTENDHRS rule to R requires you to enter the hours in the Hours Attended field in the Enter Grades section.
  • Setting the ATTENDHRS rule to M causes the system to limit the hours you can enter in the Hours Attended field to the maximum hours specified for the CRN.
Note: The ATTENDHRS rule applies to both Faculty Grade Entry and Attendance Tracking functionality.
SCALELIMIT rule

The SCALELIMIT rule for rounding student’s score.

External Code Internal Code Internal Code Group Description
2 SCALELIMIT SS Grading Mid-Term Grade Required

Use this concept to define the number of digits to display after the decimal point for Score and Percentage fields in the Faculty Grade Entry and Student Academic Review pages. The default value is 2 and the accepted values are from 1 to 6.

When you enter a score of a student's sub-component or component with a decimal value that is greater than the value that is being set as external code in the SCALELIMIT rule of the GTVSDAX form, a validation error is displayed.

For example, if the external code is set as 3 in the SCALELIMIT rule, and if you enter the student's score as xx.yyyy, the system throws a validation error.

Note: We are displaying and restricting the input to the number specified in the GTVSDAX setting. For example, if SCALELIMT is set to 3, then we display 3 decimal places and only allow entry of 3 decimal places.

Depending upon the SCALELIMIT rule set in GTVSDAX page, the system automatically converts and shrinks the value to appear as an appropriate decimal value.

When you enter the score for the sub-components with the SCALELIMIT decimal value, the Component Score and Percentage gets calculated as per the SCALELIMIT rule. Both the score and percentage values are displayed accordingly.

Similarly, the composite Grade and Percentage also gets calculated automatically as per the component score and the composite Percentage is displayed with SCALELIMIT rule.

Cap Final Grades in Reassessment

Reassessed final grades can be capped for individual CRNs or for pairs by grade mode and level code. This requires the following sets of GTVSDAX translations for the REASCAPCRN and REASCAP rules.

Internal Code Group Internal Code Translation External Code
FACWEB REASCAPCRN CRN code Grade cap
FACWEB REASCAP Grade mode code and level code Grade cap
If a final composite grade is updated as the result of a reassessment on a component or subcomponent record, the capping rules are evaluated as follows:
  • The CRN on the composite record is compared to CRNs for the REASCAPCRN rule.
  • If a match is found on the CRN code, no further capping is applied.
  • If no match is found, the grade mode ( SHRTCKG_GMOD_CODE ) and level ( SHRTCKL_LEVL_CODE ) associated with the composite record are compared to the REASCAP rule.
  • If a match is found, capping is applied. Otherwise, no capping will be applied to the final composite grade.
  • If no GTVSDAX record exists for these capping parameters, then capping will not be applied on reassessed final grades.

GTVSDAX rules used with Student Academic Review processing and electronic grade book processing

The following GTVSDAX rules are used with Student Academic Review processing and associated electronic grade book processing.

  • OVERGRADE
  • NEGGRADE
OVERGRADE rule

The OVERGRADE rule is used with Student Academic Review and electronic grade book processing in Self-Service to allow over grading, that is, to allow entry of component and subcomponent grades that are greater than the "out of value".

Use this rule to specify whether scores can be entered that are greater than the "marked out of" value, which is defined to be the maximum score. This allows faculty members to assign bonus points. For example, 110 out of 100 yields 10 bonus points.

  • Enter Y in the External Code field to specify that component and subcomponent grade scores can be greater than the out of values.
  • Enter N in the External Code field to specify that component and subcomponent grade scores cannot be greater than the out of values.
    External Code Internal Code Internal Code Sequence Number Internal Code Group Description System Required
    Y, N OVERGRADE 1 FACWEB Allow Grade Over "Out Of" Yes
NEGGRADE rule

The NEGGRADE rule is used with Student Academic Review and electronic grade book processing in Self-Service to allow negative grading, that is, to allow entry of negative grade scores for components and subcomponents.

Use this rule to specify whether scores can be entered that are negative numbers which results in the calculation of a negative percentage, even when negative percentages are not valid on the Grade Scale Definition Page (SHAGSCH).

No grade is displayed for a component with a negative score. A final composite grade is still calculated using the negative value as the grade for the component, but is only displayed when the resulting value is a positive number. When the final grade value is negative, the Composite Calculated value is displayed to show that the final mark has been calculated, but no final grade is displayed for the student.

  • Enter Y in the External Code field to specify that negative component and subcomponent grade scores can be entered.
  • Enter N in the External Code field to specify that negative component and subcomponent grade scores cannot be entered.
    External Code Internal Code Internal Code Sequence Number Internal Code Group Description System Required
    Y, N NEGGRADE 1 FACWEB Negative Grade Score Allowed Yes

Migrate from 8.x ESC Enhanced EGB

Here is some information for institutions that are migrating from the European Solution Center (ESC) version of the Electronic Grade book (the Enhanced Electronic Grade book) to the Electronic Grade book (EGB) in Banner Faculty Self-Service and Banner Student.

All the functionality in the Enhanced Electronic Grade book (EEGB) has been moved to Banner Faculty Grade Entry and the Banner Student applications.

The Self Service pages were moved to FGE and the enhancements to administrative functionality were moved to Banner Student 9.3 and above.

Set up Banner Student pages

This chapter discusses the setup needed on Banner Student administrative pages to process midterm, final, and incomplete grades, in addition to component and subcomponent grades.

Using the Faculty Grade Entry page assumes that the person has been set up as a faculty member in Banner baseline on the Faculty/Advisor Information Page (SIAINST) with a Status of Active and the Faculty indicator checked.

Faculty assignments can be added on the Faculty Assignment Page (SIAASGN), on the Schedule Page (SSASECT), or in Self-Service.

Term Control Page (SOATERM)

Use the Term Control Page (SOATERM) to set up availability of midterm and final grades, set dates for faculty access, and determine eligibility for grading.

Midterm and final grades

Determine whether midterm and final grades should be available in Self-Service for all sections for a part of term.

  • If you want midterm grades for the all sections for a part of term to be available for entry on the Web, select the Faculty Web Midterm Grades check box in the Base Part of Term information for the part of term.
  • If you want final grades for the all sections for a part of term to be available for entry on the Web, select the Faculty Web Final Grades check box in the Base Part of Term information for the part of term.

For incomplete grades, specify the default extension date in the Incomplete Extension Date field in the Base Part of Term information. The extension date may be specified for each part of term, but it does not have to be.

  • If the part-of-term for a CRN is not 1 (full term), and if there is not a default extension date for that part-of-term, the system reverts to the entry for part-of-term 1.
  • If the CRN part-of-term value is 1, and if there is no specified extension date for 1, the system will revert to the end date for part-of-term 1 as the extension date.
Faculty access

An institution can set dates for faculty access on SOATERM.

If dates have been entered for a term, the faculty access date must be within the start and end dates defined on SOATERM. If the access date is not in the defined start and end dates, the faculty member will not be able to view the CRNs on the Midterm Grades, Final Grades, and Grade book tabs. If no dates have been entered for faculty access, access is allowed.

Grading eligibility

In the Base Part of Term section of the page, if the Faculty Web Midterm Grades check box is selected for a part of term, then all sections offered in that part of term are eligible for midterm grading.

Similarly, if the Faculty Web Final Grades check box is checked, the sections in that part of term will be eligible for final grading.

The information in the Grade Display Controls section of the Term Management section of SOATERM is used together with the information on the Base Part of Term section. A term must have display enabled at the term level before the part of term controls are evaluated.

Display class list

In Midterm and Final Grades tabs, before or after grading, the faculty can view their assigned classes in a term as display only.

This can be achieved using the Display Class List check box in the Faculty and Advisor Controls section of the Term Control Page (SOATERM). If this check box is selected and grade controls are not enabled on the SOATERM and SSAWSEC pages, the student roster will be display only. The faculty can view the student roster but cannot grade the students for the CRN.

Even when the Display Class List check box is not checked, if grading is enabled for the Midterm Grades and Final Grades tabs using SOATERM and SSAWSEC pages, the faculty will be able to view and grade students. The Master Web Term Control indicator must be checked on SOATERM for grading to be active.

Note: The Display Class List check is not applicable for the Grade book.

Each “set” is defined as consecutive assignments that are OR’d together. “Consecutive” is defined by the values in the And/Or Sequence field. The “sets” themselves will be AND’d together.

For example- A physics class that has multiple quizzes and multiple labs in addition to the final. A student will be graded on the best two quizzes, the best two labs, and the final. This would be configured as “Best of” with a value of two and:

“Best of” overview

There can be situations where a student is expected to complete all of a set of assignments, but only the top scores will be used to compute the grade.

About this task

For example, an instructor may have 16 weekly quizzes but will only consider the 12 top scores. After the student has all assignments graded, the grade calculation will use the specified number of scores to calculate the composite grade. This functionality is available for both components and subcomponents.

Overgrading and negative grading

An institution can allow “over grades” and “negative grades” to be entered in the Gradebook for a student at both the component and the sub-component level.

Overgrading

Overgrading allows marks to be entered that are greater than the “marked out of” value on the component or sub-component definition; this value is defined to be the maximum score.

Overgrading allows faculty to assign bonus points or extra points. For example, a mark of 110 out of 100 yields 10 bonus points.

These bonus points are used in the weighted score calculation for the composite grade.

Negative grading

Standard behavior for gradebook composite calculation is that if the calculated score is below the minimum (lowest) low score entered on the Grade Scale Definition (SHAGSCH) page, the composite score is calculated but there is no grade calculated and no score or grade saved.

Further, if the calculated composite is below this minimum low score, the composite record will not be updated if a previous calculation was recorded.

In other words, if the composite calculation will not result in a value that can be reconciled on SHAGSCH page:

  • An existing composite record will not be updated but any previous data will persist
  • If there is not an existing composite record, one will not be created.

For simplicity in the following section, we will assume that the minimum low score entered is zero. If the grade scale you are using has a different minimum low score, you should be able to “shift” the information and the examples to match; Ellucian, as always, recommends thorough testing.

Negative grading allows marks to be entered that are negative numbers, resulting in a negative percentage calculated, even if negative percentages are not valid on the Grade Scale Definition page (SHAGSCH). No grade is displayed for a component with a negative percentage. A final composite grade is still calculated using the negative value as the grade for the component, but only displayed if the resulting value is a positive number.

Grade Book Rule Definition Page (SHAGRUL)

The Grade Book Rule Definition Page (SHAGRUL) is used to create late and resit rules.

Rules are assigned to the component or subcomponent by term using the SHAEGBC page or to an individual CRN’s components and subcomponents using the SHAGCOM page. See the online help for more information on these pages.

Resit overview

An institution can optionally set up rules to govern resit (a.k.a. re-take or repeat) processing in grade book.

About this task

This functionality is meant for students who repeat an exam or an assignment and are to be awarded a new grade or score. This is separate from the situation where an instructor needs to correct a previously assigned grade or score.

This functionality is available for both components and subcomponents.

An instructor must choose a “resit” grade change reason in order for the resit functionality to be invoked. There are two parts to the checking that will then happen (if configured):
  • The maximum number of resits allowed
  • The maximum percentage allowed for a resit. Please note that if the maximum percentage is applied, the student's score may be recalculated based on the grade scale.

Procedure

  1. Set up resit grade change codes on STVGCHG. You will need at least one grade change code with the resit indicator set. You will need at most one grade change code with the attribute set to CR (Capped Resit).
  2. Set up the resit rule values on SHAGRUL.
  3. Set up the default resit rule for components and subcomponents on SHAEGBC.
  4. Set up any specific resit rule for components and subcomponents on SHAGCOM.
    For example: A student gets 30% on the first attempt and a 90% at the second try. The resit rule has been set up so the student is credited with the minimum passing percentage of 50%. This may be because the institution considers it unfair that a student who got 51% at the first attempt is inferior to a student who failed it first and then got a high passing percent.
Late overview

An institution can optionally set up rules to govern late processing in grade book. This functionality is meant for time-sensitive assignments; a penalty can be automatically applied for a late submission.

About this task

For late processing to happen, the assignment must have a "due date" defined. Late processing functionality is available for both components and subcomponents. Separate penalties can be assessed:
  • For the first day (either by a percentage or a flat amount)
  • For each day (again, either by a percentage or a flat amount)
The penalties can be capped by:
  • A maximum number of late days
  • A minimum percentage amount (i.e. the lowest the calculated percentage can be)

Procedure

  1. Set up late grade change codes on STVGCHG. You will need at most one grade change code with the attribute set to DL (Degraded Late).
  2. Set up the late rule values on SHAGRUL.
    Late rule parameters:
    • "First Day Perc Deg per day" is the percentage degradation for the first late day.
    • "First Day Actual Deg per day" is the actual degradation of the mark for the first late day.
    • "Percentage Deg per day" is the percentage degradation per day after any applicable first late day.
    • "Actual Mark per day" is the actual degradation of the mark per day after any applicable first late day.
    • "Max Number of Late day" is the maximum number of late days to consider.
    • "Late Cap Mark in Percent" is the lowest the calculated percentage can be.
  3. Set up the default late rule for components and subcomponents on SHAEGBC.
  4. Set up any specific late rule for components and subcomponents on SHAGCOM.
Basic usage and examples

This section describes how to use late processing and provides examples for your reference.

About this task

  • Percentage takes precedence over actual if both are specified.
  • If the faculty has specified an extension date for an assignment, the extension date is used in place of the due date for late processing.
  • After the grade change code with the DL attribute has been assigned, if the faculty changes something (e.g. a new grade or a new submission date), the grade change code must be set to another code (e.g. IC) in order for the new late calculation to take place. Otherwise, the grade will be calculated without regard to late & resit rules and the DL code will remain. This is representative of what will be seen in the summary:

Score Changed to 60.
Grade scale NORMAL used to calculate Grade B Percentage 80.
Late/Resit Rules processing will be applied
Component mark is exempt or already a late/resit mark or has no score.
Resit and Late processing will be ignored.

If you do not specify a late cap mark in percent, and the instructor submits the grade more than the max number of late days, the student is given a blank score and percentage, and a failing default grade (from SHAGSCH).

The summary will look like the following example. Notice there is not a min capped percent value in the appropriate places, no score, no percentage, and no grade.

Degraded percent 56 < min capped percent or days late 6 > max days late 5.
Minimum capped percentage applied. New score , new percentage.
Component mark is late. Score degraded from to . Percentage degraded from to . Grade change code set to DL.
Late/Resit Rules have been applied.
Grade changed to .

Procedure

  1. A faculty member grades the student’s late assignment (i.e. the submission date is greater than the due date) and determines the number of days the assignment is late.
  2. If a First Day degradation is specified:
    1. Apply the appropriate First Day degradation
    2. Apply the appropriate Per Day degradation for subsequent days
      This is equivalent to calculating: First Day + Per Day * (#late days – 1)
  3. If a First Day degradation is not specified, apply the appropriate Per Day degradation for all late days
  4. After the above preliminary calculation has been done, check to see if either the grade submission is later than the maximum number of late days or the calculated new percentage is less than the minimum cap. If either condition applies, use the Late Cap in Percentage as the calculated percentage
  5. The resulting percentage (and the appropriate grade from the grade scale) will be saved with the grade change code associated with the DL (Degraded Late) attribute
    Example 1:
    • First Day percentage degradation = 10%
    • Per Day percentage degradation = 5%
    • Max late days = 5
    • Late cap = 40%

    • Student has a mark of 60% and is 5 days late.

      Calculation

      1. First Day = 10%
      2. Four subsequent late days = 4 * 5% = 20%
      3. Total degradation = 10% + 20% = 30%
      4. 30% of score = 30% of 60% = 18% degradation to be taken off actual mark
      5. 60% - 18% = 42% calculated final mark (greater than the late cap so no need to adjust)

  6. Example 2:
    • First Day percentage degradation = 0%
    • Per Day percentage degradation = 5%
    • Max late days = 5
    • Late cap = 40%

    Student has a mark of 60% and is 10 days late.

    Calculation

    • First Day = 0%
    • Ten subsequent late days = 10 * 5% = 50%
    • Total degradation = 0% + 50% = 50%
    • 50% of score = 50% of 60% = 30% degradation to be taken off actual mark
    • 60% - 30% = 30% calculated mark
    • This will be capped at 40%, because the score was more than the maximum number of days late and the calculated mark was less than the late cap.

Page setup for grade mode controls

You can set up grade controls at your institution to limit the display of grades associated with the student or with the level. You can also substitute a grade mode for use with faculty grading.

Limit grade selection

The system uses the setting of the GMODGRD rule, along with the student’s course level and grade mode found on the Student Course Registration Page (SFAREGS) and the combination of logic found on the Grade Code Maintenance Page (SHAGRDE) to determine what grades are available.

To limit the grades available for selection in the Grade field, enter Y, N, or A in the External Code field for the Internal Code Group of GMODGRD on GTVSDAX.

  • If you set the GMODGRD rule to N, the valid values displayed are for all grades for all the course’s grade modes at the student’s course level.
  • If you set the GMODGRD rule to A, the valid values displayed are for all grades, for all grade modes, for the student’s course level, with no regard for the course’s grade mode.
Substitute grade mode

Only those grades associated with the grade mode in the Mode field on SHAGRDE (where the SHRGRDO_GMOD_CODE field value is equal to the STVGMOD_GMOD_CODE_WEB field value), that are defined as Web-enabled and are applicable to the processing term are displayed in the Enter Grades section.

In the previous example, it is assumed that the grade substitution rules are set up so that the entered grade is substituted during the roll to the Academic History. Page error checking for last attendance date and hours attended

Error checking is performed for last date of attendance errors when the changes are saved.

Records with errors are not saved, and the errors are displayed in the Notification Center. When valid grades are entered for a gradable course, and a last date of attendance is not required, the records are saved without error. A last date of attendance can be entered for a student who has not been awarded a grade.

When a valid grade is entered that requires a last date of attendance (Last Attendance Date Ind is checked on SHAGRDE for the grade code), the last date of attendance must be entered. This rule applies only to final grades. The records are saved if no errors exist.

When errors exist for last date of attendance date or hours attended, error messages are displayed for the records in the Notification Center. If errors occur, changes to grades, the last dates of attendance, and attendance hours are not saved. All errors on each individual record must be corrected for that record to be saved.

When a student whose status does not reflect withdrawal from the course is given a last date of attendance, the following warning message will be generated after the user moves out of the Last Attend Date field: The student has not withdrawn from the class. The warning displays and then fades away, and the record can be saved.

The following conditions are called when the grade has the Last Attendance Date Ind checked for the term in Grading Code Maintenance Table (SHRGRDE). These conditions are also called when the grade does not require the last date of attendance per the SHRGRDE table.

  • If the last date of attendance is null when the grade used requires a last date of attendance date, the following error message is displayed: Last Date of Attendance required for this grade.
  • If the last date of attendance is entered, but the date entered is greater than the current system date, the following error message is displayed: Last date of attendance cannot be greater than current date.
  • If the last date of attendance is entered, but the date is earlier than the valid start date for the course, the following error message is displayed: Last date of attendance must be between section start date and section end date.
  • If the last date of attendance is entered, but the date is later than the last date for the course, the following error message is displayed: Last date of attendance must be between section start date and section end date.
  • If the last date of attendance is entered, but the date is an erroneous date on the calendar (such as October 32, 2012), the following error message is displayed: The Last Attend Date “10/32/2011” is not valid.
  • If the last date of attendance is entered, but the date format is incorrect (such as the format is YYYYMMDD and the date entered uses format MMDDYYYY), the following error message is displayed: The Last Attend Date “#####” is not valid.
  • This error message applies to open learning courses. If the last attendance date is outside of the section start/end date or a last attendance date before the first date of the section is entered, the following error message is displayed: Last date of attendance must be between learner start date and learner end date.
  • If the last date of attendance is entered for a student who has not withdrawn from the course, a warning is displayed in the Notification Center. This warning displays for a short time and then fades away. You can save your changes and proceed with grade processing.

The following conditions are called when the user enters attendance hours.

  • Hours attended must be between 0 and 999.99. If you enter a value greater than 999.99, or enter hours for a student that are not valid, you will receive an error.
  • You cannot enter negative numbers.
  • If hours are entered without two decimal places to the right (such as 60), the system does not add the decimal places (such as 60.00).

Hours Attended validations and calculations

This section discusses the validations for Maximum Capping (M) and Required (R) for HOURS ATTENDED field. The validations differ for the institutions with CALBSTU installed and non CALBSTU institutions for the Hours Attended column.

When is HOURS ATTENDED verified for Required?

The ATTENDHRS on GTVSDAX is setup as R and Attendance Method field code is setup on the SSASECT page then It is mandatory to enter the hours in Hours Attended column If value is NOT entered on the Hours Attended column then an error message Invalid Hours Attended value, this field is required is displayed.

When is HOURS ATTENDED verified for Maximum Capping?

The ATTENDHRS on GTVSDAX is setup as M and Attendance Method field code is setup on the SSASECT page then the Total Contact Hours is calculated for all the meetings schedule on SSASECT page for the CRN and considered for restricting the entry of Hours Attended column value. If the Hours Attended value exceeds the Total Contact Hours, an error message Hours Attended cannot be greater than the section's total contact hours is displayed.

When is HOURS ATTENDED verified for BOTH, Required and Maximum Capping?

The ATTENDHRS on GTVSDAX is setup as M or Rand Attendance Method field code is setup on the SSASECT page. The Attendance Method code has the Actual Indicator, that is. STVACCT_ACTUAL_IND is setup to Y then it is mandatory to enter the hours in Hours Attended column. If value is NOT entered in the Hours Attended column an error message Invalid Hours Attended value, this field is required is displayed. Also, If the Hours Attended value entered exceeds the Total Contact Hours, then an error message Hours Attended cannot be greater than the section's total contact hours is displayed

How is TOTAL CONTACT HOURS calculated for Max Capping?

The Total Contact Hours is calculated differently of the institutions with CALBSTU setup and NON-CALBSTU institutions. The following are the calculations

CALBSTU Institutions

  • Total Contact Hours is calculated for each meeting scheduled on SSASECT page for a CRN and stored on SSRMEET_HRS_TOTAL.
  • If a CRN has multiple meetings scheduled, the Total Contact Hours is considered by adding all the Total Contact Hours.

    For Example:

    CRN Meeting Number Total Contact Hours
    1001 1 10.2
    2 5.5
    3 7.5
    Total Contact Hours for CRN: 23.2

Non-CALBSTU Institutions

  • Total Contact Hours is calculated spontaneously on Faculty Grade Entry page, that is. each meeting scheduled on SSASECT page for a CRN.
  • The Total Contact Hours is calculated based on change of action.
  • Total Contact Hours formula:
    • Total Contact Hours = Hours Per Day x Number of meeting occurrences between Start Date and End Date.
    • Hours Per Day is the time difference between Start Time and End Time.
    • Number of Meeting Occurrences is considered from SSRMEET_MEET_NO for each meeting scheduled.
  • If a CRN has multiple meetings scheduled, the Total Contact Hours is considered by adding all the Total Contact Hours.

    For Example:

    CRN Meeting Number Total Contact Hours
    1001 1 10.2
    2 5.5
    3 7.5
    Total Contact Hours for CRN: 23.2

Assessment and reassessment

In grade book processing, assessment and reassessment can be used when the faculty member is grading a student for the component or subcomponent.

During assessment, the faculty member can enter new grades for the students. If the grades are not rolled into Academic History, the faculty member can update the existing grades. If the faculty login date is within the assessment score open date and final score cutoff date, the components and subcomponents are eligible for assessment grading.

During reassessment, the faculty member can update an existing grade with the reassessed or changed grade. If the faculty login date is within the reassessment score open date and reassessment score cutoff date, the components and subcomponents are eligible for reassessment grading. Reassessment can only be performed after the grades are rolled into Academic History and published to students.

Note: If the faculty login is not within faculty access dates for the term, the CRNs will not be displayed on the Grade book tab for the faculty member to grade, regardless of the dates on SHAEGBC.

Rounding student’s score

When you enter a score of a student’s subcomponent or component with a decimal value that is lesser or greater than six decimals, the system converts the score to a six-digit decimal.

For example, if you enter the student’s score as xx.yy, the system converts the decimal value to a six-digit value that will display as xx.yy0000.

If you enter the student’s score with more than six-digit decimal and cursor out of the Score field, the system automatically converts and shrinks the value to appear as six-digit decimal value. For example, if xx.yyyyyyyyyyyyyy value is entered, the system displayed score value will be xx.yyyyyy.

When you enter the score for the subcomponents with a six-digit decimal value, the Component Score and Percentage get calculated as per the six-digit decimal score entered. Both the score and percentage values are displayed in six-digit decimal value.

Similarly, the composite grade and percentage also gets calculated automatically as per the component score and the composite percentage is displayed with six-digit decimal value.

Set up grade book term, part of term, and CRN rules

This section explains how term, part-of-term, and CRN dates for Grade book are interpreted by the system to determine whether a mark or grade record can be displayed in Self-Service.

Before describing the different rules that can be set up, you need to determine what makes a mark or grade record available for assessment on Grade book pages. The following example illustrates how this works.

Example

You have the following requirements:
  1. The student must be actively enrolled in the selected CRN.
  2. The user must be associated with the selected CRN (as an instructor for the CRN in SSASECT).
  3. The combination of CRN, term, and student has not been rolled to Academic History or has been unrolled from Academic History.
  4. One of the following must be true:
    1. The grade record data fulfills the conditions of the EGB_REG_CLOSED_BYPASS rule in GKRRSQL, or
    2. All of the following are true:
      • The selected term is currently open for assessment.
      • The selected part of term is currently open for assessment.
      • The selected CRN is currently open for assessment.
      • The mark/grade record fulfills the conditions of the EGB_REG_OPEN_OVERIDE rule in GKRRSQL.

Items 1 through 3 can be considered to be the ‘standard’ prerequisites for a record to be available for Grade book assessment. Item 4 is where date ranges defined for the term, part of term, and CRN are evaluated against the current date of the system (database date) and against customizable rules to bypass or override those date ranges.

The EGB_REG_CLOSED_BYPASS rule can be considered to be an ‘exception rule’. It allows you to quickly authorize Grade book access to a specific record or set of records without changing the general rules that govern access to records for the selected term/part of term and CRN.

For example, let’s say that the selected term or part of term is now closed for mark assessment. However some marks are missing for a CRN in that term. To allow faculty and instructors to enter those marks in Grade book without reopening assessment for the term or part of term, an administrative user can temporarily update the EGB_REG_CLOSED_BYPASS rule in GKRRSQL as follows:

SELECT 'Y' FROM DUAL WHERE CRN='x' and :TERM_CODE='y'

When a faculty user assigned to the CRN attempts to access the mark records for the CRN and term combination, the date ranges for the term, part of term, and CRN will be ignored for those records and, provided that those records are not yet rolled in Academic History, the Self-Service user will be able to enter the missing marks. In principle, these exceptions should remain exceptions to the general rules, therefore the modification of an exception rule should be used only as a temporary measure.

By default, these exception rules are released with the following logical condition:

SELECT 'Y' FROM DUAL WHERE 1=2

This translates to ‘there is no exception’. Note: Check the above statement about the seed data.

The EGB_REG_OPEN_OVERIDE rule can be considered to be a ‘confirmation rule’. It is an additional logical condition to the date range evaluation and can be used to restrict those date ranges with any other complementary condition.

For example, let’s say that the core logic for selecting a student in EGB pages is too flexible and that an additional condition on an indicator, local to your institution, is desired; for example, you might want to specify that f_local(student_pidm, term,crn) must be equal to ‘Y’ to authorize the student mark/grade record to be amended in Grade book assessment.

For this example, the EGB_REG_OPEN_OVERIDE rule in GKRRSQL can be amended as follows:

SELECT 'Y' FROM DUAL WHERE f_local(:PIDM, :TERM_CODE, :CRN)='Y'

Then, before a record is displayed in a Grade book assessment page, in addition to verifying the exception rule, the date ranges, the student PIDM, term code, and CRN from the mark/grade record will be evaluated in the stored function f_local, and the record will be displayed only when that evaluation returns ‘Y’.

The simplest confirmation rule is the following logical condition:

SELECT 'Y' FROM DUAL WHERE 1=1

This translates to ‘this rule confirms with no exception the conditions set by the other evaluated rules’.

The display of a record in any of the following areas is conditioned by rules and an evaluation following the pattern described above:
  • Grade book assessment
  • Grade book reassessment
  • elf-service student final grades
  • Self-Service student final marks
  • Self-Service student reassessment final grades
  • Self-Service student reassessment marks

Import grades

Grades for the class roster, component roster, and subcomponent roster can be imported to Faculty Grade Entry using the options on the Tools Menu. A wizard is provided to step you through the process, including mapping columns. The data can be uploaded to the page using a recognized file type.

About this task

Data is handled as follows:
  • The student's Banner ID and additional fields are required to correctly map data during the import process. The additional fields vary depending on the type of roster being imported.
  • Alternate student IDs can be used.
  • Blank data in the spreadsheet will not be imported.
  • Imported grade data (only valid data) will overwrite existing grade data that has not been rolled.
  • In Midterm and Final Grades, the values for the grade, last date of attendance, and attendance hours can be updated.
  • In Grade book, the values for the grade, submission date, grade change reason, and comments can be updated.
  • In Midterm and Final Grade, null or incorrect data (data with errors) is not imported. It can be reviewed in a validation report, corrected, and reimported.
  • In Grade book, a null value overrides the existing value when it is imported.
  • Incomplete grades can be imported.
  • Data that is exported from the application and not changed in the spreadsheet will not be imported, as it is an exact match of existing data.
  • The import is enabled only when the corresponding roster is editable.

It is recommended that you use the export process to export a template before importing grades.

This will set up formatting that matches the import wizard. If you attempt to import data without doing this, the system will try to logically map the data for you but may not produce the results you desire.

When the process is working, the import wizard page turns dark, and a white spinning icon is displayed. Wait for the import process to finish, as clicking buttons may interrupt the process. You can use the Cancel button to stop the import process. The speed of the import is related to the number of rows in the spreadsheet and not the number of rows that will trigger an update upon import. If there is a significant number of rows that are unchanged, you can remove these from the spreadsheet before starting the import. All rows in the spreadsheet are examined and validated, even those that do not result in an update.

Use the View Profile button in the contact card to access the Student Profile page. When the student name is displayed as a link, you can click on the link to access the Student Profile page.

Courses are grouped by program and are based on the associated study path. Each program is a displayed in a separate tab. The CRNs and sections that are not associated with a study path are displayed in a separate tab (CRNs not associated with Study Path). This tab is displayed only when the student has registered for CRNs which are not associated to the study path. When the same program is associated with two different study paths, the Student Academic Review page is displayed with two tabs with the same program name. The study path and campus information displayed is associated with the program/curriculum information.

The reassessment dates (open and cutoff) in the Term or Part of Term or Section configuration sections on the SHAEGBC page must be defined to allow a faculty member to edit grades. An administrator can edit grades at any time and is not restricted by the dates configured on the SHAEGBC page.

When the faculty member has the SOAFACS rules enabled for ENTERGRADES or DISPLAYGRADES, this setting takes precedence for security level access at the CRN level. If the faculty member does not have any rules access, then the terms will not be available for review. If the faculty member logs in to use Student Academic Review processing on a date that is not within the defined reassessment open and cutoff dates, then the Student Academic Review page is displayed as read-only.

In the CRN section of the page, the Grade, Reason, and Comment fields are editable. Any grade change requires a grade change reason to save the changes. Grades cannot be Null. You can edit grades for multiple CRNs and save the changes. For component grades, you can either enter the score or the grade. If you enter both values, the score value takes precedence.

You can edit grades for multiple component and sub-component records for a CRN and save the changes. When you select a particular CRN record, the components associated with the selected CRN are displayed in the section below.

The Score, Grade, Submission Date, Extension Date, Reason, Comment, and Update Composite/Component Score fields are editable for components. The Update Composite/Component Score check box is checked by default. This check box is used to indicate whether you want to calculate and update the composite CRN score/components score.

Click the Right Arrow button to view the subcomponents as nested records that are associated with the selected component of the CRN.
