Install Ellucian Ethos Identity

You can manually complete the entire Ellucian Ethos Identity installation by downloading the Ellucian Ethos Identity installer from the Download Center or using SA Valet. You need to manually set up application-specific configurations.

The Ellucian Ethos Identity installer contains both WSO2 Identity Server 7.0.0 and the Ellucian Ethos Identity 7.0.0 extensions.

Deployment considerations

Review these deployment considerations before installing Ellucian Ethos Identity.

Single instance or clustered configuration

You can install Ellucian Ethos Identity as either a single instance, or multiple instances in a clustered configuration.

You will first set up a single instance, and then (optionally) extend the configuration to multiple instances in a clustered configuration.

Identity provider options

You can implement Ellucian Ethos Identity as your institution's primary identity provider (IdP) or in a federated configuration with an existing identity provider.

As a primary IdP, Ellucian Ethos Identity provides single sign-on for all applications that delegate authentication to it. Ellucian Ethos Identity maintains the SSO session for the user regardless of the underlying protocol used by each application. Ellucian Ethos Identity also provides for a customized login experience and self-service password change and password reset capabilities.

In a federated configuration, Ellucian Ethos Identity delegates authentication for applications that may not support the authentication protocol of the primary IdP. For example, you can configure CAS-based applications as service providers to Ellucian Ethos Identity which, in turn, you can configure as a service provider to a primary IdP. When users attempt to access a CAS-based application, they will be redirected back through Ellucian Ethos Identity to the primary IdP for authentication.

Deployment of Ellucian Ethos Identity and interfacing applications

Follow these guidelines when deploying Ellucian Ethos Identity and the products with which it interfaces.

Deploy on separate servers

To avoid conflicts between a service provider application and Ellucian Ethos Identity, Ellucian recommends that you deploy Ellucian Ethos Identity on a separate server than any products that perform SSO with Ellucian Ethos Identity. Deploying on separate servers avoids potential conflicts between browser cookies generated by Ellucian Ethos Identity and service provider applications.

TLS required for interfacing applications

Any applications that interface with Ellucian Ethos Identity must communicate using Transport Layer Security (TLS). If you have applications that use SSLv3 or older cipher suites, upgrade them to a version that can communicate using TLS.

Install Ellucian Ethos Identity 7.0.0

The Ellucian Ethos Identity installer contains both WSO2 Identity Server 7.0.0 and the Ellucian Ethos Identity 7.0.0 extensions.

Procedure

  1. Create a parent directory for Ellucian Ethos Identity.
    Linux/UNIX example: /u01/ellucian

    Windows example: E:\Ellucian

  2. Download the Ellucian Ethos Identity 7.0.0 installer file EllucianEthosIdentity_baseline-7.0.0.zip from the Ellucian Downloads or using SA Valet.
  3. Unzip the ZIP file under the parent directory.
    After unpacking the zip file, your directory structure should look like this:
    parent_directory
	--EllucianEthosIdentity_extensions-7.0.0
	--wso2is-7.0.0
    Note: Throughout the Ellucian Ethos Identity setup procedures, the wso2is-7.0.0 directory is referred to as EIS_HOME, consistent with the WSO2 website.
  4. Open a command prompt. (For Windows, right-click and run as administrator.)
  5. Change directories (cd) to the EllucianEthosIdentity_extensions-7.0.0 directory.
  6. Note: If you are on Java 17, run the following command:

    export ANT_OPTS="-Xmx2g -Dfile.encoding=UTF-8 \--add-exports java.xml/com.sun.org.apache.xpath.internal=ALL-UNNAMED \--add-exports java.xml/com.sun.org.apache.xpath.internal.objects=ALL-UNNAMED"

    Run the appropriate commands for your operating system to apply the Ellucian Ethos Identity 7.0.0 extensions to WSO2 Identity Server:
    • Linux/UNIX:

      chmod u+x apache-ant/bin/ant

      export ANT_HOME=apache-ant

      apache-ant/bin/ant new-install

    • Windows:

      apache-ant\bin\ant new-install

Ellucian Ethos Identity user stores

Ellucian Ethos Identity supports Primary and Secondary user stores.

Ellucian Ethos Identity leverages primary and secondary user stores for authentication and identity attribute assertion.

Primary user store

Ellucian Ethos Identity uses an external LDAP directory or Active directory server as a primary user store. The primary user store configuration includes the setup for administrative users.

Note: Ellucian Ethos Identity does not support using database server as a primary user store.

For more information about configuring primary user store, refer to Configuring the Primary User Store on the WSO2 documentation website for the corresponding WSO2 version.

Secondary user store

Ellucian Ethos Identity uses an LDAP directory, Active directory server, or database server as a secondary user store. Secondary user store will configure in the management console.

Directory Servers: Ellucian Ethos Identity supports directory servers as authentication user store and attribute store.

Database server (JDBC): Ellucian Ethos Identity supports JDBC for attribute assertion. that is as attribute store.

Note: Database server (JDBC) is not supported as a authentication user store. Use case for attribute assertion: UDC_Identifier is in the database and it can be retrieved using JDBC attribute store.

For more information, refer to Configuring Secondary User Stores on the WSO2 documentation website for the corresponding WSO2 version.

Specify properties for administrators

Define settings for the creation of the first Ellucian Ethos Identity administrator and properties for other users.

About this task

Ellucian Ethos Identity will create an administrative user in the primary user store when you start Ellucian Ethos Identity for the first time. Perform the following steps to define settings for creation of that user, along with settings that affect other Ellucian Ethos Identity users and administrators.

Procedure

  1. In an editor, open the deployment.toml file located in the EIS_HOME/repository/conf directory.
  2. Set the following properties to the appropriate values for the users and roles under the [super_admin] root key:
    Property Description
    create_admin_account Enter true if you want Ellucian Ethos Identity to create the administrative user in the primary user store if a user with the specified user name does not exist. Similarly, Ellucian Ethos Identity will create the specified role if it does not exist.

    If you enter true, and you are using Active Directory as the primary user store, you must also perform the procedures in Configure a secure connection from Ellucian Ethos Identity to Active Directory.

    Enter false if you plan to use an existing user and role, and do not want Ellucian Ethos Identity to create the administrative user or role.
    admin_role Enter the role name in the primary user store that will be assigned to the administrative user.

    If you set create_admin_account to false, this role must already exist in the primary user store.

    Value: admin
    username Enter the user name for the administrative user.

    If you set create_admin_account to true, and a user with this user name does not yet exist in the primary user store, Ellucian Ethos Identity will create the user.

    If you set create_admin_account to false, a user with this user name must already exist in the primary user store.

    Value: admin
    password Enter the password that will be assigned to the primary administrator in the primary user store, if Ellucian Ethos Identity creates the user. This password is ignored if the user already exists in the primary user store.

    Value: admin
    properties.CaseInsensitiveUsername Enter true if you want to allow mixed case administrator user names.

    If you set this value to true, Ellucian Ethos Identity can properly handle mixed case administrator user names.

    Setting this value to false can create problems when adding a service provider as described in Article 000033912 EIS - Illegal Access error attempting to create a new service provider in the Ellucian Downloads.

    For more information about the system administrator in your system, refer to Configuring the System Administrator on the WSO2 documentation website for the corresponding WSO2 version.

  3. Save the changes to the file.

Database connection pooling best practices

Specify data source configurations to support Ellucian Ethos Identity.

There are three <datasource> sections defined in the EIS_HOME/repository/conf/datasources/masterdatasources.xml file:
  • One is used for the actual IdP work of authenticating users and creating their persisted session objects.
  • One interacts with the local node’s registry settings.
  • One interacts with the shared registry settings.

Tune each of these data source configurations based on the nature of the transactions they support.

Each data source configuration has a <maxActive> setting which has a delivered default value of 50. While this value is appropriate for most installations to use for the JDBC connection pool that service the IdP authentication requests, you should reduce it in a clustered environment.

In a clustered environment, the local and shared registry connection pools rarely require more than 2 connections each. For those data source configurations, set maxActive to 2.

The data source configuration defining the connection pool that manages the user sessions should be much larger, but keep in mind that each node in the cluster will need to establish the same set of three connection pools with their own maxActive limits.

As such, even a connection pool limited at 25 connections will result in up to 29 connections (2 local registry + 2 shared registry + 25 user management) – which is then multiplied by the number of nodes in the cluster. So, with 3 nodes, this results in 87 max database connections which the backing database has to be configured to support.

Due to the possibility of long idle periods between peak loads, it is possible for databases and firewalls to interrupt or close JDBC connections in any of the connection pools. For this reason, it is important that the Ellucian Ethos Identity connection pools never exhaust all the available database connections.

It is also important that each data source configuration have the <testOnBorrow> setting enabled. When set to true, this setting will cause Ellucian Ethos Identity to test a JDBC connection before using it. As such, the <validationQuery> setting must define a valid query in the target database as a means of testing the connection.

Because performance would be harmed if every database operation were first preceded by a test query, the <validationInterval> setting should also be set to indicate how often a connection should be tested.

The delivered value of 30,000ms is usually sufficient to limit any performance overhead associated with the prudent testing of connections before they are used.

Set up Ellucian Ethos Identity in a clustered configuration

You can extend a single-node Ellucian Ethos Identity installation to a clustered configuration with multiple instances. A clustered configuration supports high availability and redundancy, and ensures failover if a node becomes unavailable.

About this task

If you want a single-instance (non-clustered) configuration, skip these clustering procedures and go to Apply configuration and start Ellucian Ethos Identity. Even if you implement a non-clustered configuration now, you can come back to these procedures later to extend it to a clustered configuration.

Note: Ensure that the relevant properties in the deployment.toml file are correctly configured for clustered deployments.

Procedure

  1. Update the configuration on Node 1, and make sure port 4000 is open for internal communication. 
    [clustering]
membership_scheme = "wka"
local_member_host = "<node2 IP>"
local_member_port = "<node2 PORT>" #4001
members = ["node1-IP:PORT", "node2-IP:PORT"]
    Note: Open the port 4000 only if the membership scheme is set to Well-Known Addresses (WKA).
  2. Update the same configuration on Node 2, and make sure port 4001 is open for internal communication. 
    [clustering]
membership_scheme = "wka"
local_member_host = "<node-1 IP>"
local_member_port = "<node-1 PORT>" #4000
members = ["node1-IP:PORT", "node2-IP:PORT"]
    Note: Open the port 4001 only if the membership scheme is set to Well-Known Addresses (WKA).

Requirements for clustering

Follow these requirements for a clustered configuration.

  • A separate machine for each Ellucian Ethos Identity node (See hardware recommendation for specifications of each node.)
  • Static IP address in a private/public subnet on each node
  • Multiple databases schemas: four in a configuration with two nodes, plus another database for each additional node, as detailed in the procedure below
  • A load balancer with sticky sessions
  • A back-end database server. You can also set up the database in a cluster to achieve fail-safe high availability. For more information about clustering the back-end database, contact the database vendor.
  • Full network connectivity between the nodes and the database
  • Failover handled by the load balancing device
  • SSL enabled on each Ellucian Ethos Identity, even behind a load balancing device with SSL.

Protecting sensitive data in configuration file

Secure plain text passwords in configuration files using the secure vault implementation that is built into WSO2 products.

Secure vault implementation allows you to store encrypted passwords that are mapped to aliases. This approach allows you to use aliases instead of the actual password in configuration files for better security.

For example: To store encrypted passwords, consider the admin user's password is admin in the user-mgt.xml file, use UserManager.AdminUser.Password as the password alias. Map the alias password to the actual admin password using secure vault. Ellucian Ethos Identity searches the alias in secure vault during runtime, decrypt it, and use its password.

For more information on the secure vault implementation in WSO2 products, refer to Carbon Secure Vault Implementation on the WSO2 documentation website for the corresponding WSO2 version.

The configuration directories of Ellucian Ethos Identity 7.0.x consist of configuration files which contain sensitive information like passwords. Ellucian Ethos Identity 7.0.x has a Cipher Tool feature installed by default and is used to encrypt passwords or other elements in configuration files.

For detail procedure, refer to Encrypting Passwords with Cipher Tool on the WSO2 documentation website for the corresponding WSO2 version.
