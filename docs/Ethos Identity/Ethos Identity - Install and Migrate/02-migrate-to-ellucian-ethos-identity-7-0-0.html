Migrate to Ellucian Ethos Identity 7.0.0

Migrate from Ellucian Ethos Identity 5.10.10 or later to Ellucian Ethos Identity 7.0.0. The migration preserves your existing settings and files.

Migrating Ellucian Ethos Identity Server from one version to another includes two steps:
  1. Ethos Identity instance migration
  2. Ethos Identity database migration

You must be on Ellucian Ethos Identity 5.10.10 or later to migrate to Ellucian Ethos Identity 7.0.0.

Related concepts
  • Install Ellucian Ethos Identity

Verify the administrator credentials

Ellucian Ethos Identity uses an administrative user during the migration process. Verify that the user has the required privileges to support the migration.

Procedure

  1. In a text editor, open the user-mgt.xml file located in the EIS_HOME/repository/conf/ directory.
  2. Locate the UserManager > Realm > Configuration > AdminUser node.
  3. Under that node, determine the credentials in the UserName and Password nodes.
  4. Use those credentials to log in to the Management Console.
    Verify that you can use these credentials to log in to the Management Console. If not, continue with step 5.
  5. Optional: In the user-mgt.xml file, change the entries in the UserName and Password nodes to contain the username and password of a user who can log in to the Management Console.
  6. Save the changes to the user-mgt.xml file.

Migrate the instance

The Ellucian Ethos Identity installer contains both WSO2 Identity Server 7.0.0 and the Ellucian Ethos Identity 7.0.0 extensions.

About this task

As Ellucian Ethos Identity 5.10.x is installed in a clustered environment, perform the following steps on each node.

Procedure

  1. Stop Ellucian Ethos Identity 5.10.x.
  2. Perform the following steps before the migration:
    1. In the WSO2 Identity Server 5.10.x, ensure that the registry versioning is turned off.
      1. Open the registry.xml file in the wso2is-5.10.0/repository/conf directory.
      2. Ensure that the versioningProperties, versioningComments, versioningTags, and versioningRatings are set to false.
    2. Update the grant access to all the schemas as follows:

      REGISTRY_DB 

      grant create session,create sequence, create table, create trigger,connect,dba, imp_full_database to REGISTRY_DB;

      IDENTITY_DB

      grant create session,create sequence, create table, create trigger,connect,dba, imp_full_database to IDENTITY_DB;

      REGISTRY_LOCAL1 

      grant create session,create sequence, create table, create trigger,connect,dba, imp_full_database to REGISTRY_LOCAL1;
  3. Download the Ellucian Ethos Identity 7.0.0 installer file EllucianEthosIdentity_baseline-7.0.0.zip from the Ellucian Downloads or using SA Valet.
  4. Unzip the EllucianEthosIdentity_baseline-7.0.0.zip file.
  5. Move the unzipped contents at the same level as the existing EllucianEthosIdentity directory.
    The directory structure should look like this:
    parent_directory
	--wso2is-5.10.0
	--EllucianEthosIdentity_extensions-7.0.0
	--wso2is-7.0.0
    Note: Throughout the Ellucian Ethos Identity migration procedures, the wso2is-7.0.0 directory is referred to as EIS_HOME, consistent with the WSO2 website.
  6. Open a command prompt. (For Windows, right-click and run as administrator.)
  7. Change directories (cd) to the EllucianEthosIdentity_extensions-7.0.0 directory.
  8. Run the appropriate command for your operating system:
    • Linux/UNIX:

      cd EllucianEthosIdentity_extensions-7.0.0

      chmod u+x apache-ant/bin/ant

      export ANT_HOME=apache-ant

      apache-ant/bin/ant migrate-install

    • Windows:

      cd EllucianEthosIdentity_extensions-7.0.0

      apache-ant\bin\ant migrate-install

  9. Change directory into the wso2is-7.0.0 directory.
  10. Run the appropriate command for your operating system:
    • Linux/UNIX:

      cd ../wso2is-7.0.0

      chmod u+x apache-ant/bin/ant

      apache-ant/bin/ant config-all-xml -buildfile config/build.xml

    • Windows:

      cd ../wso2is-5.10.0

      apache-ant\bin\ant config-all-xml -buildfile config\build.xml

  11. Copy/Migrate the necessary configurations from deployment.toml file of wso2is-5.10.0 to deployment.toml of wso2is-7.0.0
    1. Ensure to set the create_admin_account is to false.
    2. Copy the realm manager and other userstore and db details.
    3. Add the following property to the deployment.toml file:
      • [authorization_manager.properties]
      • GroupAndRoleSeparationEnabled = false
    4. Add the following property only in case of oracle database. For example:
      • [database.identity_db.pool_options]
      • defaultAutoCommit = false
      • [database.shared_db.pool_options]
      • defaultAutoCommit = false

Migrate the database

Migrate the Ellucian Ethos Identity 5.10.10 or later to database for use with Ellucian Ethos Identity 7.0.0.

About this task

As Ellucian Ethos Identity 5.10.10 or later is installed in a clustered environment, you need to perform the following steps on only one node:

Procedure

  1. Create a backup copy of the existing Ellucian Ethos Identity 5.10.10 or later database.
    Note: If you are using Microsoft SQL Server as the back-end database, ensure that the JTDS driver is updated to version 1.2.7.
  2. Open a command prompt. (For Windows, right-click and run as administrator.)
  3. Change directories (cd) to the wso2is-7.0.0 directory
  4. Migrate the database.
    • Linux/UNIX:

      chmod u+x bin/wso2server.sh

      bin/wso2server.sh -Dmigrate -Dcomponent=identity

    • Windows:

      bin\wso2server.bat -Dmigrate -Dcomponent=identity

      Note: Do not access the console during and after the database migration.
  5. Exit the foreground process by pressing CTRL+C.
  6. After the successful database migration, perform the following steps:
    1. remove 11c) property from migrate instance step in deployment.toml file
    2. set create_admin_account as true
  7. Start Ellucian Ethos Identity 7.0.0 as you normally start Ellucian Ethos Identity 5.10.x.
  8. Verify that WSO2 Identity Server completes startup successfully and the Management Console is available in a web browser: https://<hostname>:port/console
  9. Log in to Identity Server Console and navigate to Branding > Styles & Text > Design.
  10. Under Login Layout, select Custom for your login screens.
  11. Click Save & Publish.

Configure Office 365 service provider after migration

If you are using Office 365, perform the following steps to configure your Office 365 service provider after the migration is complete.

Procedure

  1. Log in to the Console.
  2. Click Connections tab.
  3. Click New Connection.
  4. On the Create a New Connection, click Custom Connector and then click Crete.
  5. On the Custom Connector dialog box, enter the following details as required:
    Field Description
    Name* Enter a name for the connection.
    Description Enter a description of the connection.
    Note: * indicates a required field.
  6. Click Finish.
  7. On the created custom connector, click Settings > New Authenticator > Office 365 > Next.
  8. On the Add New Authenticator, enter the following details as required:
    Field Description
    Client Id* Enter Office365 client identifier value.
    Client Secret Enter Office365 client secret value.
    Callback Url Enter value corresponding to callback url.
    Additional Query Parameters Additional parameters that will be sent in the authorization request.

    Example: login_hint=email@example.com
    Note: * indicates a required field.
  9. Click Finish.
