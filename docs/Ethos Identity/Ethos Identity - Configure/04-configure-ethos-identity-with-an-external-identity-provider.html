Configure Ethos Identity with an external identity provider

If your institution has an existing identity provider (IDP), you can implement Ellucian Ethos Identity to incorporate service providers that require non-standard protocols.

For example, you can implement Ellucian Ethos Identity to support CAS-based service providers with identity providers that natively support SAML 2.0 or WS-Federation. In this type of configuration, Ellucian Ethos Identity acts as a service provider (relying party) to an external identity provider — external with respect to itself — delegating authentication to the central IdP.

Note: WSO2 Identity Server handles local and federated authenticators differently. To avoid losing a session between these authenticators, the service provider configuration should consistently use local authentication (default) or federated authentication.
Communication between the application and an external identity provider works as follows:
  1. The browser (end user) attempts to access the application.
  2. The application redirects the user to Ellucian Ethos Identity for authentication.
  3. Ellucian Ethos Identity redirects the user to an external identity provider because Ellucian Ethos Identity is configured to use an external identity provider as the relying party for the application.
  4. After the user authenticates to an external identity provider, an external identity provider sends the SAML response back to Ellucian Ethos Identity.
  5. Ellucian Ethos Identity, in turn, generates its own SAML response which it sends back to the application.
Note that the application isn't aware of an external identity provider; it knows only about Ellucian Ethos Identity.
You can configure Ellucian Ethos Identity with any of the following as external identity provider:
  • Active Directory Federation Services (AD FS)
  • Shibboleth
  • Microsoft Azure Active Directory (AD)
  • Google IDP

Configure Ellucian Ethos Identity with AD FS as an external identity provider

These instructions are for AD FS 3.0 and assume that the required identity attributes are available in the primary user store.

If identity attributes exist in a separate directory, you need to add that directory as a secondary attribute store and create a custom claim to map the attribute. See Attribute stores and Configure claim mapping.

Configure AD FS as an external identity provider

Follow these steps to configure AD FS as an external identity provider.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Add.
  4. Enter a unique name for both Identity Provider Name and Display Name.
  5. In the Identity Provider Public Certificate field, click Browse to upload your AD FS Token Signing Certificate.
  6. In the Alias field, enter the relying party identifier by which Ellucian Ethos Identity will be known in AD FS.
    Example: https://eis.school.edu/samlsso
  7. Expand Federated Authenticators > SAML2 Web SSO Configuration.
  8. Select the Enable SAML2 Web SSO check box.
  9. In the Service Provider Entity ID field, enter your Ellucian Ethos Identity Server samlsso URL.

    Example: https://eis.school.edu/commonauth

  10. Verify the NameID format used in the SAML request.

    Example: urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified

  11. In the Identity Provider Entity ID field, enter the URL for your AD FS server Federation Server Identifier.
    You can find the Identifier in AD FS Management Console, right-click AD FS, Edit Federation Service Properties > Federation Server Identifier
    Example: https://adfs_server_URL/adfs/services/trust
  12. In the SSO URL field, enter your AD FS server URL.
    Example: https://adfs_server_URL/adfs/ls
  13. Select the Enable Assertion Signing check box.
  14. Select the Enable Logout check box.
  15. In the Logout URL field, enter your AD FS logout URL.
    Example: https://adfs_server_URL/adfs/ls
  16. Select the Enable Logout Request Signing check box.
  17. Click Register to save the configuration.

Configure Ellucian Ethos Identity as relying party for AD FS

Follow these steps to configure Ellucian Ethos Identity as the relying party for AD FS.

Procedure

  1. On your AD FS server, open AD FS Management.
  2. In the left pane, expand Trust Relationships.
  3. Right-click Relying Party Trusts and then click Add Relying Party Trust.
  4. In the Add Relying Party Trust wizard, click Start.
  5. On the Select Data Source page, select Enter data about the relying party manually and then click Next.
  6. On the Specify Display Name page, enter a display name for the relying party and then click Next.
    Example name: Ethos Identity
  7. On the Choose Profile page, select AD FS profile and then click Next.
  8. On the Configure Certificate page, accept the defaults and click Next.
  9. On the Configure URL page, do the following
    1. Select the Enable support for the SAML 2.0 WebSSO Protocol check box.
    2. In the Relying Party SAML 2.0 SSO service URL field, enter the URL for your Ellucian Ethos Identity COMMONAUTH endpoint.
      Example: https://eis.school.edu/commonauth
    3. Click Next.
  10. On the Configure Identifiers page, do the following
    1. In the Relying Party Trust Identifier field, enter the same value that you entered for Alias in Step 6 in the procedure for Configure AD FS as an external identity provider.
      Example: https://eis.school.edu/samlsso
    2. Click Add.
    3. Click Next.
  11. Complete the wizard, accepting the defaults in the remaining pages. On the Finish page, accept the option to Open the Edit Claim Rules dialog for this relying party trust when the wizard closes and click Close.
  12. Add a claim rule for samAccountName as follows:
    1. In the Edit Claim Rules dialog box, click Add Rule.
    2. On the Select Rule Template page, select Send LDAP Attributes as claims and then click Next.
    3. On the Configure Rule page, enter the values in the table below and then click Finish.
    Field Entry
    Claim rule name Enter a name for the claim rule.

    Example: samAccountName to NameID
    Attribute store Select your attribute store.

    Example: Active Directory
    LDAP Attribute column Select SAM-Account-Name.
    Outgoing Claim Type column Select Name ID.
  13. Add claim rules for the service provider claims expected by each of the service providers that you have configured for Ellucian Ethos Identity.
    Repeat the steps below to map each claim that is expected by one of your service providers.
    1. Determine the service provider claim required for the service provider:
      1. In a browser, log in to the Management Console.
      2. Click the Main tab.
      3. Go to Service Providers > List.
      4. In the row for the service provider, click Edit.
      5. Expand Claim Configuration.
      6. In the Identity Provider Claim URIs section, copy the value in the Service Provider Claim column.
    2. Back in AD FS Management, in the Edit Claim Rules dialog box, click Add Rule.
    3. On the Select Rule Template page, select Send LDAP Attributes as claims and then click Next.
    4. On the Configure Rule page, enter the values in the table below and then click Finish.
      The examples in the table are for a Banner service provider.
    Field Entry
    Claim rule name Enter a name for the claim rule.

    Example: UDCID for Banner
    Attribute store Select your attribute store.

    Example: Active Directory
    LDAP Attribute column Select the LDAP attribute that contains the value that maps to the service provider claim.

    Example: EmailAddresses
    Outgoing Claim Type column Paste the service provider claim value that you copied in Step 13.a.
  14. Back in the Edit Claim Rules dialog box, click OK.
  15. Right-click the new relying party that you created and choose Properties.
  16. In the Properties dialog box, select the Endpoints tab.
  17. Click Add SAML.
  18. In the Add an Endpoint dialog box, do the following:
    1. Enter the following values:
    Field Entry
    Endpoint Type Select SAML Logout.
    Binding Select POST.
    Trusted URL Enter your AD FS server URL.

    Example: https://adfs_server_URL/adfs/ls
    Response URL Enter your Ellucian Ethos Identity commonauth URL.

    Example: https://eis.school.edu/commonauth
    1. Click OK.
    2. Back in the Properties dialog box, click OK.
  19. Right-click the new relying party that you created and choose Properties.
  20. In the Properties dialog box, select the Signature tab and then click Add.
  21. Select and Import your Ethos Identity Signing Certificate.
  22. Click Apply.
  23. Click OK.

Procedure

  5. Expand Local & Outbound Authentication Configuration.

Add ADFS server in whitelist on Ellucian Ethos Identity

When you add ADFS server to the Ellucian Ethos Identity whitelist, it allows communication between Ellucian Ethos Identity and ADFS server.

Procedure

  1. Open a command prompt. (For Windows, right-click and run as administrator.)
  2. Change directories (cd) to the EIS_HOME directory.
  3. Run the appropriate command for your operating system:
    • Linux/UNIX:

      export ANT_HOME=apache-ant/
      apache-ant/bin/ant add-url-to-whitelist -
      Durl=https://<hostname> -buildfile config/build.xml
      where <hostname> is your external identity provider hostname.
      Example: adfs.school.edu

    • Windows:

      apache-ant\bin\ant add-url-to-whitelist -
      Durl=https://<hostname> -buildfile config\build.xml
      where <hostname> is your external identity provider hostname.
      Example: adfs.school.edu

  4. Change directories (cd) to the EIS_HOME/bin directory.
  5. Stop and restart Ellucian Ethos Identity, using the appropriate commands for your operating system:
    • Linux/UNIX:

      sh wso2server.sh stop

      sh wso2server.sh start

    • Windows:

      wso2server.bat stop

      wso2server.bat start

    Changes to the whitelist take effect only after you restart Ellucian Ethos Identity server.

Configure Ellucian Ethos Identity with Shibboleth as an external identity provider

These configuration instructions are for Shibboleth 2.4.4 and assume that the required identity attributes are available in the primary user store.

If identity attributes exist in a separate directory, you need to add that directory as a secondary attribute store and create a custom claim to map the attribute. See Attribute stores and Configure claim mapping.

Configure Shibboleth as an external identity provider

Use the following steps to set up Shibboleth as an identity provider in Ellucian Ethos Identity.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Add.
  4. Enter a unique name for both Identity Provider Name and Display Name.
  5. Click Browse to upload your Shibboleth IdP certificate. The usual file path and certificate name is $IDP_HOME/credentials/idp.crt.
  6. Expand Federated Authenticators > SAML2 Web SSO Configuration.
  7. Select the Enable SAML2 Web SSO check box.
  8. In the Service Provider Entity ID field, enter a unique name to identify your Ellucian Ethos Identity server on Shibboleth.
    Example: https://eis.school.edu/samlsso.
  9. Verify the NameID format used in the SAML request.

    Example: urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified

  10. In the Identity Provider Entity ID field, enter the URL for your Shibboleth server entityID.
    You can find it by looking in the Shibboleth IdP metadata file located in the $IDP_HOME/metadata directory.
  11. In the SSO URL field, enter your Shibboleth server SSO URL.
    Example: https://shibboleth.school.edu/idp/profile/SAML2/Redirect/SSO.
  12. Select the Enable Authentication Request Signing check box.
  13. Select the Enable Assertion Signing check box.
  14. Select the Enable Logout check box.
  15. In the Logout URL field, enter your Shibboleth logout URL.
    Example: https://shibboleth.school.edu/idp/profile/SAML2/Redirect/SLO
  16. Select the Enable Logout Request Signing check box.
  17. Click Register to save the configuration.

Configure Ellucian Ethos Identity as relying party for Shibboleth

Use these steps to configure Ellucian Ethos Identity as relying party for Shibboleth.

Procedure

  1. On the Shibboleth server, create a metadata file for your Ellucian Ethos Identity server.
    For an example metadata file, see Article 000039536, Sample Shibboleth Relying Party metadata XML, in the Ellucian Customer Center.
  2. Open the new metadata file in a text editor, and modify it as follows:
    1. Change both the ID and entityID to match the Service Provider Entity ID that you specified in Configure Shibboleth as an external identity provider.
    2. Export your Ellucian Ethos Identity signing certificate and open it in a text editor.
    3. Copy the certificate’s x509 value, paste it in the metadata file, and replace the existing x509 value in the metadata file.
    4. Change the values of all Location attributes within the metadata file to match your Ellucian Ethos Identity commonauth URL.

      Example: https://eis.school.edu/ commonauth

      The Location attribute is in the <SingleLogoutService> elements (two places) and the <AssertionConsumerService> element.
  3. Open the Shibboleth relying-party.xml file and reference your Ellucian Ethos Identity metadata file as shown in the following sample. Make sure that the metadata is added within the Metadata Configuration section in the relying-party.xml file. 
    ***********
<metadata:MetadataProvider id="eisMD"
    xsi:type="FilesystemMetadataProvider"
    xmlns="urn:mace:shibboleth:2.0:metadata"
    metadataFile="C:\Program Files
    (x86)\Internet2\Shib2IdP\metadata\eis_metadata.xml"
    maintainExpiredMetadata="true"/>
***********
  4. Add Shibboleth as a relying party within the relying-party.xml file as shown in the following sample.

    Change the id attribute to match the Service Provider Entity ID that you specified in Configure Shibboleth as an external identity provider.

    ***********
<rp:RelyingParty id="eis"
provider="https://shibboleth.school.edu/idp/shibboleth"
defaultSigningCredentialRef="IdPCredential">
<rp:ProfileConfiguration xsi:type="saml:SAML2SSOProfile"
    encryptAssertions="never" encryptNameIds="never" />
<rp:ProfileConfiguration
    xsi:type="saml:SAML2LogoutRequestProfile"
    signResponses="always"/>
</rp:RelyingParty>
***********
  5. Edit the Shibboleth attribute-filter.xml file. Under the Attribute Filter Policy section add a new policy for principal as shown in the following sample: 
    ***********
<afp:AttributeRule attributeID="principal">
<afp:PermitValueRule xsi:type="basic:ANY"/>
</afp:AttributeRule>
***********
  6. Edit the Shibboleth attribute-resolver.xml file. Under the Core Schema Attributes section, add a new resolver as shown in the following samples:
    Banner example - substitute your values for the examples in square brackets []:
    ***********
<!-- Ex: Attribute definition for cn which holds the UDCID-->
<resolver:AttributeDefinition xsi:type="ad:Simple" id=["commonName"] sourceAttributeID=["cn"]>
   <resolver:Dependency ref="[myLDAP]" />
   <resolver:AttributeEncoder xsi:type="enc:SAML1String" name="urn:mace:dir:attribute-def:[cn]" />
   <resolver:AttributeEncoder xsi:type="enc:SAML2String" name="urn:oid:2.5.4.3" friendlyName="UDC_IDENTIFIER" />
</resolver:AttributeDefinition>
***********

    Colleague example - substitute your values for the examples in square brackets []:

    ***********
<!-- Ex: Attribute definition for cn which holds the colleague_id-->
<resolver:AttributeDefinition xsi:type="ad:Simple" id=["commonName"] sourceAttributeID=["cn"]>
   <resolver:Dependency ref="[myLDAP]" />
   <resolver:AttributeEncoder xsi:type="enc:SAML1String" name="urn:mace:dir:attribute-def:[cn]" />
   <resolver:AttributeEncoder xsi:type="enc:SAML2String" name="urn:oid:2.5.4.3" friendlyName="COLLEAGUE_ID" />
</resolver:AttributeDefinition>
***********
  7. Restart Shibboleth for the changes to take effect.

Configure Ellucian Ethos Identity as an enterprise application for Microsoft Azure AD

You can use the following steps to set up Ellucian Ethos Identity as an enterprise application for Microsoft Azure AD.

Procedure

  1. Navigate to https://portal.office.com and log in to Azure AD.
  2. Enter your administrator credentials.
  3. Click Admin Centers.
  4. Click Azure Active Directory.
  5. Under All Services, click Enterprise Applications.
  6. Under All Applications, click New Application.
  7. Under Add an application, click Non-gallery application.
  8. Under Name, enter a descriptive name for Ellucian Ethos Identity Server.

    Example: Ethos Identity

  9. Click Add.
  10. On the newly created Enterprise Application, click Single sign-on.
  11. Under Single sign-on mode, select SAML-based Sign-on.
  12. Under Identifier Entity ID, enter the Ellucian Ethos Identity identifier as specified in step 6 of Configure Microsoft Azure AD as an external identity provider.
  13. Under Reply URL, enter the commonauth endpoint of your Ellucian Ethos Identity URL.

    Example: https://eis.school.edu/commonauth

  14. In the list of options, select Show advanced URL settings.
  15. Under Sign on URL, enter the samlsso endpoint of your Ellucian Ethos Identity URL.

    Example: https://eis.school.edu/samlsso

  16. Under User Attributes, enter all required attributes which need to send to Ellucian Ethos Identity.
  17. Under Download, click Metadata XML file.
  18. On the left navigation pane, click Azure Active Directory.
  19. Under Manage, click App Registration.
  20. Open the newly created application.
  21. Click Settings.
  22. Click Properties.
  23. Under Logout URL, enter the samlsso endpoint of your Ellucian Ethos Identity URL.

    Example: https://eis.school.edu/samlsso

  24. Click Save.
  25. Use the downloaded Metadata XML file in step 12 of Configure Microsoft Azure AD as an external identity provider.
  26. Click Save.

Configure Microsoft Azure AD as an external identity provider

You can use the following steps to set up Microsoft Azure AD as an external identity provider in Ellucian Ethos Identity.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Add.
  4. Enter a unique name for both Identity Provider Name and Display Name.
  5. In the Identity Provider Public Certificate field, click Browse to upload your Azure AD signing certificate.
  6. In the Alias field, enter the relying party identifier by which Ellucian Ethos Identity will be known in Azure AD.
    You can get this value from the Azure Active Directory Management console.

    Example: https://sts.windows.net/48680a22-7321-4928-adfc-e4475d338dd3/

  7. Expand Federated Authenticators > SAML2 Web SSO Configuration.
  8. Select the Enable SAML2 Web SSO check box.
  9. In the Service Provider Entity ID field, enter the identifier for your Azure AD.

    Example: https://sts.windows.net/48680a22-7321-4928-adfc-e4475d338dd3/

  10. Verify the NameID format used in the SAML request.

    Example: urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified

  11. In the list of Select Mode options, select Metadata File Configuration.
  12. On Upload ID Provider From Metadata File, click Choose File, and upload the Azure Active Directory metadata XML file. This file can download from the Azure Active Directory Management console.
  13. Click Register to create an Azure AD IDP.
  14. In the list of Registered Identity Providers, click Edit for the AzureADIdp and expand Federated Authenticators > SAML2 Web SSO Configuration.
  15. Select the Enable Logout check box.
  16. Enter https://login.microsoftonline.com/common/wsfederation?wa=wsignout1.0 as the Logout Url.
  17. Click Register to save the configuration.
  18. Click Update.

Configure Ellucian Ethos Identity with Google as an external identity provider

The configuration instructions are for Google Suite Identity Provider and assume that the required identity attributes are available in the Google G Suite Directory.

These instructions assume you have an active subscription to Google G Suite which is different from Google account.

This allows a user to use their managed Google account credentials to sign in to enterprise cloud applications through Single Sign-On (SSO).

If identity attributes exist in a separate directory, you need to add that directory as a secondary attribute store and create a custom claim to map the attribute. See Attribute stores and Configure claim mapping.

Configure Ellucian Ethos Identity as a SAML application for Google identity provider

Follow these steps to configure Ellucian Ethos Identity as a SAML application for Google identity provider.

Procedure

  1. Navigate to https://admin.google.com and log in to Google Admin Console.
  2. Enter your administrator credentials.
  3. Click Apps and then click SAML Apps.
  4. Click the plus icon to enable SSO for a SAML Application.
  5. Click SETUP MY OWN CUSTOM APP to add a new SAML application.
  6. Under Option 2, click Download to download the Google Identity Provider Metadata file.
  7. Click Next.
  8. On the Basic information for your Custom App, under Application Name, enter a descriptive name for SAML application configuration. The users can see an application name and description in Google Admin under SAML Application.
    Example: Ellucian Ethos Identity
  9. Click Next.
  10. On the Service Provider Details window, enter the details as follows:
    Label Description
    ACS URL* Enter your Ellucian Ethos Identity common authentication URL.

    Example: https://eis.school.edu/commonauth
    Entity ID * Enter a value that can uniquely identify Ellucian Ethos Identity.

    Example: myEthosIdentity

    This value will be used while configuring Google as IDP in Identity Server Management console.
    Start URL Enter the samlsso endpoint of your Ellucian Ethos Identity URL.

    Example: https://eis.school.edu/samlsso
    Signed Response Do not select the Signed Response check box.

    If only the assertion is signed, do not select the Signed Response check box.

    If the entire response is signed, select the Signed Response check box.
    Name ID Keep the default value.
    Name ID Format Keep the default value.
    Note: * indicates that the mandatory field to fill.
  11. Click Next.
  12. On the Attribute Mapping, click ADD NEW MAPPING to provide mappings between service provider attributes and available user profile fields in Google Admin account.
    Note: If you do not want map attributes, skip the above step.
  13. Click Finish.
  14. Click Attribute Mapping to map all the required attributes to be sent to Ellucian Ethos Identity.

What to do next

After application is configured, click Edit Service, change Service status to ON for everyone, and then click Save. You can turn on the service for everyone or for some users as needed.

    Example: GoogleIDP
  5. Optional: The Alias field might be required to change the default value in some authentication scenarios. If required, enter the relying party identifier by which Ellucian Ethos Identity is known in Google identity provider. This value should be equal to the value you entered as the Entity ID when configuring Google.
    Example: myEthosIdentity
  6. Expand Federated Authenticators > SAML2 Web SSO Configuration.
  7. Select the Enable SAML2 Web SSO check box.
  8. In the Service Provider Entity ID field, enter the identifier for your Google identity provider. The Service Provider Entity ID value should be equal to the value you entered as the Entity ID when configuring Google.
  9. Verify the NameID format used in the SAML request.
    Example: urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified
  10. In the list of Select Mode options, select Metadata File Configuration.
  11. On Upload ID Provider From Metadata File, click Choose File, and upload the GoogleIDPMetadata XML file you downloaded earlier.
  12. Click Register to save the identity provider configurations.
  13. In the list of Registered Identity Providers, click Edit for the GoogleIdP and expand Federated Authenticators > SAML2 Web SSO Configuration.
  14. Select the Enable Logout check box.
  15. Enter https://accounts.google.com/logout as the Logout Url.
  16. Click Register to save the configuration.
  17. Click Update to save the changes.

Configure a service provider to use Google as the identity provider

Ellucian Ethos Identity allows each service provider to use a different identity provider. Use the following steps to configure a service provider to use Google as the identity provider.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Go to Service Providers > List.
  4. Click Edit next to the service provider you want to configure to use Google identity provider.
  5. Expand Local & Outbound Authentication Configuration.
  6. Select Federated Authentication.
  7. Select your Google identity provider from the drop-down menu. If you configured more than one federated identity provider, select the appropriate one.
  8. Click Update.

Add Google Server in whitelist on Ellucian Ethos Identity

When you add Google server to the Ellucian Ethos Identity whitelist, it allows communication between Ellucian Ethos Identity and Google server.

Procedure

  1. Open a command prompt. (For Windows, right-click and run as administrator.)
  2. Change directories (cd) to the EIS_HOME directory.
  3. Run the appropriate command for your operating system:
    • Linux/UNIX:

      export ANT_HOME=apache-ant/
      apache-ant/bin/ant add-url-to-whitelist -
      Durl=https://<hostname> -buildfile config/build.xml
      where <hostname> is your external identity provider hostname.
      Example: google.school.edu

    • Windows:

      apache-ant\bin\ant add-url-to-whitelist -
      Durl=https://<hostname> -buildfile config\build.xml
      where <hostname> is your external identity provider hostname.
      Example: google.school.edu

  4. Change directories (cd) to the EIS_HOME/bin directory.
  5. Stop and restart Ellucian Ethos Identity, using the appropriate commands for your operating system:
    • Linux/UNIX:

      sh wso2server.sh stop

      sh wso2server.sh start

    • Windows:

      wso2server.bat stop

      wso2server.bat start

    Changes to the whitelist take effect only after you restart Ellucian Ethos Identity server.
