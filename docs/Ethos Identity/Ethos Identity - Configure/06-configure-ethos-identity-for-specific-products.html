Configure Ethos Identity for specific products

Configure Ellucian Ethos Identity to work with other Ellucian products and third-party products.

Ellucian CRM Products

Configure Ellucian Ethos Identity with Ellucian CRM products which support claims.

The Ellucian CRM products (Ellucian CRM Recruit, Ellucian CRM Advise, and Ellucian CRM Advance) support claims based on a set of WS-* standards.

The SAML token is either:

  • Passive mode (WS-Federation), for Ellucian CRM web-based applications
  • Active mode (WS-Trust), for SDK Connections, Outlook Client, toolkit/installer, web front ends

Define the required claims

Integration of Ellucian CRM products with Ellucian Ethos Identity requires claims for logon name and UPN.

Procedure

  1. In the Management Console, click the Main tab.
  2. Create a claim for logon name:
    1. Under Claims, click Add.
    2. On the Add New Dialect/Claim page, click Add Local Claim.
    3. On the Add Local Claim page, enter values for the logon name claim as shown in the table below, and then click Add.
    Field Entry
    Claim URI Enter http://wso2.org/claims/logonname
    Display Name Example: Logon name
    Description Example: Logon name
    Mapped Attribute Enter sAMAccountName
  3. Create a claim for UPN:
    1. Under Claims, click Add.
    2. On the Add New Dialect/Claim page, click Add Local Claim.
    3. On the Add Local Claim page, enter values for the UPN claim as shown in the table below, and then click Add.
    Field Entry
    Claim URI Enter http://wso2.org/claims/UPN
    Display Name Example: UPN
    Description Example: User principal name
    Mapped Attribute Enter userPrincipalName

Create the service providers

CRM products require two service providers for integration with Ellucian Ethos Identity: one for Ellucian CRM web-based applications and one for other Ellucian CRM connections.

Procedure

  1. Log in to the Management Console.
    Log in as a user who has access to all service providers. You can either always use the same login to maintain service providers, or give multiple users access to each service provider using the procedure in Make a service provider visible to additional administrators.
  2. Click the Main tab.
  3. Go to Service Providers > Add.
    First, you will create the service provider for non-web-based Ellucian CRM connections.
  4. On the Add New Service Provider page, in the Service Provider Name field, enter a name for the service provider.
    Example: CRM Dynamics Svc
  5. Click Register.
  6. On the Service Providers page, expand Claim Configuration.
  7. Select Define Custom Claim Dialect
  8. Add a claim URI for UPN:
    1. Click Add Claim URI.
    2. In the Service Provider Claim column, enter http://schemas.xmlsoap.org/ws/2005/05/identity/claims/upn
    3. In the Local Claim column, select the UPN claim that you created earlier.
    4. Select the Requested Claim check box.
  9. Add a claim URI for logon name:
    1. Click Add Claim URI.
    2. In the Service Provider Claim column, enter http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name
    3. In the Local Claim column, select the logon name claim that you created earlier.
    4. Select the Requested Claim check box.
  10. In the Subject Claim URI field, select the UPN claim that you created earlier.
  11. Expand Inbound Authentication Configuration > WS-Federation (Passive) Configuration.
  12. In the Passive STS Realm field, enter <your_CRM_URL>/XRMServices/2011/Organization.svc
    Example: crm.myschool.edu:443/XRMServices/2011/Organization.svc
  13. In the Passive STS WReply URL field, enter the same value that you entered in the Passive STS Realm field.
  14. Expand Inbound Authentication Configuration > WS-Trust Security Token Service Configuration.
  15. Click Configure.
  16. On the STS Configuration page, in the Endpoint Address field, enter the same value that you entered in the Passive STS Realm field.
    Example: crm.myschool.edu:443/XRMServices/2011/Organization.svc
  17. In the Certificate Alias drop down, select a certificate that CRM trusts.
  18. Click Apply.
  19. Back on the Service Providers page, click Update to create the service provider.
  20. Go to Service Providers > Add.
    Next, you will create the service provider for web-based Ellucian CRM applications.
  21. On the Add New Service Provider page, in the Service Provider Name field, enter a name for the service provider.
    Example: CRM Dynamics Web
  22. Click Register.
  23. On the Service Providers page, expand Claim Configuration.
  24. Select Define Custom Claim Dialect
  25. Add a claim URI for UPN:
    These claim definitions are identical to those for the service provider that you created earlier.
    1. Click Add Claim URI.
    2. In the Service Provider Claim column, enter http://schemas.xmlsoap.org/ws/2005/05/identity/claims/upn
    3. In the Local Claim column, select the UPN claim that you created earlier.
    4. Select the Requested Claim check box.
  26. Add a claim URI for logon name:
    1. Click Add Claim URI.
    2. In the Service Provider Claim column, enter http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name
    3. In the Local Claim column, select the logon name claim that you created earlier.
    4. Select the Requested Claim check box.
  27. In the Subject Claim URI field, select the UPN claim that you created earlier.
  28. Expand Inbound Authentication Configuration > WS-Federation (Passive) Configuration.
  29. In the Passive STS Realm field, enter <your_CRM_URL>/
    Example: crm.myschool.edu:443/
  30. In the Passive STS WReply URL field, enter the same value that you entered in the Passive STS Realm field.
  31. Expand Inbound Authentication Configuration > WS-Trust Security Token Service Configuration.
  32. Click Configure.
  33. On the STS Configuration page, in the Endpoint Address field, enter the same value that you entered in the Passive STS Realm field.
    Example: crm.myschool.edu:443/
  34. In the Certificate Alias drop down, select a certificate that CRM trusts.
  35. Click Apply.
  36. Back on the Service Providers page, click Update to create the service provider.

Apply a security policy to allow Ellucian CRM users to authenticate using Ellucian Ethos Identity

You can apply a security policy to limit which users can authenticate to Ellucian CRM applications using Ellucian Ethos Identity.

About this task

If you previously applied a security policy for Office 365, and you selected an LDAP group (such as Internal/Everyone) that also includes your Ellucian CRM users, you can skip this procedure.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Resident.
  4. Expand Inbound Authentication Configuration > Security Token Service Configuration.
  5. Click Apply Security Policy.
  6. In the Enable Security field, select Yes.
  7. Under Basic Scenarios, select UsernameToken and then click Next.
  8. On the Activate Security page, select the LDAP groups that include the users that you want to be able to authenticate to Ellucian CRM applications.
    For example, to allow all users in your LDAP to authenticate, search for the Internal/Everyone group and select the check box for that group.
  9. Click Finish and then click Update.

Make the SAML metadata accessible to CRM applications

To authenticate with a security token service, Ellucian CRM products expect a federation metadata file that contains specific details about the service.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Resident.
  4. Expand Inbound Authentication Configuration > SAML2 Web SSO Configuration.
  5. Click Download SAML Metadata.
  6. Upload the metadata file to a web server.
    Ellucian CRM requires that the metadata be accessible as a URL. As part of Ellucian CRM setup, you will point your Ellucian CRM configuration to the URL for the metadata on the web server.

Office 365

Configure Ellucian Ethos Identity with Microsoft Office 365.

Ellucian Ethos Identity uses web-based WS-Federation Passive authentication to accomplish federation with Microsoft Office 365 web-based applications and WS-Federation Active authentication for non-web-based applications. This provides support to the web-based Office 365 applications.

Ellucian Ethos Identity also provides access to email on iPhone and Android devices by the Outlook Application (when configured to use an Office 365 account type) and native Exchange on Android and iOS in addition to Skype for business on Mobile, Skype for business on Desktop, OneDrive for business, and OneDrive desktop application.

Prerequisites

Follow these prerequisites when configuring Office 365 with Ellucian Ethos Identity.

  • A valid Office 365 domain configured to use federation.
  • The ability to connect to Office 365 through an Azure Active Directory Module for Windows PowerShell. This is a basic requirement for managing Office 365.
  • Users synced into Office 365:
    • The following configuration assumes the Immutable ID in Office 365 is set to the objectGUID in Active Directory, which is the default when using Azure Active Directory sync.
    • Ellucian Ethos Identity authentication against Active Directory, or another directory server, must reference a user name that matches the Office 365 email address. In Active Directory, this means userPrincipalName.
      Note: Changing the authentication mechanism in this way dictates the format of the username you use to log in to Ellucian Ethos Identity for users and administrators.

Modify Identity settings

The following settings are required within your deployment.toml file for Office365.

Procedure

  1. In the EIS_HOME/repository/conf directory, open the deployment.toml file.
  2. Set the value of the enable_email_domain property under the [tenant_mgt] root key as follows to use the ActiveDirectory attribute that contains the e-mail address of the Office 365 account for users instead of sAMAccountName:
    Property Description
    enable_email_domain Require e-mail address format for username

    Default value: false
    In most cases, this attribute will be userPrincipalName.
  3. Set the following property: eis.userstore.JavaNamingLdapAttributesBinary=objectGUID
  4. From the EllucianEthosIdentity/config directory, run the appropriate command for your operating system.
    Linux/UNIX: 
    ANT_HOME=../apache-ant/
export ANT_HOME
../apache-ant/bin/ant configure-user-store
    Windows:
    ..\apache-ant\bin\ant configure-user-store

Add global claim mapping

The typical Office 365 configuration relies on several attributes from Active Directory that are not automatically mapped by Ellucian Ethos Identity. The following steps will create the required claims.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Claims, click Add.
  4. Under Add New Dialect/Claim, click Add Local Claim.
  5. Enter the required data for each required claim mapping, and then click Add.
  6. Repeat step 6 and 7 for each claim listed in the following table.
    Claim Ellucian Ethos Identity URI LDAP Attribute Purpose
    User Principal http://wso2.org/​claims/​upn userPrincipalName This must be the email address of the Office 365 user. Usually this is the userPrincipalName in Active Directory.
    Immutable ID http://wso2.org/​claims/​objectguid objectGUID This is the immutable ID that is set by the Azure AD sync service out of the box. If you use a different value, this claim must be populated with that value for each user.

Add service provider claim mapping

When creating a service provider for Office 365, you must map the previously defined global claims to specific claim names.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Service Providers, click List.
  4. Click Edit for the target service provider. If the service provider does not exist, then click Add under Service Providers before proceeding.
  5. Expand the Claim Configuration panel and click Define Custom Claim Dialect.
  6. Click Add Claim URI to add a new claim mapping.
  7. In the Service Provider Claim field, enter the claim name required by the service provider.
  8. In the Local Claim field, select the internal claim that contains the required value.
  9. Select the Requested Claims check box to always send the claim.
  10. Repeat step 6 through 9 for the claims in the following table.
    Service Provider Claim Internal Claim
    http://schemas.xmlsoap.org/claims/UPN http://wso2.org/claims/upn
    http://schemas.microsoft.com/LiveID/Federation/2008/05/ImmutableID http://wso2.org/claims/objectguid
    http://schemas.microsoft.com/ws/2008/06/identity/claims/role http://wso2.org/claims/role
  11. Set the Subject Claim URI to the ImmutableID service provider claim mapped above.
  12. Set the Role Claim URI to the role service provider claim mapped above.
  13. Expand Inbound Authentication Configuration > WS-Federation (Passive) Configuration.
  14. In the Passive STS Realm field, enter the Office365 realm: urn:federation:MicrosoftOnline.
  15. In the Passive STS WReply URL field, enter the Office365 federation endpoint: https://login.microsoftonline.com/login.srf.
  16. Expand WS-Trust Security Token Service Configuration.
  17. Click Configure.
  18. In the Endpoint Address field, enter urn:federation:MicrosoftOnline.
  19. In the Certificate Alias field, select the signing certificate that will be used for Office 365 and click Apply.
  20. Click Update.

Office 365 configuration

Open an Office 365 PowerShell session and connect to Office 365. It can be easier to open a PowerShell ISE session, edit the following script and run it.

Note: The X509 Certificate referenced below is the public certificate used by Ellucian Ethos Identity to sign tokens and to secure the website.
$domain = "school.edu"

$brandname = "Ellucian University"

$issuerUri= "https://auth.school.edu"

$activeLogonUri = "https://auth.school.edu/services/wso2carbon-sts.wso2carbon-stsHttpsSoap12Endpoint"

$passiveLogonUri = "https://auth.school.edu/passivests"

$mex = "https://auth.school.edu/services/mex-ut1"

$cert = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2("C:\temp\eis_public_certificate.cer")

$certBase64 = [System.Convert]::ToBase64String($cert.Export​([System.Security.Cryptography.X509Certificates.X509ContentType]::Cert))

Set-MsolDomainAuthentication -DomainName $domain -Authentication Federated -ActiveLogOnUri $activeLogonUri -IssuerUri $issuerUri -SigningCertificate $certBase64 -LogOffUri $passiveLogonUri -FederationBrandName $brandname -MetadataExchangeUri $mex -PassiveLogOnUri $passiveLogonUri -PreferredAuthenticationProtocol WsFed

After these commands run successfully, the federated Office 365 domain will begin to use Ellucian Ethos Identity for authentication.

See Article 000034651, "How to back up Azure AD Settings," in the Ellucian Customer Center for information about a power shell script that you can use to create a backup script of any current federation settings which may be used to restore the previous settings. Alternately, use the Get-MsolDomainFederationSettings command to view the current settings before making any changes.

Outlook Web App

Outlook Web App (OWA) is Microsoft Exchange Server 2010's web-based email client. OWA 2013 can use Ellucian Ethos Identity as its claims identity provider.

Configure OWA for federation

When configuring Ellucian Ethos Identity to be used for claims-based authentication with OWA and the Exchange Admin Center (EAC) in Exchange 2013, you must enable Ellucian Ethos Identity for your Exchange organization.

Procedure

  1. On the Exchange Server, set the AD FS issuer to https://ethos.school.edu/passivests.
  2. Set the URIs to https://mail.school.edu/owa/ and https://mail.school.edu/ecp/
  3. Obtain the Ellucian Ethos Identity token signing certificate thumbprint.
    1. Open the Ellucian Ethos Identity token signing certificate thumbprint in a certificate viewer.
    2. Copy the thumbprint.
    3. Assign the token-signing certificate thumbprint that you found.
  4. Using the Exchange Management Shell, enter the following code. 
    $uris = @(" https://mail.school.edu/owa/","https://mail.school.edu/ecp/")
Set-OrganizationConfig -AdfsIssuer "https://ethos.school.edu/passivests" -AdfsAudienceUris $uris -AdfsSignCertificateThumbprint"ETHOS_SIGNING_CERTIFICATE_THUMBPRINT"
  5. Enable AD FS authentication on the OWA and ECP virtual directories.
    For the OWA and ECP virtual directories, enable Federated authentication as the only authentication method and disable all other forms of authentication.
    Note: You must configure the ECP virtual directory before you configure the OWA virtual directory.
    1. To configure the ECP virtual directory, enter the following in the Exchange Management Shell. 
      Get-EcpVirtualDirectory | Set-EcpVirtualDirectory -AdfsAuthentication $true -BasicAuthentication $false -DigestAuthentication $false -FormsAuthentication $false -WindowsAuthentication $false
    2. To configure the OWA virtual directory, enter the following in the Exchange Management Shell.
      Get-OwaVirtualDirectory | Set-OwaVirtualDirectory -AdfsAuthentication $true -BasicAuthentication $false -DigestAuthentication $false -FormsAuthentication $false -WindowsAuthentication $false -OAuthAuthentication $false
  6. Restart or recycle Internet Information Services (IIS).

Configure OWA as a service provider

Set up OWA as the service provider in the Management Console.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Service Providers, click Add.
  4. Enter a Service Provider Name and Description, and click Register.
  5. Expand the Claim Configuration section.
  6. Choose the option Define Custom Claim Dialect.
  7. Click Add Claim URI.
  8. Enter the following identity provider claim URIs.
    Service Provider Claim Local Claim
    http://schemas.ellucian.com/ws/2013/12/claims/logonname http://wso2.org/claims/logonname
    http://schemas.microsoft.com/ws/2008/06/identity/claims/role http://wso2.org/claims/role
    http://schemas.xmlsoap.org/ws/2005/05/identity/claims/upn http://wso2.org/claims/upn
  9. For each Identity Provider Claim URI, select the Requested Claim check box.
  10. Expand the Inbound Authentication Configuration section.
    1. Expand the WS-Federation (Passive) Configuration section.
    2. Set the Passive STS Realm to your institution's Outlook Web App URL.
      Example: https://mail.school.edu/owa
    3. Set the Passive STS WReply URL to your institution's Outlook Web App URL.
      Example: https://mail.school.edu/owa
  11. Expand the WS-Trust Security Token Service Configuration section.
    1. Click Configure to add a new security token service.
    2. Set the Endpoint Address to your institution's Outlook Web App URL.
      For example, https://mail.school.edu/owa
    3. Select the certificate to be used for the Outlook Web App.
    4. Click Apply.
  12. Click Update.
