Advanced configuration for Ethos Identity

Advanced configurations can enhance the experience but are not required for Ellucian Ethos Identity.

Apply your custom branding

Ellucian Ethos Identity provides several branding options for the delivered assets. You can modify the logo, accent gradient, and page title.

Note: The customization branding is applicable for Ellucian Ethos Identity version 5.3.3 and higher.

Branding guidelines

Product branding is stored in the index.css file located in the following directory on the Ellucian Ethos Identity server: EIS_HOME/repository/deployment/server/webapps/ authenticationendpoint/ellucian.

You can customize authentication page styling elements including fonts, colors, and positioning. If you customize elements, you must merge the changes into future Ellucian Ethos Identity releases when you upgrade.

Files under EIS_HOME/repository/deployment/server/webapps/authenticationendpoint and EIS_HOME/repository/deployment/server/webapps/accountrecoveryendpoint directories will typically change in future releases. If you make customizations that require HTML changes, you must manually merge your customizations with the delivered Ellucian changes.

Reconcile your customizations after an upgrade

If you customize the JSP files or other assets in the WSO2 Identity Server, you must reconcile the differences in your customizations when you upgrade the Ellucian Ethos Identity product.

Upgrading the Ellucian Ethos Identity product does not move or merge your product customizations under the authenticationendpoint or accountrecoveryendpoint application. With new releases, WSO2 Identity Server delivers modified JSP files and other assets to correct bugs and introduce enhancements. In addition, Ellucian Ethos Identity delivers styling and security customizations with the latest WSO2 changes.

If you customize the JSP files or other assets, you must reconcile the differences in your customizations. If you do not reconcile the differences, it can cause broken functionality and introduce security risks. You must manually merge any customization made to JSP files or other assets under the following application:

EIS_HOME/repository/deployment/server/webapps/accountrecoveryendpoint/

EIS_HOMErepository/deployment/server/webapps/authenticationendpoint/

Note: The product branding is valid only after enabling the Ellucian Ethos Identity customization. This document is applicable to Ellucian Ethos Identity provided branding in version 5.3.3.

Anti-clickjacking

Clickjacking is an attack that tricks a user into clicking a webpage element which is invisible or disguised as another element.

Configure anti-clickjacking for single domain

Leverage the X-Frame-Options header to indicate if a browser is allowed to render Ethos Identity as framed or embedded content.

Before you begin

Make sure that you are using Ellucian Ethos Identity 5.3.2 or higher version.

Procedure

  1. Stop the Ellucian Ethos Identity server.
  2. To configure anti-clickjacking support, edit the following property in the file EIS_HOME/config/eis_config.properties:
    Property Description
    eis.anticlickjacking.url.exception To allow anti-clickjacking support, specify the value for this property as the URL which should be a whitelist.

    Example: eis.anticlickjacking.url.exception=www.ellucian.com
  3. Save the changes to the file.
  4. Navigate to EIS_HOME.
  5. Run the appropriate commands for your operating system to apply the property change to the XML file:
    Linux/Unix: 
    export ANT_HOME=apache-ant/

apache-ant/bin/ant config-all-xml -buildfile config/build.xml
    Windows:
    apache-ant\bin\ant config-all-xml -buildfile config\build.xml
  6. Start the Ellucian Ethos Identity server.

Configure anti-clickjacking for multiple domain

Allows you to specify multiple domains which can load Ethos Identity within framed or embedded content.

About this task

Update the Content Security Policy header to control resources the user agent is allowed to load from a given page. It also allows you to specify the domain in a list, or with the use of wild cards.

Example: Content-Security-Policy: frame-ancestors *.domain1.edu *.domain1.edu:* *.domain2.edu *.domain2.edu:*

Many older browsers like Internet Explorer up until version 11 don't support to the Content Security Policy.

Note:
  • The anti-clickjacking support for multiple domains feature available from EllucianEthosIdentiy_Patch_5.10.8 or later version.
  • Ethos Identity 5.10.7 or lower requires an update to 5.10.8 to support anti-clickjacking for multiple domains.

Procedure

  1. Verify that the response header filter jar exists in the <EEID_HOME>repository/components/lib folder.
  2. Make sure to add the following properties. 
    <EEID_HOME>repository/conf/tomcat/carbon/WEB-INF/web.xml
<filter>
<filter-name>ResponseHeaderFilter</filter-name>
<filter-class>com.sample.tomcat.filter.ResponseHeaderFilter</filter-class>
<init-param>
<param-name>Content-Security-Policy</param-name>
<param-value>frame-ancestors *.elluciancloud.com *.elluciancloud.com:* *.ellucian.com *.ellucian.com:* </param-value>
</init-param>
</filter>
<filter-mapping>
<filter-name>ResponseHeaderFilter</filter-name>
<url-pattern>/*</url-pattern>
</filter-mapping>
  3. Verify that the following properties were added to the <EEID_HOME>repository/conf/tomcat/web.xml 
    <filter>
<filter-name>CustomHeaderFilter</filter-name>
<filter-class>org.wso2.carbon.identity.custom.header.filter.CustomHeaderFilter</filter-class>
</filter>
<filter-mapping>
<filter-name>CustomHeaderFilter</filter-name>
<url-pattern>/*</url-pattern>
<dispatcher>REQUEST</dispatcher>
<dispatcher>FORWARD</dispatcher>
</filter-mapping>

  5. Enable the configuration management REST API and execute the step 1 from the topic Using the Configuration Management REST APIs on the WSO2 documentation website for the corresponding WSO2 version.

Publish an XACML policy to access Ellucian Ethos Identity by user store

To access Ellucian Ethos Identity by user store, you need to publish the XACML policy to Policy Decision Point (PDP).

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Expand Service Providers > List > Edit > Local & Outbound Authentication Configuration.
  4. Select the Enable Authorization check box to enable authorization and click Update.
  5. Locate the Home > Entitlement > PAP > Policy Administration, select the intended PolicyId from the Available Entitlement Policies list.
    Note: If you want to add new entitlement policy, click Add New Entitlement Policy, and click Write Policy in XML.
  6. Modify PolicyId, SP_NAME, USERSTORE_1, and USERSTORE_2 as required from the policy content and click Save Policy. 
    <Policy xmlns="urn:oasis:names:tc:xacml:3.0:core:schema:wd-17" 
PolicyId="authn_user_store_based_policy_template" RuleCombiningAlgId="urn:oasis:names:tc:xacml:1.0:rule-combining-algorithm:first-applicable" Version="1.0">
<Description>This template policy provides ability to authorize users to a given service provider(defined by SP_NAME) in the authentication flow based on the user store (USERSTORE_1 or USERSTORE_2). Users who are in the given userstores will be allowed and any other users will be denied.</Description>
<Target>
<AnyOf>
<AllOf>
<Match MatchId="urn:oasis:names:tc:xacml:1.0:function:string-equal">
<AttributeValue DataType="http://www.w3.org/2001/XMLSchema#string">authenticate</AttributeValue>
<AttributeDesignator AttributeId="http://wso2.org/identity/identity-action/action-name" Category="http://wso2.org/identity/identity-action" DataType="http://www.w3.org/2001/XMLSchema#string" MustBePresent="false"/>
</Match>
<Match MatchId="urn:oasis:names:tc:xacml:1.0:function:string-equal">
<AttributeValue DataType="http://www.w3.org/2001/XMLSchema#string">SP_NAME</AttributeValue>
<AttributeDesignator AttributeId="http://wso2.org/identity/sp/sp-name" Category="http://wso2.org/identity/sp" DataType="http://www.w3.org/2001/XMLSchema#string" MustBePresent="false"/>
</Match>
</AllOf>
</AnyOf>
</Target>
<Rule Effect="Permit" RuleId="permit_by_userstores">
<Condition>
<Apply FunctionId="urn:oasis:names:tc:xacml:1.0:function:or">
<Apply FunctionId="urn:oasis:names:tc:xacml:1.0:function:string-equal">
<Apply FunctionId="urn:oasis:names:tc:xacml:1.0:function:string-one-and-only">
<AttributeDesignator AttributeId="http://wso2.org/identity/user/user-store-domain" Category="http://wso2.org/identity/user" DataType="http://www.w3.org/2001/XMLSchema#string" MustBePresent="true"/>
</Apply>
<AttributeValue DataType="http://www.w3.org/2001/XMLSchema#string">USERSTORE_1</AttributeValue>
</Apply>
<Apply FunctionId="urn:oasis:names:tc:xacml:1.0:function:string-equal">
<Apply FunctionId="urn:oasis:names:tc:xacml:1.0:function:string-one-and-only">
<AttributeDesignator AttributeId="http://wso2.org/identity/user/user-store-domain" Category="http://wso2.org/identity/user" DataType="http://www.w3.org/2001/XMLSchema#string" MustBePresent="true"/>
</Apply>
<AttributeValue DataType="http://www.w3.org/2001/XMLSchema#string">USERSTORE_2</AttributeValue>
</Apply>
</Apply>
</Condition>
</Rule>
<Rule Effect="Deny" RuleId="deny_others"/>
</Policy>
  7. Click Publish To My PDP for the intended policy.
  8. On the Publish Policy pane, click Publish.
    For more information on this flow, refer to Publishing a XACML Policy on the WSO2 documentation website for the corresponding WSO2 version.

Copy service provider configuration through export and import

You can export or import a service provider configuration as an XML configuration file.

If you intend to create a service provider with the same configuration in different instances of Ellucian Ethos Identity perform the following steps:
  1. Create and configure the service provider in instance A.
  2. Export service provider as an XML file.
  3. Import the XML file in instance B to create the service provider with the same configuration as an instance A.
  4. Repeat steps 3 for all other instances to copy the same service provider configuration.
Note: You can take a backup of a service provider configuration using export option.

Export a service provider

You can export a service provider configuration as an XML file.

Procedure

  1. Log in to the Management Console of Ethos Identity Server instance, from where you want to export the service provider configuration.
  2. Click the Main tab.
  3. Go to Service Providers > List to see the list of service providers.
    Note: If you do not see the intended service provider to export, see Add a service provider topic to add and configure a new service provider.
  4. Go to Actions > Export for the intended service provider configuration to be exported.
  5. In the WSO2 Carbon confirmation dialog box, clear the Include Secrets check box if you do not want to include secrets when exporting.
  6. Click OK to export service provider configuration as an XML file.

Results

You have successfully exported the service provider in Service_provider_Name.xml format.

Import a service provider

If requires, you can make the configuration changes in the exported Service_provider_Name.xml and import the service provider.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Service Providers, click Add.
  4. Under Select Mode, select File Configuration.
  5. Under Upload Service Provider File, click Choose File, select the Service_provider_Name.xml file, and then click Import.
  6. Make the changes in the service provider configurations if requires and click Update.

Results

You have successfully imported the service provider and it is available under Service Providers list.

Adaptive authentication

Adaptive authentication is a method for selecting the right authentication factors depending on a user’s risk profile, tendencies, or sensitivity of a resource - by adapting the authentication to the situation.

It dynamically employs multi-factor authentication to adjust the authentication requirements for access to a given resource.

Configure IP-based adaptive authentication

IP-based adaptive authentication allows for the requirement of an additional level of authentication for users logging in from external networks or other geographic locations. Using the IP-based adaptive authentication template, you can specify network ranges using the IP address.

Procedure

  1. Log in to the Ellucian Ethos Identity management console as the admin user.
  2. On the left navigation pane, click Main.
  3. In the Service Providers tab, click List.
  4. Edit the service provider.
  5. Expand the Local & Outbound Authentication Configuration.
  6. In the list of Authentication Type options, select Advanced Configuration.
  7. Under Authentication Step Configuration, click Add Authentication Step to add an authentication step.
    It adds Step 1 under Authentication Step Configuration.
  8. Under Step 1, select the check boxes Use subject identifier from this step and Use attributes from this step.
  9. Under step 1 added in the step 6, in the list of Local Authenticators options, select basic authentication type, and click Add Authenticator.
  10. Click Add Authentication Step to add a second authentication step.
    It adds Step 2 under Authentication Step Configuration.
  11. Under Step 2 added in the previous step, in the list of Local Authenticators options, select MFA (that is Duo, fido/u2f, SMS OTP, Email OTP, etc.) authentication type, and click Add Authenticator.
  12. Under Script Based Adaptive Authentication section, add an authentication script.
  13. Use the following script or write a new authentication script which meets your requirements. 
    // Configure the network ranges here
     	var corpNetwork = ['192.168.1.0/24', '10.100.0.0/16'];
	var onLoginRequest = function(context) {
	         executeStep(1, {
			onSuccess: function (context) {
				var user = context.currentKnownSubject;
				// Extracting the origin IP of the request
				var loginIp = context.request.ip;
				Log.info('User: ' + user.username + ' logged in from IP: ' + loginIp);
				// Checking if the IP is within the allowed range
				if (!isCorporateIP(loginIp, corpNetwork)){  
					executeStep(2);
				}
			}
		});
	};
// Function to convert ip address string to long value function
  14. Click Update.
Test IP-based authentication script

You can test the sample authentication script.

Procedure

  1. Access the service provider URL with the user who logs in from an IP address that is excluded within the network range configured in the script.
  2. Click Login and note that it prompts for MFA (two-factor authentication).
  3. Sign in with your credentials and you are successfully logged into the application.
  4. Log out the application.
  5. Log in to service provider URL with user whose IP address is in the network range configured in the script.
    Note: You are successfully logged in to the application after going through the basic authentication step.

Configure Role-based adaptive authentication

Role-based adaptive authentication allows for the requirement of an additional level of authentication for users from the specified roles.

Procedure

  1. Log in to the Ellucian Ethos Identity management console as the admin user.
  2. On the left navigation pane, click Main.
  3. In the Service Providers tab, click List.
  4. Edit the service provider.
  5. Expand the Local & Outbound Authentication Configuration.
  6. In the list of Authentication Type options, select Advanced Configuration.
  7. Under Authentication Step Configuration, click Add Authentication Step to add an authentication step.
    It adds Step 1 under Authentication Step Configuration.
  8. Under Step 1, select the check boxes Use subject identifier from this step and Use attributes from this step.
  9. Under step 1 added in the step 6, in the list of Local Authenticators options, select basic authentication type and click Add Authenticator.
  10. Click Add Authentication Step to add a second authentication step.
    It adds Step 2 under Authentication Step Configuration.
  11. Under Step 2 added in the previous step, in the list of Local Authenticators options, select MFA (that is Duo, fido/u2f, SMS OTP, Email OTP, etc.) authentication type, and click Add Authenticator.
  12. Under Script Based Adaptive Authentication section, add an authentication script.
  13. Use the following script, which enforces two-factor authentication based on role. or write a new authentication script that meets your requirements. 
    var rolesToStepUp = ['admin', 'manager'];

function onLoginRequest(context) {
    executeStep(1, {
        onSuccess: function (context) {
            // Extracting authenticated subject from the first step
            var user = context.currentKnownSubject;
            // Checking if the user is assigned to one of the given roles
            var hasRole = hasAnyOfTheRoles(user, rolesToStepUp);
            if (hasRole) {
                Log.info(user.username + ' Has one of Roles: ' + rolesToStepUp.toString());
                executeStep(2);
            }
        }
    });
}
  14. Click Update.
Test Role-based authentication script

You can test the sample authentication script.

Configure User Store-based adaptive authentication

User Store-based adaptive authentication allows for the requirement of an additional level of authentication for users logging in from other user store domains.

Procedure

  1. Log in to the Ellucian Ethos Identity management console as the admin user.
  2. On the left navigation pane, click Main.
  3. In the Service Providers tab, click List.
  4. Edit the service provider.
  5. Expand the Local & Outbound Authentication Configuration.
  6. In the list of Authentication Type options, select Advanced Configuration.
  7. Under Authentication Step Configuration, click Add Authentication Step to add an authentication step.
    It adds Step 1 under Authentication Step Configuration.
  8. Under Step 1, select the check boxes Use subject identifier from this step and Use attributes from this step.
  9. Under step 1 added in the step 6, in the list of Local Authenticators options, select basic authentication type and click Add Authenticator.
  10. Click Add Authentication Step to add a second authentication step.
    It adds Step 2 under Authentication Step Configuration.
  11. Under Step 2 added in the previous step, in the list of Local Authenticators options, select MFA (that is Duo, fido/u2f, SMS OTP, Email OTP, etc.) authentication type, and click Add Authenticator.
  12. Under Script Based Adaptive Authentication section, add an authentication script.
  13. Use the following script or write a new authentication script which meets your requirements. 
    // User Store-Based from Template...

// This script will prompt 2FA to the app only for a selected set of user stores.
// If the user is in one of the following user stores, user will be prompted 2FA
var userStoresToStepUp = [STAFF, STUDENT];

var onLoginRequest = function(context) {
    executeStep(1, {
        onSuccess: function (context) {
            // Extracting user store domain of authenticated subject from the first step
            var userStoreDomain = context.currentKnownSubject.userStoreDomain;
            // Checking if the user is from whitelisted tenant domain
            if (userStoresToStepUp.indexOf(userStoreDomain) >= 0) {
                executeStep(2);
            }
        }
    });
};

// End of User Store-Based.......
  14. Click Update.

Enable logging in log4j2

Log4J 2 is a logging framework designed to address the logging requirements of enterprise applications. Log4j 2 is a new and improved version of the classic Log4j framework.

About this task

The log4j2.properties governs how logging is performed by the server and it can be found in the /conf directory. You can edit the log4j2.properties file in the /conf directory.

Procedure

  1. Navigate to the path ..\wso2is-5.10.0\repository\conf\log4j2.properties.
  2. Add logger in the log4j2.properties file and add the logger name to the loggers list. 
    logger.<Logger_Name>.name = <Component_name>
logger. <Logger_Name>.level = DEBUG

    Example:

    logger.org-wso2-carbon-identity-core.name = org.wso2.carbon.identity.core
logger.org-wso2-carbon-identity-core.level = INFO

logger.org-wso2-carbon-identity-sso-cas.name=org.wso2.carbon.identity.sso.cas
logger.org-wso2-carbon-identity-sso-cas.level=DEBUG

    For more information about the list of debugging logs for various issues, see List of logs.

  3. Add multiple loggers to the loggers list by separating them with commas. 
    loggers =…, org-wso2-carbon-identity-core, org-wso2-carbon-identity-sso-cas
    Note: Do not need to restart the server after enabling the log change.

Enable custom app password

Setting a secure password with a WSO2-2023-2617 complies with WSO's security advisory.

About this task

To communicate between back end components, Ethos Identity products have a set of internal management REST APIs. An embedded password protects these APIs by default within the product configuration. To prevent unauthorized external clients from accessing these management APIs, you must change this default password to a secure password.
Note: Ellucian set a default password.

Example: FjW8020nKEUdkzf

Procedure

  1. Stop the running Ellucian Ethos Identity service.
  2. In an editor, open the deployment.toml file located in the EIS_HOME/repository/conf directory.
  3. Generate the custom password using any of the secure password generator tools.
    Random Password Generator from https://www.avast.com/
    It generates the default password as FjW8020nKEUdkzf.
  4. Set the custom password property to the appropriate value under the [identity.auth_framework.endpoint] root key:
    Property Description
    app.password Update the default password.

    Value: app_password= "B2sL0zNkgKR1vZ9"
  5. Generate the respective SHA-256 hash value of the new password using respective tools.
    SHA256 Generator from https://tools.keycdn.com/
  6. Set the SHA-256 hash value property to the appropriate value under the [account_recovery.endpoint.auth] root key:
    Property Description
    hash The SHA-256 hash value of the password that you set using the eis.app.password property.

    Value: hash= "9c03075b98a69b60ad95b2e5e3eb23d8041be8​​f0b62d725e9806890497c92dff"
  7. Save the changes to the file.
  8. Restart Ellucian Ethos Identity, using the appropriate commands for your operating system:

    Linux/UNIX:

    sh wso2server.sh start

    Windows: 

    wso2server.bat start
