Secondary user store configuration for Ethos Identity

Ellucian Ethos Identity uses an LDAP directory, Active directory server, or database server as a secondary user store. The secondary user store will configure from the management console.

Directory Servers: Ellucian Ethos Identity supports directory servers as an authentication user store and attribute store.

Database server (JDBC): Ellucian Ethos Identity supports JDBC server for attribute assertion as attribute store.

Note: Database server (JDBC) does not support as authentication user store.

Use case for attribute assertion: UDC_Identifier is an attribute in the database and it can retrieves using JDBC attribute store.

For more information about how Ellucian Ethos Identity uses secondary user store, see About Ethos Identity secondary user stores.

Add an Active Directory secondary user store

Add an Active Directory secondary user store.

Procedure

  1. Log in to the Console.
  2. Click User Attributes & Stores > User Stores.
  3. To Add a new user store, click New User Store.
  4. On the Select User Store Type page, select Active Directory.
  5. On the Add Active Directory User Store page, under General section, enter the following information.
    Field Description
    Name* Enter a unique identifier for the user store, such as the Active Directory domain. This value is the primary key among all secondary user stores defined.
    Description Enter a brief description of the user store.
    Connection URL* Enter the LDAP URL for Active Directory.
    Note: This URL must begin with ldap:// (unsecured) or ldaps:// (secured).
    Connection Name* Enter the DN of an administrative user that can perform LDAP search operations.
    Connection Password* Enter the password of the administrative user from the Connection Name field.
    Note: This password is encrypted using the key specified in the global keystore configuration. If the private key is updated in the global keystore, the password must be entered again on each secondary user store.
    Note: * indicates a required field.
  6. Click Next.
  7. On the Add Active Directory User Store page, under General section, enter the following information.
    Field Description
    User Search Base* Enter the DN for user search. For example, an administrator at school.edu may specify CN=users,DC=school,DC=edu to search for users under the users context.
    User Entry Object Class* Enter the object class used to construct user entries. If you are unsure, leave the default value.Example: user
    Username Attribute* Enter the attribute that uniquely identifies each user, such as cn/sAMAccountName. If you are unsure, leave the default value.
    User Search Filter* Modify the filtering criteria to use any changes to the Username Attribute field or User Entry Object Class field. If these fields were not modified, leave the default value.Example: (&(objectClass=user)(|(cn=?)(sAMAccountName=?)))
    User List Filter* Enter filtering criteria for listing all the user entries in LDAP.Example: (objectClass=user)
    User ID Attribute* Attribute used for uniquely identifying a user entry.

    Example: uid
    UserID Search Filter* Filtering criteria for searching a particular user entry.

    Example: (&(objectClass=user)(uid=?))
    Username RegEx (Java)* This is the regular expression used by the back-end components for validating usernames.
    Username RegEx (Javascript)* This is the regular expression used by the front-end components for validating usernames.
    Password RegEx (Java)* This is the regular expression used by the back-end components for validating passwords.
    Password RegEx (Javascript)* This is the regular expression used by the front-end components for validating passwords.
    Note: * indicates a required field.
  8. In the Group Search Base field, enter the DN for user search.

    For example, an administrator at school.edu may specify CN=users,DC=school,DC=edu to search for groups under the users context.

  9. Click Next.
    You can preview the Invitation message with the user username and password.
  10. Click Finish to create the secondary user store.

Configure claim mappings

Ellucian Ethos Identity 5.10.0 enables System for Cross-domain Identity Management (SCIM2). To support SCIM2 additional claim mappings are required.

About this task

Perform the following steps to add required SCIM2 claim mappings for the Active Directory.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Navigate to Claims > List, under Available Claim Dialects, click http://wso2.org/claims.
  4. Under Available Claims for http://wso2.org/claims, click Edit for User ID claim and update it to the appropriate Mapped Attribute (s)* in your Active Directory.
    Example: uid
  5. Under Available Claims for http://wso2.org/claims, click Edit for Last Modified Time claim and update it to the appropriate Mapped Attribute (s)* in your Active Directory.
    Example: LastModifiedDate
  6. Under Available Claims for http://wso2.org/claims, click Edit for Created Time claim and update it to the appropriate Mapped Attribute (s)* in your Active Directory.
    Example: homePhone
    Note: The above attribute mappings are references. Actual attribute mappings may differ in your environment.

Add an LDAP secondary user store

Add an LDAP secondary user store.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under User Stores, click Add.
  4. On the Add New User Store page, enter the following information.
    Field Value
    User Store Manager Class Select: org.wso2.carbon.user.core.ldap.​UniqueIDReadWriteLDAPUserStoreManager
    Domain Name Enter a unique identifier for the user store, such as the LDAP domain. This value is the primary key among all secondary user stores defined.
    Description Enter a brief description of the user store.
    Connection URL Enter the LDAP URL.
    Note: This URL must begin with ldap:// (unsecured) or ldaps:// (secured).
    Connection Name Enter the DN of an administrative user that can perform LDAP search operations.
    Connection Password Enter the password of the administrative user from the Connection Name field.
    Note: This password is encrypted using the key specified in the global keystore configuration. If the private key is updated in the global keystore, the password must be entered again on each secondary user store.
    User Search Base Enter the DN for user search. For example, an administrator at school.edu may specify CN=users,DC=school,DC=edu to search for users under the users context.
    User Entry Object Class Enter the object class used to construct user entries. If unsure, leave the default value.

    Example: inetOrgPerson
    Username Attribute Enter the attribute that uniquely identifies each user, such as cn/uid. If you are unsure, leave the default value.
    User Search Filter Modify the filtering criteria to use any changes to the Username Attribute field or User Entry Object Class field. If these fields were not modified, leave the default value.

    Example: (&(objectClass=person)(cn/uid?))
    User List Filter Enter filtering criteria for listing all the user entries in LDAP.

    Example: (objectClass=person)
    User ID Attribute Attribute used for uniquely identifying a user entry

    Example: uid
    UserID Search Filter Filtering criteria for searching a particular user entry

    Example: (&(objectClass=user)(uid=?))
  5. Expand the Optional panel.
  6. In the Group Search Base field, enter the DN for user search.

    For example, an administrator at school.edu may specify CN=users,DC=school,DC=edu to search for groups under the users context.

  7. Click Add to create the secondary user store.

Remove Referral attribute when not using LDAP referrals

If you configure a user store so that it does not follow LDAP referrals by leaving the Referral attribute value blank, you will need to edit the <secondary_user_store_domain_name>.xml file to remove the Referral property.

Procedure

  1. Open the <secondary_user_store_domain_name>.xml file, located in: EIS_HOME/repository/deployment/server/userstores.
  2. Remove the following line: <Property name="Referral"/>.
    Note: You need to edit the file any time you modify the user store properties through the administrative console.

Add a JDBC secondary user store

Add a JDBC secondary user store.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under User Stores, click Add.
  4. On the Add New User Store page, enter the following information.
    Field Value to enter
    User Store Manager Class Select: org.wso2.carbon.user.core.jdbc.UniqueIDJDBCUserStoreManager
    Connection URL Connection URL to the database which includes additional connection parameters

    Sample values: jdbc:mysql://localhost:3306/eeid
    Connection Name The username used to connect to database with sufficient privileges to perform required operations.
    Connection Password Password for the Connection Name user.
    Driver Name JDBC driver name which used to connect to the database.

    This driver should be available in the <EEID_HOME>/repository/components/lib folder.

    For more information about JDBC configuration, refer to Configuring a JDBC User Store on the WSO2 documentation website for the corresponding WSO2 version.

  5. Click Add to create the secondary user store.

Remove the domain from group memberships

If required by a service provider, remove the domain from the group membership information that is sent to the service provider from Ellucian Ethos Identity.

About this task

Some service providers require a user's group membership to be sent back from the identity provider. For users stored in a secondary user store, group memberships are sent with the domain in front of the group name. For example, a user located in a secondary user store called STUDENTS and belonging to groups full-time-students and const-student would have their group membership sent as STUDENTS/full-time-students and STUDENTS/const-student. However, some service providers require that the group membership be sent without the domain.

Perform this procedure to map roles so that the group membership is sent without the domain.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Go to Service Providers > List.
  4. In the row for the service provider, click Edit.
  5. Select the check box Use user store domain in roles in outbound configurations.
  6. Click Update.
