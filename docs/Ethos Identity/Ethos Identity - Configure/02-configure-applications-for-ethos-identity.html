Configure Applications for Ethos Identity

Ellucian Ethos Identity requires each supported application to be created as an Applications and configured for the appropriate protocol.

Service providers can require different configurations for application and protocol combinations. These procedures describe configurations for CAS, SAML 2.0, and WS-Federation. For more information, refer to Applications on the WSO2 documentation website for the corresponding WSO2 version.

Configure CAS based applications

Central Authentication Service (CAS) is a ticket-based single sign-on protocol maintained by JA-SIG. Ellucian Ethos Identity supports the CAS protocol specification, which is used by some Ellucian products.

The following diagram shows the login and service ticket validation process for a CAS service provider against Ellucian Ethos Identity.

Supported CAS protocols

The following CAS protocols are supported by Ellucian Ethos Identity.

Protocol Supports
Login /login

Supports TARGET and SAMLart arguments for legacy SAML clients
Logout /logout
  • Supports url parameter for redirect link [CAS 1.0, 2.0]
  • Supports service parameter for automatic redirect [CAS 3.0]
Proxy Ticket /proxy [CAS 2.0]
Ticket Validation
  • /validate [CAS 1.0]
  • /serviceValidate [CAS 2.0] Supports user attributes [CAS 3.0]
  • /proxyValidate [CAS 2.0]
  • /samlValidate [CAS 3.0]

CAS single logout

CAS single logout capability is not supported by all service provider applications, it is not set by default, and it generates extraneous traffic.

If you want a service provider to use the CAS single logout capability, you must set the Enable Single Logout option on the CAS configuration panel for that service provider in the Management Console.

Configure attribute mapping

An application might require specific user store attributes that must be passed to the application. Ellucian Ethos Identity provides some default attribute that map to user store attributes. You might need to add attribute, or change the existing mappings to point to a different attribute in your directory server.

Procedure

  1. Log in to the Console.
    Log in as a user who has access to all service providers. You can either always use the same login to maintain service providers, or give multiple users access to each service provider using the procedure in Make a service provider visible to additional administrators.
  2. Click User Attributes & Stores tab.
  3. Click Attributes
  4. Under Manage Attributes, click Attributes.
  5. Review the existing attributes to determine whether you need to add attributes, or modify an existing attributes to point to a different attribute in your user store.
  6. If you need to add an attributes, follow the instructions in the WSO2 procedure.
    For more information, refer to Add custom attributes on the WSO2 documentation website for the corresponding WSO2 version. For example, you might need to add one of the claims listed in the following table:
    Claim Description
    logonname Logon name claim mapping

    Example value: sAMAccountName
    upn User principal name claim mapping

    Example value: userPrincipalName
    objectguid Object GUID claim mapping

    Example value: objectGUID
    udcid Banner UDC Identifier claim mapping

    Example value: udcid
    personid Colleague Person Identifier claim mapping

    Example value: employeeNumber
  7. Set the following properties to the appropriate values for attributes mappings:
    Property Description
    eis.add.claim.logonname Logon name claim mapping (leave blank to skip this claim)

    Example value: sAMAccountName
    eis.add.claim.upn User principal name claim mapping (leave blank to skip this claim)

    Example value: userPrincipalName
    eis.add.claim.objectguid Object GUID claim mapping (leave blank to skip this claim)

    Example value: objectGUID
    eis.add.claim.udcid Banner UDC Identifier claim mapping (leave blank to skip this claim)

    Example value: udcid
    eis.add.claim.personid Colleague Person Identifier claim mapping (leave blank to skip this claim)

    Example value: employeeNumber
    eis.add.claim.challenge.question.uris Store the URI for challenge question
    eis.add.claim.challenge.question.1 Set the claim challenge question one
    eis.add.claim.challenge.question.2 Set the claim challenge question two
  8. Save the changes to the file.
  9. If you need to modify an existing claim, follow the instructions in the WSO2 procedure.
    For more information, refer to Editing Claim Mapping on the WSO2 documentation website for the corresponding WSO2 version.

Add CAS based applications

Add a CAS based applications definition in the WSO2 Identity Server Console.

Procedure

  1. Log in to the Console.
    Log in as a user who has access to all service providers. You can either always use the same login to maintain service providers, or give multiple users access to each service provider using the procedure in Make a service provider visible to additional administrators.
  2. Click Applications tab.
  3. Click New Application.
  4. Select the Custom Application.
  5. On the Custom Application dialog box, enter the following details as required:
    Field Description
    Name* Enter a name that uniquely identifies the application.

    Example: MyApplication
    Note: * indicates a required field.
  6. Select the check box Allow sharing with organizations to share the new application with all or any selected organizations that belong to your organization.
  7. Click Create.

(Optional) Make an applications visible to additional administrators

For an applications to be visible to an administrator, that user must either have created that applications or be assigned the role associated with the applications.

About this task

When you add an applications, WSO2 Identity Server creates a role associated with that applications and assigns that role to the administrative user who added the applications. By default, other users do not see that applications in the applications list. As a result, other users cannot maintain that applications, and two users could create applications with a similar configuration which would create conflicts. This issue could arise, for example, because a different user logged in to the Console or you switched to using email address rather than username to log in.
To avoid these issues, do either of the following:
  • Perform the procedure below to assign that role to other users, so that multiple users can view and maintain the applications.
  • Always log in as the same user (for example, the administrator created by Ellucian Ethos Identity) to add or maintain applications.

Procedure

  1. Log in to the Console.
  2. Click User Management tab.
  3. Click Roles
  4. On the Roles page, search for the role associated with the applications.
    The role name is Application/<application>. WSO2 Identity Server created this role when you added the service provider.
  5. Click Assign Users in that row.
  6. On the User List of Role page, select the check boxes for any users who you want to be able to view and maintain this application.
  7. Click Finish.

Add CAS configuration

After mapping the identity claims, add the CAS Service URL for the integrating application.

Procedure

  1. Log in to the Console.
  2. Click Applications tab.
  3. Click New Application.
  4. Select the required CAS application to configure or click Edit icon .
  5. Under the General tab, configure the following details as required:
    Field Description
    Name* Enter a name that uniquely identifies the application.

    Example: MyApplication
    Description Enter a description for an application.
    Logo Enter an image URL for the application.

    If the URL is not available, a generated thumbnail will be displayed instead.

    The image recommended size is: 200x200 pixels.
    Discoverable application Select the Discoverable application check box, if the customers want to access the application through the My Account portal.
    Access URL Enter the landing page URL for this application
    Delete Click Delete if want to delete the application.
    Note: After deleting the application, it cannot be restored, and any clients relying on this application will cease to function.
    Note: * indicates a required field.
  6. Under the Protocol tab, click Configure Protocol
  7. Under Add Protocol, select CAS Configuration, and then click Next.
  8. In the Service URL field, enter the URL of the target application deployment with a trailing slash.

    The table below shows the standard URL deployment patterns for CAS-enabled Ellucian products.

    Ellucian Product URL Pattern
    Application Navigator http(s)://<host>:<port>/applicationNavigator/
    Banner Document Manager AX Web Access http(s)://<host>:<port>/appxtender/
    Banner Flexible Registration http(s)://<host>:<port>/flexibleregistration/
    Banner SSO Manager http(s)://<host>:<port>/ssomanager/
    Banner Travel and Expense Report http(s)://<host>:<port>/tvlexp/
    Banner Workflow http(s)://<host>:<port>/workflow/
    Banner XE Applications http(s)://<host>:<port>/<deploymentContext>/
  9. In the Enable Single Logout field, enter true if you want to let this application participate in single logout with other CAS application.
  10. Click Update to save the settings.

Configure Banner 8 applications

Banner 8 applications implement single sign-on using Banner SSO Manager, a component of Banner Enterprise Identity Services (BEIS).

About this task

The following steps demonstrate how to configure a Banner SSO Manager applications in Ellucian Ethos Identity. For details on configuring CAS for Banner SSO Manager, refer to the CAS Single Sign On Handbook.

Procedure

  1. Create an application for Banner SSO Manager in the Console.
  2. Create a new custom attribute mapping for the application.
    For the attribute mapping, select the identity attribute configured in the Banner SSO Manager Admin interface. For this example, the unique identifier name is UDC_IDENTIFIER and the LDAP attribute cn contains the value.
  3. Enter the Service URL for Banner SSO Manager. Include a trailing slash.
    Example: https://sso.server.edu:8443/ssomanager/
  4. Click Update to save the settings.

Import and export certificate using Ellucian Ethos Identity management console

Applications often require information to be digitally signed or encrypted when communicating with Ellucian Ethos Identity.

To facilitate secure communication, both applications exchange digital certificates. Certificate exchange entails exporting the public certificate from the keystore of one application and importing it into the keystore of the other application.

Export the public certificate from the Ellucian Ethos Identity keystore into the service provider to support secure communication.

Procedure

  2. Click Applications tab.
  3. Select the required SAML application to configure or click Edit icon .
  4. Under the Info tab, click Download IdP Metadata.
    Note: You can keep the default values for all the fields.
  5. Open the above downloaded XML file, copy the content to a text file, and save it as <name>.pem.
    Example: idp.pem
  6. Import the saved certificate to service provider (client) keystore.

Procedure

  2. Click Applications tab.

    Field Description
    Name* Enter a name that uniquely identifies the application.

    Example: MyApplication

    The image recommended size is: 200x200 pixels.

    Delete Click Delete if want to delete the application.
    Note: After deleting the application, it cannot be restored, and any clients relying on this application will cease to function.
    Note: * indicates a required field.
  4. Under the General tab, configure the following details as required:
  5. Under the Protocol tab, configure the following details as required:
    Field Description
    Issuer* Enter the Issuer value that is configured in the service provider application. This value is validated against the SAML Authentication Request issued by the service provider.
    Application qualifier Enter the application qualifier if you need to configure multiple SAML Single Sign-On (SSO) inbound authentication configurations for the same issuer value.
    Assertion consumer service URLs* Enter a valid Assertion Consumer URL where the browser redirects the SAML Response after authentication.
    Note: The Assertion Consumer URL must use lowercase http or https to conform to SAML protocol standards. For example:<samlp:AuthnRequest AssertionConsumerServiceURL="https://webadvisor.school.edu/WebAdvisor/WebAdvisor". Before Ellucian Ethos Identity 2.0, you could use uppercase characters for the URL, but this is no longer supported.
    Default assertion consumer service URL* Enter an assertion consumer service URL.

    When you configure multiple ACS URLs, it is important to set one of them as the default.
    IdP entity ID alias Enter alias

    The value must override the default Identity Provider (IdP) entity ID (localhost).
    Enable request signature validation Under Request Validation, select Enable request signature validation if the identity provider must validate the signature of the SAML 2.0 Authentication and Logout Requests that are sent by the service provider.
    Sign SAML responses Under Response Signing, select Sign SAML responses to sign the SAML 2.0 Responses returned after the authentication process.
    Bindings Under Single Sign-On Profile, select the supported bindings. They specifies the methods for transporting SAML messages within communication protocols.
    Enable IdP initiated SSO Under Single Sign-On Profile, select Enable IdP Initiated SSO so that either the IdP or the service provider can initiate single sign-on.
    Name ID format Under Assertion, enter a valid NameID format supported by Ellucian Ethos Identity. You can use the following values:
    • urn:oasis:names:tc:SAML:2.0:nameid-format:persistent
    • urn:oasis:names:tc:SAML:2.0:nameid-format:transient
    • urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress
    • urn:oasis:names:tc:SAML:1.1:nameid-format:unspecified
    • urn:oasis:names:tc:SAML:1.1:nameid-format:X509SubjectName
    • urn:oasis:names:tc:SAML:1.1:nameid-format:WindowsDomainQualifiedName
    • urn:oasis:names:tc:SAML:2.0:nameid-format:kerberos
    • urn:oasis:names:tc:SAML:2.0:nameid-format:entity
    Audiences Under Assertion, enter audience of the SAML assertion.
    Recipients Under Assertion, enter recipient of the SAML assertion.
    Enable encryption Under Assertion, select Enable encryption to encrypt the assertions.
    Enable attribute profile Under Attribute Profile, select Enable attribute profile to add a basic attribute profile where the identity provider can include the user’s attributes in the SAML Assertions as part of the attribute statement.
    Enable SLO Under Single Logout Profile, select Enable SLO so that all sessions across all authenticated service providers are terminated after the user signs out from one server. If the service provider supports a different URL than the Assertion Consumer URL for logout, enter a SLO Request URL for logging out.
    Single logout response URL Under Single Logout Profile, enter a single logout response URL. This URL indicates the application's endpoint where the single logout response should be directed.
    Single logout request URL Under Single Logout Profile, enter a single logout request URL. This URL indicates the application's endpoint where the single logout request should be directed.
    Enable IdP Initiated single logout Select Enable IdP Initiated single logout so that either the IdP or the service provider can initiate single sign-on.
    Return to URLs Enter the URL that specifies where users should be redirected after logout.
    Enable assertion query profile Under Assertion Query/Request Profile, select Enable assertion query profile.
    Certificate Under Certificate, select Provide certificate and then click New Certificate to upload the application's public certificate. This certificate is essential for validating the signatures of SAML 2.0 Requests and for generating encryption.
    Note: * indicates a required field.
  6. Click Update to save all settings.

Modify identity provider issuer

Change the Identity Provider Entity Id to the expected URI of the Issuer statement in SAML 2.0 Responses.

About this task

The identity provider issuer was established when you ran the update-resident-idp command during initial configuration. If you need to update the identity provider issuer, perform the following procedure.

Procedure

  1. Log in to the Management Console.
  2. Click the Main tab.
  3. Under Identity Providers, click Resident.
  4. Expand Inbound Authentication Configuration > SAML2 Web SSO Configuration.
  5. In the Identity Provider Entity ID field, enter a valid identity provider name or URI that will be used by all service providers.
  6. Click Update to save the settings.

Configure Colleague Self-Service

Colleague Self-Service is built on ASP.NET MVC technology and leverages SAML 2.0 SSO for single sign-on.

Procedure

  1. Create a service provider for Colleague Self-Service in the Management Console.
    For more details on configuring Colleague Self-Service, refer to Colleague Self-Service in Configure Ellucian Ethos Identity for Specific Products.
  2. Create a new custom claim mapping for the service provider. For the claim mapping, select the identity attribute configured in the Colleague Self-Service Admin interface. For this example, the unique identifier name is colleague and the local claim sAMAccountName contains the value.
  3. Configure the SAML 2.0 SSO settings. Click the Configure link to open a new page.
  4. Enter the Issuer and the Assertion Consumer URL and choose the appropriate options.
  5. Click Register to save settings and return to the Service Providers configuration page.
  6. Click Update to save all settings.

Configure Google Apps

Google Apps for Work (formerly Google Apps for Business) is a suite of cloud computing productivity and collaboration software tools and software offered on a subscription basis by Google. It includes Google's web applications Gmail, Google Drive, Google Hangouts, Google Calendar, and Google Docs.

Procedure

  1. In the Management Console, create a service provider for Google Apps.
  2. For the claim mapping, select NameID as the Service Provider Claim as shown in the following table:
    Service Provider Claim Local Claim Requested Claim
    NameID http://wso2.org/claims/emailaddress ✓
  3. Configure the SAML 2.0 SSO settings:
    1. Click the Inbound Authentication link.
    2. Click the SAML2 Web SSO Configuration link to expand the SAML configuration.
    3. Click Configure.
  4. Enter google.com/a/domain_name for the issuer, replacing domain_name with your institution's Google Apps domain.
  5. Enter https://www.google.com/a/domain_name/acs for the Assertion Consumer URL replacing domain_name with your institution's Google Apps Domain.
  6. Under Certificate Alias, select your Ellucian Ethos Identity Signing Certificate.
  7. Check the Enable Response Signing option.
  8. Check the Enable Single Logout option.
  9. Enter https://www.google.com/a/domain_name/acs for the SLO Response URL replacing domain_name with your institution's domain name.
  10. Enter https://www.google.com/a/domain_name/acs for the SLO Request URL replacing domain_name with your institution's domain name.
  11. Check the Enable Attribute Profile option.
  12. Check the Enable Idp Initiated SSO option.
  13. Click Update to save SAML configuration.
  14. Click Update to save all configurations.

Configure Google Apps to use Ellucian Ethos Identity as IDP

Allow Google Apps to use Ellucian Ethos Identity as its primary identity provider.

Procedure

  1. Log in to Google Apps Admin Console as an Administrator by navigating to https://admin.google.com.
  2. Click Security.
  3. Click Set up single sign-on (SSO).
  4. Check the Setup SSO with third party identity provider option.
  5. Enter your institution's Ellucian Ethos Identity SAMLSSO URL for Sign-in page URL.
    Example: https://idp.school.edu/samlsso.
  6. Enter your institution's Ellucian Ethos Identity SAMLSSO URL for Sign-out page URL. The URL must end with ?slo=true.
    Example: https://idp.school.edu/samlsso?slo=true.
  7. If you have enabled Change Password within Ellucian Ethos Identity, enter your Ellucian Ethos Identity Change Password URL under Change Password URL.
    If you have another web application that performs password changes, then enter the URL for that web application here.
    Example: https://idp.school.edu/password/change.
  8. Select your Ellucian Ethos Identity Token Signing certificate for the Verification Certificate.

(Optional) Make an applications visible to additional administrators

For an applications to be visible to an administrator, that user must either have created that applications or be assigned the role associated with the applications.

About this task

When you add an applications, WSO2 Identity Server creates a role associated with that applications and assigns that role to the administrative user who added the applications. By default, other users do not see that applications in the applications list. As a result, other users cannot maintain that applications, and two users could create applications with a similar configuration which would create conflicts. This issue could arise, for example, because a different user logged in to the Console or you switched to using email address rather than username to log in.
To avoid these issues, do either of the following:
  • Perform the procedure below to assign that role to other users, so that multiple users can view and maintain the applications.
  • Always log in as the same user (for example, the administrator created by Ellucian Ethos Identity) to add or maintain applications.

Procedure

  1. Log in to the Console.
  2. Click User Management tab.
  3. Click Roles
  4. On the Roles page, search for the role associated with the applications.
    The role name is Application/<application>. WSO2 Identity Server created this role when you added the service provider.
  5. Click Assign Users in that row.
  6. On the User List of Role page, select the check boxes for any users who you want to be able to view and maintain this application.
  7. Click Finish.

Procedure

Procedure

  1. Log in to the Management Console.
