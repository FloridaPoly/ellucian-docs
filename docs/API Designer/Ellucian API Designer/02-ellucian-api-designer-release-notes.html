Ellucian API Designer release notes

These release notes describe new features, enhancements, and updates in Ellucian API Designer releases.

The product documentation available on the Ellucian Documentation site supports the latest available version.

Release 1.7.0

API Designer v1.7.0 is a minor version release update to the v1.6.2 release of API Designer.

Tip: Information about upcoming or planned features or potential updates can be provided to customers by Product Management in customer communications in the Ellucian Customer Center.

API Designer Experience Card Update

With the June release, Ellucian will discontinue the configuration option in the API Designer Experience card that allows users to override the Integration API URL. Today, the API Designer Experience card includes an Integration API URL field and a toggle labeled Enable to use Ethos API integration instead of direct URL. In standard customer deployments, Integration APIs are centrally managed through Ethos, including MEP handling, and the frontend relies on the Ethos configuration. The direct URL override is not required for production use.

Before upgrading to the June 2026 release, customers must review their Experience configuration and confirm that they are using the default Ethos-based setup and not using a direct Integration API URL.

To verify their configuration, customers can do the following:
  1. In the tenant environment where they are using the API Designer, open Experience.
  2. Click the main menu icon and then click Configuration.
  3. On the Card Management > All tab, search for the API Designer card.
  4. Click the actions menu for the API Designer card, and then click Edit.
  5. Scroll down to section 2 and expand the Configuration panel.
  6. Ensure that the toggle for Enable to use Ethos API integration instead of direct URL is enabled.
Warning: If the Enable to use Ethos API integration instead of direct URL toggle is disabled and a direct Integration API URL is configured, customers must migrate to the standard Ethos-managed configuration before the June release to avoid any disruption. Customers using the default Ethos configuration will not be impacted.

Integration API URL override removed

The API Designer Experience card configuration option that allowed users to override the Integration API URL has been removed. API Designer now exclusively uses the standard Ethos-managed configuration for Integration APIs, including MEP handling. This change reduces customer confusion and aligns all deployments with the recommended Ethos-driven architecture.

This update addresses PE0008448 in the Ellucian Customer Center.

DateTime data type support

API Designer now supports a DateTime data type that includes both date and time components (for example, 2025-03-17 00:00:00). This prevents data loss when working with datetime fields and eliminates the need to convert datetime columns to strings.

For details, see Parameters.

This update addresses PD0029743 in the Ellucian Customer Center.

Function data type consistency

Users can now create and use custom fields with functions more reliably when the same field is referenced across functions and filter conditions. Updates to datatype handling ensure compatible numeric fields are recognized consistently, reducing validation issues and preventing API execution failures to improve overall stability and usability

This update addresses PD0031377 in the Ellucian Customer Center.

Similar parameter names

You can now add parameters with names that are similar but not identical without encountering validation errors. Previously, parameters with similar prefixes (for example, param and param1) were incorrectly flagged as duplicates. The validation logic now correctly distinguishes between similar but distinct parameter names.

This update addresses PD0034421 in the Ellucian Customer Center.

Parameter validation for filter operators

Validation was enhanced to consistently prevent parameter data type changes when parameters are already used in query conditions, including Between, In, and Not In operators, reducing the risk of query failures caused by incompatible parameter updates. This improvement provides more reliable query behavior and helps maintain data integrity and consistency when configuring and managing query conditions.

This update addresses PD0034671 in the Ellucian Customer Center.

Internationalization for date formats

Date input fields now display consistently according to configured regional and language preferences across all supported locales in Banner Runtime applications. Formatting behavior was validated and aligned with supported Locale Definitions standards to ensure users experience accurate, predictable, and intuitive date entry and review, improving usability and confidence when working with date values.

This update addresses PD0034758 in the Ellucian Customer Center.

Explain plan bind parameter support

API Designer users can now successfully download explain plans for parameterized models without encountering application errors, improving the reliability and usability of the feature. The update ensures explain plans generate as expected when model parameters are included, providing a more consistent and efficient experience for users working with complex models.

This update addresses PD0033565 in the Ellucian Customer Center.

Custom fields from models in API field selection

When a model is used as a data source for an API, all custom fields defined in the model now appear in the API field selection dropdown. Previously, custom fields from models were not visible when selecting fields for the API schema, limiting the reusability of model-level calculations.

This update addresses PD0034647 in the Ellucian Customer Center.

COALESCE function with duplicate column names

API Designer now correctly supports the use of the COALESCE function when working with fields that share the same column name across different data sources, preventing errors caused by ambiguous column references. This update enables APIs built on joined models to execute successfully without requiring users to rename columns or modify existing COALESCE logic, improving reliability and reducing configuration effort.

This update addresses PD0034154 in the Ellucian Customer Center.

DateAdd function supports negative values

The DateAdd function now supports negative numbers for the days parameter, enabling date subtraction. This provides parity with existing support for negative values in months and years parameters, allowing you to calculate dates in the past by subtracting days from a reference date.

This update addresses PD0034261 in the Ellucian Customer Center.

Enhanced filter operators

This release adds three new filter operators to provide more flexible data filtering capabilities:
  • BETWEEN: Allows you to filter data within a specified range by providing a start value and an end value. Each value can be a field, literal, parameter, or function.
  • IN: Allows you to filter data that matches any value in a specified list. A side section displays where you can enter multiple values as a comma-separated list.
  • NOT IN: Allows you to filter data that does not match any value in a specified list. A side section displays where you can enter multiple values as a comma-separated list.

For details, see Filter data.

This update addresses PE0008371 in the Ellucian Customer Center.

Enhanced join operators

This release adds five binary comparison operators for join conditions, enabling more flexible relationships between data sources:
  • Not Equal (!=)
  • Greater Than (>)
  • Greater Than or Equal (>=)
  • Less Than (<)
  • Less Than or Equal (<=)

These operators complement the existing Equals operator, allowing you to create more sophisticated join conditions beyond simple equality comparisons.

For details, see Join data.

This update addresses PE0008372 in the Ellucian Customer Center.

API name automatic lowercase conversion

The API name field now automatically converts text to lowercase as you type. This enhancement ensures consistency in API naming conventions and simplifies API management by standardizing the format of all API names.

For details, see Create a new API draft.

This update addresses PD0034134 in the Ellucian Customer Center.

Support for relative date filters using Today and DateAdd functions

This release supports combining the Today and DateAdd functions in filter criteria, enabling relative date comparisons.

This update addresses PD0029399 in the Ellucian Customer Center.

Accessibility improvements

This release includes accessibility improvements that enhance navigation, correct button functionality, and add missing labels throughout the application. These updates improve usability for all users and ensure better compliance with accessibility standards.

This update addresses PD0034010 in the Ellucian Customer Center.

API Designer Supports Special Characters in Text Filter Comparisons

Users can now create, preview, and save APIs that include special characters in text-based filter comparisons without encountering validation errors, improving flexibility and reducing interruptions when configuring API filters in API Designer. Validation handling for Literal filter values was updated to better support commonly used special characters, enabling a more reliable and streamlined API configuration experience.

This update addresses PD0030300 in the Ellucian Customer Center.

Bulk export and import enhancement

This release introduces new bulk export and bulk import capabilities to improve API management efficiency at scale.

  • Bulk import - The new bulk import capability enables users to import multiple APIs in a single operation. The process includes built-in validation for API and model naming conflicts, along with clear visibility into import results. Users can resolve conflicts during import and easily identify successful and failed items through improved feedback, resulting in a more controlled, transparent, and efficient workflow.

This enhancement addresses PE0008098 and PE0008099 in the Ellucian Customer Center.

Model name handling enhancement

The handling of model names was updated to comply with SQL identifier rules for table aliases in both Oracle and PostgreSQL. This allows the use of supported special characters while ensuring queries remain valid and executable.

This enhancement addresses PE0008165 in the Ellucian Customer Center.

Access controls were updated so users with the API_DESIGNER_QUERY role can now view and select all appropriate Banner tables without requiring elevated permissions. This improves usability and better aligns with intended security roles.

Release 1.6.0 updates

Ellucian provides the following updates in API Designer v1.6.0:

  • Starting with Integration API App version 9.41, API exports now include nested models along with API-level models to ensure complete and accurate API definitions. By exporting all associated model dependencies together, this enhancement reduces the risk of missing components during migration or deployment and streamlines promotion across environments. As a result, your organization gains more reliable API transfers, improved usability, and greater confidence in managing integrations. This enhancement addresses PE0007746 in the Ellucian Customer Center.
  • API Designer now provides enhanced support for nested models, enabling up to two levels of nesting and subqueries to deliver greater flexibility in API design within supported limits. When the maximum nesting depth is reached, users receive a clear and descriptive error message that explains the constraint, reducing troubleshooting time and improving overall design efficiency. This enhancement addresses PE0007856 in the Ellucian Customer Center.
  • The About dialog now provides clear messaging to indicate minimum and unsupported Integration API versions. Unsupported versions also trigger an alert when opening API Designer to ensure immediate visibility. This enhancement gives users a consistent and transparent way to confirm API version compatibility, improving awareness, reducing reliance on tool tips, and enabling more proactive upgrade planning and risk mitigation. This enhancement addresses PE0007862 in the Ellucian Customer Center.
  • Custom fields are now available for selection within filter and sort criteria, enabling users to create more flexible and meaningful queries aligned to their unique business requirements. With expanded options and built-in safeguards to ensure reliable behavior, users can more easily refine results, reduce configuration effort, and achieve more accurate and efficient data retrieval. This enhancement addresses PE0007863 in the Ellucian Customer Center.
  • Ellucian implemented accessibility improvements in API Designer to address issues affecting navigation, button functionality, and labeling. This gives you a more intuitive and inclusive user experience. These enhancements improve screen reader support, contrast, and overall usability, helping institutions meet accessibility standards while enabling users to work more efficiently and confidently within the application. This update addresses PD0031493.
  • An issue was identified where custom fields or filters using the DateAdd function could not be saved when the argument referenced a field or parameter, which resulted in parsing errors. The validation logic was updated to apply date and time checks only to literal values, allowing field-based and parameter-based arguments to be processed correctly. Users can now reliably configure and save APIs that include DateAdd functions in filters and custom fields. This reduces configuration errors and improves overall usability. This update addresses PD0031368.
  • Ellucian resolved an issue where function preview could fail if a previously selected optional argument type or parameter was reverted to an unselected state. Users can now adjust optional arguments in functions such as DateAdd, NVL, and Coalesce without encountering validation errors. This ensures a smoother and more reliable preview experience when configuring calculated fields and filters. This enhancement improves overall usability and confidence in preview results. This update addresses PD0032110.

Tip: Information about upcoming or planned features or potential updates can be provided to customers by Product Management in customer communications in the Ellucian Customer Center.

Release 1.5.1 updates

Ellucian provides the following updates in API Designer v1.5.1:

  • API Designer now prevents SQL errors caused by column aliases that begin with numeric characters by automatically prefixing those aliases with the first letter of the source table name. This ensures that all generated aliases meet database naming requirements. This update addresses PD0029481.
  • API Designer now clears the Group By configuration data when the Summarize operation is removed, which ensures that no non-valid leftover grouping definitions remain. This ensures that API input validation is no longer affected, allows for consistent cleanup, and prevents database errors during data preview. This update addresses PD0029944.
  • API Designer now prevents preview errors caused by non-valid Sort configurations when a Summarize operation is applied. Sorting is limited to fields included in the Group By clause, ensuring that only valid and supported Sort options are available. This update addresses PD0029946.
  • The Save button on the model page is updated so that the model state (including the updated name) is correctly passed and persisted during save operations. This ensures that name changes propagate consistently to the Models page list. This update addresses PD0029950.
  • You can now use API Designer to delete custom fields without encountering residual references to those fields in Summarize operation configurations.

    API Designer automatically cleans custom fields from the Group By list of summarized operations whenever you delete the Custom Fields section by using the trash icon. This ensures Summarize operations configurations remain valid and consistent with the current API structure. This update addresses PD0029952.

  • Modified API Designer SQL generation so that filter placeholders are scoped and isolated per query level. This update addresses PD0030810.

For example, when a user enters a value and then tabs through the Join fields, the system correctly registers the selection and activates the Save button, making it easy to save the data.This update addresses PD0028870.
  • Data Preview now returns correct query results when a user parameter is used with the startsWith operator in the propertyMaps configuration. This update addresses PD0029856.

Release 1.2.0 enhancements

Ellucian provides the following enhancements and updates in API Designer v1.2.0:
  • The Filter option supports additional functions:
    • Users can compare a field to a literal, to another field, or to a function for each filter criteria.
    • Users can use the Function option to choose which function to apply and then fill in the function arguments (if there are any).
    • Users are guided to literals and fields of the appropriate data type for a function when users enter function arguments.
  • The PREVIEW DATA option displays more information:
    • Users can see the number of total records and the execution time of the query after running a preview.
    • Users can download the Execution Plan for a query.
    • Users can see more than five records when they preview data, and as a user scrolls more records are automatically loaded.
  • The Security component offers new configuration choices:
    • Users can turn User Authentication on or off in addition to selecting either Basic Authentication or User Authentication.
    • Users can select multiple roles that can have permission to access the API.
    • When users configure User Authentication, the User Data Security filter over SECURITY_PRINCIPAL_ID is now optional.
    • The following message displays to let users know the default settings: Basic Authentication applied by default. User-level authentication can be enabled on this screen.
  • Users can use customized domains when they configure API Details. For details, see Add customized domains.

Release 1.2.0 updates

Ellucian provides the following updates in API Designer v1.2.0:
  • Improvements to models include the following updates:
    • When a user opens a model that is referenced by another model or API, the model information displays in read-only mode.
    • Sorted models list alphabetically when a user picks a data source.
  • The following fixes are applied:
    • The keyboard navigation in the version selection dialog and in the join type window are fixed.
    • Dates are now formatted correctly for each variant when using Ellucian Experience in Spanish locale variants.
    • The issue in which the Select All check box in the field selection window for a data source inconsistently changes status when clicked is fixed.
    • The issue in the Summarize section in which the Group By dialogs do not display a field after it is used as an ID Property is fixed.
  • The following improvements are applied:
    • In the Published APIs page list, versions of the same API sort in descending version order with the most recent version first.
    • A Clear button is added to the search input in the field selection window.
    • The StudentAid domain is added to the list of default domains.

Release 1.2.0 dependencies

API Designer dependencies are as follows:
  • Banner Integration API 9.38
  • Banner General 8.24
  • Banner Common DB Upgrade 9.39

Release 1.1.0

Ellucian API Designer v1.1.0 is a Beta minor version update to the v1.0.1 Beta release for API Designer.

Tip: Planned features or potential updates (future development)—Information about upcoming or planned features can be provided to customers by Product Management in customer communications, such as in the Ellucian Customer Center where relevant.

Release 1.1.0 enhancements

Users can:
  • Create a new draft API or create a draft of already published API.

    For details, see Create a new API draft and Create a draft copy of a published API.

  • Publish an API and republish it as major, minor or patch versions.

    For details, see API Designer versioning.

  • Export and import draft and published APIs.

    For details, see Export a single API and Import an API.

  • Deprecate or reinstate published APIs.

    For details, see Deprecate an API.

  • Delete published and draft APIs.

    For details, see Delete an API.

Release 1.1.0 updates

The following updates are applied in this release:
  • Date localization is supported.
  • Dialog boxes have improved keyboard navigation and focus control.
  • The Skip to main content accessibility button is fixed.
  • The back button in RTL languages is fixed.
  • Error messages on application startup are improved.
  • Visual improvements are made to the query section buttons and icons.
  • Users can sort roles in the Security section.
  • A date picker is added to select values when a user filters by a date field.
  • Dirty state management no longer displays Unsaved Changes Warning when there are no changes.
  • A visual indicator is added for the API version when a user views a published API.
  • Loading and progress indicators are added for user actions that require server interaction.
  • A button is added to refresh an API preview when a section is collapsed.
  • Users are redirected to the main page after a browser refresh.
  • API name and information pointers are changed.
  • Error messages because of user action-driven server errors are improved.

Release 1.1.0 issues

Ellucian is working on the following API Designer v1.1.0 issues and updates:
  • Security objects are deleted when one of the API versions is deleted when multiple versions exists. The workaround is to create the security object in Banner Access Management.
  • API data source tables with timestamp columns are not working and there is currently no workaround.
  • API schema displays the column_name property instead of the propertyName property in the API Registry.
  • With API Designer v1.1.0, users cannot:
    • Create large SQL data sets because the entities column is not a CLOB field and does not allow a user to use many large tables (The column will be changed to a CLOB field.)
    • Override a draft API that is being imported
    • Rename or delete a model

Release 1.1.0 dependencies

API Designer dependencies are as follows:
  • Banner Integration API 9.37
  • Banner General 8.23
  • Banner Common DB Upgrade 9.38

Release 1.0.1

Ellucian API Designer v1.0.1 is a Beta patch version update to the v1.0.0 Beta release for API Designer.

Versioning

API Designer v1.0.1 introduces the first phase of API versioning for API Designer.

When a user publishes an API for the first time, that version is published and saved as v1.0.0. When a user republishes the v1.0.0 API, that user is prompted to increment the version.

Tip: For the Beta release, a user can only republish an API as an incremented minor version.

The current version of a published API displays on the main page with the list of APIs in the Last Version column.

Future functionality includes the following enhancements:
  • Users will be able to publish and save an API version as a new major version, minor version, or patch version.
  • Users will be able to maintain a draft version of an API separately from the published version.
  • Users will be able to run multiple major versions of an API if multiple versions are available.

For details, see API Designer versioning.

Additional Release 1.0.1 updates

Ellucian 1.0.1 has the following updates to improve navigation, better error messaging, and accessibility fixes – including:
  • Option lists related to the +NEW button, page size, and Join button are accessible through keyboard navigation.
  • Data source lists are navigable, which means that users can select required columns by using their keyboard.
  • Labels read correctly for data source and join items.
  • The search field has a Clear All option.
  • API import error messages are added to alert users when a file cannot be imported.

Release 1.0.1 dependencies

API Designer dependencies are as follows:
  • Banner Integration API 9.36.1
  • Banner General 8.22
  • Banner Common DB Upgrade 9.37.1
