EUP bulk provisioning

You can enable EUP bulk provisioning with an Ethos Data Connect pipeline job to extract data from Banner or Colleague through user-identity-profile API endpoints. The system then pushes this data to an AWS SQS Queue, where the provisioning service can read the records.

The bulk provisioning process consists of three parts: Extract, Transform, and Load.

You can bulk provision users to multiple identity provider targets in this release of EUP, but must create a dedicated pipeline job for each target. You cannot, however, bulk provision users to targets that you have created for Okta and SCIM, and the job will fail if you create a job for these targets.

Tip: The Colleague bulk provisioning pipeline now supports all features available in the Banner pipeline, including OFFSET parameters, job report files, and bulk update operations. See Provision or update users in bulk from Colleague for details.

Extract

Fetch the user-identity-profiles API records (that is, Person records) from the Ellucian ERP (Banner, Colleague) through Ethos Proxy Fitting. You can extract data from the ERP in two ways:
  • Extract and forward all user-identity-profiles ahead to the to the SQS queue.
  • Filter user-identity-profiles records based on the Population Selection (PopSel) criteria you define for the ERP. As a result, the system only extracts and provisions data that matches the PopSel record sent in the request.

For Banner, you can enter four parameters—Application, Selection, Creator Id, and User Id—when requesting a PopSel call.

For Colleague, you can enter a single parameter, a filter code that filters the Colleague person records.

Note: If you want to extract and load all the user-identity-profile records, that is, all the person records from Banner or Colleague, leave the PopSel parameters blank when defining the parameters for the pipeline job.

Transform

Using the Banner or Colleague API, convert all EEDM JSON records into EUP agent-specific JSON records. In Transform Fitting, this is implemented. Create the Payloads in Ethos based on the EUP overall configuration, which is managed through the EUP Administrative UI.

The pipeline validates the mandatory fields for both LDAP and AD as configured. If the source field, in Banner or Colleague, for a mandatory target field is not present in the API response, Ethos would post an error. In this case, the agent cannot consume these records from the SQS queue.

Load

After the record transformation, you can make an API call to send the JSON record list to an EUP Provisioning queue in SQS. You can accomplish it by integrating SQS with an AWS API Gateway.

As part of the API Gateway, you can use an OAuth Token to authenticate API calls, which is validated by an AWS Lambda function (OAuth validation).

The EUP agent reads the messages, that is, the JSON records, and then provisions the user records to the appropriate directory service.

Provision or update users in bulk from Banner

You can create the Ethos Data Connect pipeline job to bulk provision or update users from Banner using a dedicated EUP bulk provisioning integration package provided by Ellucian. You can then run and monitor the pipeline job using the functionality in Data Connect.

Before you begin

  • Ensure that you have created and configured the necessary Ethos applications for EUP and Banner.
  • Ensure that you can access the Data Connect integration packages card on your Experience dashboard. See Set up the Data Connect Packages card in Experience for details.
  • Ensure you have the required Data Connect permissions to access the EUP bulk provisioning integration package for Banner. See Grant permissions for Data Connect integrations for details.
Tip: The Banner bulk provisioning pipeline supports the optional IDP RoleName feature. When you configure IDP role names in the EUP Administrative UI, the pipeline uses these IDP role names for provisioning operations instead of ERP role names. See Define and maintain identity provider target roles for more information about IDP role names.

Procedure

  1. Log in to Experience as an administrator in the Ethos environment where you want to run the EUP pipeline job to bulk provision users in EUP.
  2. From the Experience dashboard, use either of these methods to access the EUP bulk provisioning integration package for Banner:
    Method Description
    From the Application menu
    1. Click the applications icon in the Experience global navigation bar and then click Integration Packages.
    2. On the Integration Packages page, in the list of packages displayed at the side of this page, expand the entry for the EUP bulk provisioning package.
    From the Integration Packages card (if supported at your institution):
    1. On the Data Connect integration packages card on the Experience dashboard, click the link for the EUP bulk provisioning package.

      The title of the card on your dashboard is the name specified during card configuration by an administrator at your institution. The default title is Integration Packages.
    You must have the required Data Connect permissions for an integration package to view the link for that package in the Integration Packages card or on the Integration Packages page. The following steps assume you have the Manage permission for the EUP bulk provisioning package that you use with Banner.
    When you access an integration package in Experience, the system displays links to the pipelines for this package, both in the packages list, under the name of the package, and in the main body of the page. The list of pipelines can include different versions of the same pipeline, and you can click the link for a specific pipeline version to create, run, and manage its pipeline jobs.
  3. Click the latest version of the EUP bulk provisioning pipeline from the list.
    The system opens the page that contains a list of the existing jobs for this pipeline, if any. You can check the progress of each job on this page, manage these jobs, or create a new job.
  4. Click the New Job button, near the top of the page, to create a new EUP bulk provisioning pipeline job.
    The system opens the New Job page, which contains some sections where you can enter details for the new job, and control when to run this job.
  5. In the Basic Details section of the page, enter key information about the job.
    Field Description
    Job name (Required) Enter a descriptive name for this job. If you create multiple jobs for this pipeline, you can use this name to find this job in the list of pipelines.

    The descriptive name for the job should include the pipeline name, the environment, and an indication of the scheduled frequency. For example: Test EUP-applications-banner every 2 minutes.

    You must enter a unique name for this job. You cannot save a job with a name that matches an existing job, as the system checks for this issue and does not activate the Save button on this page if a job already exists with the name you enter in this field.

  6. In the Job Parameters section of the page, enter the parameters for this pipeline job.
    Tip: Ellucian strongly recommend that you enter values of the parameters required to define a population selection for bulk provisioning pipeline jobs. This ensures that the job provisions or updates a specific population of users to the IdP. A population is a set of Banner IDs that identify a particular cohort of students or other persons. Typical examples include first year students, active students, recent graduates, and alumni. If you do not define a population selection, the job provisions or updates all users, which adds unnecessary data to the IdP, including historical data, and requires a much longer time to complete.
    Parameter Description
    Ethos API Key (Required) Enter the API key of the Ethos application for EUP, which has credentials into the Banner Integration API Ethos application that owns the user-identity-profiles resource.

    The system uses this key to authenticate and call an API endpoint through an Ethos Proxy Fitting. Ellucian recommends that you copy the API key by opening the Ethos application in Ethos Integration, and on the Application Overview page, copy the key from the API Keys tab. You should not enter this key directly, or copy it from another application.

    The system obfuscates or masks the value of this field for security reasons by default. You can click the Show button in this field to display this value. If it already displays the value, the system displays a Hide button, instead of the Show button, which you can click to conceal the value again. If you want to add a new key, you must delete the existing key first.
    Page Limit (Optional) The page size of the Ethos API call.

    It should be between 1 to 1000, and the default value is 500. This is used to limit the JSON records fetched in a single page of an API call.
    Total Count (Optional) Enter the total count if you need to override the API response header count. Testing is easier if you do not want to extract all records based on the API total.
    Max Error Limit (Optional) The maximum error limit value after which the bulk provisioning process will stop.

    A blank value means the system will continue irrespective of the numbers of errors. If you enter a value of -1, it will stop at the first error.
    SQS API Hostname (Required) The base API URL to post messages to SQS.
    Tip: The system sets this value to eup-agent-sqs. You must not change this value for production servers.
    Application (Optional) The Application for the population selection in Banner. It is the functional area that controls the population and one of the values that uniquely identify the population in the system.

    You can locate this value in the corresponding field on the Population Selection Extract Data (GLAEXTR) page in Banner. See Population Selection Extract Data (GLAEXTR) page for more information. Ellucian strongly recommend that you define a population selection for bulk provisioning pipeline jobs, as noted.
    Selection (Optional) The Selection ID for the population selection in Banner. This ID identifies the selection, the set of rules that select the Banner IDs in the population and is one of the values that uniquely identify the population in the system.

    You can locate this ID in the corresponding field on the Population Selection Extract Data (GLAEXTR) page in Banner. See Population Selection Extract Data (GLAEXTR) page for more information. Ellucian strongly recommend that you define a population selection for bulk provisioning pipeline jobs, as noted and you must provide the Selection ID to define the selection for a job.
    Creator Id (Optional) The Creator ID for the population selection in Banner. This ID is the Oracle ID of the user who created the population selection, and is one of the values that uniquely identify the population in the system.

    You can locate this ID in the corresponding field on the Population Selection Extract Data (GLAEXTR) page in Banner. See Population Selection Extract Data (GLAEXTR) page for more information. Ellucian strongly recommend that you define a population selection for bulk provisioning pipeline jobs, as noted.
    User Id (Optional) The User ID for the population selection in Banner. This ID is the Oracle ID of the user who selected (as opposed to created) the population selection, and is one of the values that uniquely identify the population in the system.

    You can locate this value in the corresponding field on the Population Selection Extract Data (GLAEXTR) page in Banner. See Population Selection Extract Data (GLAEXTR) page for more information. Ellucian strongly recommend that you define a population selection for bulk provisioning pipeline jobs, as noted.
    IDP Label (Required) The label of the Identity Provider (IdP) target to which you want to bulk provision users with this pipeline job.

    EUP can provision users to one or more identity provider targets, where each target has a label, which identifies the target, and a platform type, the third-party identity provider service associated with the target. See Create an identity provider target for details.

    Tip: You can only enter one label when configuring a pipeline job, which means you can only bulk provision users to one target only with a single job. If you want to bulk provision users to another target or targets, you must create a dedicated pipeline job for each target.

    The label you enter here must exactly match the label you have defined for the target in the EUP Administrative UI. As such, Ellucian recommends that you copy and paste this label from the UI. It displays the label in the corresponding column of the identity provider target list, which you can access by clicking the Identity Provider Configuration link in the header bar of the UI. It also displays the label when you open a target from this list, in the Identity Provider Label field on the Global Configuration tab and with the IDP Label subtitle on the Role Provisioning Rules tab.

    If you enter an incorrect label, the pipeline job fails immediately with an error message that refers to the label issue. You cannot bulk provision users to Okta or SCIM targets in this release of EUP, and if you enter a label for these targets here, the job will also fail, again with an error message to this effect.
    Offset From Enter the Offset From value to filter user records returned by the person-filters query. The specified value determines the starting point for retrieving results. For example, setting the Offset From value to 10 will skip the first nine records and begin returning results from the tenth record onward.

    The Offset From setting enables you to identify specific users with data issues, making it easier to locate and resolve those issues. The default Offset From value is zero.

    Note: Enter a numeric value in this field. The system generates a validation error if you enter non-numeric values. Do not enter a negative value.
    Offset To Enter the Offset To value to specify the endpoint for user records returned by the person-filters query. The value determines the maximum number of records to retrieve. For example, setting Offset To to 20 will return records up to the 20th record in the result set. The default Offset To value is set to the last record of the query.
    Note: Enter a numeric value in this field. The system generates a validation error if you enter non-numeric values. Do not enter a negative value.
    Operation Type Select the operation type.
    • Create—Select this type if you only want this pipeline job run to bulk create users in the IdP, only.
    • Create/Update—Select this type if you want this pipeline job run to bulk create or update users in the IdP. That is, the job considers all users in the IdP. If a user does not exist in the IdP, it provisions a new user, based on the latest data for that user in the ERP. If a user already exists in the IdP, it updates that user, again using the latest data in the ERP.
    When selecting the operation type, consider the following issues:
    • The create or update operation sends bulk users to the real-time workflow for AgentLDAP and AgentAD, but the patch update flow for Microsoft Entra ID.
    • Ellucian strongly recommended that you use the same population selection criteria for both types.
    • A pipeline job run for the Create/Update operation type requires considerably more time to complete, compared to bulk create job runs.
    • If you expect that the pipeline job run will only create new users in the IdP, then select the Create type when configuring the job, and not the Create/Update type.
  7. In the Job Run Details section of the page, specify when you want the job to run.
    You can decide whether to run the job immediately or on a schedule that you can define in this section. See Create a pipeline job for details and examples,
  8. In the Advanced Options section of the page, modify the default settings if needed.
    See Create a pipeline job for more information.
  9. Turn on the Enable Diagnostic Log switch if you want diagnostic logs to be created for this job run.

    After the job run is complete, you can view the diagnostic logs for it using the menu in the Actions column on the job runs page for the pipeline.

    If you enable this setting, diagnostic logging is enabled only for the current job run. If you run the job again and want to generate diagnostic logs, you will need to edit the job parameters and enable the diagnostic log again. Similarly, for a scheduled job, diagnostic logging is enabled only for the first scheduled run. If you want to enable diagnostic logging for subsequent runs, you will need to edit the job parameters.

  10. Click Save to create a new pipeline job.
    The system only actives the Save button when you have entered values for all required parameters, including a unique name for the job. It does not activate the button if the name you have entered already exists.
    When you click Save, the system creates the new pipeline job and returns you to the job runs page for the pipeline. If you decided to run the job immediately, it starts the job now. Otherwise, it will run the job according to the schedule you defined.

    Click the refresh icon to update the information as the job run progresses. See Monitor a pipeline job for information on how to monitor a Data Connect pipeline job.

  11. When the job finishes, check the overall status of the job run and troubleshoot any errors.
    See Troubleshoot a pipeline job and related topics for more information. For an EUP bulk provisioning pipeline job, you can:
    • View the job report file to check the number of error records and the number of records successfully sent to SQS.
    • Check the EUP agent logs after completing the job.
    • Verify that the job run provisioned users in the respective identity providers.
    Note: If the job run fails, it might be due to specific records, while the remaining records are processed successfully. View the job reports for more details and click the View Errors link to identify the failed users.
    You can open the job report file from the Job page, in the table of job runs, by clicking the file icon in the Actions column in this table for the job. The report file is a text file, so you can view it online. You can also download the file, which contains the following entries:
    • USER GIVEN COUNT
    • POPULATION FILTER
    • IDP LABEL
    • MAXIMUM RETRIEVABLE COUNT
    • PROCESSED RECORDS COUNT
    • PROCESSED PAYLOADS COUNT
    • PROCESSED ERRORS COUNT

    For a successful job run, the error count (PROCESSED ERRORS COUNT) should be zero, whereas the values for the other counts should match.
