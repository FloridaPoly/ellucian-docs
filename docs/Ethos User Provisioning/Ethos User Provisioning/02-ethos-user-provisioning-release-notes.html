IDP Role Name mapping

This release introduces an optional IDP Role Name field in the EUP Administrative UI. This field allows you to map the role name from your ERP system to a corresponding role name in your identity provider system.

When you configure an IDP Role Name for a role, EUP uses the IDP Role Name value to check for role existence in the target identity provider and performs all user provisioning operations using this IDP Role Name instead of the ERP role name.

The IDP Role Name functionality is available in the Event Consumer and both bulk provisioning pipelines.

Note: If you are an existing customer who changes to use IDP Role Names, and you have existing users with ERP role names already provisioned in your identity provider, you are responsible for cleaning up the ERP role names in your target identity provider. EUP will not perform any operations on the previous ERP role names when you begin using IDP Role Names.

Colleague bulk provisioning pipeline enhancements

The Colleague bulk provisioning pipeline now supports the same capabilities that are available in the Banner bulk provisioning pipeline. These enhancements include:

  • OFFSET parameters: Use the OFFSET From and OFFSET To job parameters to process a subset of users in your bulk provisioning job.
  • Job report file: Generate a detailed report file that shows the results of your bulk provisioning job.
  • Bulk update operations: Update existing user accounts in your identity provider, not just create new accounts.

For more information about using these features with Colleague, see the bulk provisioning pipeline documentation.

U.A.E. support

Ellucian has now expanded its regional support for EUP in this release, to include the U.A.E.

Message ID

Users can view information about provisioning requests in the Additional Details window, which they can open from the Ethos User Provisioning Metrics page in Experience. In this release, Ellucian has added a new Message ID section to this window that contains the unique ID from BEP. It also provides a copy icon , displayed beside the ID in the window, which copies the ID in a single click. This access to the ID facilitates faster and more efficient tracking and debugging of provisioning requests from BEP to EUP.

Vanity URLs and CORS

A vanity URL, also referred to as a branding link or custom short URL, is a short, memorable, and branded web address that redirects users to a longer, more complex URL. Institutions using Provisioning Metrics can now configure and manage vanity URLs in Experience to deliver a more branded and personalized user experience. This functionality leverages CORS so that users can directly access a vanity URL from an institutional URL without having to go through an Ellucian-specific URL.

Okta API Version field

When users create an identity provider target for Okta, they must define a value for the Okta API Version field, which specifies the version EUP uses when sending requests to the Okta APIs. The values they enter for this field must conform to the format vX, where X is the version number. For example, v1, v2, and so on. The value cannot refer to the version number only (1 or 2, say) or include other characters, such as an equals sign (v=1). Ellucian has updated the corresponding documentation resources to this effect.

  • If your current EUP agent version is before 1.17.0, it is recommended that you perform a fresh install directly to EUP 1.22.0.

The new version of the agent in this release supports an additional property, oauth_Url, in the configuration file eup-agent-config.json. The value of this property depends on the region in which you have installed EUP.

  • This release includes a new version of the EUP bulk provisioning pipeline for Colleague, Version 2.1.0. Again, this is an automatic update, and institutions do not have to create new pipeline jobs for this new version.
  • This release includes a new version of the EUP agent. Ellucian has certified the EUP agent for EUP release 1.19.0 and this release.
  • This release fixes the following product defects:
    • PD0025153—EUP Agent Code-Group memberships are added without group mappings.
    • PD0025769—Bulk Provisioning is wrongly decoding acute accents.
    • PD0026361—User Already Exists error in EUP-Microsoft Active Directory (AD).
    • PD0026406—Banner-Bulk Update using wrong searchable attribute to Find Existing users.
    • PD0026412—Custom Array Extension attributes not working in EUP for proxyAddresses attribute - MCCKCSAAS.

For more information, including relevant links, see the corresponding sections below.

BEP IDs in EUP log files

The unique ID from BEP is now captured as CorrelationEventId across all EUP log components.

This enhancement improves observability by enabling administrators to trace a single user provisioning event end-to-end—from its origin in BEP through all intermediate systems to its final representation in EUP metrics.

Bulk provisioning—create and update

EUP bulk provisioning pipelines now support a new bulk create\update operation for Microsoft Entra ID, AgentLDAP, and AgentAD.

Administrators can select either bulk create or bulk create\update when configuring pipeline jobs for Banner or Colleague. This enhancement streamlines user management by allowing institutions to provision and update users in bulk within supported Identity Providers (IdPs).

Note: The bulk create\update operation typically requires more processing time than bulk create and institutions should use the same population selection criteria across both operations.

EUP agent libraries

In this release, Ellucian has moved the EUP agent from the deprecated ldapjs Node.js libraries to the latest ldapts libraries for on-premises provisioning. This ensures that the agent does not use the deprecated libraries, which are no longer supported.

Reliable message delivery to the EUP agent

This release introduces multiple enhancements to ensure reliable message delivery between the API Gateway and the EUP agent.

The connection between the API Gateway and the EUP agent has been upgraded, including new health check logic. Messages are now automatically pushed back to AWS SQS to enable manual re-entry if delivery fails, preventing message loss even when the agent is temporarily unavailable.

EUP agent upgrade

  • If your current EUP agent version is 1.17.0 and above, Ellucian strongly recommends that you use the upgrade script.
  • If your current EUP agent version is before 1.17.0, it is recommended that you perform a fresh install directly to EUP 1.21.0.

Release 1.20.0

A list of the new features and enhancements introduced in the Ethos User Provisioning release 1.20.0.

Updates for Microsoft Entra ID

Microsoft recently renamed Azure Active Directory (Azure AD) to Microsoft Entra ID.

In this release, Ellucian has updated its documentation resources and user interfaces for EUP to reflect this change. This also affects how you filter requests in the Provisioning Metrics Experience application. See Ethos User Provisioning Metrics page for details.

Pagination issue in Provisioning Metrics

This release fixes a pagination issue on the Ethos User Provisioning Metrics page. Users can apply search and filter criteria to the request list on this page, and EUP paginates the list as required after they apply these criteria.

Before the fix, the system prevented users from navigating through the paginated list. In this release, they can apply search and filter criteria and navigate through the list as expected. This fix addresses Product Defect PD0022965 in the Ellucian Customer Center.

Role limits

Previously, institutions reported that they could only add a maximum of 89 roles in the EUP Administrative UI. This behavior was because of an issue with ECP, where it incorrectly considered the number of roles to be larger than it actually was. After resolving this issue, institutions can now add the required number of roles, as expected.

This fix addresses Product Defect PD0023542 in the Ellucian Customer Center.

Support for Ellucian rebranding

Ellucian has updated all pages in the EUP Administrative UI in this release to reflect the visual identity changes introduced in its latest rebranding exercise. To accommodate the rebranding, Ellucian has also updated the UI to support the current release of the Ellucian Path Design System (Version 7.18.1). These changes have no functional impact in the component.

Release 1.19.0

A list of the new features and enhancements introduced in the Ethos User Provisioning release 1.19.0.

Upgrading the EUP agent

This release includes a new version of the EUP agent. You can download the latest version of the agent, as a .zip file, from Ellucian Downloads, which you access through the Ellucian Customer Center.

An installation of the EUP agent includes an upgrade script.
  • If you have already installed a version of the agent, after version 1.17.0, Ellucian recommends that you upgrade to the latest version of this agent using the upgrade script. You only have to provide a single parameter, the location of the version of the agent you have currently installed, during the upgrade process.
  • If you have installed an earlier version of the EUP agent, before version 1.17.0, you must upgrade to version 1.17.0 first, before you can use the upgrade script.
Note: After the upgrade is complete, run npm install command on both Windows and Linux.

UI upgrade

Ellucian have introduced a major upgrade to the look-and-feel of the EUP Administrative User Interface (UI) in this release, designed to enhance the user experience and provide a more intuitive, user-friendly UI. The key updates include:
  • Additional help icons for many fields and controls in the UI. These icons provide contextual access to help text, at the most appropriate time, for users of the UI.
  • Moving the functionality to generate OAuth credentials to the General Settings tab in the UI, instead of having to generate these credentials for individual identity provider targets. The system only activates this functionality if you have created and configured at least one AgentAD or AgentLDAP target in the UI.
  • Replacing all check boxes in the UI with switches, to match the design conventions in other Ellucian SaaS components and solutions. Also, the length of many text fields in the UI has increased, so that users can now clearly see the configuration options in these fields.
  • Updating the labels for the Configuration and Roles tabs in the UI to the more descriptive Global Configuration and Role Provisioning Rules labels, respectively.
  • Enabling users to select a searchable attribute for a role from the field mapping list for that role, rather than having to define this attribute in the UI

Deprovisioning

In this release, Ellucian have introduced some significant changes to the deprovisioning logic in EUP. When configuring deprovisioning for AgentAD and AgentLDAP identity provider targets, you can now configure role-level deprovisioning on the Global Configuration tab in the EUP Administrative UI, as part of the overall configuration of the targets for these providers. The configuration of deprovisioning based on an attribute value trigger is configured for each role, on the Deprovisioning tab for that role. Do note that the system only deprovisions a user if that user does not have an active role, and does not occur if a user has one or more active roles. See Deprovisioning and related topics for details.

Session check in the Administrative UI

To prevent accidental changes, the EUP Administrative UI now performs a session check, to ensure that you can only configure a single tenant in a single browser window. So, if you open the UI on two tabs in a window, for the same tenant, but switch tenants in one of these tabs, the system displays an informational message in the other tab, stating that it has detected a session change, with an option to reload the session. See EUP Administrative User Interface (UI) for more information.

Reprovisioning

Ellucian has introduced support in EUP for reprovisioning in this release, so that it now supports reprovisioning for Okta, AgentAD, and AgentLDAP. See Reprovisioning for details.

Bulk provisioning updates

Institutions can bulk provision users in EUP using dedicated Data Connect pipelines for both Banner and Colleague. Ellucian has introduced a new version of this pipeline for Banner, Version 4.1.0, in this release. Any existing pipeline jobs created using previous versions of this pipeline will automatically use the new version. You do not have to recreate these jobs.

The new version of the pipeline introduced in this release also resolves an issue with the payload size. Previously, this pipeline sent payloads for larger batches in a single file to process. This caused issues when large number of custom attributes are configured, which increased the payload size which was not then being processed. The new version of the Banner pipeline resolves this issue by decreasing the payload batch size that is then successfully processed in the scenario described.

A related update relates to the job report that administrators can access after they run the latest version of the pipeline job for Banner. In this release, this job report now includes additional entries, which provide information about the job run and the numbers of users it successfully provisioned, or did not provision. This can help administrators when troubleshooting bulk provisioning in their environments.

Updates

For a list of the issues addressed in Ethos User Provisioning 1.19.0, see the Related Defects and Related Enhancements tabs on the Ethos User Provisioning 1.19.0 release page in the Ellucian Customer Center.
